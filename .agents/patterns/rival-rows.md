# Rival rows

> **What:** the rows inside Rivals cards: the hub's rival rows (name, "N ahead" / "N behind" pills) and the song comparison rows on Rival Detail, Rivalry and the Duo dual-pane category cards (album art, instrument icon, title, artist, "#rank Name" pills and a rank-delta badge). **Read when:** changing a Rivals row, its status pills or its album art, or adding a new surface that compares the player with a rival.

Status: **current**, 2026-10-10. Provenance: #558 (owner report from iPhone), #603 (one card per list; Android and Windows song rows adopt R3).

## Intent

Every Rivals card says who is ahead the same way: a red or green capsule with text in it. A song comparison row also shows the song's album art, like every other song row in the app, so people recognise songs at a glance.

## Rules

1. **R1. One row component per kind, shared by every surface.** Apple: hub rows are `RivalRowContent`, song rows are `RivalSongRowContent` (Rival Detail, Rivalry, Duo `RivalDualCategoryCard`, so iPhone, iPad, Duo and Mac). Android: `RivalRow` / `RivalSongRow`, drawn like the Apple rows since #603 (hub row: green/red standing dot, name, the two pills, chevron; song row: art over the instrument icon, title, artist, R3 pills, ▲/▼ badge). Windows: `RivalRowView` / `RivalSongRowView`. A page never draws its own variant.
2. **R2. One status pill.** Standing is drawn as a capsule: the status tint at 16 % fill, a 40 % 1 pt stroke and semibold caption text in the readable tint (red text uses the lighter `RivalStatusText.red`, ≈ 6.5:1 on the dark cards). Apple `RivalStatusPill`, Android `RivalPill`, Windows `FSTRivalPillStyle`. Green is `BrandTokens.statusGreen`, red `BrandTokens.statusRed`, neutral the primary text colour. Every pill carries text, so colour is never the only signal (HIG Color: "Avoid relying solely on color … convey it another way, like text labels", **should**).
3. **R3. Song rows: "#rank Name" pills (agent decision #558; Android and Windows #603).** The bottom line of a song comparison row is two pills, "#12 Player" and "#13 Rival": the leader's green, the trailer's red, both neutral when tied. The trailing ▲/▼ rank-delta badge stays (Android `RivalDeltaBadge`: arrow, or "=" when tied, over the unsigned abbreviated gap, `RivalHeadToHead.deltaMagnitude`; Windows: the unsigned rank gap under a Segoe Fluent arrow, "=" when tied). Apple since #558, Android and Windows since #603, on every song-row surface; no score or score-delta chips (dropped with the owner's "align to the iOS design", #603), so the spoken label no longer reads a score gap. [Agent decision below](#agent-decision-apple-song-row-pills-558); [Windows decision](#agent-decision-windows-song-rows-and-one-card-603).
4. **R4. Album art leads every song row.** The row's leading column shows the song's art through the shared bounded-cache `ArtworkTile` at the native song-row size (Apple 44 pt; Android 48 dp; web 40 px), with the standard placeholder when there is none; it is decorative and hidden from accessibility (HIG Images). The instrument icon sits directly below the art; the column is vertically centred in the row, so art alone sits in the middle (owner, #558). The art comes from the catalogue the page already loads (`songsById`); no new reads.
5. **R5. One accessibility element per row, wrapping at large sizes.** A song row reads as one element: "Song, Lead, you rank 12, Rival ranks 13, you lead" (or "Rival leads", "tied"), naming the instrument when the chart is known because a combo scope lists one song once per instrument (#444; web icon alt text, Windows parity), with a 44 pt minimum height. Pills sit on one line when they fit, one per line otherwise, and at accessibility text sizes each pill wraps instead of truncating (HIG Typography: "Keep text truncation to a minimum as font size increases", **should**). A hub row reads as one Button element, "Name, N songs ahead, N songs behind" (never a "shared" count, #40), at least 44 pt tall and full width; at accessibility text sizes its "N ahead" / "N behind" pills stack one per line so no word breaks mid-word (#411; HIG Typography: "consider stacking text above secondary items"). Both row kinds keep wrapped text leading-aligned inside their link label (`.multilineTextAlignment(.leading)`). Apple tests: hosted `RivalRowAccessibilityTests` and `RivalDetailAccessibilityTests`, iPhone journey `RivalsAccessibilityJourneyTests/testRivalRowsAreReadableAtAX5`, device journeys `RivalDetailFrozenAccessibilityJourneyTests` (#444). Android (#603): `RivalHeadToHead.songRowLabel` ("Song, Lead, You rank 12, Rival rank 13, you lead by 1 rank"), a 48 dp minimum and the pills in a `FlowRow`.
6. **R6. One card per list; rows draw no card of their own (owner #603).** Owner: "Compete: Rivals cards need consolidation into a single card like iOS / Rival page: Cards have web-style which is good start but I think they should align to the iOS design / Sub-page also needs consolidation to one card". Every list of rival rows is one card with hairlines between its rows ([surface-materials](surface-materials.md) R8): the hub's and Compete's rivals cards (rows, then View All Rivals inside, [view-all-cta](view-all-cta.md) R1), each Rival Detail category, All Rivals and Rivalry. Apple: `FestivalGlassSection`. Android: `RivalPreviewRows` and Rival Detail's categories put the rows in one `GlassCard` (`fst.rivals.card`) separated by the shared `RowSeparator`; All Rivals and Rivalry, which can list hundreds of rows, keep their lazy grid in one column with no item spacing and wrap each row in a `RivalCardSegment` (`fst.rivals.card.segment`, `GlassCardSegment`), so the touching segments draw one card whose corners and outline close only at its ends. A split fold keeps them in the leading pane (`foldLaneItem`). The First Run rivals demos group their rows the same way. Material 3 Lists: a list is one container whose items are separated by dividers; the rows are the card's list items, each one Button (R5). As on the #543 boards ([leaderboard-row](leaderboard-row.md) R10), a list never draws a card per row. Rows keep their own focus/press target and spoken name; View All, sort and selection (All Rivals' wide split) are unchanged. Windows: `ItemsRepeater` cards use `RowSeparators` (a `RowSeparator` hairline in the row template); the virtualized `ListView` lists (All Rivals, Rivalry) draw the card through `GroupedRows.ApplyToContainer` slices and fade in as one card (`FadeIn.Together`, [load-transition](load-transition.md) R11).

### Agent decision: Apple song row pills (#558)

Agent decision (#558, 2026-10-09, owner may override with `/choose`). The owner asked: "Bottom row should be the red and green pills from other rivals cards. Album art should appear in these cards too- vertically centered if the only thing, above instrument icon if both present."

| Option | What you'd see | Guidance (strength) | Web / pattern precedent | Trade-offs |
|---|---|---|---|---|
| **A. "#rank Name" pills (chosen)** | "#12 You" and "#13 Rival" as hub-style capsules, the leader green, the trailer red, neutral when tied; ▲/▼ badge kept. | HIG Color "Avoid relying solely on color" (**should**): text in every pill plus the arrow badge and a spoken leader. | The hub rows' pills (R2), the exact pills the owner points at. | Least churn; keeps the wide iPad/Mac layout. |
| B. Web/Android/Windows delta chips | "You #rank" · rank-delta and score-delta chips · "Rival #rank", no trailing badge. | Same guidance. | Web `RivalSongRow`, Android `RivalSongRow`. | Not the "pills from other rivals cards"; rebuilds the row and adds scores. |

**Chose A.** No platform **must** applies; the owner's explicit words outrank web parity in the precedence table, and A reuses the one shared pill (R2) rather than adding chips. `RivalSongRowTests` pins the tints, art placement, spoken label and AX stacking.

### Agent decision: Windows song rows and one card (#603)

Agent decision (#603, 2026-10-10, owner may override with `/choose`). The owner (Android report, Windows checked as the same feature): "Compete: Rivals cards need consolidation into a single card like iOS / Rival page: Cards have web-style which is good start but I think they should align to the iOS design / Sub-page also needs consolidation to one card." Windows had the same gaps: All Rivals and Rivalry drew a card per row, the hub and Rival Detail cards had no separators, and song rows were web-style (compact "#you you · #them rival" text plus one pill; Rivalry added score and score-delta chips).

| Option | What you'd see | Guidance (strength) | Web / pattern precedent | Trade-offs |
|---|---|---|---|---|
| **A. iOS row everywhere, one card per list (chosen)** | Every song row: art over the instrument icon, title, artist, "#12 You" / "#13 Rival" pills, ▲/▼ rank gap; each list one card with hairlines. | Fluent/WinUI: "Vertical list → `ListView`" and `DividerStrokeColorDefaultBrush` for "separator lines" (winui-design); keep the platform collection and virtualisation. | iOS `RivalSongRowContent` (R3), #543 grouped boards (`GroupedRows`). | Rivalry loses the score columns; its sorts are rank-based, so nothing it sorts by disappears. |
| B. One card, keep the web full row on Rivalry | Cards consolidated; Rivalry keeps "You #rank score" · chips · "Rival #rank score". | Same. | Web `RivalSongRow`. | Two song-row layouts (breaks R1) and not "align to the iOS design". |

**Chose A.** No platform **must** applies; the owner's explicit words ("align to the iOS design", "consolidation to one card") outrank web parity, and A keeps one row component (R1) and reuses the #543 grouping rather than adding a card style.
