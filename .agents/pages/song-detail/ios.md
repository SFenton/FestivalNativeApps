# Song Detail — iPhone notes

> **What:** iPhone implementation state, native decisions, gotchas and open gaps for Song Detail. **Read when:** changing Song Detail on iPhone. Behavior: [spec.md](spec.md).

## Implemented (partial)

- `SongScorePreview` lazily loads up to **ten** typed scores per visible chart via `GET /api/leaderboard/{songId}/{instrument}?top=10&offset=0` (the batched `/all?top=10` returned 403; no speculative fallback, no nine eager requests). Separate URL/ETag from the 25-row Solo chart. States: loading, empty, error/Retry, rows, View Full.
- Hidden chart removes its card but keeps its charted Intensity; the invalid-score leeway changes each preview request.
- Shared score row with the [score accuracy](../../controls/score-accuracy/ios.md) badge (explicit FC vs graded).
- Top-toolbar Paths action when any non-Karaoke path chart is enabled ([chopt-paths/ios.md](../../controls/chopt-paths/ios.md)); official Shop action (`fst.song-detail.shop`, toolbar bag) and badge when the song is in a validated Shop feed. The PWA's floating View Paths / Item Shop pills stay native toolbar actions (installed-PWA gap #8).
- **Shop action colour (operator, 2026-09-28):** while Shop highlighting is on, the toolbar bag sits in a circle that breathes between the web's base `rgb(18 24 38 / 96%)` and the status colour — green `#1E7F46` in shop, gold `#CFA500` new, red `#EF4444` leaving (leaving wins) — over the web's 3 s ease-in-out cycle (raised cosine, `ShopStatusBreathe.intensity`) plus a matching soft glow at the peak. It runs on `TimelineView(.animation)`: a `repeatForever` state animation left a static fill because the navigation bar re-hosts toolbar items (`shopBreathe*`, `FortniteFestivalWeb/src/styles/animations.module.css:104-132,197-208`). Reduce Motion, an inactive scene or `FST_DEBUG_STILL_BACKGROUND` show the static status colour. The spoken label adds the status ("Item Shop, New in the Item Shop"). Highlighting off → plain bag. `ShopStatusTone`/`ShopStatusBreathe` in `Features/Shop/ShopStatusPulse.swift`. TODO(orchestrator): `#EF4444` has no brand token (`statusRed` is `#C62828`).
- **Text colour (operator):** all Song Detail, Paths, score-row and band-row text uses `FestivalText.primary` (white): artist, year, entry counts, empty/error text, rank, Paths field labels. Disabled Paths options use `FestivalText.disabled`. Stars on band song rows use the shared `StarRating` (web star art), never SF `star`.
- **Pinned identity (gap #6):** once the hero title's bottom edge passes under the navigation bar, a `.principal` toolbar item fades in (0.2 s; none with Reduce Motion) with 28pt art + one-line `.headline` title (`fst.song-detail.pinned-title`). It is hidden from VoiceOver while the hero is visible, so the title is never read twice; `navigationTitle` carries the song title for the back-history menu. Chosen over a pinned in-content header because the nav bar already owns the top edge on iOS (Liquid Glass scroll-edge effect) and a second sticky layer would eat card space. Scroll detection: `onGeometryChange` on the hero title in the `.scrollView` coordinate space, whose origin is the scroll view frame **below** the bar (measured iOS 26.5: frame minY 116, title maxY 49 at rest), so the rule is `maxY <= 0` (`SongDetailPinnedTitlePolicy`). Do not add `safeAreaInsets.top` to the scroll view's global minY: both are 116, which double-counts and pins the title at rest. Only the Bool is stored, so scrolling does not re-evaluate the page body every frame.
- **Leaderboard cards (gap #7, operator follow-ups):** web `InstrumentCard` layout. Above the glass card, one header element (`fst.song-detail.card-header.<instrument>`): 48pt instrument icon (scaled with `.title3`), `.title3.bold` name and, when the service sets `showLeaderboardEntryTotals`, a "`N` entries" subtitle (the in-card count line is gone); a chart with no scores reads "No scores recorded yet" (web `songDetail.noScores`), shows the web's `noScoresSubtitle` sentence in the card, and has **no** View full action (operator batch 3; View full is also hidden while loading, kept on failure). Inside: top-ten rows (the selected player's own row gets the web's purple highlight), then — like the web's spotlight footer — the selected player's own row when they are ranked outside the top ten (`fst.song-detail.spotlight.<instrument>`, `SongPreviewSpotlightPolicy`; hidden while invalid-score filtering is on, since the score index rank is unfiltered), then "View full leaderboard" as a purple Liquid Glass button (opaque purple under Reduce Transparency / contrast overrides; spoken "View full `<chart>` leaderboard", same `fst.song-detail.leaderboard.*` ID), then the selected-player history action. Rows fade in with the shared `festivalFadeInOnAppear()` via `detailFadeInOnAppear()`, which skips the fade under `FST_DEBUG_STILL_BACKGROUND` (a mid-fade frame failed an XCUITest contrast audit). Song Detail, Shop, Song Leaderboard and Player History set `festivalFadeInEnabled` off under that flag (`detailFadeTestSafe()`); Shop, Solo and History rows use the staggered `festivalFadeIn(isLoaded:index:)` through `detailStaggeredFadeIn`, which passes no index once the first screenful has settled (`FadeStagger`) so rows recreated by List/LazyVStack recycling never fade twice. Player History: the sort sheet applies live (Done only) and changing sort scrolls back to the top (`ScrollViewReader`, operator rule); the Solo chart and Shop have no sort. The Paths text table puts the Note (fret) column on its own line: five 20pt cells overflowed a fifth of a phone card into a strip that failed the contrast audit. Band leaderboard cards are not on Song Detail yet, so "band leaderboards last" has nothing to order; score rows already put the score before the gold accuracy badge, and Intensity is already an icon grid with spoken labels. No separate "Leaderboards" header.
- **No hero Shop chip (operator):** the "Item Shop: New/Leaving" chip under the title was removed; the pulsing toolbar action and its spoken status carry it.
- **FC badge:** full-combo accuracy follows the web's `goldOutlineSkew` — gold bold italic `98%` (no "FC" prefix), transparent fill, 2pt gold outline sheared -8° (`GoldSkewBadgeShape`); "FC" only when a full combo has no accuracy. The outline is inset before shearing and drawn with `strokeBorder`; the text is italic, not transformed. The badge is one accessibility element with the fixed 96pt frame, and the FC fill is `black.opacity(0.001)`, not `.clear`: SwiftUI drops a clear fill, so the inset stroke became the only drawn path and the reported frame shrank to 94pt, splitting the badge column (`assertAlignedScoreColumn`); a `transformEffect` widened it the same way. Shared with the Solo chart, as on the web. Spoken labels unchanged. TODO(orchestrator): [score-accuracy/ios.md](../../controls/score-accuracy/ios.md) still calls the white-bordered badge an intentional deviation; update it (outside this lane's files).
- Intensity card now shows the real `InstrumentIcon` per charted instrument instead of its text label (the icon carries `instrument.label` as its own accessibility label, so nothing is lost for VoiceOver), and both the Intensity card and each `SongScorePreview` card use `festivalGlass(.card)`. "Intensity" and each chart's own heading use the shared white Title Case `FestivalSectionHeader`, not raw `Text(...).font(.title2.bold())`. Lead/Pro Lead's icon (chips too) now uses the keys variant when `Song.usesKeyboardIcon` (`sig == "Keyboard"`).
- `SongScorePreview` adds a "View `<chart>` score history" action, shown only when a player is selected, pushing `AppRoute.playerHistory(song, instrument)`. Web's only route to `/history` is a "View all scores" action under the selected player's own score-history graph (`ScoreHistoryChart.tsx`, `SongDetailPage.tsx:675`), gated on that player having history for the song; that graph is not ported, so this per-chart action is the interim equivalent, gated only on player selection rather than on having history data. The web solo leaderboard page has no `/history` link of its own to mirror.

## Native decisions

| Web | iPhone | Why |
|---|---|---|
| View All after the ten rows | View Full at the card bottom, as on the web (moved back from the top 2026-09-28; the old offscreen-tap stall is re-covered by `testSongDetailShowsTopScorePreviewAndFullChart`) | Parity |
| View All only when rows exist | View Full also when loading/empty/error | An empty or failed preview must still reach the full chart |
| Reload on reappear | Preview cards and the Shop list keep rows already loaded for the same request key when `.task` re-runs after a pop; reloading flashed a spinner and collapsed cards (the Song → Song Leaderboard → Back jitter) | Stable Back |
| Pinned art + marquee title header | Nav-bar principal title after the hero scrolls away | Native bar owns the top edge; see Implemented |
| FAB Paths, bottom controls | Top toolbar Paths action; in the sheet a one-line title/zoom/Close bar, the path image/table filling the sheet, and a compact bottom row of Instrument / Difficulty / View menu pickers on glass capsules (web-like, operator audit 2026-09-28; stacks vertically at accessibility sizes) | Content gets the space |
| Four icon-based Intensity meters with header artwork | Icon + `DifficultyMeter` per charted instrument, no header artwork treatment yet | Incremental: icons landed this wave, the fuller header redesign has not |
