# Song Detail — iPhone notes

> **What:** iPhone implementation state, native decisions, gotchas and open gaps for Song Detail. **Read when:** changing Song Detail on iPhone. Behavior: [spec.md](spec.md).

## Implemented (partial)

- `SongScorePreview` lazily loads up to **ten** typed scores per visible chart via `GET /api/leaderboard/{songId}/{instrument}?top=10&offset=0` (the batched `/all?top=10` returned 403; no speculative fallback, no nine eager requests). Separate URL/ETag from the 25-row Solo chart. States: loading, empty, error/Retry, rows, View Full.
- Hidden chart removes its card but keeps its charted Intensity; the invalid-score leeway changes each preview request.
- Shared score row with the [score accuracy](../../controls/score-accuracy/ios.md) badge (explicit FC vs graded).
- Top-toolbar Paths action when any non-Karaoke path chart is enabled ([chopt-paths/ios.md](../../controls/chopt-paths/ios.md)); official Shop action (`fst.song-detail.shop`, toolbar bag) and badge when the song is in a validated Shop feed. The PWA's floating View Paths / Item Shop pills stay native toolbar actions (installed-PWA gap #8).
- **Shop action colour (operator, 2026-09-28):** while Shop highlighting is on, the toolbar bag sits in a circle that breathes between the web's base `rgb(18 24 38 / 96%)` and the status colour — green `#1E7F46` in shop, gold `#CFA500` new, red `#EF4444` leaving (leaving wins) — over the web's 3 s ease-in-out cycle (raised cosine, `ShopStatusBreathe.intensity`) plus a matching soft glow at the peak. It runs on `TimelineView(.animation)`: a `repeatForever` state animation left a static fill because the navigation bar re-hosts toolbar items (`shopBreathe*`, `FortniteFestivalWeb/src/styles/animations.module.css:104-132,197-208`). Reduce Motion, an inactive scene or `FST_DEBUG_STILL_BACKGROUND` show the static status colour. The spoken label adds the status ("Item Shop, New in the Item Shop"). Highlighting off → plain bag. `ShopStatusTone`/`ShopStatusBreathe` in `Features/Shop/ShopStatusPulse.swift`. TODO(orchestrator): `#EF4444` has no brand token (`statusRed` is `#C62828`).
- **Text colour (operator):** all Song Detail, Paths, score-row and band-row text uses `FestivalText.primary` (white): artist, year, entry counts, empty/error text, rank, Paths field labels. Disabled Paths options use `FestivalText.disabled`. Stars on band song rows use the shared `StarRating` (web star art), never SF `star`.
- **Pinned identity (gap #6):** once the hero title's bottom edge passes under the navigation bar, a `.principal` toolbar item fades in (0.2 s; none with Reduce Motion) with 28pt art + one-line `.headline` title (`fst.song-detail.pinned-title`). It is hidden from VoiceOver while the hero is visible, so the title is never read twice; `navigationTitle` carries the song title for the back-history menu. Chosen over a pinned in-content header because the nav bar already owns the top edge on iOS (Liquid Glass scroll-edge effect) and a second sticky layer would eat card space. Scroll detection (issue #315): the hero reports its title's bottom edge in the scroll content (`SongHeaderText(onTitleBottomChange:)` in `songHeaderContentSpace()`), and the `ScrollView`'s `songHeaderScrollAway(headerBottom:)` pins the title once the scroll offset reaches it, the same reader the song leaderboards use. The former `.scrollView`-space frame (`SongDetailPinnedTitlePolicy`, still Full Rankings') moves whenever the bar lays out again; content coordinates do not. Hosted `SongHeaderTextTests.heroTitleBottomIsMeasuredInTheContent`. Only the Bool is stored, so scrolling does not re-evaluate the page body every frame. **iPhone Duo (owner-approved, #363):** the same item is used under the vertical bar, where `songBarTitleKeepsBarVisible()` stops iOS 27 minimizing the navigation bar on scroll, so nothing shows at the top while the hero is visible and the pinned title appears once it scrolls away (not the R14 system title; `DuoSongTitleJourneyTests`).
- **Leaderboard cards (gap #7, operator follow-ups):** web `InstrumentCard` layout. Above the rows, one header element (`fst.song-detail.card-header.<instrument>`): 48pt instrument icon (scaled with `.title3`), `.title3.bold` name and, when the service sets `showLeaderboardEntryTotals`, a "`N` entries" subtitle (the in-card count line is gone); a chart with no scores reads "No scores recorded yet" (web `songDetail.noScores`), shows the web's `noScoresSubtitle` sentence in the card, and has **no** View full action (operator batch 3; View full is also hidden while loading, kept on failure). Below it: top-ten rows as separate glass rows (the selected player's own row gets the web's purple highlight), then — like the web's spotlight footer — the selected player's own row when they are ranked outside the top ten (`fst.song-detail.spotlight.<instrument>`, `SongPreviewSpotlightPolicy`; hidden while invalid-score filtering is on, since the score index rank is unfiltered), then "View full leaderboard" as a purple Liquid Glass button (opaque purple under Reduce Transparency / contrast overrides; spoken "View full `<chart>` leaderboard", same `fst.song-detail.leaderboard.*` ID). Rows fade in with the shared `festivalFadeInOnAppear()` via `detailFadeInOnAppear()`, which skips the fade under `FST_DEBUG_STILL_BACKGROUND` (a mid-fade frame failed an XCUITest contrast audit). Song Detail, Shop, Song Leaderboard and Player History set `festivalFadeInEnabled` off under that flag (`detailFadeTestSafe()`); Shop, Solo and History rows use the staggered `festivalFadeIn(isLoaded:index:)` through `detailStaggeredFadeIn`, which passes no index once the first screenful has settled (`FadeStagger`) so rows recreated by List/LazyVStack recycling never fade twice. Player History: the sort sheet applies live (Close only, [modal-shell](../../patterns/modal-shell.md) R4) and changing sort scrolls back to the top (`ScrollViewReader`, operator rule); the Solo chart and Shop have no sort. The Paths text table puts the Note (fret) column on its own line: five 20pt cells overflowed a fifth of a phone card into a strip that failed the contrast audit. Band leaderboard previews come last, after every instrument card (see below); score rows already put the score before the gold accuracy badge, and Intensity is already an icon grid with spoken labels. No separate "Leaderboards" header.
- **Hero text (issue #315, pattern [song-header](../../patterns/song-header.md)):** the hero's title (`.title.bold()`), artist and year come from the shared `SongHeaderText`, the same column as Song Leaderboard: full width beside the art, one marqueeing line each, Reduce Motion truncation and accessibility-size wrapping from `MarqueeText`. The pinned bar title is the shared `SongBarTitle`, as wide as the bar leaves between Back and the trailing actions (no fixed cap; the #315 review found a 240 pt cap leaving the slot half empty). Hosted `SongHeaderTextTests` check its width; there is no XCUITest journey because XCUITest cannot query the pinned title after a swipe (master's `SongDetailJourneyTests.testSongDetailPinnedTitleAndCardLayout` fails the same way).
- **No hero Shop chip (operator):** the "Item Shop: New/Leaving" chip under the title was removed; the pulsing toolbar action and its spoken status carry it.
- **FC badge:** full-combo accuracy follows the web's `goldOutlineSkew` — gold bold italic `98%` (no "FC" prefix), transparent fill, 2pt gold outline sheared -8° (`GoldSkewBadgeShape`); "FC" only when a full combo has no accuracy. The badge stays a plain `Text` element (hittable inside the Solo row's link) with a centred `stroke` on the full, non-inset sheared path (`GoldSkewBadgeShape`); the text is italic, not transformed. SwiftUI derives the reported frame from the drawn shapes: an inset `strokeBorder` reported 94pt and a `transformEffect` widened it, both splitting the badge column (`assertAlignedScoreColumn`); a container element with `.contentShape(.accessibility, …)` fixed the frame but was no longer hittable inside the row link. Shared with the Solo chart, as on the web. Spoken labels unchanged. TODO(orchestrator): [score-accuracy/ios.md](../../controls/score-accuracy/ios.md) still calls the white-bordered badge an intentional deviation; update it (outside this lane's files).
- Intensity card now shows the real `InstrumentIcon` per charted instrument instead of its text label (the icon carries `instrument.label` as its own accessibility label, so nothing is lost for VoiceOver), and both the Intensity card and each `SongScorePreview` card use the material `festivalCard()` (issue #291). "Intensity" and each chart's own heading use the shared white Title Case `FestivalSectionHeader`, not raw `Text(...).font(.title2.bold())`. Lead/Pro Lead's icon (chips too) now uses the keys variant when `Song.usesKeyboardIcon` (`sig == "Keyboard"`).
- **Score History section (operator batch 6.39; #324):** the selected player's history is a section of this page after Intensity, with the shared `InstrumentSelector`, the best five scores and, above five, View All Scores to the separate sortable Score History page ([view-all-cta](../../patterns/view-all-cta.md) R8); see [player-history/ios.md](../player-history/ios.md). The per-card "View `<chart>` score history" link (the only "Your score…" text on these cards, batch 6.38) is gone.
- **Loading (operator batch 6.41):** only a spinner (`fst.song-detail.loading`) shows until every visible chart's top ten (`SongDetailPreloader`, in parallel) and the history have loaded; then the header, Intensity, Score History and cards fade in with the web stagger. Only content visible at load fades: `.festivalFadeInScope()` closes the fade once the page scrolls, so cards the `LazyVGrid` builds (or rebuilds) later appear instantly (issue #30). Cards adopt the preloaded reads (`SongScorePreview(preloaded:)`) and still reload themselves on a new publication, leeway or Retry; later history reloads are quiet.
- **One leaderboard row design (operator batch 7.4):** no card around a chart's rows; each row is its own 48 pt card (`RankingRowSurface`; material since issue #295), the selected player's row the web's `purpleHighlight` with bold rank and name (batch 6.42); failures and empty charts sit on their own glass card. "View full leaderboard" is the shared `PurpleActionLabel` (batch 6.29). Accuracy pills are sized for "XX.X%" (batch 7.8).
- **Season column on wide cards (issue #32):** the web `InstrumentCard` shows season (and difficulty, accuracy) only when the card is at least 520 px wide (`resolveTopScoresColumns`, `topScoresLayout.ts`; stars from 768). `SongScorePreview` measures its rows column (`onGeometryChange`) and fits the card with `LeaderboardRowColumns.fit(.topScores, …)` ([leaderboard row columns](../../controls/leaderboard-row-columns/ios.md), issue #37), which also gives the top ten and spotlight one rank/score width; the `ScoreSeasonPill` sits before the score (blank placeholder when a row has no season, like the web's hidden pill). iPhone cards are always narrower, so iPhone shows none; iPad/Mac widths will. The Solo chart now shows season from 520 pt of chart width too. Open gaps: difficulty pill and the 520 accuracy gate are not ported (accuracy pills stay, operator batch 7.8). Test: `songLeaderboardEntryRowSeasonColumnFollowsTheCard`.
- **Rows open profiles (issue #33):** each preview row with an account is one `NavigationLink` button (web `InstrumentCardRowLink`) with the in-card chevron: another player → `.player`, the selected player's own top-ten row → `.statistics`, the spotlight footer → `.songLeaderboard(…, page, focusSelected: true)` at the page containing their rank, where the row is scrolled to the centre (web `navToPlayer`, hint "Jumps to your position in the full leaderboard"); anonymous rows stay inert (`SongPreviewSpotlightPolicy.route`). VoiceOver reads one button per row ("#2, Fixture Player 2, 99,800, Full combo, accuracy 98%") with a hint naming the destination. Child texts no longer inherit the row's `fst.song-detail.preview-row.*` ID, so UI tests query them through the row button (`previewText` in `SongDetailJourneyTests`). `FST_DEBUG_SONG` pushes Song Detail with `navigationDestination(item:)`, so a row tapped there lands *under* it; drive through `fst.songs.row.*` instead.
- **Band previews (issue #34):** after the instrument grid, one section per band size (Duos, Trios, Quads; `SongBandPreviewSection.swift`, web `SongBandLeaderboardPreview`), all fed by **one** keyless read, `GET /api/leaderboard/{songId}/bands/all?top=10[&accountId=]` (`FestivalAPI.songBandLeaderboards`, query-only `accountId`, no selected-profile headers; the only band read on this page). Each section: a `.title3.bold` header (`fst.song-detail.band-header.<type>`) with "No scores recorded yet" or, when `showLeaderboardEntryTotals`, "`N` bands"; then up to ten band rows (`fst.song-detail.band-row.<type>.<i>`) as `RankingRowSurface` glass cards, each a `NavigationLink` to Band Detail (`.band`) with a chevron, members with instrument icons, then rank, score, `StarRating` and accuracy pill; the selected player's band (`selectedBandEntry ?? selectedPlayerEntry`, matched by `bandId` or `bandType`+`teamKey`, `SongBandLeaderboardPreview.isSameBand`) gets the purple highlight in place or is appended after the ten (`fst.song-detail.band-selected.<type>`). The appended row follows the solo spotlight's rule (issue #307, `SongBandRowNavigation.previewRoute`): it opens `.songBandLeaderboard(song, bandType:, page:, focus:)` at the page containing its rank, with the band's row highlighted and scrolled into view (hint "Jumps to your band's position in the full leaderboard"); a selected band inside the ten, like every other row, opens Band Detail (hint "Opens band"); then "View full leaderboard" (`PurpleActionLabel`, spoken "View full `<type>` leaderboard", `fst.song-detail.band-leaderboard.<type>`) to `.songBandLeaderboard`. Empty sizes show the web's `noBandScoresSubtitle` sentence on a glass card (`fst.song-detail.band-empty.<type>`) and no View full (as the web). A failed read shows an error card with Retry per section (`fst.song-detail.band-retry.<type>`); the read never blocks the page spinner. VoiceOver reads one button per row ("Rank 1, A + B, score 94,500, 5 stars, full combo, accuracy 96.5%", prefixed "Your band, " when selected; `SongBandPreviewText`). Responses are validated (`SongBandLeaderboardsResponse.validate`: same song, known unique sizes, `count` = rows, rows filed under their own size) and reloaded on a new publication or selected player. Quick Links gain `band-<type>` rows after the instruments. No promoted selected-band section: native has no selected-band identity yet. Tests: `FestivalAPIBandsTests` (`songBandPreview*`), `BandsRenderTests` (`songBandPreview*`), XCUITest `SongDetailJourneyTests.testSongBandPreviewsLinkToBandsAndFullBandLeaderboard` (dedicated mock on `127.0.0.1:18934`; skips when absent), `QuickLinksOrderJourneyTests.testSongDetailMenuListsSectionsInPageOrder`. Its `.all` audit skips elements under the top bar (shared toolbar avatar, text under the scroll-edge fade) and re-measures any other contrast finding on the composited screenshot (`assertHeaderContrast`): the auditor flagged the white empty-state sentence on its glass card although it renders far above 4.5:1.
- **Instrument cards on a fold (#343):** `SongDetailCardGrid` lays the cards in adaptive 360 pt columns, `HingeGrid` normally and the eager `HingeEagerGrid` at accessibility sizes (a lazy grid of tall AX5 cards hung the main thread in a lazy-layout loop). Both follow [hinge-columns](../../patterns/hinge-columns.md): in an iPhone Duo book pose the two-card row's gutter is the fold at every text size, and unfolding reflows in place. Cards sharing a row start at the same top edge in both grids, flat and folded (R8, #365: the lazy grid had centred the shorter card, so Pro Lead sat lower than a taller Pro Bass).

## Native decisions

| Web | iPhone | Why |
|---|---|---|
| View All after the ten rows | View Full at the card bottom, as on the web (moved back from the top 2026-09-28; the old offscreen-tap stall is re-covered by `testSongDetailShowsTopScorePreviewAndFullChart`) | Parity |
| View All only when rows exist | View Full also when loading/empty/error | An empty or failed preview must still reach the full chart |
| Reload on reappear | Preview cards and the Shop list keep rows already loaded for the same request key when `.task` re-runs after a pop; reloading flashed a spinner and collapsed cards (the Song → Song Leaderboard → Back jitter) | Stable Back |
| Pinned art + marquee title header | Nav-bar principal title after the hero scrolls away | Native bar owns the top edge; see Implemented |
| FAB Paths, bottom controls | Top toolbar Paths action; in the sheet a one-line title/zoom/Close bar, the path image/table filling the sheet, and a compact bottom row of Instrument / Difficulty / View menu pickers on glass capsules (web-like, operator audit 2026-09-28; stacks vertically at accessibility sizes) | Content gets the space |
| Four icon-based Intensity meters with header artwork | Icon + `DifficultyMeter` per charted instrument, no header artwork treatment yet | Incremental: icons landed this wave, the fuller header redesign has not |
