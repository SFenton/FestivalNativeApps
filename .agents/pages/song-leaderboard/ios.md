# Solo leaderboard — iPhone notes

> **What:** iPhone implementation state and decisions for the Solo chart. **Read when:** changing the Solo page on iPhone. Behavior: [spec.md](spec.md).

- Implemented: 25-row pages via the shared `RankingsPagerView` (also used by [full-rankings/ios.md](../full-rankings/ios.md) and band rankings) — first/previous/info/next/last with ≥44pt actions on an opaque two-row Fluent plate that stays readable over art; enabled/disabled boundaries tested. Same `fst.song-leaderboard.page-*` IDs as before this became a shared component. The web uses icon-only portal controls — intentional Fluent deviation, not pixel parity.
- Nav chrome (2026-09-28, operator: navigation "doesn't look good or native"): a `.principal` toolbar item replaces the concatenated `"Song - Instrument"` title with an `InstrumentIcon` beside a two-line song-title/instrument-label stack, plus inline title display mode. Rows are glass cards (`festivalGlass(.card)`, hidden separators) instead of a flat opaque table.
- Rows now navigate: tapping opens `AppRoute.player`, or `.statistics` for the currently selected player — closing the previously-open "rows cannot open player profiles" gap. `SongLeaderboardEntryRow`'s own initializer is unchanged, so Song Detail's preview keeps working.
- Accuracy/FC via the shared row ([score-accuracy/ios.md](../../controls/score-accuracy/ios.md)); the full List keeps separate row and `fst.score.accuracy.*` IDs.
- AccessibilityXXXL: the fixed song header left no usable List viewport and `99,900` wrapped into `99,90` + `0`. The header/disclosure now scroll above scores inside the same List, and rank/name, whole score and accuracy each get a full-width line; ordinary sizes keep compact columns.
- A live probe decoded one real 25-row Lead chart (2026-09-25); tapping into a live Solo page on device is not yet shown.
- **Selected-player spotlight (Lane L2, 2026-09-28):** the selected player's row gets an accent-purple border overlay when it's on the current page (`.overlay { RoundedRectangle.stroke(BrandTokens.accentPurple) }` at the `SoloLeaderboardScreen` call site — `SongLeaderboardEntryRow` itself is untouched, so Song Detail's preview keeps working). A pinned footer below the `List` (above `RankingsPagerView`) shows the selected player's score for *this exact song/instrument* whenever they have one, sourced entirely from the already-loaded `FestivalSession.selectedPlayerScores[song.songId]?[instrument]` — **no extra network read**, matching the web's `playerData.scores.find(...)` (`LeaderboardPage.tsx:88-91`). Tapping the footer opens Statistics, matching the web's footer (`navigate('/statistics')`, `LeaderboardPage.tsx:476-500`). **Native addition beyond web:** when the selected player's row isn't on the visible page, a trailing jump button (`fst.song-leaderboard.spotlight-jump`) calls `move(to: LeaderboardPaging.page(forRank:pageSize: 25))` to re-page straight to it — the real web footer never repaginates (it's a fixed portal over whatever page is loaded), so this is a deliberate native improvement for a paginated `List`, not parity. IDs: `fst.song-leaderboard.spotlight-footer`, `fst.song-leaderboard.spotlight-jump`. VoiceOver: the footer's row label is "Your rank, `<ordinal>`." (`RankingFormatting.ordinal`); the main list's highlighted row keeps its default combined label (its `.accessibilityElement(children: .contain)` container isn't a good fit for a full-label override — deferred, border-only highlight there for now). Hosted in `SoloLeaderboardSpotlightHostedTests.swift` (visible/highlighted, off-page/jump-control, and no-selection states), built via the real `selectPlayer`/`viewPlayer` path so the score index is never hand-assembled.
- Open: announced page change and stable VoiceOver focus (unchanged by the 2026-09-28 nav pass — `soloLeaderboardVisualStates` was re-run and still passes, which does not by itself certify either); full accessibility-label override for the highlighted main-list row (see above). Warm-offline "last seen scores" banners predate online-only — remove, don't extend.
