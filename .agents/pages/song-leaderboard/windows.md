# Solo song leaderboard — Windows notes

> **What:** what the Windows per-song solo leaderboard implements and its open gaps. **Read when:** changing `windows/Festival.App/Pages/LeaderboardsSongPage*`, `Controls/LeaderboardEntryRow` or `SongLeaderboardViewModel`. Behavior: [spec.md](spec.md); iPhone reference: [ios.md](ios.md).

## Implemented

- Route `AppRoute.SongLeaderboard(songId, instrument, page)` (Song Detail's "View Full Leaderboard"). The song resolves from the session catalogue (missing → failure state). `GET /api/leaderboard/{song}/{instrument}?top=25&offset=` with `leeway` (one decimal) only when Settings filters invalid scores. Page count uses `localEntries ?? totalEntries`; an explicit out-of-range page is corrected once totals arrive; superseded responses are dropped.
- Header scrolls with the rows inside the one `ScrollViewer` (operator batch 7.8: it scrolls away under the title bar; no gap above row one); the pinned row and pager float over the bottom of the rows (`Controls/BoardFooter`, web fixed footer).
- Footer edge (issues #93, #308, web `useScrollFade`, [scroll-edge](../../patterns/scroll-edge.md) R2–R4/R7): rows are clear at the footer's top (the **Your Page** button when shown), opaque 36 epx above it on a linear ramp, and hidden beneath it. The ramp's depth is `BoardFooterEdgeFade.FadeDepth` = min(remaining scroll, 36), so it shrinks over the last 36 epx of scroll and nothing is dimmed at the end (`Controls/BoardFooterFade` on `BoardFadeSource`/`BoardFadeHost`, `Festival.Core/Domain/BoardFooterEdgeFade`). Contrast themes, Windows transparency effects off, Increase Contrast and Less Transparency make the depth 0: a hard cut at the footer's top, so rows never show between or behind the footer's controls (before #308 those modes turned the mask off and rows showed between the pager buttons). Under a contrast theme a window-colour `FooterPlate` (footer height, not hit-testable) sits behind the footer so row text does not show between the pager buttons or beside **Your Page** (issue #197). Composition-only: hit testing, focus and UIA still use the real rows.
- End-of-list spacing (issue #293): scrolled to the end, the last row sits one row gap (4 epx) above the footer's top: the **Your Page** button, the pinned row, or the pager when no player or no score is selected (the missing row collapses, no empty slot). `BoardFooter.Inset` alone provides that gap; `ScrollContent` has no bottom padding (its old 4 epx doubled it to 8). Journeys `song-board-end-gap-anonymous|no-score|player` in `tools/windows/journeys/boards-ui.json` check it with `assertgap`; verified live (Through the Fire and Flames / Lead, `SFentonX` and anonymous, 2026-10-04). The header has no gradient band; it sits on the song-cover backdrop like Song Detail's.
- Rows: rank and score columns share the widest rank/score text on the page **including the pinned row** (web `computeRankWidth` / score `ch` width; `SongLeaderboardRowViewModel.RankChars`/`ScoreChars`), so the pinned row lines up with the list (batch 7.9); **Your Page** sits above the pinned row rather than beside it. Accuracy uses the web `AccuracyDisplay` (`ScoreBadge`): tinted pill or skewed gold FC outline, fixed 58 epx (fits "XX.X%"), no "FC" prefix (batches 7.1/7.11).
- Header ([song-leaderboard-header](../../patterns/song-leaderboard-header.md)): the shared `Controls/SongLeaderboardHeader` (also the band song board's, issue #317; it skips the cover under Save Data or `--no-art`): 80 epx static cover (the shell background switches to the song cover, `IBackdropPage`), title (heading 1) and artist as one-line marquees ([song-header](../../patterns/song-header.md) R2), instrument icon (keys variant for keyboard songs) + label, "N <Instrument> entries" only when `showLeaderboardEntryTotals` and the total is above zero (web `LeaderboardPage` `totalEntries > 0`; an empty board never says "0 Bass entries", issue #197). Invoking the header (`fst.song-leaderboard.song`, one flat button named by the song title) opens Song Detail (web `LeaderboardPage` `onTitleClick={goToSongDetail}`, #317 review). Journey `song-board-header` (`tools/windows/journeys/boards-ui.json`) asserts the title, artist, instrument and total text and their order, then invokes the header and lands on Song Detail.
- Rows (shared `LeaderboardEntryRow`, operator batch 7.7; web `LeaderboardEntry` column order): rank, name, season (rows from 520 epx), score, accuracy badge (gold skewed outline for FC), stars (rows from 700 epx), chevron; separate frosted rows 4 epx apart; below 420 epx the column gaps tighten. The selected player's row opens Statistics, anyone else their profile; rows without a usable account ID are not interactive.
- Selected player: highlighted in place, and pinned above the pager from `FestivalSession.SelectedScoreIndex` (no extra read), only while `IsSelectedProfileCurrent` (same publication). With invalid-score filtering on, an invalid score uses its valid variant (shown unranked, no jump) or no pinned row. **Your page** jumps to their page when their row is elsewhere; the list scrolls to the highlighted row after a page change. The web footer never re-pages (native addition, as on iPhone).
- Shared pager (`fst.song-leaderboard.page-*`; batch 7.4: keyboard paging, hidden for one page; journey `tools/windows/journeys/boards-ui.json`), Back restores the page (kept view model), F5 reloads. Only page bounds disable its buttons: the async page commands allow concurrent runs (`RankingsPagerViewModel`), because a running command reported CanExecute false, the focused button disabled itself and the pager handed focus to another one, so a second Enter on **Next page** jumped to the last page (issue #197). Superseded loads are dropped, so a second press during a load is safe.
- Row automation: the pinned row's ID goes on its inner Button through `LeaderboardEntryRow.RowAutomationId` (an ID set on the UserControl never reaches UIA, so the pinned row used to repeat the list row's `.row.<accountId>`). A name trimmed by the column (narrow windows, large text) shows in full as the row's tooltip; Narrator already reads it in the row name. The name reads ", season N" only while the season shows (rows from 520 epx; issue #262 — before it the season was never read), and the season text is `fst.score.season.<accountId>` (Raw, for `raw=` tests).
- Live contrast switch (issue #242): `LeaderboardEntryRow` sets its surface, text and accuracy-badge brushes in code (`ApplySurface`). Switching a contrast theme on or off with a board open used to leave the rows' translucent dark fill, the purple pinned row and the gold badge in place, with system text backplates on top. Rows now re-apply on `ContrastTheme.Changed` (subscribed on Loaded, unsubscribed on Unloaded, re-applied through `DispatcherQueue.TryEnqueue`, as in `StarRow`). The row hover/pressed tints and the pager's disabled-button brushes are inline theme dictionaries instead of `StaticResource` aliases, which kept the old theme's brush. Under a contrast theme, the selected or pinned row's FC badge draws its outline and text in HighlightText on the Highlight fill, with no backplate. It used to draw them in WindowText, which Windows covered with a backplate.
- Load-swap gate (issue #71): first load, F5, invalid-score leeway reloads and paging run the shared web sequence (300 ms content-out, centered ring, 500 ms ring-out, row stagger). The new rows/empty/error state commits while hidden and rapid selections are latest-wins; Reduce Motion swaps immediately. The rows (or "No scores yet.") and the pinned row (with **Your Page**) take the content role; the song header and pager stay in place while another page loads (issue #93, web `PaginatedLeaderboard` keeps its pagination mounted; `ShowContent` follows the committed state only). A failed first load fills the page with the failure (`ShowPageError`). A failed reload after the board has shown (paging, F5, leeway) keeps the song header and shows the failure with **Retry** in the rows' place (`ShowRowsError`, the inline `RowsStatus`; issue #283, web `LeaderboardPage` keeps its header above `EmptyState`). The pinned row, **Your Page** and pager hide until a retry succeeds (load-transition R4; `PinnedRowGate.Begin(hidden:)` keeps the pinned row hidden through a same-page retry, and `ShowSpotlight` is false while failed). Keyboard focus never falls to the title bar's Back button. When the failure hides the focused pager button, or Retry's own card hides during its reload, `Controls/FailedReloadFocus` moves focus to **Retry** once the swap settles, or to the pager's first button when the retry loaded (agent decision, issue #283). Full Rankings and Band Rankings use the same hand-off.
- Pinned row entrance (issue #295): the pinned row used to sit outside the gate, so it popped in under the ring before the rows and never faded. On the first load and when the invalid-score leeway changes it now fades out with the old rows (opacity only, so its slot, the pager and the footer edge stay put) and fades in with the first row (`PinnedRowReveal.RevealDelay`, row 0's 125 ms stagger); paging, F5 and Retry keep it visible and usable beside the ring, like the web footer (issue #270, [load-transition](../../patterns/load-transition.md) R2 agent decision, `PinnedRowGate` keyed by the leeway). A score index that arrives after the rows are shown fades the row in on its own (`PinnedRowReveal.FadesOnArrival`). The gate (`LoadSwapVisual` with `IsGated`, XAML opacity transition) sits on the `SpotlightGate` `LoadSwapGate`, which also removes the hidden row from UI Automation, and the entrance (`FadeIn.Play`, composition visual) on the inner `SpotlightPanel`: with both on one element the app crashed in testing (stowed exception 0xc000027b), as the rows avoid by gating the repeater and animating its children. Reduce Motion shows the pinned row with the rows. Live-verified on (Don't Fear) The Reaper / Lead with `SFentonX` (first load, paging, **Your Page**, tap to Statistics, `--reduce-motion`), 2026-10-04.

Debug build, single 3840×2160 monitor at 300%; `a11y_matrix.py --scan` (with a session-local wrapper adding Text size 200% and display scale 100%/150%) on 8 fixture states (anonymous p1, selected p1/p2, out-of-range page, single page, empty, failure, invalid-score filter), plus live-service runs of Through the Fire and Flames / Lead with `SFentonX` selected. Axe.Windows 0 errors in every run below.
