# Solo song leaderboard — Windows notes

> **What:** what the Windows per-song solo leaderboard implements and its open gaps. **Read when:** changing `windows/Festival.App/Pages/LeaderboardsSongPage*`, `Controls/LeaderboardEntryRow` or `SongLeaderboardViewModel`. Behavior: [spec.md](spec.md); iPhone reference: [ios.md](ios.md).

## Implemented

- Route `AppRoute.SongLeaderboard(songId, instrument, page, revealSelected)` (Song Detail's "View Full Leaderboard"; its selected row eleven passes its page with `revealSelected`, path `?page=N&navToPlayer=true` as web). A page change that lands on the selected row centres it once its own entrance has finished, rushing the fades still waiting so the rows it reaches fade in together (`SelectedRowReveal`; immediate under Reduce Motion; issues #307 and #323). The song resolves from the session catalogue (missing → failure state). `GET /api/leaderboard/{song}/{instrument}?top=25&offset=` with `leeway` (one decimal) only when Settings filters invalid scores. Page count uses `localEntries ?? totalEntries`; an explicit out-of-range page is corrected once totals arrive; superseded responses are dropped.
- Header scrolls with the rows inside the one `ScrollViewer` (operator batch 7.8: it scrolls away under the title bar; no gap above row one); the pinned row and pager float over the bottom of the rows (`Controls/BoardFooter`, web fixed footer).
- Keyboard (issue #409): the rows are one Tab stop with Up/Down between them; Tab goes rows → pinned row → pager, and Shift+Tab walks back to the song header. Before #409 a row reached with the arrows scrolled only to the viewport's bottom edge, under the floating pinned row and pager (WCAG 2.4.11). `BoardFooter.Inset` now scrolls it clear. Journeys: `cols-song-board` and `cols-song-board-focus-clear` in `tools/windows/journeys/a11y-leaderboard-columns.json`.

- Footer edge (issues #93, #308, #305, web board pages' `useScrollMask`, [scroll-edge](../../patterns/scroll-edge.md) R2–R4/R7): rows are clear at the footer's top (the pinned row when shown), opaque 40 epx above it on a linear ramp, and hidden beneath it. The ramp's depth is `BoardFooterEdgeFade.FadeDepth` = min(remaining scroll, 40), so it shrinks over the last 40 epx of scroll and nothing is dimmed at the end (`Controls/BoardFooterFade` on `BoardFadeSource`/`BoardFadeHost`, `Festival.Core/Domain/BoardFooterEdgeFade`). Contrast themes, Windows transparency effects off, Increase Contrast and Less Transparency make the depth 0: a hard cut at the footer's top, so rows never show between or behind the footer's controls (before #308 those modes turned the mask off and rows showed between the pager buttons). Under a contrast theme a window-colour `FooterPlate` (footer height, not hit-testable) sits behind the footer so row text does not show between the pager buttons (issue #197). Composition-only: hit testing, focus and UIA still use the real rows. The fade doesn't depend on the selected player's row (issue #305): with no score the rows fade 40 epx above the pager the same way (`tools/windows/journeys/a11y-board-footer-fade-no-player.json`).
- End-of-list spacing (issue #293): scrolled to the end, the last row sits one row gap (4 epx) above the footer's top: the pinned row, or the pager when no player or no score is selected (the missing row collapses, no empty slot). `BoardFooter.Inset` alone provides that gap; `ScrollContent` has no bottom padding (its old 4 epx doubled it to 8). Journeys `song-board-end-gap-anonymous|no-score|player` in `tools/windows/journeys/boards-ui.json` check it with `assertgap`; verified live (Through the Fire and Flames / Lead, `SFentonX` and anonymous, 2026-10-04). The header has no gradient band; it sits on the song-cover backdrop like Song Detail's.
- Rows: rank and score columns share the widest rank/score text on the page **including the pinned row** (web `computeRankWidth` / score `ch` width; `SongLeaderboardRowViewModel.RankChars`/`ScoreChars`), so the pinned row lines up with the list (batch 7.9). Accuracy uses the web `AccuracyDisplay` (`ScoreBadge`): tinted pill or skewed gold FC outline, fixed 58 epx (fits "XX.X%"), no "FC" prefix (batches 7.1/7.11).
- Header ([song-leaderboard-header](../../patterns/song-leaderboard-header.md)): the shared `Controls/SongLeaderboardHeader` (also the band song board's, issue #317; it skips the cover under Save Data or `--no-art`): 80 epx static cover (the shell background switches to the song cover, `IBackdropPage`), title (heading 1) and artist as one-line marquees ([song-header](../../patterns/song-header.md) R2), instrument icon (keys variant for keyboard songs) + label, "N <Instrument> entries" only when `showLeaderboardEntryTotals` and the total is above zero (web `LeaderboardPage` `totalEntries > 0`; an empty board never says "0 Bass entries", issue #197). Invoking the header (`fst.song-leaderboard.song`, one flat button named by the song title) opens Song Detail (web `LeaderboardPage` `onTitleClick={goToSongDetail}`, #317 review). Journey `song-board-header` (`tools/windows/journeys/boards-ui.json`) asserts the title, artist, instrument and total text and their order, then invokes the header and lands on Song Detail.
- Rows (shared `LeaderboardEntryRow`, operator batch 7.7; web `LeaderboardEntry` column order): rank, name, season (rows from 520 epx), score, accuracy badge (gold skewed outline for FC), stars (rows from 700 epx), chevron. The page's rows are one grouped card (issue #543, owner-approved native variant, [leaderboard-row](../../patterns/leaderboard-row.md#owner-approved-variant-one-card-per-board-page-543)): rows touch (`StackLayout Spacing="0"`), `GroupedRows.IsEnabled` gives the first and last row the card's corners and draws an inset hairline between neighbours, hidden beside the selected row. Before #543 they were separate frosted rows 4 epx apart (the web's look). Below 420 epx the column gaps tighten. The selected player's row opens Statistics, anyone else their profile; rows without a usable account ID are not interactive.
- Selected player: highlighted in place, and pinned above the pager from `FestivalSession.SelectedScoreIndex` (no extra read), only while `IsSelectedProfileCurrent` (same publication). With invalid-score filtering on, an invalid score uses its valid variant (shown unranked, no jump) or no pinned row. The pinned row itself follows pattern `leaderboard-row` R7 (issue #307), the same rule as the band board's footer: while their row is on another page it jumps there (`SelectedRowAction.Footer`, Narrator "Your rank, 60th. Jump to your position. …") and the list scrolls to the highlighted row; once the row is on the page (or unranked) it opens Statistics ("… Open your statistics. …"). The separate **Your Page** button was removed (one invoke per row, Fluent list items; web PR #168). An arrival with `revealSelected` (Song Detail's row eleven) scrolls to the highlighted row the same way.
- Shared pager (`fst.song-leaderboard.page-*`; batch 7.4: keyboard paging, hidden for one page; journey `tools/windows/journeys/boards-ui.json`), Back restores the page (kept view model), F5 reloads. Only page bounds disable its buttons: the async page commands allow concurrent runs (`RankingsPagerViewModel`), because a running command reported CanExecute false, the focused button disabled itself and the pager handed focus to another one, so a second Enter on **Next page** jumped to the last page (issue #197). Superseded loads are dropped, so a second press during a load is safe.
- Row automation: the pinned row's ID goes on its inner Button through `LeaderboardEntryRow.RowAutomationId` (an ID set on the UserControl never reaches UIA, so the pinned row used to repeat the list row's `.row.<accountId>`). A name trimmed by the column (narrow windows, large text) shows in full as the row's tooltip; Narrator already reads it in the row name. The name reads ", season N" only while the season shows (rows from 520 epx; issue #262 — before it the season was never read), and the season text is `fst.score.season.<accountId>` (Raw, for `raw=` tests).
- Live contrast switch (issue #242): `LeaderboardEntryRow` sets its surface, text and accuracy-badge brushes in code (`ApplySurface`). Switching a contrast theme on or off with a board open used to leave the rows' translucent dark fill, the purple pinned row and the gold badge in place, with system text backplates on top. Rows now re-apply on `ContrastTheme.Changed` (subscribed on Loaded, unsubscribed on Unloaded, re-applied through `DispatcherQueue.TryEnqueue`, as in `StarRow`). The row hover/pressed tints and the pager's disabled-button brushes are inline theme dictionaries instead of `StaticResource` aliases, which kept the old theme's brush. Under a contrast theme, the selected or pinned row's FC badge draws its outline and text in HighlightText on the Highlight fill, with no backplate. It used to draw them in WindowText, which Windows covered with a backplate.
- Load-swap gate (issue #71): first load, F5, invalid-score leeway reloads and paging run the shared web sequence (300 ms content-out, centered ring, 500 ms ring-out, row stagger). The new rows/empty/error state commits while hidden and rapid selections are latest-wins; Reduce Motion swaps immediately. The rows (or "No scores yet.") and the pinned row take the content role; the song header and pager stay in place while another page loads (issue #93, web `PaginatedLeaderboard` keeps its pagination mounted; `ShowContent` follows the committed state only). A failed first load fills the page with the failure (`ShowPageError`). A failed reload after the board has shown (paging, F5, leeway) keeps the song header and shows the failure with **Retry** in the rows' place (`ShowRowsError`, the inline `RowsStatus`; issue #283, web `LeaderboardPage` keeps its header above `EmptyState`). The pinned row and pager hide until a retry succeeds (load-transition R4; `PinnedRowGate.Begin(hidden:)` keeps the pinned row hidden through a same-page retry, and `ShowSpotlight` is false while failed). Keyboard focus never falls to the title bar's Back button. When the failure hides the focused pager button, or Retry's own card hides during its reload, `Controls/FailedReloadFocus` moves focus to **Retry** once the swap settles, and when the retry loads, back to the pager button that was pressed (its first enabled button if that one is now disabled; agent decision, issue #283, [load-transition](../../patterns/load-transition.md) R4). Full Rankings and Band Rankings use the same hand-off; journeys `song-board-`, `full-rankings-` and `band-rankings-failed-page-retry-recovers` in `boards-ui.json` check it.
- Pinned row entrance (issue #295): the pinned row used to sit outside the gate, so it popped in under the ring before the rows and never faded. On the first load and when the invalid-score leeway changes it now fades out with the old rows (opacity only, so its slot, the pager and the footer edge stay put) and fades in with the first row (`PinnedRowReveal.RevealDelay`, row 0's 125 ms stagger); paging, F5 and Retry keep it visible and usable beside the ring, like the web footer (issue #270, [load-transition](../../patterns/load-transition.md) R2 agent decision, `PinnedRowGate` keyed by the leeway). A score index that arrives after the rows are shown fades the row in on its own (`PinnedRowReveal.FadesOnArrival`). The gate (`LoadSwapVisual` with `IsGated`, XAML opacity transition) sits on the `SpotlightGate` `LoadSwapGate`, which also removes the hidden row from UI Automation, and the entrance (`FadeIn.Enter` on the rows' arm, so a scroll that rushes the rows starts it too, #323; composition visual) on the inner `SpotlightPanel`: with both on one element the app crashed in testing (stowed exception 0xc000027b), as the rows avoid by gating the repeater and animating its children. Reduce Motion shows the pinned row with the rows. Live-verified on (Don't Fear) The Reaper / Lead with `SFentonX` (first load, paging, the pinned row's jump (then the **Your Page** button, removed in #307), tap to Statistics, `--reduce-motion`), 2026-10-04.

## Accessibility tests (issue #443)

The #93 footer and paging behaviours are gated in CI. The `windows-ui` job runs `tools/windows/journeys/a11y-song-leaderboard.json` (`ui_ci.py` runs `song-leaderboard`, `-text-225` and `-reduced-motion`) and the song-board pages of `a11y-board-footer-fade.json` (`song-leaderboard-footer-fade`, `-text-225`). They check the pinned row's and pager's Narrator phrases and states, 40×40 epx targets, the header → rows → pinned row → pager order, and that the fade layer stays out of the control view. They also check that a keyboard page change keeps the header, pinned row and pager in order with focus on Next. The Tab order is checked separately from the reading order, with `key:tab`/`key:shift+tab` and `assertfocus` at each stop. On page 1 it is header → row → pinned row → Next → Last. While the next page loads it is Next ↔ pinned row ↔ header, with no row and no disabled First/Previous. On page 2 First and Previous rejoin. These checks run at 100% and 225% text and with Reduce Motion, plus the fade states and the R7 hard edge. Any change to the footer, the pager or the load swap must keep these pages passing (`tools/windows/tests/test_song_leaderboard_a11y_journey.py` pins them). No accessibility defect was found.
