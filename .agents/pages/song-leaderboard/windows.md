# Solo song leaderboard — Windows notes

> **What:** what the Windows per-song solo leaderboard implements and its open gaps. **Read when:** changing `windows/Festival.App/Pages/LeaderboardsSongPage*`, `Controls/LeaderboardEntryRow` or `SongLeaderboardViewModel`. Behavior: [spec.md](spec.md); iPhone reference: [ios.md](ios.md).

## Implemented

- Route `AppRoute.SongLeaderboard(songId, instrument, page, revealSelected)` (Song Detail's "View Full Leaderboard"; its selected row eleven passes its page with `revealSelected`, path `?page=N&navToPlayer=true` as web). The song resolves from the session catalogue (missing → failure state). `GET /api/leaderboard/{song}/{instrument}?top=25&offset=` with `leeway` (one decimal) only when Settings filters invalid scores. Page count uses `localEntries ?? totalEntries`; an explicit out-of-range page is corrected once totals arrive; superseded responses are dropped.
- Header scrolls with the rows inside the one `ScrollViewer` (operator batch 7.8: it scrolls away under the title bar; no gap above row one); the pinned row and pager float over the bottom of the rows (`Controls/BoardFooter`, web fixed footer).
- Footer edge (issue #93, web `useScrollMask` over a viewport that ends at the footer): rows fade out over 40 epx just above the footer's top (the pinned row when shown) and are hidden beneath it; the band eases out over the last 40 epx of scroll so the last row is clear at the end (`Controls/BoardFooterFade` on `BoardFadeSource`/`BoardFadeHost`, `Festival.Core/Domain/BoardFooterEdgeFade`). Contrast themes, Windows transparency effects off, Increase Contrast and Less Transparency keep the plain list under the footer's solid surfaces. Under a contrast theme a window-colour `FooterPlate` (footer height, not hit-testable) sits behind the footer so row text does not show between the pager buttons (issue #197). Composition-only: hit testing, focus and UIA still use the real rows.
- End-of-list spacing (issue #293): scrolled to the end, the last row sits one row gap (4 epx) above the footer's top: the pinned row, or the pager when no player or no score is selected (the missing row collapses, no empty slot). `BoardFooter.Inset` alone provides that gap; `ScrollContent` has no bottom padding (its old 4 epx doubled it to 8). Journeys `song-board-end-gap-anonymous|no-score|player` in `tools/windows/journeys/boards-ui.json` check it with `assertgap`; verified live (Through the Fire and Flames / Lead, `SFentonX` and anonymous, 2026-10-04). The header has no gradient band; it sits on the song-cover backdrop like Song Detail's.
- Rows: rank and score columns share the widest rank/score text on the page **including the pinned row** (web `computeRankWidth` / score `ch` width; `SongLeaderboardRowViewModel.RankChars`/`ScoreChars`), so the pinned row lines up with the list (batch 7.9). Accuracy uses the web `AccuracyDisplay` (`ScoreBadge`): tinted pill or skewed gold FC outline, fixed 58 epx (fits "XX.X%"), no "FC" prefix (batches 7.1/7.11).
- Header: 80 epx static cover (the shell background switches to the song cover, `IBackdropPage`), title (heading 1), artist, instrument icon (keys variant for keyboard songs) + label, "N <Instrument> entries" only when `showLeaderboardEntryTotals` and the total is above zero (web `LeaderboardPage` `totalEntries > 0`; an empty board never says "0 Bass entries", issue #197).
- Rows (shared `LeaderboardEntryRow`, operator batch 7.7; web `LeaderboardEntry` column order): rank, name, season (rows from 520 epx), score, accuracy badge (gold skewed outline for FC), stars (rows from 700 epx), chevron; separate frosted rows 4 epx apart; below 420 epx the column gaps tighten. The selected player's row opens Statistics, anyone else their profile; rows without a usable account ID are not interactive.
- Selected player: highlighted in place, and pinned above the pager from `FestivalSession.SelectedScoreIndex` (no extra read), only while `IsSelectedProfileCurrent` (same publication). With invalid-score filtering on, an invalid score uses its valid variant (shown unranked, no jump) or no pinned row. The pinned row itself follows pattern `leaderboard-row` R7 (issue #307), the same rule as the band board's footer: while their row is on another page it jumps there (`SelectedRowAction.Footer`, Narrator "Your rank, 60th. Jump to your position. …") and the list scrolls to the highlighted row; once the row is on the page (or unranked) it opens Statistics ("… Open your statistics. …"). The separate **Your Page** button was removed (one invoke per row, Fluent list items; web PR #168). An arrival with `revealSelected` (Song Detail's row eleven) scrolls to the highlighted row the same way.
- Shared pager (`fst.song-leaderboard.page-*`; batch 7.4: keyboard paging, hidden for one page; journey `tools/windows/journeys/boards-ui.json`), Back restores the page (kept view model), F5 reloads. Only page bounds disable its buttons: the async page commands allow concurrent runs (`RankingsPagerViewModel`), because a running command reported CanExecute false, the focused button disabled itself and the pager handed focus to another one, so a second Enter on **Next page** jumped to the last page (issue #197). Superseded loads are dropped, so a second press during a load is safe.
- Row automation: the pinned row's ID goes on its inner Button through `LeaderboardEntryRow.RowAutomationId` (an ID set on the UserControl never reaches UIA, so the pinned row used to repeat the list row's `.row.<accountId>`). A name trimmed by the column (narrow windows, large text) shows in full as the row's tooltip; Narrator already reads it in the row name.
- Live contrast switch (issue #242): `LeaderboardEntryRow` sets its surface, text and accuracy-badge brushes in code (`ApplySurface`). Switching a contrast theme on or off with a board open used to leave the rows' translucent dark fill, the purple pinned row and the gold badge in place, with system text backplates on top. Rows now re-apply on `ContrastTheme.Changed` (subscribed on Loaded, unsubscribed on Unloaded, re-applied through `DispatcherQueue.TryEnqueue`, as in `StarRow`). The row hover/pressed tints and the pager's disabled-button brushes are inline theme dictionaries instead of `StaticResource` aliases, which kept the old theme's brush. Under a contrast theme, the selected or pinned row's FC badge draws its outline and text in HighlightText on the Highlight fill, with no backplate. It used to draw them in WindowText, which Windows covered with a backplate.
- Load-swap gate (issue #71): first load, F5, invalid-score leeway reloads and paging run the shared web sequence (300 ms content-out, centered ring, 500 ms ring-out, row stagger). The new rows/empty/error state commits while hidden and rapid selections are latest-wins; Reduce Motion swaps immediately. The rows (or "No scores yet.") and the pinned row take the content role; the song header and pager stay in place while another page loads (issue #93, web `PaginatedLeaderboard` keeps its pagination mounted; `ShowContent` follows the committed state only). A failed reload still replaces the page with the failure state.
- Pinned row entrance (issue #295): the pinned row used to sit outside the gate, so it popped in under the ring before the rows and never faded. It now fades out with the old page (opacity only, so its slot, the pager and the footer edge stay put) and fades in with the first row (`PinnedRowReveal.RevealDelay`, row 0's 125 ms stagger). A score index that arrives after the rows are shown fades the row in on its own (`PinnedRowReveal.FadesOnArrival`). The gate (`LoadSwapVisual`, XAML opacity transition) sits on the `SpotlightGate` grid and the entrance (`FadeIn.Play`, composition visual) on the inner `SpotlightPanel`: with both on one element the app crashed in testing (stowed exception 0xc000027b), as the rows avoid by gating the repeater and animating its children. Reduce Motion shows the pinned row with the rows. Live-verified on (Don't Fear) The Reaper / Lead with `SFentonX` (first load, paging, **Your Page**, tap to Statistics, `--reduce-motion`), 2026-10-04.
