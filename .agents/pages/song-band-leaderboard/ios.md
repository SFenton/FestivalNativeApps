# Song band leaderboard — iPhone notes

> **What:** iPhone implementation state and decisions for `/songs/:songId/bands/:bandType`. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md) (currently a stub — this file is the source of truth for what's actually built until spec.md is promoted).

Source: `FortniteFestivalWeb/src/pages/leaderboard/band/SongBandLeaderboardPage.tsx`, `.../components/bands/SongBandScoreFooter.tsx`. Service: `FSTService/Api/LeaderboardEndpoints.cs:98` (`/api/leaderboard/{songId}/bands/{bandType}`) — pure, keyless `GET` (`MetaDatabase.GetSongBandLeaderboard`/`GetSongBandLeaderboardEntryForAccount`/`...ForTeam`, only `SELECT`s).

- Implemented: paginated `ScrollView`/`LazyVStack` of `SongBandPreviewRow` glass cards, the same card as Song Detail's band previews (web `PlayerBandCard` + `SongBandScoreFooter` on both pages; issue #90 replaced the thinner `List` cells, 4 pt vertical padding, with it). Not a `List`: the cards are `NavigationLink`s and a `List` would add a second disclosure chevron. Reuses `RankingsPagerView`/`RankLoadState`. A toolbar `Menu` switches `BandType` in place (mirrors `BandRankingsScreen`'s `bandTypeMenu`) rather than re-navigating, since the web page also lets the visitor switch band size without leaving. Cards navigate to `AppRoute.band(bandId:name:bandType:teamKey:)`; the focused band from Song Detail is highlighted (issue #307, see below).
- Not implemented: the instrument-combo filter (`BandFilterPill`/`BandInstrumentFilterModal`, `?combo=`) and the "selected profile's row" pin (`selectedAccountId`/`selectedBandTeamKey` query params) — both are secondary refinements on top of the base leaderboard and are deferred rather than guessed at; the `combo` parameter is already threaded through `FestivalAPI.songBandLeaderboard` so a future picker only needs UI.
- Entry from Song Detail (issue #34): each band preview's "View full leaderboard" pushes `.songBandLeaderboard(song, bandType:)` for that size; the previews themselves read `/api/leaderboard/{songId}/bands/all` (see [song-detail/ios.md](../song-detail/ios.md)).
- IDs: `fst.song-band-leaderboard.band-type-menu`, `fst.song-band-leaderboard.row.<bandId-or-teamKey>:<rank>`, `fst.song-band-leaderboard.page-first/previous/page-info/next/last`.
- Tests: `BandsTests.swift` (Core) covers `SongBandLeaderboardResponse`/`SongBandLeaderboardEntry` decoding, song/band-type validation and `pageCount`'s `localEntries` fallback. Hosted coverage: `BandsRenderTests.swift` (loaded, empty, band-type switch) (Lane U4, 2026-09-28).
- **Load/reload fade (issue #71):** The band leaderboard runs the shared `FestivalReloadGate` on load and on a band size or page change: old results leave at once, the spinner fades in, holds ≥400 ms, fades out (500 ms) and the results fade/stagger in; Reduce Motion swaps instantly. See [iPhone motion](../../design/apple/iphone.md#motion).
- **Selected band focus (issue #307):** `.songBandLeaderboard(song, bandType:, page:, focus:)` opens the board at `page` with a `SongBandRowFocus` (equal non-empty `bandId`, or same size and `teamKey`; web `isSameSongBandEntry`). The focused band's card gets the purple highlight and is scrolled to the centre once its page loads (`SelectedRowReveal`; instant under Reduce Motion); changing band size drops the scroll. Song Detail's appended selected-band row opens it this way, like the solo spotlight row (see [song-leaderboard/ios.md](../song-leaderboard/ios.md) for the shared rule). The pinned selected-band footer (issue #306) must use the same rule: `SongBandRowNavigation.footerAction(for:pageEntries:)` → `.openProfile` opens Band Detail (hint "Opens band"); `.jump(page:)` calls the screen's `jump(to:focusing:)` (hint "Jumps to your band's position"). The mock's `fixture-pulse` Duos board lists ranks 1–14, rank 14 being `fixture-player-1`'s appended band. Tests: `bandRowFocusMatchesSameBand`, `bandPreviewRowsRouteLikeTheSoloSpotlight`, XCUITest `SongDetailJourneyTests.testSongBandPreviewsLinkToBandsAndFullBandLeaderboard` (taps the appended row, expects `fst.song-band-leaderboard.row.fixture-band-fixture-player-1:14` hittable). On 2026-10-05 that test stalled before the new steps at Song Detail's second swipe ("main thread busy", the existing render loop in [song-detail/ios.md](../song-detail/ios.md)), so the jump was confirmed with `ios_sim.py drive` via Quick Links (`fst.quick-links.item.band-Band_Duets`, then `tap:fst.song-detail.band-selected.Band_Duets`) against the mock and live service.
