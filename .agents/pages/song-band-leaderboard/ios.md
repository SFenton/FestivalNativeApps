# Song band leaderboard — iPhone notes

> **What:** iPhone implementation state and decisions for `/songs/:songId/bands/:bandType`. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md) (currently a stub — this file is the source of truth for what's actually built until spec.md is promoted).

Source: `FortniteFestivalWeb/src/pages/leaderboard/band/SongBandLeaderboardPage.tsx`, `.../components/bands/SongBandScoreFooter.tsx`. Service: `FSTService/Api/LeaderboardEndpoints.cs:98` (`/api/leaderboard/{songId}/bands/{bandType}`) — pure, keyless `GET` (`MetaDatabase.GetSongBandLeaderboard`/`GetSongBandLeaderboardEntryForAccount`/`...ForTeam`, only `SELECT`s).

- Implemented: paginated `ScrollView`/`LazyVStack` of `SongBandPreviewRow` glass cards, the same card as Song Detail's band previews (web `PlayerBandCard` + `SongBandScoreFooter` on both pages; issue #90 replaced the thinner `List` cells, 4 pt vertical padding, with it). Not a `List`: the cards are `NavigationLink`s and a `List` would add a second disclosure chevron. Reuses `RankingsPagerView`/`RankLoadState`. A toolbar `Menu` switches `BandType` in place (mirrors `BandRankingsScreen`'s `bandTypeMenu`) rather than re-navigating, since the web page also lets the visitor switch band size without leaving. Cards navigate to `AppRoute.band(bandId:name:bandType:teamKey:)`; the focused band from Song Detail is highlighted (issue #307, see below).
- Not implemented: the instrument-combo filter (`BandFilterPill`/`BandInstrumentFilterModal`, `?combo=`) and the selected *band* identity (`selectedBandTeamKey`; natives have no selected band, so only `accountId` is sent) — the `combo` parameter is already threaded through `FestivalAPI.songBandLeaderboard` so a future picker only needs UI.
- Entry from Song Detail (issue #34): each band preview's "View full leaderboard" pushes `.songBandLeaderboard(song, bandType:)` for that size; the previews themselves read `/api/leaderboard/{songId}/bands/all` (see [song-detail/ios.md](../song-detail/ios.md)).
- IDs: `fst.song-band-leaderboard.band-type-menu`, `fst.song-band-leaderboard.row.<bandId-or-teamKey>:<rank>`, `fst.song-band-leaderboard.page-first/previous/page-info/next/last`.
- Tests: `BandsTests.swift` (Core) covers `SongBandLeaderboardResponse`/`SongBandLeaderboardEntry` decoding, song/band-type validation and `pageCount`'s `localEntries` fallback. Hosted coverage: `BandsRenderTests.swift` (loaded, empty, band-type switch) (Lane U4, 2026-09-28).
- **Load/reload fade (issue #71):** The band leaderboard runs the shared `FestivalReloadGate` on load and on a band size or page change: old results leave at once, the spinner fades in, holds ≥400 ms, fades out (500 ms) and the results fade/stagger in; Reduce Motion swaps instantly. See [iPhone motion](../../design/apple/iphone.md#motion).
- **Selected band focus (issue #307):** `.songBandLeaderboard(song, bandType:, page:, focus:)` opens the board at `page` with a `SongBandRowFocus` (equal non-empty `bandId`, or same size and `teamKey`; web `isSameSongBandEntry`). The focused band's card gets the purple highlight and is scrolled to the centre once its page loads (`SelectedRowReveal`; instant under Reduce Motion); changing band size drops the scroll. Song Detail's appended selected-band row opens it this way, like the solo spotlight row (see [song-leaderboard/ios.md](../song-leaderboard/ios.md) for the shared rule).
- **Selected-band footer (issue #307, web `FixedLeaderboardPlayerFooter`):** with a selected player every page request adds `accountId` (part of the request key; such pages skip the snapshot cache) and `SongBandLeaderboardResponse.selectedEntry` (`selectedBandEntry ?? selectedPlayerEntry`, validated to the board's size) is pinned between the list and `RankingsPagerView`, drawn by the Solo board's shared `SelectedScoreFooterRow` (compact `SongLeaderboardEntryRow`, `LeaderboardEntry(selectedBand:)`, own `.songLeaderboard` columns). That band's page row gets the purple highlight too (`isSelected`). The footer follows the Solo footer (pattern [leaderboard-row](../../patterns/leaderboard-row.md) R5): `SongBandRowNavigation.footerAction(for:pageEntries:)` → `.openProfile` while the row is on this page (`NavigationLink` to Band Detail, `fst.song-band-leaderboard.spotlight-open`, label "Your band's rank, 29th. Open band."); `.jump(page:)` otherwise (`jump(to:focusing:)` → that page, row revealed and highlighted; `fst.song-band-leaderboard.spotlight-jump`, "Your band's rank, 29th. Jump to your band's position."). Container `fst.song-band-leaderboard.spotlight-footer`. The web footer always opens the band; the native jump is the deliberate #307 rule shared with the Solo board.
- **Fixture and tests:** the mock's `fixture-pulse` Duos board lists ranks 1–29 (page 2 holds 26–29); rank 29 is `fixture-player-1`'s band, which `/bands/all` appends to Song Detail's Duos preview and the per-size read returns as `selectedPlayerEntry`. Tests: `bandRowFocusMatchesSameBand`, `bandPreviewRowsRouteLikeTheSoloSpotlight`, `selectedFooterLabelsNameTheDestination`, `songBandLeaderboardDecodesSelectedPlayerBand`, hosted `songBandLeaderboardFooterJumpsOffPageAndOpensBandOnPage` (macOS, both labels), XCUITest `SongDetailJourneyTests.testSelectedBandRowAndFooterJumpOrOpenLikeTheSoloSpotlight` (needs `mock_service.py --port 18934`): reaches the Duos section through Quick Links, never swiping Song Detail (repeated drags can trip its known render loop, see [song-detail/ios.md](../song-detail/ios.md)); asserts the appended row's label, the focused rank-29 row hittable with "Your band" label, Open band on page 2, Jump from page 1 back to the row, and Open band leaving for Band Detail.
