# Song band leaderboard — Windows notes

> **What:** what the Windows per-song band leaderboard implements and its open gaps. **Read when:** changing `windows/Festival.App/Pages/BandsSongLeaderboardPage*` or `SongBandLeaderboardViewModel`. Behavior: [spec.md](spec.md); iPhone reference: [ios.md](ios.md).

## Implemented

- Route `AppRoute.SongBandLeaderboard(songId, bandType, page, revealSelected)` (`/songs/{id}/bands/{type}?page=N&navToBand=true`, web); an unknown band type falls back to Duos. Read `GET /api/leaderboard/{songId}/bands/{bandType}?top=25&offset=[&accountId=]` (pure `SELECT`s; `accountId` only when a selected player has a safe ID, never a selected-profile header), validated against the requested song/size and page size, including its `selectedPlayerEntry`/`selectedBandEntry` (members present, same size).
- Header (issue #317; [song-leaderboard-header](../../patterns/song-leaderboard-header.md)): the shared song leaderboard header `Controls/SongLeaderboardHeader`, the same control as the solo board (80 epx static cover, 56 below a 760 epx window; the shell background switches to the static song cover). It shows the song title (heading 1) and the artist as one-line marquees ([song-header](../../patterns/song-header.md) R2), the band size (`Duos`/`Trios`/`Quads`) where the solo board shows the instrument, and "N <Size> entries" only when the response's `showLeaderboardEntryTotals` is true and the total is above zero (web `SongBandLeaderboardPage` `SongInfoHeader` subtitle; the solo rule). It used to be a `<Size> Leaderboard` heading with the song as a secondary link and the count always shown. Switching the size updates the band line at once and clears the previous size's total, which returns only when the new size's response commits (never during its load gate or after it fails; pattern R5, unit test `SizeSwitchDropsTheOldTotalUntilTheNewSizeCommits`, journey `song-band-leaderboard-slow-switch-total` with `--song-band-slow Band_Quad`). Invoking the header (`fst.song-band-leaderboard.song`, one flat button named by its visible lines, e.g. "Fixture Pulse, Synthetic Quartet, Duos, 29 Duos entries", with help text "Opens Song Details"; #465) opens Song Detail, like the web's `onTitleClick={goToSongDetail}`. The page change announcement names the board (`<Song>, <Size> leaderboard`).
- Beside Song Detail (#667, [song-leaderboard-header](../../patterns/song-leaderboard-header.md) Variants): at the root of the on-demand split's trailing pane the header drops the song and is titled by the band size alone at heading level 1 (`fst.song-band-leaderboard.board-title`, no icon), renamed at once by a size switch; full-width pushes keep the song header. Journey: `split-song-band-board-title` (`a11y-split-panes.json`).
- Agent decisions (issue #317, recorded as the Windows variant in [song-leaderboard-header](../../patterns/song-leaderboard-header.md#variants); the owner may override): the header stays fixed above the size switcher instead of scrolling away like the solo board, because the band rows' load gate hides the `ListView` (and any `ListView.Header`) during size swaps and the row UIA from #196 relies on the `ListView`. The former separate song-title `HyperlinkButton` became the whole header's Song Detail invocation (#317 review: the web `SongInfoHeader` title area is pressable on both boards; pattern Variants "Windows title invocation"). The page now uses the solo compaction (smaller art below 760 epx, page-title style always) instead of its own 560 epx rule.
- Band size switcher: Fluent `SelectorBar` (Duos · Trios · Quads) switching in place and returning to page 1.
- Rows (`ListView`, virtualized): rank, each member's instrument icons + name + per-song member score, then the team score footer (web `SongBandScoreFooter`) with team score, FC badge (gold outline), accuracy pill and star images (`StarRow`), and a trailing chevron (`E76C`, decorative) because the card navigates. The footer is `Controls/BandScoreFooterPanel`, shared with the Song Detail preview row: the badges move to a line under the score when they don't fit (once for the whole list, `BandScoreFooterPanel.IsSection`; [leaderboard-row R8](../../patterns/leaderboard-row.md)), so the score never truncates (at 200% text in narrow windows it had truncated; issue #264). Every row of a page shares one rank rail sized by the page's widest rank (`SongBandRow.RailRank`: an invisible bold copy in each rank cell, 40 epx unscaled floor, tabular digits; [leaderboard-row rank column](../../patterns/leaderboard-row.md#rank-column-width-594), issue #594), so a 4+ character or bold rank no longer pushes its members out of line. `windows-ui` gates the rail with `tools/windows/journeys/a11y-song-band-rank-column.json` on `song_band_preview_fixture.py --bands far` (a 10,025-band Duos board): pages 40 (#976–#1,000) and 400 (#9,976–#10,000) `assertaligned` the raw `<row>.rank` and `<row>.members` of #999/#1,000 and #9,999/#10,000 at default text (compact, medium) and 225% text (`-large-text` twins, the pair scrolled to the list top); without the hidden rail copy every page fails. A row opens `AppRoute.Band(bandId, bandType, teamKey)`.
- One grouped card (issue #543, owner-approved native variant, [leaderboard-row](../../patterns/leaderboard-row.md#owner-approved-variant-one-card-per-board-page-543)): items touch (`ItemContainerStyle` Margin 0) and `ContainerContentChanging` applies `GroupedRows.SliceFor` (the first and last item take the card's 12 epx corners, and an inset `RowSeparator` hairline sits between neighbours), with the container's corner radius following the slice and `FocusVisualMargin` 0 so the focus rectangle hugs the item. Before #543 each band was its own 8 epx-radius card 6 epx apart. Each `ListViewItem` is one Narrator stop. `ContainerContentChanging` sets its UIA name to `SongBandRow.PageAnnouncement` (`Rank N. <member>, <instruments>, <score> points. … Team score X points, full combo, A% accuracy, N gold stars`) and its AutomationId to `.row.<bandId>:<rank>`. Every template part, including `InstrumentIcon`'s inner `Image`, is `AccessibilityView.Raw`, because Raw on a parent does not hide its children in WinUI. A custom peer must honour Raw too: `StarRowPeer` reported itself a control element regardless, so every card exposed a second "5 stars" stop until issue #510 (its `IsControlElementCore`/`IsContentElementCore` now follow `AutomationProperties.AccessibilityView`). The Song Detail preview keeps the shorter `Announcement`.
- High contrast: the accuracy pill uses `FSTAccuracyPillFillBrush` (navy by default, `SystemColorButtonFaceColor` in HighContrast) with `FSTNeutralPillStrokeBrush`/`FSTNeutralPillTextBrush`. Before this, the static navy fill under system text was unreadable in Desert.
- Selected player's band (issues #306 and #307; [leaderboard-row](../../patterns/leaderboard-row.md) R5 and R7, same markup and rule as the Solo board `LeaderboardsSongPage`): the response's `selectedPlayerEntry`, used only when its members include the selected account (`SongBandLeaderboardResponse.PinnedEntry`), is pinned in the shared floating `LeaderboardEntryRow` (`fst.song-band-leaderboard.spotlight-footer`, `SongBandSpotlightRow`) directly above the pager on **every** page (web `hasSelectedFooter`). It shows rank, the joined roster (`MarqueeText`, static under Reduce Motion), season, score, accuracy/FC badge and stars. The row itself is the control (no separate Your Page button): while the band ranks on another page it jumps there (`SelectedRowAction.Footer`, Narrator "Your band's rank, 29th. Jump to your band's position. …") and the list scrolls to the highlighted row once its own entrance has finished, rushing the fades still waiting so the rows it reaches fade in together (`SelectedRowReveal`, then `RevealRow`, centred, no animation; immediate under Reduce Motion; [load-transition](../../patterns/load-transition.md) Windows selected-row reveal, journey `selected_reveal_journey.py`); on its own page it opens Band Detail ("… Open band. …", web `getBandProfileRoute`). An arrival from Song Detail's appended band row (`revealSelected`) lands on that page and reveals the row the same way. On its own page the card gets the purple player-row fill in place (`FSTPlayerRow*`, web `isSelected`) with player-row text, and its Narrator name starts "Your band.". The pin follows the size switch and the selected player (`Activate`/`Deactivate` on `FestivalSession.Settings`), is absent without a player or band score, and clears on failure. Its columns are fitted over the page's entries plus itself (`SongBandSpotlightRow.Pinned`; web `widthEntries`, leaderboard-row R1), so a wider rank or an accuracy/stars column elsewhere on the page is reserved on the pin. `BoardFooter.Inset` pads the list by the footer's height so nothing is covered at the end; rows end at the whole footer (pin and pager) through the shared `BoardFooterFade` ramp (see Footer edge), and under a contrast theme the window-colour `FooterPlate` it sizes (footer height plus its 12 epx bottom margin, not hit-testable) hides rows passing beneath it (scroll-edge R7, as Solo #197 and Band Rankings #209). **Reveal timing:** a freshly swapped `ListView` defers `ScrollIntoView`, and scroll requests made in the same dispatcher tick (`ScrollIntoView` + `UpdateLayout`) or inside `LayoutUpdated` never commit, so the list stayed at the top (found by the live #307 journey on page 15 of 379). `RevealRow` therefore works once per `CompositionTarget.Rendering` frame: it asks the list to realize the row, then calls `StartBringIntoView` (ratio 0.5), and stops when the row lies inside the list, when the rows change, when the page unloads or after 60 frames. In practice the row is realized on frame 2 and centred on frame 3. The pin is gated with the rows only on the first load and when the band size or selected player changes, and fades in with row 0 (`PinnedRowReveal.RevealDelay`; `PinnedRowGate` keyed on size + account in a `LoadSwapGate`, [load-transition](../../patterns/load-transition.md) R2, #270): paging (including its own jump), F5 and Retry keep it shown beside the spinner, and while gated it is out of UI Automation and the Tab order. A selected entry of another size, or without members, rejects the response.
- Paging with the shared board pager (`LeaderboardsPager`, operator batch 7.4; floating over the rows); empty state `No band scores found` / `No <Size> scores have been recorded for this song yet.`; failure via `ServiceStatusView`. Late responses for an older size/page are discarded. Only page bounds disable the pager's buttons: `BandsPagerViewModel`'s async commands allow concurrent runs, as `RankingsPagerViewModel` has since #197. Before issue #431 the running command reported CanExecute false, so the focused **Next page** disabled itself mid-load and the pager handed keyboard focus to **Previous page** (journey `load-swap-song-band-leaderboard`, `tools/windows/journeys/a11y-load-swap.json`).
- Pinned band row accessibility (issue #461, for #306): `tools/windows/journeys/a11y-song-band-pinned.json` (CI `windows-ui` runs `song-band-pinned` at compact and medium and `song-band-pinned-text-225` at compact) asserts the pin's Narrator phrases ("Jump to your band's position" off its page, "Open band" on it), 40 epx pin and pager targets, the reading and Tab order rows → pin → pager, Enter jumping to the "Your band." row clear of the pin (also under Reduce Motion), the pin leaving on empty Trios and returning on Duos, and no pin without a player. The 225% run found the centred jump leaving the row partly under the pin: `BoardFooter.Inset` now grows aligned requests too, so `RevealRow` centres in the area above the footer, and `IsInViewport` counts a row as in view only above the list's footer padding.
- Board accessibility (issue #510, for #196): `tools/windows/journeys/a11y-song-band-leaderboard.json` (CI `windows-ui` runs `song-band-board` at compact and medium and `song-band-board-text-225` at compact) asserts each card's full Narrator phrase, `ListItem` role with Invoke, 40 epx height, that its rank, members, accuracy pill and stars exist only in the raw view, header → size switcher → rows order, Down/Up between rows, Enter → Band Detail and Back; the empty size's level 2 heading after the switcher with no list, pager or total left; the failure's level 2 title then a 40x40 epx Retry with Tab/Shift+Tab; and the accuracy pill's fill (navy, ButtonFace with a ButtonText edge under Desert, navy again) while switching contrast in the running app. **Failed, fixed (#510):** the star row was a separate control-view `Image` inside every card (see Rows).
- Footer edge with no selected player (issue #305): the #308 ramp below is the same with or without the pinned player row; `tools/windows/journeys/a11y-board-footer-fade-no-player.json` asserts it. Under a contrast theme the window-colour `FooterPlate` backs the pager here too (pager height plus its margin).
- Load-swap gate (issue #71): first load, band-size changes and paging run the shared web sequence (300 ms content-out, centered ring, 500 ms ring-out, row stagger). New rows/empty/error state commits while hidden; rapid choices are latest-wins. Reduce Motion swaps immediately.
- Footer edge (issue #308, web board `Page.tsx` `useScrollMask`, 40 px linear, [scroll-edge](../../patterns/scroll-edge.md) R2–R4/R7): Rows end at the floating footer (pinned band and pager) through the shared bottom-chrome ramp `BoardFooterFade.Attach` (`Controls/BoardFooterFade`, the same component as Song Leaderboard): clear at the footer's top, opaque 40 epx above it on a linear ramp, the depth min(remaining scroll, 40) so nothing is dimmed at the end. Contrast themes, Windows transparency effects off, Increase Contrast and Less Transparency make it a hard cut at the footer's top. The source is the `BoardFadeSource` wrapper (the load swap animates the list's own visual) and the raw-view `EdgeFadeLayer` `fst.song-band-leaderboard.footer-fade` reports `hidden`, `fading:40`, `end` or `hard-edge` (journeys `tools/windows/journeys/a11y-board-footer-fade.json` and `-hard.json`). The list is the page's only `ListView` board, whose scroll viewer appears only after its template is applied; `BoardFooterFade` finds it on the list's first `SizeChanged`, else the ramp stayed at `end` mid-list on the CI runner (#538). Before #308 the rows met the pager at a hard edge.
- Loading placement ([load-transition](../../patterns/load-transition.md) R13, #624): the ring centres between the retained header and the floating pager, not in the whole page. `LoadSwapVisual.PlaceSpinner` insets the Raw `fst.song-band-leaderboard.loading-region` while the ring is active; the ring stays the one named busy stop. Journey: `a11y-loading-placement.json` (`assertcentred` region → ring, `assertgap` region → pager 0 epx; normal and text-225).

## Evidence

Fixture screenshots (mock service, compact/medium/wide): `windows/reports/screenshots/song-band-leaderboard-{compact,medium,wide}.png`. At compact (500 epx) the shell keeps the navigation pane open, leaving ~340 epx of content; the header art shrinks to 56 epx below a 760 epx window.

Validation pass (issue #196, 2026-10-03; live public service plus fixtures):

| Configuration | Result |
|---|---|
| Compact, medium, wide, maximized, snap-left (live, Duos/Quads, paging) | Layout correct; the floating pager overlays the last visible row by design (operator batch 7.4). Non-drum instrument icons can stay blank for about 1 s right after a list rebuild while their shared bitmaps decode. |
| Dark (default) | Correct. The app is dark-only (`RequestedTheme="Dark"`), so the system Light theme is a deliberate no-op. |
| HC Desert, Night Sky, Aquatic, Dusk | Axe 0. Desert failed before the accuracy-pill fix (navy fill under system text). |
| Text 200% / 225% (compact, medium) | Axe 0; text wraps in place. Icons, stars and chevron keep their fixed size. |
| No animations, no transparency | Axe 0; Reduce Motion swaps rows without the gate. |
| Display 100% / 150% | Not changeable on the shared 300% host desktop. Layout is in epx and was checked at every preset. |
| Keyboard | The console was locked, so SendInput Tab walks were unavailable. UIA confirms one focusable `ListItem` per row, `SelectorBar` items and pager buttons in reading order. Journeys drive selection, row invoke and Back through UIA patterns. |

Journeys `song-band-leaderboard-switch-and-detail` (rows, Trios empty, Quads, row → Band, Back, header → Song Detail), `song-band-leaderboard-pinned-band` (fixture player: pin on page 1, pin kept while paging to its own page, gone on empty Trios, back on Duos, pin → Band Detail; #306), `song-band-leaderboard-entry-totals` (`--song-band-totals` fixture: `showLeaderboardEntryTotals` true; the shared mock now also sends it on per-size reads), `song-band-leaderboard-slow-switch-total` and `song-band-leaderboard-error` (`tools/windows/journeys/bands.json`) cover the reachable states. They assert with `assertname`/`assertbelow`/`waitgone` that the title names the song, the artist and band line follow it, the band line names the selected size after every switch, the total shows only when the flag is true and the board has entries, no `<Size> Leaderboard` heading remains, and the header is one button that opens Song Detail. Accessibility (#465): `tools/windows/journeys/a11y-song-leaderboard-header.json` (`ui_ci` `song-leaderboard-header` and `-text-225`) checks the header's Narrator phrase, button state, heading 1 title, 40x40 epx target, header → size switcher → rows order and Tab/Shift+Tab, Enter → Song Detail, a keyboard size switch (Right) that drops the old total from the name at once, and that an unresolved song leaves no header button or tab stop. **Failed, fixed (#465):** Narrator read the header button by its title alone and never reached the artist, band size or total inside it; the name now carries every visible line.

## Open

- No instrument-combo filter (`?combo=`). A selected *band* (`teamKey` query, web `selectedBandEntry`) is not sent, so only the selected player's band is pinned.
- Entry point from Song Detail (band leaderboard previews/links) is owned by the Songs lane; its `SongBandPreviewRowView` accuracy pill uses the same contrast-aware pill roles since issue #264.
