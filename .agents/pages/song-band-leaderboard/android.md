# Song band leaderboard — Android notes

> **What:** what the Android per-song band leaderboard implements. **Read when:** changing `ui/bands/SongBandLeaderboardScreen.kt` or `SongBandLeaderboardViewModel`. Behavior: [spec.md](spec.md); references: [ios.md](ios.md), [windows.md](windows.md).

## Implemented

- `SongBandLeaderboardRoute(songId, bandType, page = 1, navToBand = false)` (unknown type → Duos) → `GET /api/leaderboard/{songId}/bands/{bandType}?top=25&offset=` (pure read), validated against song, size and page size. Song Detail's band previews read the same route with `top=10` and, with a selected player, `accountId=` (adds `selectedPlayerEntry`; pure `SELECT`). Rows (`BandScoreRow`) stack the team score under the members below 400 dp and carry an in-card chevron. Debug: `FST_DEBUG_ROUTE=songBandLeaderboard:<songId>[:<bandType>[:<page>[:reveal]]]`.
- Header (patterns [song-header](../../patterns/song-header.md) R1–R4 and [song-leaderboard-header](../../patterns/song-leaderboard-header.md) R1, R3, R4; issues #315, #317): the solo board's shared Song Detail `SongHeader` (web `SongInfoHeader` with `onTitleClick`): 64 dp art, the full-width one-line marquee title and `artist · year · length`. The whole header is one heading button ("Open song") to Song Detail (test `SongHeaderTitleUiTest`). The band size sits where the solo board's instrument goes: `SongBoardSwitcher`, the solo board's header drop-down, text only ("Trios ▾", like the web's `SongInfoHeader` band subtitle). There is no entry count, because the solo header shows none (#317). The top bar stays empty until the header scrolls away, then shows the song title as a one-line marquee (`scrolled`, `marqueeTitle`). In a hinge split the header stays in the leading pane, so the bar stays empty. Before #317 the bar always read `<Size> Leaderboard` and the header carried `<Size> · N entries`. The shared backdrop shows the song's static cover (`SongCoverBackdrop`, song-leaderboard-header R4).
- Band size switcher: the header drop-down (`Role.DropdownList`, click label "Switch band size", 48 dp, the menu checks the current size), switching in place and returning to page 1. It replaced the M3 segmented buttons (#317 agent decision; the owner may override). The owner asked for the solo header "just saying Duos/Trios/Quads instead of {instrument name}", and the solo board switches its instrument from that same spot. A size or page change runs the shared load swap (issue #71; spinner `fst.song-band-leaderboard.loading`). The anchored pager stays visible and usable below the spinner (last loaded page count, like web placeholder data), so a newer page tap supersedes the pending one ([load-transition R4](../../patterns/load-transition.md), issue #149; test `BandsUiTest.songBandLeaderboardPagerSupersedesAPendingPage`). The pinned band row keeps its slot but is hidden, unread and untouchable under the spinner (`LoadSwap.pinnedContentModifier`, load-transition R2; test `BandsUiTest.songBandLeaderboardHidesTheStalePinnedBandWhileThePageLoads`).
- Rows (glass cards, lazy): rank, each distinct member's instrument icons (keys variants for keyboard songs) + name + per-song member score, team score, gold `FC` outline badge, accuracy, `★ stars`. A row opens `BandRoute(bandId, membersLabel, bandType, teamKey)`.
- TalkBack: one merged `Button` per row with click label "Open band" and `bandScoreAnnouncement`: "Rank N, <member>, <instruments>, <score>, …, band score X, full combo, Y% accuracy, 5 gold stars | N stars" (gold reads as "5 gold stars", never "6 stars"; [star rating](../../controls/star-rating/android.md)). Order: back → (song title once scrolled) → search → profile → song header (title, artist · year · length; one heading stop that opens the song) → band size ("Duos, Switch band size, drop down list") → rows → pinned band → pager.- Large text (font scale ≥ 1.3, `isLargeText`): a member's score wraps under the name (`BandMemberScoreLine` FlowRow) instead of breaking the name mid-word, and the footer (`BandScoreFooter` FlowRow) wraps accuracy + stars under the team score instead of clipping the stars.
- Hinge: across a **separating** vertical hinge (half-open book/passport fold) `SongBandLeaderboardLayout` puts the song header and size switcher on the leading side (`.controls-pane`, scrollable) and the rows and pager on the trailing side (`BandLayout.listSplit`), per the M3 foldables rule "Never place interactive content or critical information across the hinge area". Flat folds (book unfolded, tri-fold) keep one column. Unlike `rememberSingleColumn` pages, the split also applies under TalkBack/large text (band-page convention); verified at font 2.0.
- Shared pager, empty state (`No Band Scores Found` / `No <Size> scores have been recorded for this song yet.`), failure `ServiceStatusView` (fixed height inside the list). Content is centered at ≤840 dp on wide windows.

## Open

- Entry point from Song Detail belongs to the Songs lane. No instrument-combo filter.
- Selected band (issue #307, [leaderboard-row](../../patterns/leaderboard-row.md) R7): with a selected player whose account ID is valid, every page read adds `accountId=` (allowlisted pure `SELECT`, no selected-profile headers) and the service's `selectedPlayerEntry` is highlighted purple in place and pinned above the pager with the solo board's `SelectedScoreFooterRow` (`SongBandLeaderboardEntry.footerLeaderboardEntry`: members label as the name, team score, accuracy/FC, stars; tag `.spotlight-footer`). The band board now uses the shared `RankingsBoardLayout` (fade above the footer, rows clipped above it, the pager in the bottom bar rather than a list item; in a hinge split the footer and pager sit under the controls). Off its page the footer jumps there ("Jump to your band's position") and centres the row; on the page it opens the Band page ("Open band"). Song Detail's appended band row opens `SongBandLeaderboardRoute(page, navToBand = true)`. Tests: `BandsUiTest.songBandLeaderboardPinsTheSelectedBand…`, `…WithoutAPlayerPinsNothing`, `…FooterJumpsToTheBandsPageAndRevealsIt`, `…OpenedForTheBandRevealsItsRow`.
- One board plan (issue #172, [leaderboard-row](../../patterns/leaderboard-row.md) R1, R5): `bandBoardColumns` fits the rank column to the page rows and the pinned band (an off-page "#9,968" too) and puts the member cards' rank and members where the pinned footer row puts its rank and name (20 dp inset, the footer's gap). `SongBandBoardColumnsUiTest` measures both at 1.0 and 2.0 text.
