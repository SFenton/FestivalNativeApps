# Suggestions — iPhone notes

> **What:** iPhone implementation state and decisions for the Suggestions tab. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md) (still a stub — this file is the source of truth for what's actually built until spec.md is promoted).

Source: `FortniteFestivalWeb/src/pages/suggestions/SuggestionsPage.tsx`, `.../suggestionsHelpers.ts`, `.../modals/SuggestionsFilterModal.tsx`, `.../components/{CategoryCard,VirtualizedSuggestionsList,SuggestionsLoadSentinel}.tsx`; core algorithm `packages/core/src/suggestions/{suggestionGenerator.ts (2221 lines),suggestionFilterConfig.ts}`. Suggestions are entirely client-computed from the catalogue (`GET /api/songs`) and the selected player's own compact score index (`GET /api/player/{accountId}`) — both pure, keyless, already-fetched reads; no suggestion-specific endpoint exists.

## Implemented

- **`FestivalCore/SuggestionGenerator.swift`**: a from-scratch Swift port of the web `SuggestionGenerator` class — same seeded PRNG (Mulberry32, bit-for-bit via `SeededSuggestionRng`), same anti-repetition session state (`sessionShownSongs`, per-category `used` history, skip-streak-smoothed `shouldEmit` probability table), same `selectNewFirst` new-first-with-fallback selection, same decade-variant re-titling (`buildDecadeVariant`). Ported category families: `near_fc_any`/`near_fc_relaxed`/`unfc_<instrument>`/`samename_nearfc`, star progress (`almost_six_star`/`star_gains`/`more_stars`), unplayed (`unplayed_any`/`unplayed_<instrument>`/`first_plays_mixed`), `variety_pack`, `artist_sampler_*`/`artist_unplayed_*`, `samename_*`, `almost_elite(+instrument)`, `pct_push(+instrument)`, `stale_global_N`/`stale_<instrument>_N`, and percentile improvement (`same_pct_improve`/`same_pct_<bucket>`/`pct_improve_<bucket>`/`pct_improve_<instrument>_<bucket>`/`improve_rankings_<instrument>`) — each with its decade sibling where the web has one.
- **Not ported this wave**: rival-driven pipelines (`song_rival_*`, `lb_rival_*` — no rival data source in the app yet) and band suggestions (`band_*` — Suggestions here is solo-profile only; band mode is a separate `mode: 'band'` branch on the web that needs a selected-band context this app doesn't have). `near_max_*` (CHOpt theoretical-max-score gap) is also skipped: it needs a `maxScores` field on the catalogue `Song` that the native `Song` model doesn't decode yet (owned by the Songs domain, not this lane — flagged as a seam gap below).
- **`FestivalCore/SuggestionFilterSettings.swift`**: persisted filter draft mirroring `SuggestionsFilterDraft` — per-instrument visibility plus a global + per-instrument toggle per `SuggestionCategoryType` (11 types; rival/near-max types omitted since they're unported). Storage is minimal-diff (`Set<String>` of *disabled* keys only), so an untouched filter round-trips to empty `Data`, matching `SongPlayerScoreFilter`'s convention. `SuggestionCategoryFilter.visible(_:effectiveInstruments:filter:)` applies it to already-generated categories in one pass (equivalent to the web's `shouldShowCategory`+`filterCategoryForInstruments`+`shouldShowCategoryType`+`filterCategoryForInstrumentTypes` pipeline), trimming a multi-instrument category's songs rather than always dropping the whole category.
- **`SuggestionsScreen`**: one `FestivalGlassSection` glass card per category (`.agents/design/apple/liquid-glass.md` — "Settings, Profile, Statistics, Suggestions, Rivals, Leaderboard groups: one card per group"), flat rows inside (`SuggestionSongRowView`: artwork tile, title/artist, star row, FC badge, accuracy percent, "Top N%" when a rank is known). `LazyVStack` in a `ScrollView` with `onAppear`-triggered `loadMore()` on the third-from-last visible card (web "virtualized incremental loads"), 10 categories per page (`SuggestionsViewModel.pageSize`). Toolbar filter button (gold tint when `filter.isActive()`) opens `SuggestionsFilterSheet` (`.festivalSheet(.large)`, staged draft + Apply/Cancel-with-discard-confirmation, mirroring `SongsFilterSheet`). "Start New Mix" button once a mix is exhausted (`SuggestionGenerator.resetForEndless()`). Rows push `AppRoute.songDetail(item.song)`.
- **`FestivalSession+Suggestions.swift`**: `SuggestionsViewModel` owns one `SuggestionGenerator` per (selected accountId, catalogue's observed publication) pair; changing either invalidates and rebuilds it (fresh mix, matching the web's `suggestionCacheKey`). Changing the filter only re-derives `visibleCategories(appVisibleInstruments:)` from the already-generated list — no regeneration, matching the web's separate generation/filtering split.
- States handled: no selected profile (Choose Profile via `\.openProfile`, `StatisticsScreen`'s pattern), scores syncing (202), player load failure (retry), catalogue load failure (retry), initial loading, empty (no scores yet vs. filtered-to-empty), loaded list, exhausted-mix footer.

## Simplified vs. web this pass

- Rival/band/near-max categories unported (see above).
- Filter sheet edits are staged with a discard-confirmation Cancel, but there's no first-run slide deck (`suggestionsSlides`) and no `SUGGESTIONS_CATEGORY_LIMIT` mix-limit banner distinct from "Start New Mix" — the two are collapsed into one footer state (`hasMore == false`).
- No scroll-position restoration (`suggestionsScrollRestoration.ts`) or cross-tab session cache (`suggestionsSessionCache.ts`) — a fresh mix builds each time the tab's source identity changes.

## Known seam gaps (flagged for the orchestrator, not fixed here)

- `SuggestionsScreen` computes Settings-visible instruments itself from the same nine `fst.settings.show*` `@AppStorage` keys `FestivalRootView` already reads, because `FestivalRootView.content(for:)` constructs `SuggestionsScreen(session: session)` without passing `visibleInstruments` the way `tabStack` does for other Wave 2 hubs. Passing it through would remove the duplication.
- `SuggestionFilterSettings.storageKey` (`"fst.suggestions.filter"`) is a new persisted `@AppStorage` key; Settings' "Reset Settings" registry (Lane A, `dec1cbf`) should include it alongside `SongPlayerScoreFilter.storageKey` so a full reset clears it too.
- `near_max_*` needs the catalogue `Song` model to carry CHOpt per-instrument max scores (owned by the Songs/Core domain).
