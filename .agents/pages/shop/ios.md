# Item Shop — iPhone notes

> **What:** iPhone implementation and decisions for the Shop route. **Read when:** changing Shop on iPhone (Lane S). Behavior: [spec.md](spec.md); offers/badges: [shop-offers/ios.md](../../controls/shop-offers/ios.md).

- `ShopScreen` is a pushed route (not a tab). Entry: the leading drawer (Lane A); removing the older Songs toolbar Shop button is a Lane S task ([PROGRESS.md](../../../PROGRESS.md)).
- **Title (#375; [page-tools-and-nav-chrome](../../patterns/page-tools-and-nav-chrome.md) R14):** `festivalNavigationTitle("Item Shop")` with the system's automatic display mode, so the pushed page inherits Songs' large title and matches every root in every iPhone and Duo pose. Never set a Shop-only display mode or font. HIG Toolbars (iOS): "Use a large title to help people stay oriented" (should). Test: `DuoPageTitleJourneyTests.testItemShopTitleMatchesRootTitleSize{,Unfolded}`.
- List rows are the **shared Songs `SongRowView`** (issue #18; web `ShopPage` list renders the Songs `SongRow`): same glass card surface, 44pt art and one-line `MarqueeText` title + "artist · year · duration" that auto-scrolls when too long instead of wrapping (both lines wrap at accessibility sizes). `SongRowShopOffer` swaps the profile/score area for Shop's trailing **Leaving clock, bag slot, then chevron** (installed-PWA gap #17); a New offer shows no badge, only its gold outline, like the web (#562; [shop-offer-status](../../patterns/shop-offer-status.md), [shop-offers](../../controls/shop-offers/ios.md)); ~60pt tall, 6pt apart. Red/gold `ShopRowPulseBorder` for Leaving/New, none for plain offers (web passes only `shopHighlightRed/Gold`). `ShopRowPolicy` draws the catalogue song when matched, else a display-only `Song(shopOffer:)` that never routes to Detail. Do not reintroduce a Shop-only row view.
- Text and the bag glyph use `FestivalText.primary` (white, operator 2026-09-28); only the decorative chevron is `FestivalText.deemphasized`.
- Row structure: the list is a `ScrollView` + `LazyVStack`, not a `List` (a `List` adds its own disclosure chevron *before* the bag). The Detail `NavigationLink` wraps the shared row, which reserves the bag slot (`ShopRowMetrics`); the official bag `Link` is a **sibling overlay** on that slot (never nested, per the one-action-per-row rule in [architecture](../../platforms/apple/architecture.md)). No catalogue match → no chevron, bag only. At accessibility sizes the bag becomes a labelled "Open Official Item Shop" action under the row.
- Accessibility (#397, hosted, runs in `apple-ci`): `ShopRowAccessibilityTests` pins the shared row in the Shop. A matched row is one button named title, artist line and Shop state ("New", "Leaving Tomorrow", so state is never colour alone). A display-only offer is static text at every size. Each bag is a link named "<title>, Open Official Item Shop". Reading order is row then its bag. Bags are ≥ 44 × 44 pt on the row's trailing edge. At AX5, title and artist wrap and the bag is a full-width ≥ 44 pt action under its row. HIG Accessibility: "Provide VoiceOver descriptions for all interface elements"; default control size 44×44 pt (iOS/iPadOS).
- The loaded list fades in with the shared `festivalFadeInOnAppear()` (no fade under Reduce Motion).
- First-screen art: `load()` warms up to 12 covers (`ShopArtworkPrimePolicy`) through `FestivalSession.preparedArtwork` at the row's `maxPixels` (132) while the catalogue loads, bounded by 900 ms, like the Songs first-paint gate. Shared bounded caches only; nothing persisted.
- Hide Shop in Settings removes the action and returns an open Shop route to Songs with a notice.
- Explicit empty card vs scalable unavailable/Retry for HTTP errors.
- Structural comparison against web phone captures (390×844) only; not pixel parity.
- Warm "publication unverified" Shop rows after connection loss predate online-only; do not extend. The strong recent-art cache tier stays ([architecture](../../platforms/apple/architecture.md)).
- **Sort (issue #379, [catalogue-sort](../../patterns/catalogue-sort.md); native and web, agent decision in [spec.md](spec.md#sort-native-and-web-agent-decision-379)):** a toolbar Sort button before Filter (Songs' `arrow.up.arrow.down` icon, `fst.shop.sort`, label "Sort Item Shop", value "<Mode>, <direction>" such as "Title, ascending", plus ", paused; showing Title order" while paused; accent blue, gold unless Title ascending) opens the Songs Sort sheet itself, `SongsSortSheet(modes: ShopSortChoice.modes, identifier: "fst.shop.sort")`: "Sort By", one Sort Mode radio group of **Title, Artist, Year, Duration** (`fst.shop.sort.mode`), the shared Sort Direction control (`fst.shop.sort.direction.{ascending,descending}`), red Reset to Title A–Z (`fst.shop.sort.reset`) and the system Close (`fst.shop.sort.done`). Choices apply live and persist in `fst.shop.sortMode` / `fst.shop.sortAscending` (apart from Songs; a player deselect keeps them). `ShopOfferSort` (FestivalCore) orders the filtered offers with `SongCatalogSort` (the Songs comparator), and the list and grid render that one order; a changed sort scrolls to the top. **Duration** reads lengths from the catalogue only when it, the Shop feed and the session observed the same publication (`ShopOfferSort.durations`, `SongShopPublicationPolicy`); otherwise the offers show title order in the chosen direction under a `FreshnessDisclosure` (`fst.shop.sort-paused`) and the choice is kept. iPhone: a sheet (HIG popovers › "Avoid popovers in compact views"; sheets › "Support swiping vertically to dismiss"); page tools Sort, Filter in the tab-bar accessory (`PageToolOrder.primary`, `.secondary`). Tests: `ShopOfferSortTests`, `ShopSortRenderTests`, device `testShopSortReordersOffersAndPersists`.
- **Filter (issues #19, #376, native only; the web Shop has none):** a toolbar Filter button (`line.3.horizontal.decrease`, `fst.shop.filter`, label "Filter Item Shop", value "No filters" or "Hiding" + the switched-off groups, e.g. "Hiding Leaving Tomorrow"; accent blue, gold while active) opens `ShopFilterSheet`: the shared `FestivalModal` ("Filter Shop", system Close top-right `fst.shop.filter.done`, swipe to dismiss) over a grouped `Form` with one Availability section of three switch rows — New, Available, Leaving Tomorrow (`fst.shop.filter.{new,available,leavingTomorrow}`) — and a destructive Reset Filters row (`fst.shop.filter.reset`), styled like the Songs Filter sheet. `ShopOfferFilter` (FestivalCore) keeps feed order; **Available = neither New nor Leaving Tomorrow**, so the three groups partition the feed (an offer flagged both is in both). The switches are **include toggles that start on** (#376, like `SongShopFilter`): the default and Reset list every offer, turning a switch off hides its group (an offer in two groups hides only when both are off), the filter is active only while a switch is off, and all off shows the no-match card. Switches apply live (no Cancel/Apply, like Songs). It reads the raw feed flags, so it still works with Shop highlights off. A filter that hides every offer shows "No offers match these filters" with its own Reset (`fst.shop.filter-empty{,.reset}`), never the genuine-empty card. HIG: toggles › "Use the switch style only in a list row" and "Clearly identify what the toggle affects" (an on switch means its offers show); sheets › "Support swiping vertically to dismiss"; modality › "Always provide an obvious, platform-conventional dismissal"; toolbars › "keep a short title under 15 characters". Tests: `ShopOfferFilterTests`, `ShopFilterRenderTests`, device `testShopFilterSheetNarrowsOffersAndResets`.
- **Filter (issues #19, #376, native only; the web Shop has none):** a toolbar Filter button (`line.3.horizontal.decrease`, `fst.shop.filter`, label "Filter Item Shop", value "No filters" or "Hiding" + the switched-off groups, e.g. "Hiding Leaving Tomorrow"; accent blue, gold while active) opens `ShopFilterSheet`: the shared `FestivalModal` ("Filter Shop", system Close top-right `fst.shop.filter.done`, swipe to dismiss) over a grouped `Form` with one Availability section of three switch rows — New, Available, Leaving Tomorrow (`fst.shop.filter.{new,available,leavingTomorrow}`) — and a destructive Reset Filters row (`fst.shop.filter.reset`), styled like the Songs Filter sheet. `ShopOfferFilter` (FestivalCore) keeps feed order; **Available = neither New nor Leaving Tomorrow**, so the three groups partition the feed (an offer flagged both is in both). The switches are **include toggles that start on** (#376, like `SongShopFilter`): the default and Reset list every offer, turning a switch off hides its group (an offer in two groups hides only when both are off), the filter is active only while a switch is off, and all off shows the filtered-empty state. Switches apply live (no Cancel/Apply, like Songs). It reads the raw feed flags, so it still works with Shop highlights off. A filter that hides every offer shows the shared centred `FestivalEmptyState` (`fst.shop.filter-empty`, issue #377): "No Item Shop songs match your filters" / "Try changing your filters to see more songs." (same wording as Android) with no card and no Reset button (Reset Filters lives in the Filter sheet), below any Shop disclosures, never the genuine-empty state. The genuine-empty Shop uses the web copy "No songs in the Item Shop" / "Check back later — the shop updates regularly." (`fst.shop.empty`, `ShopEmptyCopy`). The old "No offers match these filters" did not match the web, whose Shop has no filters ([empty-error-states](../../patterns/empty-error-states.md) R8, decisions). HIG: toggles › "Use the switch style only in a list row" and "Clearly identify what the toggle affects" (an on switch means its offers show); sheets › "Support swiping vertically to dismiss"; modality › "Always provide an obvious, platform-conventional dismissal"; toolbars › "keep a short title under 15 characters". Tests: `ShopOfferFilterTests`, `ShopFilterRenderTests`, device `testShopFilterSheetNarrowsOffersAndResets`.
- **Saved Shop filter (#376):** `fst.shop.offerFilter` holds the switched-off groups as comma-separated raw values in display order (`ShopOfferFilter.encoded()`; "" = default all on; all off is stored explicitly). `ShopOfferFilter.decodeSaved` reads the older #19 "show only" bools `fst.shop.filter{New,Available,LeavingTomorrow}` only while the new key is empty — all off → all on, any on → the same groups on — so the visible offers never change on update; every save clears them (the `SongGeneralFilter.decodeSaved` legacy-key precedent). Unknown tokens or text over 128 characters fall back to all on (hides nothing).
- Open: full focus order, landscape, rapid-gesture races on device, Shop WebSocket.
- **Load/reload fade (issue #71):** Shop runs the shared `FestivalReloadGate` on load and on a List/Grid switch, retry or publication change: old results leave at once, the spinner fades in, holds ≥400 ms, fades out (500 ms) and the results fade/stagger in; Reduce Motion swaps instantly. See [iPhone motion](../../design/apple/iphone.md#motion).
