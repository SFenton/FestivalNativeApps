# compete (`/compete`) — iPhone notes

> **What:** iPhone implementation state and decisions for the Compete phone hub. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md) (stub — this file is the source of truth for what's actually built until spec.md is promoted).

Source: `FortniteFestivalWeb/src/pages/compete/CompetePage.tsx`. This is the phone tab shown once a player is selected (`FestivalSection.compete`, wired up by Lane A's `FestivalRootView`); `CompeteScreen` receives `festivalRootChrome` from `FestivalRootView.tabStack(_:)` externally and must not apply it again itself.

- Implemented: `CompeteScreen` (`Features/Compete/CompeteScreen.swift`) with two `FestivalSectionHeader` groups:
  - **Leaderboards** — `CompeteInstrumentLeaderboardSection` per Settings-visible instrument: a live Top-5 `totalscore` preview via `session.rankings(instrument:rankBy:page:pageSize:)`, reusing Lane L's `AccountRankingRow`/`RankingsSkeletonRows`/`RankLoadState` (`Features/Leaderboards/RankingsSupport.swift`) so the cards render identically to `LeaderboardsScreen`'s own overview cards. "View Full Leaderboard" pushes `AppRoute.fullRankings(instrument:rankBy: "totalscore")`.
  - **Rivals** — reuses `RivalInstrumentSongSection` from `Features/Rivals/RivalsScreen.swift` (same live per-instrument rivals preview, "View All Rivals" push) for every Settings-visible instrument, passing `emptyMessage: "No rivals found for \(instrument.label) yet."` (matches the web's `compete.noRivalsSubtitle`) so an empty result renders that sentence instead of hiding — unlike `RivalsScreen`, which leaves `emptyMessage` nil and hides empty per-instrument sections (fixed 2026-09-28: previously Compete's "Rivals" header could show with nothing under it when every visible instrument had no rivals).
  No player selected → `RivalsChooseProfileState`.
- Simplified vs. web this pass: no "your rank" spotlight row when the player is outside the Top 5 (the web's `getPlayerRanking`/`getPlayerComboRanking`; `LeaderboardsScreen` itself has the same simplification today — see its own `ios.md`), no settings-derived multi-instrument "combo" ranking scopes (`resolveSupportedRankingScopes`), only single-instrument scopes. `CompeteInstrumentLeaderboardSection` reuses Lane L's *components* (read-only) but is this lane's own file/type — no edits to `Features/Leaderboards/**`. Compete intentionally does **not** adopt Rivals' Common Rivals/Combo sections — matches both this screen's own prior scope and the web's `CompetePage`, which has neither.
- **Quick Links + toolbar chrome (landed 2026-09-28):** Compete is a genuine `TabView` root (unlike Rivals, Rival Detail and Rivalry, which are reached as pushed pages from the drawer), so it follows the [Toolbar order rule](../../controls/app-navigation/ios.md#toolbar-order-rule-tab-roots) fully: `QuickLinksToolbarItem` (default `.topBarTrailing` placement) precedes `FestivalRootTrailingItems(session:)` in its own `.toolbar`, and the whole view applies `.festivalProvidesRootTrailingItems()` so the shared bell/avatar capsule stays rightmost. Two coarse sections register on the section containers themselves (not per-instrument): `leaderboards` "Leaderboards" (`trophy.fill`) and `rivals` "Rivals" (`person.2.fill`). `RivalInstrumentSongSection` (shared with `RivalsScreen`) is instantiated with `registersQuickLink: false` here so its own per-instrument tag doesn't also register into Compete's coarser controller. Verified live via `tools/ios_sim.py drive --route compete` + `tap:fst.quick-links.open`: the menu shows exactly "Leaderboards"/"Rivals", and the bell/avatar capsule stays at the trailing edge.
- **One leaderboard design (operator batch 7.4/7.6/7.7, Lane AP5):** no card around a preview; each row its own glass row (`AccountRankingRow(glassSurface: true)`, the selected player's web purple, bold), names truncate instead of marqueeing, and "View Full Leaderboard" is the shared purple `PurpleActionLabel`.
- **Loading (#35, 2026-10-01):** each leaderboard preview shows the white system spinner (`FestivalLoadingView`, label "Loading <Instrument> leaderboard") in a glass card under its instrument header, like the Rivals sections. Section headers render immediately. Previously it showed `RankingsSkeletonRows`: those redacted bars hide from accessibility, and the Rivals spinners sit below the fold, so the first screen had no progress indicator. HIG basis: Loading ("for waits beyond a moment or two, you can use system progress indicators … indeterminate otherwise") and Progress indicators ("Display progress indicators in a consistent location"). Each spinner is replaced by that section's rows, empty copy or `ServiceStatusInline` error. `LeaderboardsScreen` keeps its own page-level spinner. Test: `competeScreenRendersSpinnersWhileSectionsLoad`. The loaded/error tests exclude "Loading".
- **Back keeps the page (#39, 2026-10-01):** every leaderboard and rivals section remembers its loaded `CompeteSectionLoadKey` (instrument, selected account, publication revision) in a `ReappearanceLoadGate`. Back from View Full Leaderboard or a rival page therefore keeps the rows, the layout and the scroll position. Before the fix, `.task(id:)` restarted on reappearance and reset each card to its spinner, so every card collapsed, re-expanded and faded in again under the pop. A failed or cancelled load still retries on return, and a new publication or account reloads. Tests: `competeKeepsLoadedLeaderboardsWhenItReappears` (hosted; fails without the gate) and `ReappearanceLoadGateTests`. See [architecture](../../platforms/apple/architecture.md#reappearance-keeps-loaded-content).
- **No Leaderboards overview link (#36, 2026-10-01):** the web's `CompetePage` links each scope only to its own full board (header "See All" and "View Full Leaderboards" → `Routes.fullRankings`); it never links to the overview. The iPhone hub's extra "Leaderboards Overview" row and the Duo carousel's Overview card and Leaderboards-pane See All were removed. Each instrument's "View Full Leaderboard" still pushes `AppRoute.fullRankings`; the overview stays in the drawer, like the web sidebar. HIG basis (Designing for iOS): "Limit onscreen controls to keep primary content and tasks prominent". Tests: `CompeteRenderTests` and `competeDualShowsLeaderboardsAboveRivals` assert the label is absent; `RivalsJourneyTests.testCompeteHasNoOverviewButtonAndViewFullLeaderboardPushesFullRankings` taps through to "Lead Rankings". In XCUITest the section's container identifier overrides the link's `.view-all` identifier, so match the "View Full Leaderboard" label.
- **Songs column fits or hides (#38, 2026-10-01):** on a portrait iPhone the songs played/total column squeezed usernames (the bold selected name truncated, e.g. "Fixture Play…"). Each leaderboard card now shows songs only when its longest name fits beside them; otherwise the whole card hides them, so columns stay aligned, and VoiceOver reads them as the row's value. Mechanism and tests: [leaderboard-row-columns/ios.md](../../controls/leaderboard-row-columns/ios.md). HIG basis: Lists and tables "Keep item text succinct."; Typography "Where width is constrained, inline items … can crowd text into truncation or overlap".
- Known pre-existing quirk: the card's outer `accessibilityIdentifier` (`fst.compete.leaderboard-card.<instrument>`) overrides the inner `.loading`/`.view-all` IDs on device, so drive scripts must tap "View Full Leaderboard" by label.
- IDs: `fst.compete.leaderboard-card.<instrument>`, `fst.compete.leaderboard-card.<instrument>.loading`, `fst.compete.leaderboard-card.<instrument>.view-all`; rival rows reuse `RivalRowContent`'s combined accessibility label with no additional identifiers.
- Tests: covered indirectly by `RivalsTests.swift` (Rivals Core models/endpoints) and Lane L's `RankingsTests.swift` (Rankings Core models/endpoints), since this screen has no Compete-specific Core logic of its own. `tools/ios_sim.py shot`/`drive --tab compete` verified real Top-5 rows and rival previews against the live public service (2026-09-28).
- Leaderboard previews use `InstrumentSectionHeader` (web SM, 36 pt icon) above each card; rows and the "View Full Leaderboard" link fade in on load (2026-09-28, Lane AP2).
