# Compete — Android notes

> **What:** Android state of `/compete`. **Read when:** changing `core|data|presentation|ui/compete/**` in `android/`. Rivals notes: [../rivals/android.md](../rivals/android.md).

- Phone tab (`CompeteTab`, compact width with a selected player) and pushed `CompeteRoute`. Port of web `CompetePage`: scopes from `CompeteScopes.resolve` (web `resolveSupportedRankingScopes`: per family the combo first when 2+ charts in OG band / Pro Strings, then each chart).
- Leaderboards group: per scope a Top 10 Total Score card (instrument boards reuse the Leaderboards feature's `rankings`/`playerInstrumentRanking` and `AccountRankingRow`; combo boards read `GET /api/rankings/combo?combo=&rankBy=totalscore&page=1&pageSize=10` and `/api/rankings/combo/{accountId}`), the player's own row below a divider when ranked outside the top rows, "View full leaderboards" → `FullRankingsRoute` (single charts only; no native combo board yet). Combo 404 = "No scores yet".
- Rivals group: per scope 3 above / 3 below (`rivals/{chart|hexCombo}`), See All → All Rivals and rows → Rival Detail with the scope (`song:<chart>` or `combo:<hex>`). Empty/no-player copy from web `compete.*`.
- Every read retries independently (inline status); all leaderboards failed → full-page status. Quick Links (shared `QuickLinksAction`: bottom sheet on compact windows, menu otherwise; instant jumps, 7.15) list Leaderboards (trophy) / Rivals (people), web `CompetePage` IDs `leaderboards`/`rivals` (`RivalQuickLinks.compete`); hidden on a full-page failure. Same adaptive grid as Rivals.
- **Loading (#65, 2026-10-02):** every leaderboard and rivals card shows `RivalCardLoading` (Material 3 indeterminate `CircularProgressIndicator` in a 120 dp glass card, TalkBack "Loading <scope> leaderboard" / "Loading <scope> rivals") under its header until that card's rows, empty copy or inline `ServiceStatus` replace it. Leaderboard cards previously showed static `RankingsSkeletonRows` bars, so the first screen had no progress indicator (iOS #35 made the same change). The Leaderboards overview cards keep their skeleton rows under the page load swap. Test: `CompeteUiTest.sectionsShowProgressIndicatorsUntilRowsOrErrorsArrive`.
- **Return from View Full Leaderboard (#82, 2026-10-02):** checked against iOS #39/#35. `CompeteViewModel` is keyed by account + visible charts and stays on the back stack, so Back shows the laid-out grid at its scroll position with no placeholder or re-read (no jitter; the emulator is unavailable on the Windows host, so this was checked in Robolectric by sampling 120 frames of the return). The model now follows `FestivalApi.publicationChanges` (`filterNotNull().distinctUntilChanged().drop(1)`, like `ShopStore`): a newer publication refreshes every board and rivals read in place (`RetryingLoader.refresh` keeps loaded cards; failed reads retry), the same publication does nothing, and an account or chart change builds a new model. Tests: `CompeteUiTest.returningFromFullLeaderboardKeepsCompeteInPlaceWithoutReloading`, `CompeteLogicTest.newerPublicationRefreshesInPlaceAndSamePublicationDoesNot` / `firstObservedPublicationDoesNotReloadAndNewerOneRetriesFailures`.
