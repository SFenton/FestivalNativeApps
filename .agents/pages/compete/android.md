# Compete — Android notes

> **What:** Android state of `/compete`. **Read when:** changing `core|data|presentation|ui/compete/**` in `android/`. Rivals notes: [../rivals/android.md](../rivals/android.md).

- Phone tab (`CompeteTab`, compact width with a selected player) and pushed `CompeteRoute`. Port of web `CompetePage`: scopes from `CompeteScopes.resolve` (web `resolveSupportedRankingScopes`: per family the combo first when 2+ charts in OG band / Pro Strings, then each chart).
- Leaderboards group: per scope a Top 10 Total Score card (instrument boards reuse the Leaderboards feature's `rankings`/`playerInstrumentRanking` and `AccountRankingRow`; combo boards read `GET /api/rankings/combo?combo=&rankBy=totalscore&page=1&pageSize=10` and `/api/rankings/combo/{accountId}`), the player's own row below a divider when ranked outside the top rows, "View full leaderboards" → `FullRankingsRoute` (single charts only; no native combo board yet). Combo 404 = "No scores yet".
- Rivals group: per scope 3 above / 3 below (`rivals/{chart|hexCombo}`), See All → All Rivals and rows → Rival Detail with the scope (`song:<chart>` or `combo:<hex>`). Empty/no-player copy from web `compete.*`.
- Every read retries independently (inline status); all leaderboards failed → full-page status. Quick Links (shared `QuickLinksAction`: bottom sheet on compact windows, menu otherwise; instant jumps, 7.15) list Leaderboards (trophy) / Rivals (people), web `CompetePage` IDs `leaderboards`/`rivals` (`RivalQuickLinks.compete`); hidden on a full-page failure. Same adaptive grid as Rivals.
- Board rows (issue #38): each card reports its row width to `rememberAccountColumns(…, fitNamesTo =)`, which measures the widest name in the card, pinned row included. `LeaderboardColumnLayout.fit` shows the `X / Y` songs column only if rank · full name · songs · score · chevron fit at the rankings row's 16 dp padding and 12 dp spacing. Otherwise the whole card hides it, and also before the first layout. Rank and score widths stay shared, so the columns stay aligned. The row's TalkBack description keeps "N / M songs". At font scale ≥ 1.3 the stacked row keeps songs on its own line. Pixel 9 portrait (≈362 dp rows) hides songs for fixture names like "Fixture Rank 10"; landscape (two-column grid) shows them. Other rankings surfaces pass no `fitNamesTo`: they keep songs unless names would collapse below 32 dp (Leaderboards overview cards measure their row width for that, issue #114; the paginated full boards pass no width yet).
- **Loading (#65, 2026-10-02):** every leaderboard and rivals card shows `RivalCardLoading` (Material 3 indeterminate `CircularProgressIndicator` in a 120 dp glass card, TalkBack "Loading <scope> leaderboard" / "Loading <scope> rivals") under its header until that card's rows, empty copy or inline `ServiceStatus` replace it. Leaderboard cards previously showed static `RankingsSkeletonRows` bars, so the first screen had no progress indicator (iOS #35 made the same change). The Leaderboards overview cards keep their skeleton rows under the page load swap. Material 3 (agent decision, #173): progress indicators are Communication components with a context label (`material-3` `references/component-catalog.md`: "Add `aria-label` for context (e.g., "Loading messages")"), so each card's `contentDescription` names its scope; the indicator stays the canonical `FestivalLoading` `CircularProgressIndicator` (`empty-error-states` R5), not the M3 Expressive `LoadingIndicator`, so loading looks the same app-wide. It is non-interactive (no 48 dp target) and shows a static arc at animator scale 0. Tests: `CompeteUiTest.sectionsShowProgressIndicatorsUntilRowsOrErrorsArrive` and `spinnersGiveWayToEmptyCopyAndRivalsErrors` (rows, "No … rankings yet", "No rivals found …" and the inline error each replace their card's labelled spinner), connected `CompeteDeviceJourneyTest.cardsShowLabelledProgressUntilRowsArrive` (indeterminate progress semantics, TalkBack label in reading order, ATF checks, no hinge straddle). `FakeTransport.beforeRespond` holds reads open for these.
- **Return from View Full Leaderboard (#82, 2026-10-02):** checked against iOS #39/#35. `CompeteViewModel` is keyed by account + visible charts and stays on the back stack, so Back shows the laid-out grid at its scroll position with no placeholder or re-read (no jitter; the emulator is unavailable on the Windows host, so this was checked in Robolectric by sampling 120 frames of the return). The model now follows `FestivalApi.publicationChanges` (`filterNotNull().distinctUntilChanged().drop(1)`, like `ShopStore`): a newer publication refreshes every board and rivals read in place (`RetryingLoader.refresh` keeps loaded cards; failed reads retry), the same publication does nothing, and an account or chart change builds a new model. Tests: `CompeteUiTest.returningFromFullLeaderboardKeepsCompeteInPlaceWithoutReloading`, `CompeteLogicTest.newerPublicationRefreshesInPlaceAndSamePublicationDoesNot` / `firstObservedPublicationDoesNotReloadAndNewerOneRetriesFailures`. **#185:** the board cards' measured row width (issue #38) was a plain `remember`, so the recomposed destination drew its first frame back with an unmeasured plan: on wide cards the `X / Y` songs column dropped out for one frame (fully visible at animator scale 0). The width now comes from the shared `rememberRankingRowWidth()` (saved with the destination; `leaderboard-row` R1), also used by the Leaderboards overview cards and Full/Band Rankings. On the half-opened Book Fold the connected test then found a second first-frame jump: `AdaptiveCardGrid` lost its measured window bounds and saw no hinge (its own posture collector starts empty), so the first frame laid the grid out as one full-width column, and the wider card flashed its songs column before the two hinge columns returned. Every destination-level layout measurement now uses the saved helpers in `ui/common/MeasuredLayout.kt`, and every page reads hinges through `shellPosture()` ([android platform rule](../../platforms/android.md#navigation)). Tests: `CompeteReturnColumnsUiTest` (1280 dp, native graphics; the songs cells under the card and the card's bounds are checked on every frame of the return; it fails with the grid's old `remember`) and `MeasuredLayoutTest`.
- Combo rankings handlers are pure `SELECT`s (`FSTService/Api/RankingsEndpoints.cs:528-613`, `Persistence/MetaDatabase.cs:7357-7392`), inside the allowlisted `/api/rankings/*` family and named in the service-safety table.
- IDs: `fst.compete.grid`, Quick Links `fst.quick-links.open|item.<leaderboards|rivals>`, `.section.<leaderboards|rivals>`, `.leaderboard-card.<scope>`, `.leaderboard-card.<scope>.loading`, `.rivals-card.<scope>`, `.rivals-card.<scope>.loading`, `.board.see-all.<scope>`, `.rivals.see-all.<scope>`, `.rank.<scope>.<key>`, `.spotlight.<scope>`, `fst.compete.scope-header.<stacked|row>`. ## Validation (issue #185, 2026-10-06): return from View Full Leaderboard

Rule: Compete → View Full Leaderboards → Back puts the card back at the same position, with the same rows and the same columns on every frame. It shows no loading placeholder and makes no re-read while the publication and account are unchanged. Fixed two first-frame jumps, both caused by measured layout kept in a plain `remember`:
- On wide cards the songs column dropped out for one frame. Fix: the shared `rememberRankingRowWidth()` (`leaderboard-row` R1).
- The grid itself drew one full-width column for a frame. This was found on Book Fold half-open, where the narrow lane's card flashed its songs column. There were two causes. The grid's measured bounds were not saved, and the page read the hinge from its own `currentWindowAdaptiveInfo()`, which starts with no hinges. Fix: `AdaptiveCardGrid` now uses the saved `rememberMeasuredBounds` and reads the hinge from the shell's `shellPosture()`.

Tests:
- `CompeteReturnColumnsUiTest` (Robolectric, 1280 dp, every frame)
- Connected `CompeteDeviceJourneyTest.leaderboardsGroupOpensTheFullBoardAndComesBack`: songs cells on each of 60 frames, unchanged card bounds, no `.loading`, ATF.

Live public service with `SFentonX`, no profile headers. The 19 configurations ran on the build with the row-width fix: they compare end states, so they cannot see a one-frame flash. The grid and posture fix was then confirmed by the per-frame connected test and a recorded half-open Book Fold run. Animator scale was 0 unless noted. Each run compares UIAutomator trees and screenshots before leaving and after Back: all texts are the same, there is no `.loading` node, and the only diff is the Quick Links FAB reappearing (`page-tools-and-nav-chrome` R7 resets the toolbar on navigation). When the FAB overlaps a row, Compose reports the row's uncovered bounds, so its right edge shrinks to the FAB's left edge. This is not a layout move.
