# Settings — Android notes

> **What:** what the Android Settings page implements, where every setting lives, its reset registry and native decisions. **Read when:** changing `ui/settings/SettingsScreen.kt`, any `AppSettings` field, or adding a persisted key anywhere in the Android app. Behavior: [spec.md](spec.md); references: [ios.md](ios.md), [windows.md](windows.md).

## Implementation

| Piece | Where |
|---|---|
| Model | `core/settings/AppSettings.kt` (every field, `sanitized()`, `withInstrumentVisible` last-visible guard, `resetAppSettings()`, derived `shopHighlightEnabled` / `orderedVisibleMetadata`) |
| Codecs | `core/settings/SettingsModels.kt`: `MetadataField` (web `DEFAULT_METADATA_ORDER`, web keys `seasonachieved`/`lastplayed`), `PathColumnKey`, `PathDisplayMode`, `SettingsOrder` (normalize/decode/encode/move), `ScoreLeeway` (clamp half-away-from-zero to 0.1, `+1.0%` format, web `maxScoreLeewayDesc`) |
| Registry | `core/settings/SettingsRegistry.kt`: every DataStore key with `ResetPolicy.AppSetting` (Reset removes it) or `Kept`; `retiredKeys` lists keys older builds wrote, which `data/SettingsRepository.kt` `RetiredSettingsMigration` deletes when the store opens |
| Store | `data/SettingsRepository.kt`: `update { }` (atomic decode → transform → sanitize → write), `resetAppSettings()`, `readBlob`/`writeBlob` for registered string blobs (first-run and notification seen-state) |
| Page model | `presentation/settings/SettingsViewModel.kt` (setters, Reset, service version), `presentation/settings/ServiceInfoPoller.kt` (5 s Service Info poll + progress memory) |
| Service Info | `core/serviceinfo/ServiceInfo.kt` (wire model without infrastructure fields, `ServiceProgressReducer`, `ServiceInfoText`, `ServiceInfoRows`), `data/serviceinfo/FestivalApiServiceInfo.kt` (`serviceInfo()`, `serviceVersion()`), `ui/settings/ServiceInfoSection.kt` |
| Page | `ui/settings/SettingsScreen.kt`; Licenses: [licenses/android.md](../licenses/android.md) |
| List/detail (wide windows, #371) | `core/settings/SettingsPanes.kt` (`SettingsDetail`: id, title, hint, row tag; `SettingsPanes.available/shown`; `SettingsDetailText` placeholder copy), `SettingsScreen.kt` `SettingsDetailPlaceholder` / `SettingsDetailContent`, `LicensesScreen.kt` `LicensesPane`, `PrivacyPolicySheet.kt` `PrivacyPolicyPane` |

**Adding a persisted key anywhere in the app:** declare it in `SettingsRegistry.entries` with its reset policy. `SettingsModelTest` fails when a key written through the repository is unregistered. **Removing one:** move its name to `SettingsRegistry.retiredKeys` so existing installs drop the stored value.

## Decisions

- No Diagnostics section in any build (owner, #374): the web's Tap Diagnostics / Tap Telemetry toggles are not ported, and the app never calls the web-only `POST /api/debug/client-interactions`. Their `fst.settings.tapDiagnostics` / `fst.settings.tapTelemetry` keys are retired.
- Rows: whole-row `toggleable(role = Switch)` with title + description; a disabled row appends its reason so TalkBack reads why.
- Reorder (`ui/settings/ReorderList.kt`, batch 6.11) looks like the web's dnd-kit list: one bordered block of subtle rows with a ⋮⋮ handle and a semibold label, no numbers or arrow buttons. Drag the handle, or long-press anywhere on a row (the web's 150 ms touch activation) with a haptic tick; TalkBack/Switch Access use the rows' Move up / Move down custom actions. Song Row Visual Order shows directly under its toggle when enabled (no dropdown). Also used by the Songs sort sheet.
- Labels follow the web: metadata "Difficulty" (not "Game Difficulty", batch 6.13); First Run Guides rows show only the page name and a blue "Show" button (no slide counts, batch 6.16).
- Licenses entry (batch 6.17) is the web's navigation row: a section header (title + description) on the page with a trailing chevron, not a card. Licenses centres its column at 840 dp on wide windows (M3 expanded-width body cap); Settings on wide windows is a list/detail split instead (#371). The modifier order is `widthIn(max = 840.dp).fillMaxWidth()`: `fillMaxWidth()` first pins the minimum width to the parent and the cap is then ignored (issue #121, 958–968 dp on tablets).
- Read-only title/value rows (Version rows, App Version, the Service Info state row) are one component, `ui/settings/SettingsValueRow.kt` ([settings-value-row](../../patterns/settings-value-row.md); issue #121, consolidated in #184): title and value sit side by side when both fit at their intrinsic widths plus a 12 dp gap, otherwise the value stacks 4 dp under the title (and supporting text). A fixed `Row` with a `weight` value crushed "Service" into a one-letter column beside the long origin at font scale 2.0 and on 360 dp folded covers; a font-scale threshold stacked wide tablet columns needlessly and squeezed half-open fold panes at 1.0. Never write another fit `Layout` in a Settings row: pass `supporting`/`trailing` to `SettingsValueRow`.
- Service Info: labels, units and the monotonic reducer port the web/Apple tables verbatim; the body's `postgresConnectionTarget`/`serviceInstance` have no model fields, so they are never decoded or logged. The card is **not** a live region (issue #121, deliberate deviation from the web's `aria-live`): on a real emulator a polite live region announced when TalkBack scrolled the card into view (the 5 s poll starting) and TalkBack then spoke nothing for the next five focus moves; without it all 99 items read in order. Focusing the state row reads the current state; the phase row speaks its title with the percent, units and discovery attempts as state and, whenever it draws a bar, exposes `ProgressBarRangeInfo` (indeterminate when the total is unknown, like the web's `role="progressbar"`; issue #184), so TalkBack ends it with "Progress bar".
- Service Info and Material 3 (`material-3` skill, `references/component-catalog.md` § Lists and § Progress indicators): rows use Body Large headlines with Body Medium `onSurfaceVariant` supporting text; the indicator is determinate (`value`) when the total is known and `indeterminate` otherwise, with a built-in progress-bar role, which Compose exposes as `progressBarRangeInfo` (determinate or `Indeterminate`) with the phase label as the content description. The bar is 10 dp (web `.progressTrack` 0.65rem, iOS 10 pt), not M3's 4 dp default. Deliberate deviations: the dark-only brand theme, translucent glass cards, the web's purple track colours, and no live region (#121).
- Not ported: profile-name refresh (POST), ZIP export (not allowlisted), light trails / mobile header buttons (no cursor or FAB chrome on Android), default search target (global search has no tabs to default).
- List/detail on wide windows ([split-panes](../../patterns/split-panes.md) R6, owner #371): when `AdaptiveLayoutPolicy.showsTwoPanes` is true (expanded width, or a separating vertical hinge in book posture) Settings is always two panes, the same gate and list width as Songs/Licenses (`listPaneWidth`, else up to the hinge), separated by space with no drawn divider. With nothing selected the right pane is `SettingsDetailPlaceholder` (`fst.settings.detail-placeholder`): the shared `FestivalEmptyState` with a 48 dp Settings icon, "Settings" and "Select a setting to see more options here", vertically centred. Toggles, feedback rows, Experimental Ranks and Reset stay in the list and never change the pane. Show Instruments, Item Shop, Accessibility, Show Instrument Metadata, Version, Service Info, First Run Guides, Licenses and Privacy Policy become chevron rows (`NavigationRow`, `fst.settings.open.<id>`; Licenses `fst.settings.licenses`, Privacy `fst.settings.privacy-policy`) with `selected` semantics and a purple tint; the pane (`fst.settings.detail.<id>`) shows the section's header and controls. App Settings' multi-option controls (CHOpt Path Default View, CHOpt Text Path Column Order, Song Row Visual Order while its switch is on, Maximum Score Leeway while Filter Invalid Scores is on) become value rows with chevrons; a selected row whose switch turns off returns the pane to the placeholder. The selection survives rotation (`rememberSaveable`); an open Privacy modal moves into the pane when the window becomes two-pane. Service Info polls only while its pane is shown. Quick Links still scroll the list. Phones (compact/medium, folded covers) are unchanged.
- Quick Links: see [quick-links/android.md](../../controls/quick-links/android.md).
