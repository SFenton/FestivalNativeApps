# Settings — iPhone notes

> **What:** what the iPhone Settings page implements, native decisions and open gaps. **Read when:** changing Settings on iPhone (Lane A owns `Features/Settings`). Behavior: [spec.md](spec.md).

## Decisions and gotchas

- **List/detail in wide landscape** (owner-approved, issue #371; replaces #355's two columns here): wherever Settings can split (iPad landscape and the iPhone Duo inner display in landscape), the list sits on the left. With nothing selected, the right pane shows a vertically centred Settings icon, "Settings" and "Select a setting to see more options here" (`fst.settings.placeholder`). Plain toggles and buttons act in the list. Every group with more options is a chevron row, `fst.settings.topic.<topic>` (`SettingsTopic`), that opens on the right with a Close button: Song Row Visual Order, CHOpt Paths, Accessibility, Item Shop, Show Instruments, Show Instrument Metadata, Version, Service Info, First Run Guides, Licenses and Privacy Policy, which is inline there and a sheet elsewhere. Turning Independent Visual Order off (its switch or Reset) while Song Row Visual Order is open closes it back to the placeholder (R6, issue #372); its "Turn on…" note (`fst.settings.song-row-order.off`) now shows only for a deep link. The complete rule is [split-panes](../../patterns/split-panes.md) R6. iPhone, portrait, the folded Duo and compact tiles keep the single page in one readable column. The Mac Settings window panes keep two balanced columns ([wide-columns](../../patterns/wide-columns.md) R7). Debug: `FST_DEBUG_TAB=settings FST_DEBUG_ROUTE=settingsTopic:<topic>`. Order, Quick Links, stagger and VoiceOver order stay the one-column sequence. HIG Designing for iPhone Duo: "a width reflow (Music goes from stacked to two columns)" (should); HIG Layout: "Accommodate Dynamic Type… horizontal views may stack" (should). Tests: `WideColumnsTests` (`balancedSplitEvensTheColumns`, `readableColumnsStackAtAccessibilitySizes`, `readableWidthCapsEachColumn`, `macSettingsWindowHoldsTwoColumns`), hosted `WideColumnStackHostedTests`.
- **No scroll-bar setting** (issue #356, agent decision; owner may `/choose`): Settings never gets an "Always Show Scroll Bars" toggle. Pages keep the system indicators ([scroll-indicators](../../patterns/scroll-indicators.md) R1–R2; HIG [Settings](https://developer.apple.com/design/human-interface-guidelines/settings): "Don't duplicate global accessibility, scrolling, or authentication options", should).
- Section order follows the web: … Version · Service Info · First Run Guides · Licenses · Privacy Policy · Reset. App Settings row order is the web's: icons, independent visual order (+ inline list), Path default view, text path column order, Filter Invalid Scores (+ leeway), experimental ranks, then the native-first Report an Issue and Request a Feature rows (issue #78).
- **Reorder lists** (`SettingsReorderList`, batch 6): drag a row by its leading grip (44 pt target); anywhere else scrolls. A drag gesture over the whole row — `.gesture`, `.simultaneousGesture` or long-press-sequenced — stopped the Settings `ScrollView` from scrolling on iOS 26, so only the grip carries the gesture; the page disables scrolling while a row is lifted (`SettingsReorderDragActiveKey`). Rows expose **Move Up/Move Down** actions and "n of m" values.
- **Licenses row**: the web's standalone link (section title + description + white chevron, no card). **Privacy Policy row** (issue #98): same style, opens a sheet ([privacy-policy](../../controls/privacy-policy/ios.md)). **Reset**: web header plus a full-width red button; the confirmation uses the web title "Reset Settings".
- Sections reveal with `festivalFadeIn(isLoaded: true, index:)` in a plain `VStack` (a lazy stack would replay the fade on recycled cards).
- Row labels: title (semibold, the web's `toggleLabel`) and detail both `FestivalText.primary` (white-text rule), detail in `.subheadline` with 4 pt spacing (HIG list-row subtitle; operator 2026-09-28). Settings, First Run and What's New use `FestivalText` tokens only; chevrons are `deemphasized`.
- **Disclosure state for VoiceOver** (issue #20, probed on iOS 26.5): SwiftUI `DisclosureGroup` leaves UIKit `accessibilityExpandedStatus` *unsupported* in both states, and SwiftUI has no public expanded-status modifier, so the header's value carries it: `"<choice>, Collapsed|Expanded"` (`SettingsChoiceAccessibility.value`). XCUITest reports the header as `DisclosureTriangle`, but that role carries no state. Put the identifier on the label, not the group (iOS 26 group identifiers override nested ones).
- Indeterminate progress sweeps the web's 38 % segment, but holds a still empty track under Reduce Motion and in UI-test runs (`FST_DEBUG_STILL_BACKGROUND`): a `repeatForever` animation stalls XCUITest idling. The spoken value is "In progress — total not yet known".

- Section headers use `textSecondary` (not system gray) over translucent artwork gaps; three visible headers pass rendered-pixel ≥4.5:1 on `art-white`.
- Last Played switch still shows a date under Title (temporary native deviation until Last Played sort); experimental ranks stay disabled.
- The Form keeps its scroll position across tab switches: UI tests must try the reverse swipe for an earlier toggle.
- Every persisted setting is registered and has cold-start round-trip and reset coverage (Lane A, 2026-09-27). Groups render as `FestivalGlassSection` cards ([liquid-glass.md](../../design/apple/liquid-glass.md)).
- **Quick Links adopted** (Lane P follow-up, 2026-09-28): `app-settings`, `item-shop`, `show-instruments`, `show-metadata`, `version`, `service-info` (the `service` section), `first-run` (tags `FirstRunSettingsSection` from the call site, no edit to that FRE-lane file), `licenses` (the `about` section) and `reset`, matching the spec order/icons. `refresh-profile-name`/`export` are left out — this screen has no such rows yet (see Open below) — rather than pointing a quick link at nothing. Tab root with its own page action, so it now ends its single `.toolbar` with `FestivalRootTrailingItems(session:)` and calls `.festivalProvidesRootTrailingItems()`, per the toolbar-order rule.
- **Hosted + XCUITest coverage** (Lane U4, updated by AP4 2026-09-28): `SettingsRenderTests.swift` (defaults, inline reorder lists without Check Publication, the inline Paths-default accordion (`WhatsNewAndServiceInfoTests`), `SettingsReorderList` render, fixture-tools gate, What's New pull threshold, `SettingsServiceSummary` branches); `SettingsJourneyTests.swift` (accessibility toggle survives relaunch, grip drag reorders CHOpt columns and a swipe over the list still scrolls, View Licenses → third-party only, Reset restores defaults; needs `mock_service.py --port 18790`); `FestivalCoreTests/SettingsBatch6Tests.swift` (reorder math, invalid-score policy).
- **`SettingsRegistry.SettingDefault` gained a `.data(Data)` case** (Lane P, 2026-09-28) so Suggestions' own `SuggestionFilterSettings.storageKey` (a Codable-JSON `@AppStorage(Data)`, default `Data()`) is included in "Reset App Settings" and the persistence round-trip test, without SettingsScreen needing to understand that type's contents — it only resets the key to empty `Data()`, matching `SuggestionFilterSettings`'s own "absent/empty means defaults" contract.
