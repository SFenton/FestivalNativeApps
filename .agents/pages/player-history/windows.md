# Player history — Windows notes

> **What:** the Windows score-history page for the selected player. **Read when:** changing `windows/Festival.App/Pages/PlayerHistoryPage*` or `PlayerHistoryViewModel`. Behavior: [spec.md](spec.md).

- **A separate page again (#324, owner: "We should go to a sub-page with sorts like web app"; supersedes operator 6.39's fold-in).** `AppRoute.PlayerHistory(songId, instrument)` (`/songs/:id/:instrument/history`, notifications, Song Detail's View All Scores, [view-all-cta](../../patterns/view-all-cta.md) R8) navigates the content `Frame` to `PlayerHistoryPage`; the title-bar back button returns. Song Detail is a pushed page, not cached, so Back rebuilds it at the top, the same as its leaderboard View All ([back-keeps-place](../../patterns/back-keeps-place.md) out of scope: pushed-page caching is a deferred navigation decision). Song Detail keeps the chart and its top five rows ([song-detail/windows.md](../song-detail/windows.md)).
- Reads `GET /api/player/{accountId}/history?songId=&instrument=` via `FestivalApiClient.GetPlayerHistoryAsync` (202 → Syncing, 404 → Unregistered; rows re-filtered to the song/chart like the web) and the catalogue (`LoadCatalogAsync`, cached) for the header. No selected-profile header.
- Layout (web `PlayerHistoryPage`): a fixed top row with the song-first header (`SongLeaderboardHeader`: art, title → Song Detail, artist, instrument; [song-leaderboard-header](../../patterns/song-leaderboard-header.md)) and the page's Sort beside it (web header actions); below it a `ScrollViewer` of shared `LeaderboardEntryRow`s ([leaderboard-row](../../patterns/leaderboard-row.md); date label, score, accuracy/FC, stars, season) 4 epx apart, staggered fade-in. The song cover is the page backdrop (`IBackdropPage`). No chart: the web page has none and Song Detail already shows it. Compact (< 760 epx) narrows the padding to 12,8.
- **Agent decision (#324; owner may override with `/choose`):** the header and Sort stay fixed above the scrolling rows, like the band leaderboard's fixed header, rather than scrolling away; the web pins its header actions in the same place.
- Song header (#315 + #324): `SongLeaderboardHeader`'s title and artist are the shared `SongHeaderText` Page column ([song-header](../../patterns/song-header.md) R1–R3): one-line `MarqueeText`s that scroll on overflow, ellipsize with motion off and wrap in-page at 150%+ text; never a page-local subtitle. `song-header-title.json` `player-history-*` and `a11y-song-header-text.json` `song-header-text-history` check `fst.history.title`/`.artist` on this page, and `SongHeaderMarkupTests.SongLeaderboards_UseTheSharedHeader` guards the markup.
- States (`PlayerHistoryPhase`): NoPlayer ("No Player Selected"; a deselect while open, since a cold link without a player opens Songs via `AppRouteParser.RequiresPlayer`, operator 2026-09-28), Loading (`ProgressRing`), Unregistered ("History Unavailable", registered users only), Syncing ("Still Syncing" + Retry), Empty ("No History Yet", also when the invalid-score filter leaves nothing), Failed (`ServiceStatusView`), Loaded. A selected-player change re-reads; an invalid-score filter or leeway change re-sorts in place.
- Sort: a `DropDownButton` (shows "Score ↓", spoken "Sort by Score, descending") + `MenuFlyout` with radio items (Date/Score/Accuracy/Season, Ascending/Descending, Reset) that applies immediately and scrolls back to the top (web: apply scrolls to top). This Fluent command-menu idiom (same as Songs' `SortButton`, [page-tools-and-nav-chrome](../../patterns/page-tools-and-nav-chrome.md) Windows page actions row) replaces the web modal with Apply/Cancel. Default Score descending; not persisted (matches the web). The personal-best row is highlighted wherever the sort puts it (`PlayerScoreHistorySort.HighScoreIndex`).
- IDs: `fst.history.{title,artist,instrument,total,song}`, `fst.history.{list,rows,message,retry}`, rows `fst.history.row.<yyyyMMddHHmmss>` (local time, so the ID depends on the host's time zone; Song Detail's top-five rows are `fst.song-detail.history.row.<…>`), `fst.history.sort.open`, `fst.history.sort.mode.{date,score,accuracy,season}`, `fst.history.sort.direction.{ascending,descending}`, `fst.history.sort.reset`; failure `fst.service-status.{title,retry}`. Song Detail's card keeps `fst.history.*`.
- Fixture: `tools/mock_service.py` history rows use the production int accuracy scale (`991200`); `fixture-history-multi` has 8 Lead / 2 Bass / 3 Drums points (paging), `fixture-history-fail` returns 500 (failed state), `fixture-syncing` 202, `fixture-player-2` 404.
