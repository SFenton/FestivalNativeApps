# Player history — iPhone notes

> **What:** iPhone implementation state and decisions for score history. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md). Endpoint safety: [service-safety](../../platforms/service-safety.md).

Source: `FortniteFestivalWeb/src/pages/leaderboard/player/PlayerHistoryPage.tsx`, `.../modals/PlayerScoreSortModal.tsx`. Service: `FSTService/Api/PlayerEndpoints.cs:733-790` (`/api/player/{accountId}/history`) — pure, keyless `GET` of a precomputed cache, confirmed by reading the handler body; never writes.

- Implemented: `PlayerHistoryScreen` (`Features/SongLeaderboard/PlayerHistoryScreen.swift`) reads `session.selectedPlayer` and calls `FestivalCore`'s new `PublicEndpoint.playerHistory(accountId:songId:instrument:)` (added to the shared enum; also added `.playerNotifications` in the same pass — see `controls/notifications/ios.md`). States: no player (`ContentUnavailableView`), loading, `.unregistered` (HTTP 404), `.syncing` (HTTP 202), empty-for-instrument, loaded. Loaded rows sit in one `List` with `.scrollContentBackground(.hidden)` and flat, non-glass rows (per `liquid-glass.md`'s "avoid per-row glass in long lists"); the personal-best row gets a tinted purple background instead of a separate glass card. `PlayerHistorySortSheet` ports `PlayerScoreSortModal` 1:1 (mode + direction, Cancel/Reset/Apply with a discard-changes alert), reusing the `SongsSortSheet` form pattern.
- Native addition beyond the web: a Swift Charts (iOS 16+) score-over-time line chart above the list, shown only for 2+ dated entries, with the personal-best point in gold.
- Simplified vs. web this pass: invalid-score filtering (`useScoreFilter`) is not applied to history rows natively; sort state resets to `score`/descending each visit (matches the web — it is not persisted there either).
- **Not reachable via app navigation yet.** Song Detail and the solo leaderboard (`SoloLeaderboardScreen`, Lane L) have no link to `.playerHistory(song:instrument:)`. `AppRoute.playerHistory` and `AppRouteDestination`'s case already exist (Wave 0); only the entry-point link is missing. Verified via a hosted render test instead of `tools/ios_sim.py shot`/`drive` (see below); flagged for the Songs/Leaderboards lanes to add a per-instrument "History" affordance.
- IDs: `fst.history.sort.open`, `fst.history.sort.mode`, `fst.history.sort.direction`, `fst.history.sort.{cancel,apply,reset}`, `fst.history.chart`.
- Tests: `PlayerHistoryTests.swift` (Core) covers sort ordering/tiebreaks, high-score index, response validation and payload song/instrument scoping. `PlayerHistoryNotificationsRenderTests.swift` (`FestivalUITests`, macOS-hosted) drives the screen end-to-end against a keyless fixture transport (publication + songs + history, rejecting `X-API-Key` and any `x-fst-selected-*` header) and writes a PNG when `FST_HISTORY_RENDER_OUT` is set — the only available visual evidence until a real navigation path exists.
