# Player history — iPhone notes

> **What:** where the selected player's score history lives on iPhone. **Read when:** changing score history, its page, its sort, its deep link or its endpoint. Behavior: [spec.md](spec.md). Endpoint safety: [service-safety](../../platforms/service-safety.md).

Source: `FortniteFestivalWeb/src/pages/songinfo/components/chart/ScoreHistoryChart.tsx` (+ `components/common/GraphCard.tsx`, `hooks/chart/useChartData.ts`), `src/pages/leaderboard/player/PlayerHistoryPage.tsx`, `modals/PlayerScoreSortModal.tsx`, `hooks/data/useSortedScoreHistory.ts`. Service: `FSTService/Api/PlayerEndpoints.cs:733-790` (`/api/player/{accountId}/history`), a pure keyless `GET` of a precomputed cache.

- **Preview on the song page, every score on its own page (issue #324, owner request; supersedes operator batch 6.39's in-place expansion).** `SongScoreHistorySection` (`Features/SongDetail/SongScoreHistorySection.swift`) sits after Intensity on Song Detail when a player is selected and has history for the song. One read per song on every instrument: `FestivalAPI.songHistory(accountId:songId:)` (`FestivalCore/FestivalAPI+SongHistory.swift`, the same endpoint without `instrument`; 404 unregistered, 202 syncing). Anything but available rows hides the section, like the web. The full list moves to its own page because the owner asked for it and the web (`ScoreHistoryChart` → `PlayerHistoryPage`) and Android do the same ([view-all-cta](../../patterns/view-all-cta.md) R8); the HIG "limit the number of rows" advice is watchOS-only and is not the rationale.
- Section: header "Score History" / "Select a bar to see more score details." above one glass card holding a **required** `InstrumentSelector` (graph look, shown even for one instrument, web `showSingleInstrumentSelector`) over the visible instruments with history (`SongScoreHistoryModel.instruments`, preferred → Lead → first), then the chart: accuracy bars on a trailing 0–100% axis (web `accuracyColor`, gold for a 100% full combo), the score line (`#4C7DFF`) on the leading axis, the web legend, and a pager. Points keep their series index as x and the x domain is the visible window, so paging slides the window without re-laying out points (operator batch 7.11). Tapping a bar shows its row under the chart. Below the card: the best five scores as separate rows (best first; the best purple and bold), never more, then — only with more than five (web `chartData.length > 5`) — the purple **View All Scores** ([view-all-cta](../../patterns/view-all-cta.md) R1, `ListDetailLink` + `PurpleActionLabel`), which pushes `.playerHistory(song, instrument)` for the selected instrument (the trailing pane in a split). There is no in-place expansion or "Show top scores".
- **Date axis (#314):** each date is centred under its bar on every page through the shared `barChartDateAxis` ([chart-date-axis](../../patterns/chart-date-axis.md) R1), the same axis as Profile Rank History; Swift Charts' default numeric axis put the label's leading edge at the bar centre. HIG Charts (`charts.md`, consider): "Anchor an unassociated-looking label to its grid line with a tick."
- **Instrument switch (issue #31, operator request; the web swaps instantly).** The selector updates at once; the chart and the rows below the card fade out together (easeIn 0.15 s), the new instrument swaps in with animations disabled, then fades in (easeOut 0.25 s) — `ScoreHistorySwap.plan` (Core). History for every instrument is already loaded, so "data loaded" is the next frame. A newer choice cancels a running swap; returning to the shown instrument mid-fade just fades back in. Reduce Motion (system or the app's `fst.accessibility.reduceMotion`) swaps instantly (HIG Accessibility: reduce automatic motion). The card keeps its size: the section measures the chart width once and passes it in (no first-frame pager pop), the pager's space is reserved (hidden, not in VoiceOver) for every instrument when any selectable instrument pages (`SongScoreHistoryModel.reservesPager`), and the card's height is pinned for the swap and released with an ease after it (only shrinks if a bar's detail row was open). The chart's accessibility label names the new instrument.
- **Season only on wide pages (issue #32):** the web list rows show a `SeasonPill` ("S40") before the score only when the viewport is at least 520 px (`QUERY_SHOW_SEASON`, `packages/theme/src/breakpoints.ts`); the tapped bar's detail card always shows it. iOS measures the Song Detail scroll view width (`onGeometryChange`, `viewportWidth`) and asks `ScoreRowSeasonPolicy` (Core, `.historyList` / `.historyDetail`, breakpoint 520 pt = CSS px). The iPhone app is portrait-only (≤440 pt), so its list rows never show the season and the "Season N" caption under the date is gone; only the detail row does. `ScoreSeasonPill` (`Features/SongLeaderboard/ScoreSeasonPill.swift`): "S9" in a 44×24 pt `@ScaledMetric` capsule, colours inverted for the catalogue's current season (`FestivalSession.catalogCurrentSeason`); accessibility text sizes drop the fixed frame, read "Season 9" and stack it under the date. The row label stays one line at standard sizes (web `truncate`; `minimumScaleFactor(0.75)`). VoiceOver reads "date, season N" (or "current season N"), score…. The Duo pane (`SongDetailDualSource`) passes no season. Open gaps: the web's difficulty pill (shown with the season) and its accuracy gate (hidden below 420 px) are not ported.
- **Score History page:** `PlayerHistoryScreen` (`Features/SongLeaderboard/PlayerHistoryScreen.swift`, route `AppRoute.playerHistory(song, instrument)`, `/songs/:id/:instrument/history`; View All Scores, deep links, notifications, the Duo pane's View All and Mac menus all open it). A `List`: the shared `SongHeaderRow` ([song-header](../../patterns/song-header.md) R1; caption "<Instrument> · Score History", pinned bar title once it scrolls away, the Mac keeps its window title), then every score of the chart as `ScoreHistoryListRow`s (the Song Detail row, `fst.history.row.<n>`, staggered fade on first load) sorted by `PlayerScoreHistorySort` (Core; web `useSortedScoreHistory`), default Score descending; the best score in the current order is purple and reads "best score" (web `highScoreIndex`, it moves with the sort). States (web `PlayerHistoryPage`): no player → "No Profile Selected" / "Select a player to view score history." + Choose Profile; loading `FestivalLoadingView`; error `ServiceStatusView` "History Unavailable"; 404 "Score history is only available for registered users."; 202 `ServiceUnavailableView` "History Is Syncing" with Retry; empty "No score history for this instrument." ([empty-error-states](../../patterns/empty-error-states.md)). No chart on this page (the web has none).
- **Rows at accessibility sizes (#385):** `ScoreHistoryListRow`, which every consumer shares (Song Detail list and detail row, Score History page, Duo pane, First Run demos), stacks at accessibility text sizes: the date (wrapping between words), the season pill, then the score and accuracy on one line when they fit (`ViewThatFits`), else the accuracy under the score. The score stays one line and scales down rather than break between digits ([leaderboard-row](../../patterns/leaderboard-row.md) R2/R8; same as `RankingRowLayout`). The one-line row broke "850,000" into "85 / 0, / 00 / 0" on an iPhone at AX5. Standard sizes keep the web's single line, and VoiceOver's row label is unchanged. HIG Typography (`typography.md`, consider): "Where width is constrained, inline items … can crowd text into truncation or overlap; consider stacking text above secondary items."
- **Sort:** one page action, "Sort" (`arrow.up.arrow.down`, gold when not Score descending, VoiceOver value "Score, descending"), only with rows: the iPhone tab-bar accessory (`festivalPageTool`, [page-tools-and-nav-chrome](../../patterns/page-tools-and-nav-chrome.md)), a toolbar item elsewhere, ⌘-Sort on the Mac (`macPageCommands`). It opens `PlayerHistorySortSheet` (web `PlayerScoreSortModal`): `FestivalModal` "Sort Player Scores" ([modal-shell](../../patterns/modal-shell.md), compact detent; a popover on the Mac like Songs' Sort), "Mode" (Date / Score / Accuracy / Season, inline picker), "Sort Direction" (the shared `SortDirectionControl`, "Oldest first, low to high" / "Newest first, high to low") and a red "Reset Sort Settings". Changes apply live and scroll the list to the top; sort state is per visit (web component state).
- Invalid-score filtering (`useScoreFilter`) is not applied to history rows natively.
