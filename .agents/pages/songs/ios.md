# Songs — iPhone notes

> **What:** what the iPhone Songs page implements, native decisions that differ from the web, gotchas and open gaps. **Read when:** changing Songs on iPhone. Behavior: [spec.md](spec.md). Wave 1 task list: [PROGRESS.md](../../../PROGRESS.md) (Lane S).

## Implemented (partial)

- Live public Songs by default (728 songs decoded on 2026-09-25); fixtures via loopback override.
- List search: on iPhone iOS 26.1+ the tab-bar accessory's "Search songs or artists" field-button (issue #42, see below); elsewhere an inline `.searchable` list filter, prompt "Filter Songs". Both are separate from [global search](../../controls/global-search/ios.md), the header Search button; the A–Z rail is centred in a region with a fixed top (it does not move when the large title collapses) and ends above the floating Filter/Sort; section titles are pinned on an opaque `appBackground` backing with a hairline; rows arriving from a load fade in (`festivalFadeIn`, first screen only); no visible "Item Shop: New" chip (the gold row outline marks it; VoiceOver keeps the label); title-ordered list by default, scene-owned instrument filter (now applied via [Filter](../../controls/songs-filter/ios.md), not its own toolbar Menu), Detail/Solo navigation, accessible notice when a publication change or hidden instrument clears a route/filter.
- `.festivalRootChrome(session:)` owns the top-right profile button and (drawer, Lane A) — Songs no longer keeps its own profile button/sheet or an Item Shop toolbar button; Shop is reached from the drawer. The in-page "Choose Profile" empty state uses `@Environment(\.openProfile)`.
- Sort + Filter are a `ToolbarItemGroup(Self.pageActionPlacement)` (`.topBarTrailing` on iOS, `.primaryAction` elsewhere); both tint gold when their applied choice is non-default. Per the [toolbar order rule](../../controls/app-navigation/ios.md#toolbar-order-rule-tab-roots), Songs ends its own `.toolbar` with `FestivalRootTrailingItems(session:)` and applies `.festivalProvidesRootTrailingItems()` so the shared bell+avatar capsule (which owns its own `ToolbarSpacer`) stays the rightmost item: `[drawer] … [sort] [filter] [quick links] [bell] [avatar]`.
- Duration and Item Shop sorts show a **Quick Links** toolbar menu ([quick-links/ios.md](../../controls/quick-links/ios.md)); Title/Artist/Year hide it because the section-index scrubber already owns jump navigation there.
- Sort: Title/Artist/Year/Duration + conditional Item Shop with Leaving/In/Not sections, plus Score/Percentile/Stars for a selected player on one instrument, grouped into the web's quick-link buckets ([songs-sort/ios.md](../../controls/songs-sort/ios.md)).
- Filter: selected-player Shop toggles, score/FC checks, the single-chart Instrument picker and, with an instrument, Percentile and Stars buckets; every change applies at once ([songs-filter/ios.md](../../controls/songs-filter/ios.md)).
- **Profile presets (Lane A3):** `PlayerStatNavigator.showSongs` (root) saves a `SongsFilterPreset` through `SongsPresetStore`; Songs reads it as its normal saved state. Presets match the web updaters: instrument Songs Played/FCs → that chart's check + Score ascending; `.stars(_, starKey:)` → only that star bucket + Stars ascending; `.percentile(_, scoredOnly:)` → Percentile ascending (+ Has Scores); `.percentileBucket` → only that bucket, saved sort kept, ascending. Each first clears the chart's checks and both bucket filters (web `cleanFilters`). Links: `PlayerStatLinks.instrumentStars`, `.instrumentPercentile`, `.percentileBucket` (Profile tiles still to be wired by the Profile owner).
- Right-edge Contacts-style section-index scrubber for Title/Artist/Year sorts; animates in/out when the sort mode does or doesn't have a meaningful key ([songs-section-index/ios.md](../../controls/songs-section-index/ios.md)).
- Rows are `festivalGlass(.card)` cards with tightened List row insets (2pt vertical) to match the web list's 2pt virtual row gap; cards drop the trailing disclosure chevron per Apple HIG (see Native decisions).
- Selected-player card: status chips ([chips](../../controls/songs-instrument-status-chips/ios.md)) or typed metadata pills ([metadata](../../controls/song-score-metadata/ios.md)); duration (e.g. 6:06) shown, including at accessibility sizes. The pill order honors Settings' `fst.settings.songRowVisualOrder` (`SongProfileCardPolicy.reordered`), applied after visibility filtering so the reorder never adds, drops or invents a field.
- `#if DEBUG` env `FST_DEBUG_SONG=<title-or-songId>` auto-pushes that song's Detail once the catalogue loads (local `.navigationDestination(item:)`, independent of the shared route stack) so `tools/ios_sim.py shot`/`drive` can reach Song Detail without manual navigation.
- Row title and artist·year·duration use `Design/MarqueeText.swift` (2026-09-28), a native port of web's `MarqueeText.tsx`/`MarqueeText.module.css`: auto-scrolls a two-copy track only once measured wider than its row, dwell-pauses at each end like the web keyframe, falls back to static `.truncationMode(.tail)` under Reduce Motion, and stops (no timer) once its row leaves the List or the scene backgrounds. This replaced a `.fixedSize(horizontal: false, vertical: true)` that let long combinations (e.g. "6 Foot 7 Foot"'s artist/year/duration on folded Duo) wrap to a second line instead of staying on one. Pure cycle math lives in `MarqueeTiming` (unit-tested, `MarqueeTimingTests`); should also be adopted by `Features/SongDetail/SongDetailScreen.swift`'s title header (web's `SongInfoHeader.tsx`) and `Features/Suggestions/SuggestionCategoryCardView.swift` (web reuses the same `SongInfo.tsx` there) — both outside this lane's ownership.
- Shop/Duration sort groupings are now real `List` `Section`s (matching the Title/Artist/Year section-index groups) instead of a plain row styled to look like a header; see [quick-links/ios.md](../../controls/quick-links/ios.md) for why they still register as Quick Links rather than a scrubber section.
- First reveal waits for the catalogue **and** the first ~12 visible rows' artwork to decode (bounded to 900ms so slow/unreachable art can never block it), then cross-fades in — a native-only addition (the web has no equivalent first-paint gate; it reveals rows immediately and fades each `<img>` in independently). See `SongsScreen.primeFirstArtwork(for:)`.

## Native decisions (deliberate deviations)

| Web | iPhone | Why |
|---|---|---|
| Lower Search/Sort dock, bottom sheets | iOS 26.1+ iPhone: search, Filter and Sort (and Quick Links) in the tab-bar accessory, inline beside the minimized tab bar while scrolled (issue #42). iOS 17–26.0 iPhone: `.searchable` filter, Filter and Sort as floating round glass buttons. Duo/iPad/Mac: `.searchable` and toolbar items. Global Search in the header; full-height system sheets that apply immediately with Done | A `.bottomBar` toolbar renders behind the Liquid Glass tab; a `TextField` or `Menu` in the accessory does not work |
| Row is a link with a trailing chevron in most lists | Card-style row **is** the tap target, no chevron | Apple HIG: card rows drop the disclosure indicator. Implemented as an invisible, stretched `NavigationLink` behind the visible glass card (`ZStack` + `.opacity(0)`), combined into one VoiceOver stop — a List row's automatic accessory only appears for a *visible* `NavigationLink` label |
| Icons-off fallback to Lead even if hidden | First **visible/filtered** chart | Respect Settings |
| Last Played hidden under Title | Toggle-controlled date under Title | Until Last Played sort ships |
| First-run Filter Songs carousel | Absent | Pending |
| Instrument selector always visible in Filter | Instrument section only when a player is selected | Matches web's practical gating: Filter itself only opens with player/Shop data on mobile |

## Gotchas

- `TabView` retains a failed Songs view: its `.task` is keyed by publication **and visibility** and must retry when the tab returns, even if Settings already fetched a valid catalogue at the same generation. A cancelled older request must not overwrite the replacement with a late error.
- Service errors use `ServiceUnavailableView` (scrolls at large text; scroll the error view itself). `.refreshable` only on the loaded List.
- No-results view uses a wrapping title and bright semantic text; an instrument-only empty result says no songs **match the filters**.
- Grouped (Shop-sort) and section-indexed (Title/Artist/Year) Lists share one `songRowInsets` (2pt vertical, 16pt horizontal) so cards stay tight and clear the floating tab.
- At AX sizes, only the chip-visible row mode stacks title/artist full-width above art and chips.
- Real Liquid Glass (`glassEffect`, iOS/macOS 26+) does not reproduce through `NSHostingView.cacheDisplay`: hosted pixel tests that render a `festivalGlass` surface must force the deterministic fallback (`fst.accessibility.moreContrast = true` in the test's `UserDefaults`/`@AppStorage`), or every state renders byte-identical. See `deterministicGlassDefaults()` in `SongScreenStatesTests.swift`/`SelectedSongRowRenderTests.swift`.
- **Scroll-away feedback loop (issue #5):** moving the tools into the bar removes the large title, and restoring it changes `contentInsets.top` (116 ↔ 232pt) at an unchanged offset. The old `offset + inset > 24` check flipped on every inset change, so the main thread never went idle and the app was killed after scrolling down and back up with a profile selected. `ScrollAwayGate` only re-decides when the offset moves (≥ 0.5pt), measures from the smallest top inset seen at the current width (reset on a width change), and uses hysteresis (enter > 24pt, exit < 8pt). Regression: `ScrollAwayGateTests` and `SongsChromeJourneyTests/testScrollingBackToTopNearTheTopStaysResponsive`. The XCUITest needs `tools/mock_service.py --large-catalogue` exported as `TEST_RUNNER_FST_SONGS_SCROLL_FIXTURE_URL`; it skips on the two-song fixture, and the old logic fails it with "main thread busy for 30.0s". Debug a hang with host `sample <pid>`, because the xcresult spindumps had no samples.
- **Scroll-driven state must not re-run the Songs body (issue #8):** `listScrolled`, the passed section titles, the section bar's bottom edge and `toolsInBar` used to be `@State` on `SongsScreen`. They change while you scroll, mostly near the top (title collapse, first headers, bar appearing, tools moving), and each change re-ran the whole screen: re-filter and re-sort the catalogue, re-diff about 760 List rows and re-render every visible row. Bursts of these passes hung the app near the top. They now live in `SongsScrollChrome` (`@Observable`, no-op writes dropped, bar edge ignores < 0.5pt). `SongsScreen.body` never reads it; only `SongsSectionBar`, `SectionBarRowMask` and `SongsPageTools` do. An in-app stress pass (production anonymous, then the large fixture with a profile) went from 76 to 17 body passes, and from 158 body passes and 147 sorts to 12 and 1. Don't add new scroll- or geometry-driven `@State` to `SongsScreen`: put it on the chrome and read it in a small subview or modifier. Regression: `SongsScrollChromeTests` and `SongsChromeJourneyTests/testScrollStressNearTheTopDoesNotRebuildTheScreen`, which asserts at most 20 bodies and 10 sorts during the pass and a run loop awake span under 2 s. It needs the large fixture, like the #5 test.
- **Section-title edge fade (issue #10):** the system soft scroll-edge effect fades content only under bars (navigation bar, toolbars), never under a custom floating title, so `SectionBarRowMask` used to cut rows off hard at the title. Its mask now starts at the title's bottom edge and stacks a `LinearGradient` band (`SectionBarEdgeFade`: 28pt, smoothstep stops) under the far-reaching `RowMaskShape`. Rows are fully hidden behind the title text and fully opaque 28pt below it. System Reduce Transparency, system Increase Contrast and the app's Reduce Transparency / Increase Contrast toggles set the band to 0, which gives a hard edge. That matches the opaque `festivalGlass` fallback, so the title never sits next to see-through rows. The mask keeps the same view structure in every state, so a settings change never rebuilds the List. Don't add a backing or glass behind the title: HIG Layout says "Prefer scroll-edge effects to solid/semi-opaque backgrounds beneath controls", and the title is part of the content layer. Regression: `SectionBarEdgeFadeTests`. Before iOS 26 the opaque pinned headers stay; the bar there has no fade either.
- **Measuring Songs hangs (Debug only):** `FST_DEBUG_STALL_LOG=<absolute path>` starts `MainThreadStallMonitor`. It rewrites a JSON report with `maxStallMs` (longest unit of work between run loop activities, sleep excluded), `maxAwakeMs` (catches a #5-style loop), stalls of 100 ms or more, and `counters` (`songs.body`, `songs.sort`). `FST_DEBUG_SONGS_SCROLL_STRESS=1` replays `SongsScrollStress.plan` after load: 60 animated `scrollTo` jumps between the top and sections 1–3, plus trips 10–20 sections down and back. Use `ios_sim.py shot --wait 45 --env …` so XCUITest's accessibility snapshots (100–350 ms each on Songs) don't pollute the numbers. Its remaining 200–400 ms stalls are `UICollectionView` cell creation during long animated jumps, a driver artefact heavier than a finger fling. No crash report was ever found for #8; treat a report of a "crash" while scrolling as a possible hang first.
- UI tests: query `fst.songs.list`; see [xcuitest pitfalls](../../testing/apple/xcuitest.md).
- `primeFirstArtwork(for:)` only runs on the very first `.loading → .loaded` transition (`prior == nil` in `reload()`); pull-to-refresh and retries after an error that already had prior rows never re-block on artwork, matching the existing retain-on-error behavior.

## Online-only cleanup

Done for this page: Songs (and Song Detail/SongScorePreview/SongPathsSheet/Shop) no longer render the `OfflineDisclosure` warm-cache banner for `isStale` payloads. The separate "showing live songs without publication verification" notice (headerless/unverified-but-live responses) is unrelated and unchanged, as are the publication-mismatch/paused-filter notices required by `AGENTS.md`'s safety invariants.

## Root navigation-notice card (`fst.songs.navigation-notice`)

`SongsScreen`'s top-of-list notice card (2026-09-28 operator ask) is generic: it just shows whatever `navigationNotice` string the root passes it, and clears when dismissed or replaced. Root shell (`App/FestivalRootView.swift`, Lane W1's file, not this lane's) sets that string for three separate resets: publication change, selected-profile change ("Selected profile changed. Returned to Songs…") and Shop being hidden. The operator asked to remove only the **profile-change** notice; that is entirely a root-side change (deleting the `songsNotice = "Selected profile changed…"` assignment there). This page's card needed no change — it keeps showing the other two legitimate notices unmodified, and simply stops receiving the removed one once the root no longer sets it.

## Operator batches 6–7 (Lane A3)

- **Section titles (iOS 26):** once the list has scrolled, the current section's title floats just below the navigation bar (`SongsSectionBarLabel` overlay) and the List is masked from its bottom edge (`SectionBarRowMask`: a `Shape` mask plus a gradient band), so rows fade out there with no backing over the artwork. In-list titles are flat rows (no `Section`: a header-less plain `Section` drew an opaque band) that still carry the rail / Quick Links targets; `onGeometryChange` on each picks the floating title: a title has reached the bar once its `.scrollView` minY is at most the List's top content inset + 1pt (`SongsScrollChrome.headerPassed`; issue #9). `.scrollView` space starts at the screen top under the bars, and the old `minY <= 0.5` named a section only after its title had slid another 116pt behind them, so the bar trailed by one section after every rail jump and while scrolling. The inset comes from `ScrolledAwayTracker` in a lock-protected `TopInset` box, because the geometry transform is `@Sendable`. Instant jumps (rail and Quick Links) also call `SongsScrollChrome.jump(to:in:)`, which marks every title up to the target as passed and none after it, because titles dismantled during a jump never report again. The List's `fst.songs.list` identifier sits before the bar overlay; after it, it replaced the bar's `fst.songs.section-bar`. Tried and rejected: a top `safeAreaBar` (hid the large title), `scrollEdgeEffectStyle(.hard)` (dimmed the large title, dark band), a mask laid out inside the safe area (hid the large title) and `ignoresSafeArea` on the mask (the scroll view never went idle). Before iOS 26 the opaque pinned headers stay.
- **Tools in the tab-bar accessory (issue #42, iPhone iOS 26.1+):** search, Filter (selected profile) and Sort register into `tabViewBottomAccessory` (`PageToolsPresentation.accessory`; [nav accessories](../../design/apple/nav-accessories.md) rules 2, 3, 8 and 13), and the tab bar minimizes on scroll so they ride inline beside it. The search control is `SongsSearchAccessoryButton` (`fst.songs.search.open`, VoiceOver "Search Songs", value = the query; inline Clear `fst.songs.search.clear`). It opens `SongsSearchBar` (`fst.songs.search.field`, Cancel `fst.songs.search.cancel`) in the page's bottom inset, focused, above the keyboard; Return keeps the query, Cancel clears it. The rules are pure (`SongsSearchAccessoryRules`, tested by `SongsSearchAccessoryTests`). `.searchable` is not attached in this mode and the tools do not move into the navigation bar (`PageToolsHandOff.toolsInBar` is false). UI tests reach the field through `SongsUITestSupport.songsSearchField`/`songsSearchEntry`, which handle both modes; regression `SongsChromeJourneyTests` (large fixture).
- **Tools rise into the bar (issue #13, iOS 17–26.0 iPhone only since #42):** for every viewer (the old selected-profile gate left anonymous Sort and Quick Links floating), scrolling 24pt past the collapsed title (`onScrollGeometryChange`, iOS 18+, decided by `ScrollAwayGate`) disables the floating Filter/Sort/Quick Links registrations and shows them as navigation-bar items (`QuickLinksController.prefersToolbar`); within 8pt of the top they float again. iOS 17 keeps them floating. The rule and timing are `PageToolsHandOff`: the bar items arrive in a `snappy(0.3)` transaction while the dock buttons shrink toward the trailing edge and fade with the same timing (`FloatingPageControls` animates its overlay on the registered IDs, because registrations change outside the scroll transaction); under system or app Reduce Motion both halves are a 0.2 s cross-fade. The **Filter Songs** field uses `.navigationBarDrawer(displayMode: .always)` on iPhone, so it stays pinned under the bar while scrolled. The inline title is a permanent empty `.principal` item on iPhone, not a toggled `toolbar(removing: .title)`: removing the title also removed the large title, so the top inset jumped 116 ↔ 232pt on each hand-off and "Songs" returned late at the top. With Quick Links in the bar (Year/Duration/Shop sorts), the system moves the bell and avatar into its own **More** overflow, keeping three trailing groups. Regression: `PageToolsHandOffTests`, `SongsChromeJourneyTests/testToolsAnchorInTheBarWhileScrolled` (anonymous and profile; large fixture).
- **Rail reserve:** the trailing safe-area inset adds only the rail reserve beyond the rows' 16pt margin (22pt rail + 2pt margin + 6pt gap = 30pt total), and nothing when the rail is hidden (Year, Duration, Shop, player sorts). Card-to-screen-edge gap at 402pt with the rail: **48 → 30pt**; without it 16pt (unchanged). The iPhone Duo folded display has no trailing cutout inset, so the same 30/16pt apply. Scroll indicators stay visible (overlays; they never took layout space).
- **Rows:** FC is the web `goldOutlineSkew` badge (as on Song Detail); percent pills are sized for "XX.X%"; stars use the web `MiniStars` circles and the intensity meter is scaled to the pills' height; the primary metric never wraps under a long title (marquee). Songs in the Item Shop get the web's `shopPulse` border (green / gold new / red leaving, 0 → 0.7 over 2 s, static under Reduce Motion or UI tests; `ShopRowPulseBorder`) and the bag icon.
- **Filter:** web order (score checks, Item Shop, Instrument selector with Season / Percentile / Stars / Intensity), Select All / Clear All (red) as trailing header actions, red Reset. **Sort:** Ascending / Descending titled rows with the description beneath, red Reset.
- Quick Links and the A–Z rail jump instantly (no animated scroll).

## Open (iPhone)

Grouped-Songs full audit (intermittent nil-element Dynamic Type) and saved-Shop-sort + failed-Shop contrast ([accessibility](../../testing/apple/accessibility.md)); landscape and largest type across modes; Quick Links for Year and any profile/band-scored sort (no native sort exists yet for those); selected-profile sorting; band rows; invalid-score action.

`Song.sig` (`"Guitar"`/`"Keyboard"`, `Song.usesKeyboardIcon`) is decoded and drives the keyboard/pro-keys `InstrumentIcon` variant in the instrument status chips. `Song.maxScores` (`"maxScores"`, keyed by the same service instrument ID as `Instrument.rawValue`, e.g. `"Solo_Guitar"`; not every chart has an entry) is decoded via `Song.maxScore(for:)` for a future Suggestions `near_max_*` family — unused elsewhere in this lane.
- **Load/reload fade (issue #71):** Songs runs the shared `FestivalReloadGate` on load and on a sort, direction, filter, instrument, search or publication change (the spinner shows while typing, before the debounce, like web): old results leave at once, the spinner fades in, holds ≥400 ms, fades out (500 ms) and the results fade/stagger in; Reduce Motion swaps instantly. See [iPhone motion](../../design/apple/iphone.md#motion).
