# Songs — Android notes

> **What:** what the Android Songs page implements, native decisions and open gaps. **Read when:** changing Songs on Android (`ui/songs/`, `core/songs/`, `presentation/SongsViewModel.kt`). Behavior: [spec.md](spec.md).

## Implemented

- Live keyless `/api/songs` through `FestivalApi.catalog()`; loading / service status / empty / populated; pull to refresh re-checks the publication.
- Pipeline `SongListPipeline.run` (pure, unit-tested): search (250 ms debounce) → chart + intensity-bucket filter → Shop filter → selected-player score/FC filter → sort → headers/sections. Saved Shop and score choices that can't apply **pause** with a notice card (`fst.songs.notice.*`) instead of guessing: Shop hidden, Shop feed not loaded, Shop/catalogue publication mismatch, score filters with hidden charts, no player, Filter Invalid Scores, or scores from another publication.
- Sort sheet (`fst.songs.sort`): see [songs-sort/android.md](../../controls/songs-sort/android.md). Sort and Filter sheets **apply live** (operator rule): no Cancel/Apply or discard prompt, just Reset and the shared header **Close** icon button (issue #23; it replaced Done and keeps the `.done` tag).
- Every sort without the section index groups rows into the web's quick-link buckets (`SongQuickLinkBuckets`, first-seen order, ≥ 2 buckets): headers `fst.songs.section.<mode>.<token>` (Shop keeps `fst.songs.shop-section.<token>`) that are also the **Quick Links** items (`<webId>:<token>`, title "{Sort} Quick Links"). The shared control shows them as a bottom sheet from the floating toolbar on compact windows and a menu elsewhere; only Title/Artist keep the right-edge section index.
- **Operator deviations from the web (2026-09-28):** Year sort has no section index; its headers are decades ("1970s" …, "Unknown Year"). Duration buckets are minutes — "Under 1 Minute", "1–2 Minutes" … "9–10 Minutes", "Over 10 Minutes", "Unknown Duration" (tokens `lt1`, `1to2` … `9to10`, `gt10`, `unknown`) — instead of the web's `lt2…gte5`.
- Filter sheet (`fst.songs.filter`, selected player only): the web `FilterModal` structure, see [songs-filter/android.md](../../controls/songs-filter/android.md). Clearing the chart filter resets a single-chart sort to Title (web `normalizeSongSettings`).
- **Filter Invalid Scores** (`core/songs/SongInvalidScores.kt`, `presentation/songs/SongScoreAdapter`): each chart shows its effective score — the raw score when valid (`ml` ≤ leeway, else ≤ CHOpt max × (1 + leeway/100)); the best `vs` variant valid at the leeway (rank from its `rt` tiers, population from the catalogue's `populationTiers`, decoded into primitive arrays); else the legacy `validScore*` fields; else none. Over CHOpt Threshold keeps the raw invalid score. Rows then show a pulsing red alert (gold warning when only over-threshold scores are shown), its own TalkBack stop (`fst.songs.invalid-score.<id>`), opening the **Filtered Score** alert (web text per variant) with **OK** / **Settings**. Chips, metadata, filters and sorts all use effective scores; nothing pauses.
- Persistence (`data/songs/SongsPreferences`, keys `fst.songs.filters`, `fst.songs.playerScoreFilters`, `fst.shop.viewMode`, all `ResetPolicy.Kept`): the player filter is bounded typed JSON; a corrupt value blocks the list with **Reset Filters** (`fst.songs.filter-invalid`). Confirmed deselection clears only the player predicates (`watchDeselection`).
- Rows (`ui/songs/SongRow.kt`): glass card, 48 dp art, marquee title/subtitle (shared `FestivalMarqueeText`: web 8 s cycle, draw-phase only; ellipsis under reduced motion; Shop titles use it too), a **Shop outline pulse** (web `shopPulse`: 2 px border, opacity 0 → 0.7 → 0 over 2 s; green in Shop, gold New, red Leaving Tomorrow) and a Shop badge circle that **breathes** in the same status colour (3 s), both from one shared list-level transition read in the draw phase (no animation when nothing pulses; reduced motion/Remove animations hold 0.7 / the status colour), then either **status chips** (balanced wrap: one row of nine on a phone card, centered) or **metadata pills** in Settings order with Last Played last, or an explicit score state (`Loading scores`, `Scores syncing`, `Player scores paused until songs update`, `No score`, …). One TalkBack stop speaking `SongRowModel.announcement`.
- Scores come from `container.selectedProfile` (profile lane) via `SelectedProfileState.songScoreSource`, which requires catalogue, score read and session to share the observed publication.
- First-paint gate: the first reveal waits ≤ 900 ms for the first 12 rows' artwork via Coil, then fades in with the shared `Modifier.festivalFadeIn` (web `fadeInUp`, 400 ms; instant under reduced motion). Later updates never re-block. It opens as soon as the catalogue is loaded, even when saved filters match nothing (fixed 2026-09-28: the list was blank).
- Bucket headers are **sticky** `stickyHeader`s on an opaque strip, so rows never show through (shared backlog); a header's Quick Links index counts the headers before it (and the notices, not the search field, which sits outside the list).
- **Pinned-header edge fade (issue #49, port of iOS #10):** rows used to be cut off hard at the pinned strip's bottom edge. `Modifier.pinnedHeaderEdgeFade` on the `LazyColumn` now masks a 28 dp band just below the strip (which pins at the list's top edge, under the top app bar on phones or the pinned search field on wider windows) (`BlendMode.DstIn` vertical gradient with smoothstep stops on an offscreen layer), so rows fade out there. The strip stays opaque, so the header text is unchanged. The geometry is in `core/songs/SongHeaderEdgeFade.kt` (`SongHeaderEdgeFadeTest`). The band sits at the pinned header's resting height even while the next header pushes it away, so headers and rows pass through the same band. Under the first header, the fade ramps in over the first 28 dp scrolled. Nothing is drawn while no header is pinned (top of the list, Title/Artist sorts), so the offscreen layer is skipped then. The edge state is a `derivedStateOf` read only in the layer and draw lambdas, so scrolling never recomposes. Increase Contrast (system high-contrast text/contrast level or the app toggle) and the app's Reduce Transparency keep the hard edge, as on iOS. Reduce motion is not involved because the fade is static. The mask is drawing-only: hit testing, semantics and TalkBack order are unchanged.
- Empty list: the shared `festivalEmptyStateItem` (web "No songs match your filters." / "Try adjusting your search or filters."), vertically centred in the viewport (6.33).
- Metadata stars and the intensity meter sit in pill-height boxes so every pill in a row shares one height (7.18).
- Sort-driven rows: single-chart and Last Played sorts lead with their field; Last Played shows only while sorting by it (unfiltered: the most recent chart's icon + date beside the chips); Max Score %/Diff show "score / max" plus a red→green metric pill (web `maxScoreColor`); metadata order is the sort's **metadata priority** unless Settings' independent visual order is on.
- Section index (Title/Artist): animates in/out, one accessibility element with the current section as its state and **Next/Previous section** custom actions.
- Expanded widths / separating hinge: list + Song Detail panes (`fst.songs.detail-pane`).

## Native decisions

| Web | Android | Why |
|---|---|---|
| Lower search dock | **Compact windows (issue #84, port of iOS #42):** search joins Sort/Filter/Quick Links in the **pinned** bottom floating toolbar (`FestivalScreen(pinActions = true)`), not under the top app bar. At the top of the list it is a field-shaped button (`fst.songs.search.open`, placeholder or query plus inline Clear `fst.songs.search.clear`); after 24 dp of downward scroll it **minimizes** to a 48 dp search icon (gold while a query filters) and expands again on upward scroll or at the top (`FloatingToolbarMinimizer`, `core/shell/FloatingToolbarPolicy.kt`). Tapping it (or Ctrl+F) replaces the tools with a focused `TextField` (`fst.songs.search`) and a Close arrow (`fst.songs.search.close`); the shell lifts the toolbar above the IME (`FestivalScreen(actionsAboveKeyboard)`, `FloatingToolbarLift`), and Back, the Search key or losing focus close it with the query kept. Wider windows keep the field **pinned above the list** and their actions in the top app bar (unchanged). | M3 places screen actions in the top app bar by default; the M3 Expressive floating toolbar is a supported pattern and the shell already had one. The toolbar stays pinned (issue #52: nothing leaves the screen); only the search shrinks, so the bottom NavigationBar is never duplicated or covered. TalkBack never minimizes (an icon-only control still announces "Search songs" with the query as its state); Remove animations snaps the resize. Global search stays in the top app bar. Composable `actions` lambdas must read state objects inside the lambda: the toolbar re-runs the registered lambda only for state reads, not for changed captured values. |
| Nine chips wrap 5+4 at 390 px | One row when the card fits nine 34 dp chips (Pixel 9 does), else balanced rows | Same balancing rule as Apple `SongChipRows` |
| Metadata spacing via CSS | `FlowRow` right-aligned; first field top-trailing | Grows at large text instead of clipping |
