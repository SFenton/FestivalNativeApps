# Songs — Windows notes

> **What:** what the Windows Songs page implements, native decisions and open gaps. **Read when:** changing `windows/Festival.App/Pages/SongsPage*`, `SongsViewModel`, `SongListPipeline` or `SongRowProjection`. Behavior: [spec.md](spec.md).

## Implemented

- Live keyless `GET /api/publication` + `/api/songs` (+ `/api/shop` and the selected player's `/api/player/{id}`, both best-effort) through the shared gate. Catalogue shared with the background and Song Detail via `FestivalSession`.
- Pipeline (`Domain/SongListPipeline.cs`): search → General filters (Year, Duration, Double Bass) → selected-instrument chart/difficulty (player only) → Shop availability (Shop visible only) → player score filter → sort → group. A saved choice that can't apply **pauses** with an `InfoBar` notice instead of guessing: Shop feed missing or catalogue/Shop/session publications differ; player filters while scores are loading/202/failed/mismatched or while every checked chart is hidden in Settings.
- **Filter Invalid Scores** (web `useScoreFilter` + `SongsPage` substitution; `Domain/SongInvalidScores.cs`, `SongScoreSource.ForSongs`): scores resolve instead of pausing. A score is invalid when its `minLeeway` (`ml`) exceeds the leeway or, without one, when it exceeds the chart's CHOpt maximum × (1 + leeway/100); it is replaced by the best `validScores` variant valid at the leeway (rank from its `rankTiers`), else the legacy `validScore`, else dropped. Filters, sorts, chips and metadata all see the resolved score. All of it comes from the profile read and the catalogue: no per-song leaderboard reads. Gap: filtered population (`populationTiers`) is not decoded yet, so a fallback's percentile uses the unfiltered total.
- **Over CHOpt Threshold** (web `overThreshold`, offered only while Filter Invalid Scores is on): a global switch and a "<Instrument> Over CHOpt Threshold" switch per chart (`fst.songs.filter.score.{global|chart.<chart>}.over-threshold`). On a checked chart the raw invalid score is kept (not replaced) and the song passes only when that raw score is over the threshold; it stays saved but inert while Filter Invalid Scores is off. The fixture service has no `ml`/`maxScores`, so fixture journeys show only the toggle and an empty result (`tools/windows/journeys/boards.json`); the logic is unit-tested (`SongInvalidScoresTests`).
- Rows (`SongRowItem`, projected once per rebuild): same-publication Item Shop **pulse ring** (`Controls/ShopPulseRing`, `Domain/SongRowShopPulse`): a 2 epx ring over the card, green `#2ECC71` in Shop, gold `#FFD700` New, red `#EF4444` Leaving Tomorrow, opacity 0 → 0.7 (gold 0.75) → 0 every 2 s ease-in-out like the web's `shopPulse`; static at the peak when motion is off; none when highlighting is disabled or the Shop is hidden. Every ring follows one shared compositor clock sampled at 30 steps/s (one keyframe animation however many rows are realized), held still while the window is hidden; with a selected player and scores **available for the catalogue's publication**, either nine status chips (icons on, no chart filter) or Settings-ordered metadata pills for the first visible/filtered chart; otherwise an explicit row state (`Loading scores`, `Scores syncing`, `Scores unavailable`, `Player scores paused until songs update`, `No score`).
- Sort: Title/Artist/Year/Duration + **Item Shop** (members first ascending; buckets Leaving Tomorrow / In Shop / Not In Shop in first-seen order, unlabeled when only one) + **Has FC** (web `hasfc`: on the filtered chart with a matching score index, scored rows first then No FC before FC; buckets No FC / FC / No Score; without a chart filter or scores it is title order, as the web's empty per-chart score map gives). Item Shop is hidden from the choices while Hide Item Shop is on.
- Sticky section headers with nothing showing through (operator batches 3 + 5): the current section's label sits in a bar (`StickyHeader`) **above** the list viewport, so rows disappear at the list's top edge instead of passing beneath a header. In-list headers (`AreStickyGroupHeadersEnabled=False`, no template divider/padding/min height) scroll up into it; the first section has no in-list header because the bar names it. Checked for issue #91 (2026-10-02, iPhone bucket headers on a dark band): every group, A–Z or Duration/Year/Shop/score bucket, uses the same `GroupStyle.HeaderTemplate` (a bare `TextBlock`, transparent container) and `StickyHeader` has no background, so bucket sorts already match Title/Artist; no change. Re-validated across window sizes, themes and scaling for #282, which also hid an unlabeled section's empty header from Tab and UIA (see Validation (issue #282)). The label comes from realized-row geometry (`SongSectionHeader`: the first row whose bottom is below the viewport top), not `ItemsStackPanel.FirstVisibleIndex`, which is stale while a jump is still settling (#48: after a backward jump in a compact window the bar kept the old letter). A Jump pick sets the label straight from the chosen group, then re-checks it after the next layout pass.
- Section push (issue #288, 2026-10): the bar used to swap its label when the previous section's last row passed the top, after the incoming in-list title had already slid away under the list edge, so the title jumped. Now `SongSectionHeader.Push` (tested) picks the pinned and incoming sections from the in-list titles' real positions. Once the incoming title enters the edge-fade band (`SongHeaderEdgeFade.Depth`, 40 epx since #308), a Raw copy (`IncomingHeader` in the hit-test-invisible `PushLayer` canvas, `Margin="0"` because `FSTSectionHeaderStyle` adds a top margin of 8) is drawn exactly over it and rises to the bar, pushing `StickyHeader` up 1:1 through `StickyBar`'s clip. Both offsets are compositor expressions over the scroll viewer's manipulation property set (`Clamp(C + s.Translation.Y, -H, 0)` and `Max(0, V + C + s.Translation.Y)`), so they move in the same frame as the rows, and reverse when scrolling up. Nothing animates on its own, so Reduce Motion has nothing to stop. The in-list title turns transparent but stays the Level 2 UIA heading. A Jump pick scrolls the picked title into the bar (`JumpPinDelta`), so the section's first row sits under it. Z bottoms out with its own title visible in the list. Verified with `--auto-scroll-speed 15 --auto-scroll-span 1000` frame captures at 300%: the copy moves 7–8 px per frame at band entry and at hand-off, with no step, in both directions. Fluent (`winui-design`): keep the platform `ListView` and virtualization rather than a custom list. Every lookup of the list's scroll viewer goes through `EnsureScroller()`: auto-scroll used to find it first and skip the `ViewChanged` subscription, leaving the bar stale during automated scrolls.
- Pinned-header edge fade (issues #49, #308, iOS #10/#30, [scroll-edge](../../patterns/scroll-edge.md)): while `StickyHeader` shows, rows fade out over a 40 epx linear ramp (`Domain/SongHeaderEdgeFade.cs`, web `useScrollMask`) at the list's top edge instead of clipping hard. The ramp's depth is `SongHeaderEdgeFade.FadeDepth`: min(scroll offset, 40, the nearest realized section title's `TitleLimit`). An incoming title therefore ends the ramp at its own top and is never dimmed while it pushes the pinned one out, and after an A–Z or Quick Links jump (title pinned exactly) the depth is 0 and the first row is fully opaque (R8). `TopEdgeFade` evaluates the same formula on the compositor (an `ExpressionAnimation` on the gradient's `EndPoint` over the scroller's manipulation property set and the title tops the page inserts on each `ViewChanged`), so the cut tracks the scroll frame by frame. WinUI 3 has no `UIElement.OpacityMask`, so `Controls/TopEdgeFade.cs` uses the composition opacity-mask technique: a `CompositionVisualSurface` of `ListFadeSource` (the grid around `Zoom`) is drawn through a `CompositionMaskBrush` with an absolute linear gradient into a sprite on the hit-test-invisible `ListFadeHost`, and the source's own composition visual is set to opacity 0. Setting the composition visual's opacity leaves XAML hit testing, focus and UIA order alone (a half-faded row still opens its Song Info). The fade ramps in with the first 40 epx of scroll, so the top of the list is never faded. It falls back to the hard edge, with no mask, when a contrast theme is on, Windows transparency effects are off (`UISettings.AdvancedEffectsEnabled`), or in-app Reduce Transparency or Increase Contrast is on. Changes are tracked with `UISettings.ColorValuesChanged`/`AdvancedEffectsEnabledChanged`, because `AccessibilitySettings.HighContrastChanged` throws `0x80070490` in a desktop app. The overlay scroll indicator in the top 40 epx fades with the rows. The host is `Controls/EdgeFadeLayer` (`fst.songs.edge-fade`, UIA raw view only, so Narrator skips it), whose ItemStatus names the edge state (`SongHeaderEdgeFade.Status`): `hidden` (no pinned header: loading, empty, error or Jump open), `hard-edge`, `top`, `clear` (scrolled, but a title sits at the edge so the depth is under 1 epx: a Jump landing) and `fading`. UIA journeys: `tools/windows/journeys/a11y-songs-edge-fade.json` (every state on the large fixture catalogue, including a runtime Increase Contrast switch and `edge-jump-landing`, which asserts `clear` after jumping to P) and `a11y-songs-edge-fade-hard.json` (run with `--mode hc-desert` or `no-transparency`). Validation pass (issue #249, 2026-10-04, live service): no fade at the top, a fade once scrolled at compact/medium/wide/maximized/snap-left/snap-right in light and dark themes, at text 200%, and at display scale 100% and 150%; a hard edge with legible header text under Desert and Night sky contrast themes, with transparency effects off and with in-app Increase Contrast + Reduce Transparency. Axe found 0 errors and the Tab order was unchanged. The one exception: the fixture `edge-fading` compact scan reports `BoundingRectangleSizeReasonable` twice, for a row's artist text clipped to a sliver at the list's top edge. That's the known WinUI viewport-edge clipping class ([windows-accessibility](../../testing/windows-accessibility.md) item 3), scroll-position dependent and independent of the composition mask. The same pass found the pinned title naming a stale section ("#" over G rows) after one large programmatic scroll jump (a UIA Scroll-pattern set: the final `ViewChanged` fires before the panel realizes the new rows). `OnScrollerViewChanged` now re-reads it once after layout settles, and `edge-fading` / `edge-back-to-top` assert the label. Fluent (`winui-design`): there's no Gallery or Toolkit fade control (`winapp find-ui` found none), and WinUI 3 has no `OpacityMask`, so keeping the platform `ListView` with a composition mask is the compliant route.
- A new sort scrolls back to the top (operator batch 5).
- Jump index: Escape, Back (title-bar Back, Alt+Left, XButton1, via `IPageBack`), a click beside the letters, or any new search/sort/filter result returns to the list without jumping (gap 5b, operator batch 6.1); focus returns to Jump. Escape works from Jump and the toolbar too, opening focuses the current section's label, and Jump fades in and out (issue #231, [section-index/windows.md](../../controls/songs-section-index/windows.md)).
- Compact: rows end 12 epx from the right edge like the left; the list reserves no gutter for its overlaying scroll indicator (operator 7.24; was 16 epx). Anonymous rows are 64 epx: the art spans the wrapped second row only while it has chips (6.3).
- Filter flyout is always available. Without a player it shows only **General** (Year, Duration, Item Shop availability when visible, Double Bass). With a player it adds score/FC sections and Selected Instrument Filters (chart + 1–7 intensity, season, percentile, stars). Apply scopes checks to visible charts; hidden checks are disclosed. Clearing the selected player resets every Songs filter (General, Shop availability, instrument, player checks) and reverts a player-only sort to Title ↑, like web `resetSongSettingsForDeselect` (#359). A player-to-player switch keeps them.
- A damaged saved player filter shows "Saved Filters Can't Be Read" with Reset (`fst.songs.filter-invalid`) instead of the list.
- Sections (operator 2026-09-28, all platforms): Year sorts group by **decade** ("1970s" … "Unknown Year"); Duration sorts use one-minute buckets "Under 1 Minute", "1–2 Minutes" … "9–10 Minutes", "Over 10 Minutes", "Unknown Duration" (`SongCatalogQuery.DecadeBucket` / `DurationBucket`). **This deliberately deviates from the web**, whose Duration quick links use four buckets (`songQuickLinks.ts`); Quick Links take the section labels.
- Jump index: `SemanticZoom` over group headers plus a **Jump** toolbar button (`fst.songs.section-index-button`); disabled when there is a single unlabeled group and under the **Year** sort (no quick-jump there, operator 2026-09-28).
- Rows stagger in with the shared fade (`FadeIn`, after the art-priming gate) and re-stagger on sort/filter/search changes.
- First-paint gate: the first reveal waits (≤ 900 ms) for the first 12 rows' art to decode, then fades in (instant under reduced motion).
- Songs in the Item Shop carry a small bag badge on the album art, coloured like the row's pulse (green / gold New / red Leaving; operator batch 7.19). Metadata pills, stars and the intensity meter share one 22 epx height (7.18); the primary metric stays top-right, so a long title never pushes it down.
- Player sorts (web `SortModal` + `compareByMode`): with a player, **Last Played** (the filtered chart, else each song's latest play across visible charts); with a player and one chart, **Score, Percentage, Percentile, Stars, Season, Intensity, Difficulty, Max Score %, Max Score Diff** (`SongListPipeline.MetricSort`). Unscored rows sort after scored ones before the direction applies (so descending lists them first, as on the web), except Max Score % / Diff, which keep scored rows first; one unlabeled section; without the score index or chart they fall back to Title. Profile presets sort like the web updaters: Songs Played / FCs by Score, a star level by Stars, a placement band keeps the sort.
- Sort flyout: Sort By radio list, then Ascending / Descending rows with the web descriptions ("A–Z, low–high") as subtitles (7.21); Sort and Filter Reset are the web's full-width red button (7.10).
- `MarqueeText` for titles/subtitles (see [design/windows.md](../../design/windows.md#motion)).

## Layout by window size

| Width | Toolbar | Row trailing content |
|---|---|---|
| Compact (< 640 epx page) | Search full width; Sort/Filter/Jump (icon) below | Chips/pills wrap under the title (`FlowPanel`) |
| Medium | One row: search (≤ 440) + Sort/Filter/Jump | Chips inline from 760 epx list width; first pill top-right, rest wrap right-aligned |
| Wide (≥ 1100 epx page) | List + detail columns; list toolbar as compact | Chips/pills wrap under the title |

## Two columns (wide)

From a **1100 epx page** (e.g. a 1440 epx window with the expanded pane) the page splits into a 560 epx list and the selected song's Song Detail (`DetailFrame`, `fst.songs.detail-pane`; operator 2026-09-28, mirroring Android foldables/iPad). The list switches to single selection, the first row is selected so the detail is never empty, a sort/filter keeps the selection when the song survives (else the first row), and keyboard arrowing loads the detail 180 ms after it stops. Clicks select instead of pushing. The list column uses the narrow toolbar (search on its own row) and wraps chips under titles. With no rows, or below 1100 epx, it is a single column again and the embedded page is released. Links inside the embedded detail push full pages on the Songs stack.

## Native decisions

| Web / iPhone | Windows | Why |
|---|---|---|
| Filter only with a player/band | Filter is always shown; without a profile it contains only General filters | Web changed for issue #77 |
| Shop filter pauses without a player (iPhone) | Shop availability applies without a player, but is inert while Hide Item Shop is on | Shop membership is public data |
| Right-edge scrubber | `SemanticZoom` + Jump button | Windows-native quick jump (Start, Mail, Photos) |
| Marquee always scrolls on overflow | Same (operator 2026-09-28): scrolls whenever it overflows, phase-aligned; stops when motion is off, the window is hidden or the row is unrealized | Composition animation only; see perf notes in [design/windows.md](../../design/windows.md#motion) |

| iPhone search/tools dock into the nav bar on scroll (iOS #13) and bottom accessory (iOS #42) | Search, Sort, Filter and Jump sit in the `Actions` row above the `ListView`; only the list scrolls | Fluent persistent page header; checked for issue #52 (2026-10-01): UIA rects identical before/after scrolling at compact and medium, Sort/Filter flyouts and Jump open while scrolled, Esc returns focus. ## UI journeys

`python tools/windows/songs_journey.py [--sizes compact,medium,wide] [--shots DIR] [--only NAME[,NAME…]]` (fixture `tools/mock_service.py`, throwaway `FST_SETTINGS_PATH`): selected-player rows → Item Shop sort → Leaving Tomorrow filter → reset → Song Detail; Item Shop grid/list/compact → Song Detail; Paths image → text → not generated; Karaoke warning dismissal; no player; hidden Shop. Lock-tolerant state scenarios (UIA patterns only, so they also run on a locked console): `songs-search` (match → No Results → clear), `songs-sort` (Artist ↓ → Year sections, Jump hidden → reset), `songs-jump` (zoomed-out letter grid with the current letter focused → Esc from Jump and grid → letter → rows and heading), `songs-filter-empty` (decade filter → centred No Results with no Clear Filters button (#377) → the flyout's Reset), `songs-syncing` (202 notice + "Scores syncing" rows), `songs-denied` (403 notice + "Scores unavailable"), `songs-filter-invalid` (unsupported saved decade → readable pause + reset) and `songs-error` (unreachable origin → retryable service status). The `songs-sort-*` scenarios cover every reachable Sort state, including a `{relaunch}` step and Shop feeds behind a loopback proxy ([songs-sort/windows.md](../../controls/songs-sort/windows.md#states-and-reachability)). Rows expose `fst.songs.row.<songId>`. IDs must sit on UIA-visible elements (text, buttons), not `Border`/`StackPanel`/`ItemsRepeater` (`fst.songs.sort.form` and `fst.songs.notices` have no UIA peer: wait on `fst.songs.empty` (the shared `EmptyStateView` title), `fst.songs.sort.mode` or `class=Microsoft.UI.Xaml.Controls.InfoBar`).


Scroll stress (issue #247; iOS #8/#22 check): `python tools/windows/songs_scroll_stress.py [--sizes compact,medium,wide] [--rounds 2] [--live [--profile ID:NAME]] [--keep DIR] [--out result.json]`. Each phase holds one `desktop` lock from launch to close, so other lanes' GUI work and queue waits stay out of the measurement. `near-top` ping-pongs the list over its first 1500 epx at 2000 epx/s (`--auto-scroll-speed/--auto-scroll-span`); `flings` uses UIA Scroll-pattern jumps (top ↔ 2–5%, bottom → 55% → top) and posted End/Home, so both run on a locked console (`--wheel` adds real wheel bursts on an unlocked one). It fails on any `songs-sections` perf event after the data settled (one per `SongsViewModel.Sections` pipeline run, i.e. a rebuild/re-sort), a `ui-frames` `max=` over 250 ms, missing 5 s frame summaries (hang), the list not back at `scroll=0`, a sticky section header that does not match the rows after non-animated jumps to 25/50/75/100/0% (`sticky_mismatch`, run after the measured window because tree dumps walk the whole list; issue #288's push keeps the previous section current while the next title is still visible below the bar), or an app that does not exit cleanly on close (`FstUia close` reports `exitCode`/`killed`). The UIA Scroll pattern itself costs UI time: 40 no-op `scrollto 0` calls at the top gave up to 88 ms frame gaps, so `flings` maxima (typically 125–180 ms) include driver overhead that `near-top` (in-app timer, ≤ 105 ms) does not. `tools/windows/journeys/songs-scroll-a11y.json` runs the top/mid/bottom/back-to-top scroll states through `a11y_matrix.py` (live-safe: anonymous, no fixture rows).

Instrument status chips have their own fixture and journey pages (`tools/windows/instrument_status_fixture.py`, `tools/windows/journeys/instrument-status.json`, run through `a11y_matrix.py`): every chip state, the resize breakpoint (`assertbelow`/`assertlevel`) and chip IDs `fst.songs.instrument-status.<songId>.<ServiceId>` ([instrument status chips](../../controls/songs-instrument-status-chips/windows.md)).

Scroll round trips near the top (issue #245) live in `tools/windows/journeys/songs-scroll.json` (UIA `scrollto:`, wheel, resize-while-scrolled and auto-scroll ping-pong pages; fixture and `--live` variants), run through `a11y_matrix.py --pages` ([testing](../../testing/windows.md#accessibility)).

## Gotchas

- `SongsViewModel` re-reads the catalogue, Shop and scores on `FestivalSession.PublicationAdvanced`; until the catalogue is re-read, Shop accents and scores stay paused (`ShopOffersForCatalog` is null on mismatch).
- Trailing content is built in the phase-1 `ContainerContentChanging` pass (text renders first); crossing the 760 epx breakpoint re-realizes rows.
- A non-animated jump (UIA Scroll pattern from Narrator/automation, `ChangeView(…, disableAnimation: true)`) raises its last `ViewChanged` before the rows at the new offset are realized, so a header read from that event alone keeps the old letter ('#' over L rows after a jump to 50%). `OnScrollerViewChanged` re-reads once on the next `LayoutUpdated` and once more at Low dispatcher priority after a final (non-intermediate) change (issues #247, #249).
- `--auto-scroll` drives `ChangeView` from a 16 ms `DispatcherQueueTimer`; a tick after the window closed failed fast in `CoreMessagingXP.dll` (0xc000027b, WER `combase` 8000ffff) at every perf-run close. The timer now stops on page `Unloaded` and window `Closed` (issue #247).
