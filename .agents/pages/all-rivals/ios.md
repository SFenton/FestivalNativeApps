# all-rivals (`/rivals/all`) — iPhone notes

> **What:** iPhone implementation state and decisions for the full rival list of one scope. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md) (stub — this file is the source of truth for what's actually built until spec.md is promoted).

Source: `FortniteFestivalWeb/src/pages/rivals/AllRivalsPage.tsx`. Service: same `RivalsEndpoints.cs`/`LeaderboardRivalsEndpoints.cs` reads as [rivals/ios.md](../rivals/ios.md).

- Implemented: `AllRivalsScreen` (`Features/Rivals/AllRivalsScreen.swift`), reached via `AppRoute.allRivals(scope:)`. **Landed 2026-09-28:** the web's route takes independent `category`/`mode`/`rankBy` query parameters; native `AppRoute.allRivals` now carries the same information as one typed, `Hashable` `RivalScope` (`.song(instruments:)`, `.leaderboard(instrument:rankBy:)` or `.combo(token:instruments:)` — see [rivals/ios.md](../rivals/ios.md)) instead of the earlier packed-string `RivalAllCategory` workaround (removed; this lane had orchestrator permission to change the `AppRoute` case itself, so the string-packing seam is gone). A `.song` scope with exactly one instrument is a normal per-instrument list; two or more is "Common Rivals" (`RivalCommonRivals.intersect` over the full, not preview-capped, per-instrument lists). The screen loads the full (unlimited) rival list for its scope into a single `FestivalGlassSection`, with loading/empty/error states, before pushing `AppRoute.rivalDetail(scope:)` with the same scope.
- Simplified vs. web this pass: a `.combo` scope always names one server-computed list (matching what `RivalsScreen` actually links to); there's no independent settings-derived re-resolution at this route the way the web's `resolveRivalCombos` does.
- Tests: `RivalsTests.swift` covers `RivalScope.debugToken` round-tripping (used only by `DebugLaunchRoute`) and the new combo-endpoint URL/validation coverage. `tools/ios_sim.py drive --route rivals` plus a scripted tap into a "View All Rivals" row verified the push and the typed-scope title/list rendering live (2026-09-28, `Lead Rivals` full list for account `195e93ef108143b2975ee46662d4d0e1`).
- **Title (#557, all Apple platforms through the shared screen).** The list starts with `InstrumentPageTitle` `.header` (`fst.all-rivals.title`): the instrument icon left of the large name for a single-instrument scope (song or leaderboard rivals), no icon for Common, Combo and Pro Drums Family (`AllRivalsScreen.titleInstrument(for:)`, web `AllRivalsPage` `InstrumentHeader iconOnly` only when `isInstrument`). iOS uses the inline display mode, and once the heading scrolls under the bar `InstrumentPageTitleToolbarItem` (`fst.all-rivals.pinned-title`) shows the compact icon and name, like Full Rankings; the Duo vertical bar keeps the system title (`InstrumentPageTitleToolbarItem.pinsTitle(in:)`, shared with Full Rankings). The rows sit in one untitled `FestivalGlassSection`: never repeat the page name as a section title above them. Rules: [page-tools-and-nav-chrome](../../patterns/page-tools-and-nav-chrome.md) R18, [section-headers](../../patterns/section-headers.md) R11. HIG Icons: "Match icon weight to adjacent text unless intentionally emphasizing one"; HIG Toolbars: "Give each window a useful title to confirm location". Tests: `AllRivalsTitleTests`, hosted `RivalsRenderTests.allRivalsTitleIsOneHeadingAboveTheRows`, and the apple-ci iPhone journey `RivalsJourneyTests.testAllRivalsTitleLeadsTheListAndPinsAfterScroll` (default and AX5, rendered title contrast, pinned title, title-region `performAccessibilityAudit`; the fixture's six rivals only overflow the screen at AX5, and the audit runs last because it restores the system text size) and `RivalsJourneyTests.testAllRivalsDuoVerticalBarKeepsSystemTitle` (simulated Duo `folded` and `unfolded-landscape` windows through `FST_DEBUG_DUO_WINDOW`, so it runs on the CI iPhone: the system title is in the bar and no pinned copy appears, at the top and after the title scrolls away; on a real Duo the vertical bar minimizes the top bar, system title included, on scroll, so there it requires the system title back at the top instead).
- **Experimental ranks gate (#541):** All Rivals reads its route scope through `RivalScope.coerced(experimentalRanks:)`, so a leaderboard scope with an experimental metric loads Total Score while the switch is off. Rival Detail and Rivalry do the same. See [experimental-ranks](../../patterns/experimental-ranks.md).
