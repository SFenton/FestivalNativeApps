# Leaderboards overview — iPhone notes

> **What:** iPhone implementation state and decisions for the leaderboards overview cards. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md) (currently a stub — this file is the source of truth for what's actually built until spec.md is promoted).

Source: `FortniteFestivalWeb/src/pages/leaderboards/LeaderboardsOverviewPage.tsx`, `.../components/RankingCard.tsx`, `.../components/BandRankingCard.tsx`, `.../helpers/rankingHelpers.ts`, `.../helpers/bandRankingHelpers.ts`. Service: `FSTService/Api/RankingsEndpoints.cs:187` (`/api/rankings/{instrument}`) and `:680` (`/api/rankings/bands/{bandType}`) — both pure, keyless `GET`s (read-only DB query, no writes), confirmed by reading the handler bodies.

- Implemented: one top-ten card (`pageSize: 10`) per Settings-visible instrument (`fst.settings.show*` `@AppStorage` keys, read directly by the screen — no new init parameter, no edit to `FestivalRootView`) plus one card per band size (`BandType.allCases`, always shown — band visibility has no Settings toggle on the web app either). A `primaryAction` toolbar `Menu` picks the shared `RankingMetric`; band cards narrow it via `RankingMetric.bandMetric` (maps `maxscore` → `totalscore`, matching the web client's `coerceBandRankingMetric` fallback). Rows navigate to `AppRoute.player`/`.band`; "View All" goes to `.fullRankings`/`.bandRankings`. Glass cards (`festivalGlass(.card)`), five-row skeleton while loading, independent per-card retry on failure, inline empty text, pull-to-refresh.
- Simplified vs. web this pass: no "your rank" spotlight rows (`getPlayerRanking`/`getSelectedMemberRankings`), no rank-history chart, no band-combo filter, no quick-links rail, no first-run slides — Wave 2 follow-up. Per-card loads are sequential, not a `TaskGroup`, to avoid capturing the `@MainActor` `FestivalSession` in a `@Sendable` closure; each card still gets its own skeleton/retry. No live reload on publication rollover (pull-to-refresh covers it); every read still goes through `FestivalAPI`'s publication-consistency pipeline.
- IDs: `fst.leaderboards.card.<instrument>`, `fst.leaderboards.band-card.<bandType>`, `fst.rankings.row.<accountId>`, `fst.band-rankings.row.<teamKey>`, `fst.rankings.rank-by-menu`.
- Tests: `RankingsTests.swift` (Core) covers decoding, per-metric dispatch, page-count math and `RankingFormatting`. No hosted-UI/XCUITest coverage yet. `tools/ios_sim.py shot --tab leaderboards` against the live public service (2026-09-28) rendered real top-10 Lead/Duos rows correctly.
