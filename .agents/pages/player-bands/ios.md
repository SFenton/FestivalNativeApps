# Player bands — iPhone notes

> **What:** iPhone implementation state and decisions for `/bands/player/:accountId`. **Read when:** changing this page on iPhone. Behavior: [spec.md](spec.md) (currently a stub — this file is the source of truth for what's actually built until spec.md is promoted).

Source: `FortniteFestivalWeb/src/pages/band/PlayerBandsPage.tsx`, `.../pages/player/components/PlayerBandCard.tsx`. Service: `FSTService/Api/PlayerEndpoints.cs:647` (`/api/player/{accountId}/bands`) — pure, keyless `GET`: `GlobalLeaderboardPersistence.GetPlayerBandsList` returns an empty page when the band-search projection is missing rather than rebuilding anything (`GlobalLeaderboardPersistence.cs:3873-3896`), unlike `/api/bands/search`'s fallback.

- Implemented: native segmented `Picker` (All/Duos/Trios/Quads, `PlayerBandGroup`) in place of the web's filter sheet — a fixed four-option control fits Apple HIG's segmented control better than a modal. Paginated card list of `PlayerBandEntry` rows (member names + `InstrumentIcon`s + appearance count), reusing `RankingsPagerView`/`RankLoadState` from the Leaderboards lane's `RankingsSupport.swift` (same module, read-only reuse). Rows navigate to `AppRoute.band(bandId:name:bandType:teamKey:)`, carrying `bandType`/`teamKey` from the row so Band Detail never needs the blocked `/api/bands/{bandId}` lookup.
- **Card list (issue #319):** a `ScrollView` + `LazyVStack` of `PlayerBandRow` cards (the shared row card with an in-card chevron, web `PlayerBandCard` `frostedCard`), 8 pt apart and 16 pt in from the edges; the same row the profile's bands section uses. Not a `List`: the rows are `NavigationLink`s and a `List` would add a second chevron. Cards fade out above the pinned `RankingsPagerView` and are not drawn beneath it (`bottomChromeFade`, [scroll-edge](../../patterns/scroll-edge.md)); the pager wears the rows' card surface ([leaderboard-row](../../patterns/leaderboard-row.md) R5, [surface-materials](../../patterns/surface-materials.md) R1). HIG Materials (`materials.md`): "Use standard materials within the content layer"; HIG Buttons (`buttons.md`): 44x44 pt minimum hit region.
- Simplified vs. web this pass: no `?name=` route-title carry-through from a prior band-search result (global search's band results open the band page, not this list, so it does not matter yet); no FAB "filter" registration (`useFabSearch`) — the segmented control is always visible instead.
- Entry points: Bands landing, Mac context menus, and the profile's inline bands section (issue #312). Its View All opens on All, and each group's View All Bands (N) opens on that group (`AppRoute.playerBands(accountId:displayName:group:)`, default `.all`; `PlayerBandsScreen(group:)` seeds the picker). The profile's cards are the same `PlayerBandRow`.
- IDs: `fst.player-bands.group-picker`, `fst.player-bands.row.<bandId-or-teamKey>`, `fst.player-bands.page-first/previous/page-info/next/last` (from the shared `RankingsPagerView`).
- Tests: `BandsTests.swift` (Core) covers `PlayerBandListResponse`/`PlayerBandEntry` decoding, `membersLabel` name-fallback joining and `pageCount` math. Hosted coverage: `PlayerBandsRenderTests` cases in `apple/Tests/FestivalUITests/BandsRenderTests.swift` (loaded+pager, empty); XCUITest: `BandsJourneyTests.testPlayerBandsPagesPastTheFirstPage` (Lane U4, 2026-09-28).
- **Board footer fade accessibility (issue #473, for #329; iPhone, Duo, iPad, Mac):** the cards' 40 pt fade above the pager ([scroll-edge](../../patterns/scroll-edge.md) R3/R9) is drawing only: at AX5 the cards grow, a card crossing the fade keeps its spoken label and stays reachable while its middle is above the pager, the pager's five named controls stay 44 pt and on screen, and at the end of a page the last card rests whole above the pager. HIG Accessibility: iOS, iPadOS default control size 44×44 pt; "Support enlargement up to 200%". Test: `BoardFooterFadeJourneyTests/testBoardFooterFadeAtLargestText` (iPhone, in `apple-ci`; runs on iPad too) with `performAccessibilityAudit`; hosted reading order and fade-band checks in `BottomChromeFadeHostedTests`.
- **Load/reload fade (issue #71):** Player Bands runs the shared `FestivalReloadGate` on load and on a group or page change: old results leave at once, the spinner fades in, holds ≥400 ms, fades out (500 ms) and the results fade/stagger in; Reduce Motion swaps instantly. See [iPhone motion](../../design/apple/iphone.md#motion).
