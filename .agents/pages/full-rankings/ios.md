# Full rankings — iPhone notes

> **What:** iPhone implementation state and decisions for the paginated full rankings and band rankings pages. **Read when:** changing either page on iPhone. Behavior: [spec.md](spec.md) (currently a stub — this file is the source of truth for what's actually built until spec.md is promoted; band-rankings/spec.md is a separate stub covering the same screen).

Source: `FortniteFestivalWeb/src/pages/leaderboards/FullRankingsPage.tsx`, `.../BandRankingsPage.tsx`, `.../helpers/rankingHelpers.ts` (`LEADERBOARD_PAGE_SIZE = 25`). Service: same two pure `GET`s as [leaderboards/ios.md](../leaderboards/ios.md), requested here with `pageSize: 25` and a specific `page`.

- Implemented: `FullRankingsScreen` (`AppRoute.fullRankings`) and `BandRankingsScreen` (`.bandRankings`) both render a native `List` (rows → `.player`/`.band`) plus the shared `RankingsPagerView` — the same First/Previous/`page / totalPages`/Next/Last control as the Solo chart ([song-leaderboard/ios.md](../song-leaderboard/ios.md)), so paging is identical everywhere. `FullRankingsScreen` adds an instrument switcher (scoped to Settings-visible instruments, keeping the current chart selectable even if just hidden) and the metric `Menu`; `BandRankingsScreen` adds a band-size switcher and a four-metric menu (no Max Score for bands). Switching any picker resets to page 1. `totalPages` = `ceil(totalAccounts|totalTeams / pageSize)`, always ≥1. Stale-response guard: a superseded request's result is dropped by comparing a `RequestKey` before applying it (same pattern as the Solo chart).
- **Selected-player spotlight, `FullRankingsScreen` only (Lane L2, 2026-09-28):** rows use the shared `AccountRankingRow(isSelected:)` accent highlight when the selected player is on the current page. When they're not, a pinned footer below the `List` (above `RankingsPagerView`) fetches their own row (`playerInstrumentRanking`, independent of `page` — matches the web's separate `playerRanking` query on `FullRankingsPage.tsx`) and shows it via `RankingSpotlight.placement` (same Core logic as the overview cards: pending/unranked/failed/footer). **Native addition beyond web:** the footer row has a distinct trailing "jump to your page" button (`LeaderboardPaging.page(forRank:pageSize:)`, `fst.full-rankings.spotlight-jump`) that re-pages the `List` directly — the real web footer (`FullRankingsPage.tsx:531-552`) only links to the player's profile and never repaginates, since native's paginated `List` can usefully jump instead. No selected-band pinned row: same "no selected-band identity natively yet" gap as [leaderboards/ios.md](../leaderboards/ios.md), not ported for `BandRankingsScreen`.
- Simplified vs. web: no band-combo filter. Picker changes update `@State` in place rather than pushing a new `AppRoute`, since neither page has the Solo chart's deep-link-bookmark-correctness requirement.
- IDs: `fst.full-rankings.page-*`, `fst.full-rankings.instrument-menu`, `fst.band-rankings.page-*`, `fst.band-rankings.band-type-menu`, `fst.band-rankings.rank-by-menu`, shared `fst.rankings.rank-by-menu`, `fst.full-rankings.spotlight-footer`/`.spotlight-jump`/`.spotlight-footer.unranked`/`.spotlight-footer.loading`.
- Verified live against the public service (2026-09-28): `tools/ios_sim.py shot --route fullRankings:Solo_Guitar` and `--route bandRankings:Band_Duets` both rendered real paginated rows (a 729-song Lead board, 34,788 pages at `adjusted`; a Duos board, 72,450 pages at `totalscore`) — confirms wire shape, pagination math and roster formatting against production data. Spotlight footer hosted in `LeaderboardsHostedTests.swift` (`fullRankingsScreenShowsSpotlightFooterWithJumpControl`); no XCUITest coverage yet.
