# Full rankings — iPhone notes

> **What:** iPhone implementation state and decisions for the paginated full rankings and band rankings pages. **Read when:** changing either page on iPhone. Behavior: [spec.md](spec.md) (currently a stub — this file is the source of truth for what's actually built until spec.md is promoted; band-rankings/spec.md is a separate stub covering the same screen).

Source: `FortniteFestivalWeb/src/pages/leaderboards/FullRankingsPage.tsx`, `.../BandRankingsPage.tsx`, `.../helpers/rankingHelpers.ts` (`LEADERBOARD_PAGE_SIZE = 25`). Service: same two pure `GET`s as [leaderboards/ios.md](../leaderboards/ios.md), requested here with `pageSize: 25` and a specific `page`.

- Implemented: `FullRankingsScreen` (`AppRoute.fullRankings`) and `BandRankingsScreen` (`.bandRankings`) both render a native `List` (rows → `.player`/`.band`) plus the shared `RankingsPagerView` — the same First/Previous/`page / totalPages`/Next/Last control as the Solo chart ([song-leaderboard/ios.md](../song-leaderboard/ios.md)), so paging is identical everywhere. `FullRankingsScreen` adds an instrument switcher (scoped to Settings-visible instruments, keeping the current chart selectable even if just hidden) and the metric `Menu`; `BandRankingsScreen` adds a band-size switcher and a four-metric menu (no Max Score for bands). Switching any picker resets to page 1. `totalPages` = `ceil(totalAccounts|totalTeams / pageSize)`, always ≥1. Stale-response guard: a superseded request's result is dropped by comparing a `RequestKey` before applying it (same pattern as the Solo chart).
- **Shared pinned pager, Full Rankings (issue #294, 2026-10):** Full Rankings now uses the Song Leaderboard pattern ([song-leaderboard/ios.md](../song-leaderboard/ios.md)), not a page-specific floating bar. A `ScrollView` + `LazyVStack` of the compact glass rows ([leaderboards/ios.md](../leaderboards/ios.md)) sits above a bottom chrome in `.safeAreaInset(edge: .bottom)`, outside the reload gate. The chrome is the spotlight footer plus the shared `RankingsPagerView(idPrefix: "fst.full-rankings")`: `« ‹ 1 / 34,691 › »` with spoken "First page" … "Last page". Its `page / total` badge is one adjustable element ("Page, 2 of 48"; swipe up/down pages). Rows fade out above the chrome (`ScrollEdgeFade.bottom` mask, measured in the `fst.full-rankings.page` space), and the content keeps a `ScrollEdgeFade.distance` bottom margin, exactly as on Song Leaderboard. `body` reads `bottomChromeTop` and passes it to the mask: read only inside the mask's lazy `GeometryReader`, the first page kept an opaque mask (rows drawn behind the pager) until a scroll re-rendered the page (live iPhone 17 Pro capture, 2026-10-04; Song Leaderboard has the same read pattern and is left to #293). The page total survives page loads (`shownEntries`/`board` cleared only on an instrument or Rank By switch). On the Duo vertical bar, `RankingsPagerView` renders nothing and `RankingsPagerToolbarContent` supplies the rail pager (B2). HIG design principles: "Keep visual and interaction behavior consistent so people learn quickly and can predict new interactions". The instrument switcher left the floating pill: it is a toolbar `Menu` (`fst.full-rankings.instrument-menu`, label "Instrument", value the chart name) whose label is the chart icon (`InstrumentIcon.menuImage`), grouped with Rank By in the `.festivalPageAction` slot on every layout. On Mac and iPad it is also View › Instrument ▸ (`MacInstrumentCommands`, `.macInstrumentCommands`): HIG Toolbars › macOS, "Every toolbar item must also be a menu-bar command because people can customize or hide the toolbar". `RankingsFloatingBar`/`RankingsGlassPager` now serve only Band Rankings (unchanged: band pill with `person.3.fill`, pager capsule, `ViewThatFits` fallbacks). Lists keep `rankingsListRailClearance` (`DeviceLayout.cutoutInsets.trailing`, camera only).
- **Title with instrument icon (issue #294):** the first scroll item is `RankingsPageTitle(.header)`: the chart icon (`@ScaledMetric` 36 pt relative to `.largeTitle`, decorative, `accessibilityHidden`) left of "Lead Rankings" in `.largeTitle.bold()`, combined into one header element (`fst.full-rankings.title`). The bar uses `.navigationBarTitleDisplayMode(.inline)` with `navigationTitle` kept for the bar identifier, back menu and window title. Once the header scrolls under the bar (`SongDetailPinnedTitlePolicy.isHeroHidden`), the principal slot shows `RankingsPageTitle(.pinned)`: a 24 pt (`.headline`-relative) icon plus a `.headline` `MarqueeText` (`fst.full-rankings.pinned-title`). Before that it shows a 1×1 hidden placeholder, so the bar never falls back to plain title text and there's no opacity-0 copy for the Dynamic Type audit. This is the same artwork-plus-title swap as Song Leaderboard. The principal title is skipped on the Duo vertical bar (custom views aren't drawn in the rail), so folded Duo shows the system inline title above the icon header, as Song Detail and Song Leaderboard do. HIG Icons: "Match icon weight to adjacent text"; Toolbars › iOS: the title condenses to the bar as people scroll. On macOS the window title stays text and the in-content header carries the icon.
- **Ranked count:** first scroll line under the large title, "868,901 ranked players" / "N ranked bands" (web `PageHeader` subtitle, `rankings.totalRanked`), `RankingsCountHeader`: `.subheadline` semibold, primary white (`fst.full-rankings.ranked-count`, `fst.band-rankings.ranked-count`). Not `navigationSubtitle`: the system subtitle rendered too small (operator, 2026-09-28). Title stays "Lead Rankings" (web: "Lead Leaderboards").
- **Text colour:** `FestivalText.primary` for every label (songs column, Bayesian line, empty/unranked text); disabled pager symbols use `FestivalText.disabled`. Each loaded page fades in once (`festivalFadeInOnAppear` on the list, not per row on scroll).
- **Tab-bar accessory:** the pinned pager (Band Rankings: the floating bar) stacks above the accessory (safe-area inset), never inside it. Moving the pager into the accessory was rejected: the slot holds global Search plus at most one page action ([nav-accessories.md](../../design/apple/nav-accessories.md)), and a five-control pager plus switcher doesn't fit beside Search, least of all when the accessory goes inline beside the minimized tab bar. The cost is two stacked bottom bars while the tab bar is expanded.
- **Selected-player spotlight, `FullRankingsScreen` only (Lane L2, 2026-09-28):** rows use the shared `AccountRankingRow(isSelected:)` accent highlight when the selected player is on the current page. When they're not, a pinned glass row in the bottom inset (above the shared pager) fetches their own row (`playerInstrumentRanking`, independent of `page` — matches the web's separate `playerRanking` query on `FullRankingsPage.tsx`) and shows it via `RankingSpotlight.placement` (same Core logic as the overview cards: pending/unranked/failed/footer). **Native addition beyond web:** the footer row has a distinct trailing "jump to your page" button (`LeaderboardPaging.page(forRank:pageSize:)`, `fst.full-rankings.spotlight-jump`) that re-pages the `List` directly — the real web footer (`FullRankingsPage.tsx:531-552`) only links to the player's profile and never repaginates, since native's paginated `List` can usefully jump instead. No selected-band pinned row: same "no selected-band identity natively yet" gap as [leaderboards/ios.md](../leaderboards/ios.md), not ported for `BandRankingsScreen`.
- Simplified vs. web: no band-combo filter. Picker changes update `@State` in place rather than pushing a new `AppRoute`, since neither page has the Solo chart's deep-link-bookmark-correctness requirement.
- IDs: `fst.band-rankings.pager` (capsule), `fst.full-rankings.page-*` (`first`, `previous`, `info`, `next`, `last`), `fst.full-rankings.title`, `fst.full-rankings.pinned-title`, `fst.full-rankings.instrument-menu`, `fst.band-rankings.page-*`, `fst.band-rankings.band-type-menu`, `fst.band-rankings.rank-by-menu`, shared `fst.rankings.rank-by-menu`, `fst.full-rankings.spotlight-footer`/`.spotlight-jump`/`.spotlight-footer.unranked`/`.spotlight-footer.loading`.

- **Load/reload fade (issue #71):** Full Rankings and Band Rankings run the shared `FestivalReloadGate` on load and on an instrument, Rank By or page change: old results leave at once, the spinner fades in, holds ≥400 ms, fades out (500 ms) and the results fade/stagger in; Reduce Motion swaps instantly. See [iPhone motion](../../design/apple/iphone.md#motion).
