# Full rankings — iPhone notes

> **What:** iPhone implementation state and decisions for the paginated full rankings and band rankings pages. **Read when:** changing either page on iPhone. Behavior: [spec.md](spec.md) (currently a stub — this file is the source of truth for what's actually built until spec.md is promoted; band-rankings/spec.md is a separate stub covering the same screen).

Source: `FortniteFestivalWeb/src/pages/leaderboards/FullRankingsPage.tsx`, `.../BandRankingsPage.tsx`, `.../helpers/rankingHelpers.ts` (`LEADERBOARD_PAGE_SIZE = 25`). Service: same two pure `GET`s as [leaderboards/ios.md](../leaderboards/ios.md), requested here with `pageSize: 25` and a specific `page`.

- Implemented: `FullRankingsScreen` (`AppRoute.fullRankings`) and `BandRankingsScreen` (`.bandRankings`) both render a native `List` (rows → `.player`/`.band`) plus the shared `RankingsPagerView` — the same First/Previous/`page / totalPages`/Next/Last control as the Solo chart ([song-leaderboard/ios.md](../song-leaderboard/ios.md)), so paging is identical everywhere. `FullRankingsScreen` adds an instrument switcher (scoped to Settings-visible instruments, keeping the current chart selectable even if just hidden) and the metric `Menu`; `BandRankingsScreen` adds a band-size switcher and a four-metric menu (no Max Score for bands). Switching any picker resets to page 1. `totalPages` = `ceil(totalAccounts|totalTeams / pageSize)`, always ≥1. Stale-response guard: a superseded request's result is dropped by comparing a `RequestKey` before applying it (same pattern as the Solo chart).
- **Floating glass pager (Lane PB, gap #10 in [apple-gaps.md](../../testing/pwa-reference/apple-gaps.md)):** both boards are now a `ScrollView` + `LazyVStack` of the same compact glass rows as the overview (see [leaderboards/ios.md](../leaderboards/ios.md)), with `RankingsFloatingBar` in `.safeAreaInset(edge: .bottom)`: a `festivalGlassCapsule(.control)` pager `« ‹ 1 / 34,757 › »` (`RankingsGlassPager`: SF Symbols `chevron.left.2`/`chevron.left`/`chevron.right`/`chevron.right.2`, 44 pt scaled targets, spoken "First Page" … "Last Page"; the label is one adjustable element "Page, 1 of 34,757", swipe up/down to page) beside the board switcher as an interactive glass pill (instrument icon + name; band glyph + size). `ViewThatFits` falls back to an icon-only pill, then pager above pill (large Dynamic Type). Inside the `TabView` the page's bottom safe area already ends above the tab bar **and** the tab-bar bottom accessory (global Search, Lane A2), so the bar floats above both and rows scroll under it; verified on the iOS 26.5 iPhone 17 Pro. Pre-26 falls back through `FestivalGlass` (frosted material). The pager state (clamping, enabled edges, `label`, `accessibilityValue`) is Core `RankingsPagerState` (`RankingsPager.swift`). The page/total is kept across page loads (`BoardSummary`) so the bar doesn't flicker, and cleared on an instrument/metric switch (pill stays, pager returns with the new board). The rank-by menu stays in the toolbar; the switcher leaves the toolbar except on the Duo vertical bar, where the floating bar renders nothing and the switcher + `RankingsPagerToolbarContent` stay in the rail (B2). The text `RankingsPagerView` footer remains only for song leaderboards and Player Bands.
- **Ranked count:** first scroll line under the large title, "868,901 ranked players" / "N ranked bands" (web `PageHeader` subtitle, `rankings.totalRanked`), `RankingsCountHeader`: `.subheadline` semibold, primary white (`fst.full-rankings.ranked-count`, `fst.band-rankings.ranked-count`). Not `navigationSubtitle`: the system subtitle rendered too small (operator, 2026-09-28). Title stays "Lead Rankings" (web: "Lead Leaderboards").
- **Text colour:** `FestivalText.primary` for every label (songs column, Bayesian line, empty/unranked text); disabled pager symbols use `FestivalText.disabled`. Each loaded page fades in once (`festivalFadeInOnAppear` on the list, not per row on scroll).
- **Tab-bar accessory:** the floating bar stacks above the accessory (safe-area inset), never inside it. Moving the pager into the accessory was rejected: the slot holds global Search plus at most one page action ([nav-accessories.md](../../design/apple/nav-accessories.md)), and a five-control pager plus switcher doesn't fit beside Search, least of all when the accessory goes inline beside the minimized tab bar. The cost is two stacked bottom bars while the tab bar is expanded.
- **Selected-player spotlight, `FullRankingsScreen` only (Lane L2, 2026-09-28):** rows use the shared `AccountRankingRow(isSelected:)` accent highlight when the selected player is on the current page. When they're not, a pinned glass row in the bottom inset (above the floating pager) fetches their own row (`playerInstrumentRanking`, independent of `page` — matches the web's separate `playerRanking` query on `FullRankingsPage.tsx`) and shows it via `RankingSpotlight.placement` (same Core logic as the overview cards: pending/unranked/failed/footer). **Native addition beyond web:** the footer row has a distinct trailing "jump to your page" button (`LeaderboardPaging.page(forRank:pageSize:)`, `fst.full-rankings.spotlight-jump`) that re-pages the `List` directly — the real web footer (`FullRankingsPage.tsx:531-552`) only links to the player's profile and never repaginates, since native's paginated `List` can usefully jump instead. No selected-band pinned row: same "no selected-band identity natively yet" gap as [leaderboards/ios.md](../leaderboards/ios.md), not ported for `BandRankingsScreen`.
- Simplified vs. web: no band-combo filter. Picker changes update `@State` in place rather than pushing a new `AppRoute`, since neither page has the Solo chart's deep-link-bookmark-correctness requirement.
- IDs: `fst.full-rankings.pager` / `fst.band-rankings.pager` (capsule), `fst.full-rankings.page-*` (`first`, `previous`, `info`, `next`, `last`), `fst.full-rankings.instrument-menu`, `fst.band-rankings.page-*`, `fst.band-rankings.band-type-menu`, `fst.band-rankings.rank-by-menu`, shared `fst.rankings.rank-by-menu`, `fst.full-rankings.spotlight-footer`/`.spotlight-jump`/`.spotlight-footer.unranked`/`.spotlight-footer.loading`.
- Verified live against the public service (2026-09-28): `tools/ios_sim.py shot --route fullRankings:Solo_Guitar` and `--route bandRankings:Band_Duets` both rendered real paginated rows (a 729-song Lead board, 34,788 pages at `adjusted`; a Duos board, 72,450 pages at `totalscore`) — confirms wire shape, pagination math and roster formatting against production data. Spotlight footer hosted in `LeaderboardsHostedTests.swift` (`fullRankingsScreenShowsSpotlightFooterWithJumpControl`). Paging journeys: `FullRankingsPagerJourneyTests` (Next/Last/Previous/First values and edge enablement over 48 pages; instrument switch resets to page 1) against `python3 tools/mock_service.py --large-rankings --port 8766`, skipped when that fixture isn't listening; single-page states in `LeaderboardsJourneyTests`.
