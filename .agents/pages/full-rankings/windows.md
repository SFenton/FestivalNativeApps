# Full rankings — Windows notes

> **What:** what the Windows paginated global rankings page implements, its live findings and open gaps. **Read when:** changing `windows/Festival.App/Pages/LeaderboardsFullRankingsPage*` or `FullRankingsViewModel`. Behavior: [spec.md](spec.md); iPhone reference: [ios.md](ios.md); band variant: [band-rankings/windows.md](../band-rankings/windows.md).

## Implemented

- Route `AppRoute.FullRankings(instrument, rankBy)` (unknown or missing `rankBy`, including a bare `/leaderboards/all` deep link, → Total Score, web `DEFAULT_METRIC`). 25-row pages of `GET /api/rankings/{instrument}?rankBy=&page=&pageSize=25`; page count `ceil(totalAccounts / 25)` (≥1); an out-of-range page is clamped once totals arrive; a superseded response (older instrument/metric/page) is dropped.
- Combo mode (issue #602, web `FullRankingsPage` with a `combo` param): `AppRoute.FullRankings(..., Combo: "0f")` ↔ `/leaderboards/all?combo=0f&rankBy=…` (a malformed or cross-group `combo` falls back to `instrument=`, default Lead). It pages `GET /api/rankings/combo?combo=&rankBy=&page=&pageSize=25` and pins the selected player's rank from `GET /api/rankings/combo/{accountId}?combo=&rankBy=`. The combo ranking is per metric, so Rank By re-reads it; paging does not. The header shows the board's icons in a row above "Lead + Bass + Drums + Tap Vocals Rankings", the 32 epx single icon collapses, and there is no instrument picker (`ShowInstrumentPicker`), as on the web. Rank By stays. Agent decision ([page-tools-and-nav-chrome](../../patterns/page-tools-and-nav-chrome.md) R18 Windows variant, decision posted on #602): the web shows only the icon row as the combo page's title (an `aria-label` on a generic `div`); Windows keeps the icon row and adds the visible text title below it, because it is the page's heading 1 and Narrator's landmark (Apple's combo board does the same). Everything else (pager, pinned row, load swap, footer fade) is shared with the instrument mode.
- Header: instrument icon, "<Instrument> Rankings" (heading 1), "N ranked players"; instrument switcher (Settings-visible charts plus the current one) and Rank By, both radio `MenuFlyout`s; switching either returns to page 1. Rank By shows only with Settings' Experimental Ranks on (issue #541); while it is off a deep-linked or saved experimental `rankBy` loads Total Score, and revisiting with it on restores the requested metric (`requestedMetric`, `SyncExperimentalRanks`). The picker's instrument icon and the Rank By glyph render at the same 18 epx height (operator 2026-09-28; the icon is never shrunk). Rows read "X / Y" (web `getSongsLabel`). The selected player's spotlight loads behind a white ring with no subtitle.
- Rows in one grouped card (`ItemsRepeater` in a `ScrollViewer`; rows touch with inset hairlines between them through `GroupedRows.IsEnabled`, issue #543, owner-approved native variant, [leaderboard-row](../../patterns/leaderboard-row.md#owner-approved-variant-one-card-per-board-page-543)); the selected player's row is highlighted. A page change scrolls to the top, or to the selected row when it is on the new page.
- Pinned "your rank" row above the pager on every page whenever the selected player is ranked, their own page included (issue #318, [leaderboard-row](../../patterns/leaderboard-row.md) R7; web `FullRankingsPage` `hasPlayerFooter = !!playerRanking`): `RankingSpotlightViewModel(pinned: true)` places it with `RankingSpotlight.PlacePinned`, which never goes inline; the overview cards keep `Place` and still hide a player in their top rows (web `RankingCard`). The own-row read is per instrument, independent of the page, and always made; until it answers, the player's page row stands in. The pinned row is itself the control (R7, `SelectedRowAction.Footer`, the same rule as the song and song band boards since #307): while the player's row is on another page it runs the spotlight's `JumpCommand` (`LeaderboardEntryRow.Command`) and is named "Your rank, 40th. Jump to your position. …"; once the row is on the shown page (or the shown page is its rank's page) it opens the player's profile (detail column in two columns), named "… Open your statistics. …". There is no separate **Your page** button (removed in the #318 review: it split R7's one control in two). Before #318 the footer was hidden while the player's row was on the page. Loading / unranked / inline-failure states as on the overview.
- Shared pager (`LeaderboardsPager`): First · Previous · "page / total" (polite live region, "Page 2 of 34,760") · Next · Last; First/Last collapse below 380 epx; hidden with one page; Left/Right/Home/End in the pager, Ctrl+Left/Right on the page.
- Rows are the shared `LeaderboardEntryRow` (operator batch 7.7): frosted rows grouped in the page's one card since #543, the `X / Y` songs label then the blue rating, like the web `RankingEntry`.
- Back restores the page, switcher and metric: pushed pages keep their view model per back-stack entry (`LeaderboardsPageState`, keyed by the route object Frame hands back).
- Load-swap gate (issue #71): first load, F5, instrument/metric changes and paging run content out (300 ms) → centered ring → ring out (500 ms) → row stagger. Old rows stay only during content-out; new rows, empty and failure states are applied while hidden; rapid choices are latest-wins. Reduce Motion skips the waits and swaps immediately. `ShowContent` is not gated by the swap (issue #208): collapsing the content mid-page-change dropped keyboard focus from the pager to the window.
- The pinned "your rank" row is part of the gate when its value can change (issue #270, [load-transition](../../patterns/load-transition.md) R2 agent decision): `SpotlightGate` (a `LoadSwapGate`, keyed by `PinnedRowGate` on instrument + Rank By) fades it out with the rows and removes it from UI Automation, so a Rank By or instrument switch never shows the old value beside the spinner. Paging, F5 and Retry keep it visible and usable beside the spinner, like the web footer (`footerAnimKey={cacheKey}` ignores the page). After a gated reload it fades in with the first row (`PinnedRowReveal`), and a late own-rank read fades in on its own. `FullRankingsViewModel` keeps the old instrument's spotlight until the new board commits; a failed switch drops it. Same mechanism as the song leaderboard (#295).
- After the pinned row's jump the page centres the selected row (`StartBringIntoView`, ratio 0.5) once the load swap reveals the new page (`ContentRevealed`), after a forced layout pass, and skips the scroll-to-top for that page: centring rows the repeater had not yet laid out, or racing a pending `ChangeView(0)`, intermittently left the row off screen (#318 review, 2 of 6 keyboard runs before, 9 of 9 after). Since #571 the forced layout and an in-view re-check are the shared `SelectedRowReveal.CentreRow`, which the song leaderboard uses too. The centring runs through `SelectedRowReveal` (issues #307 and #323): it waits for the row's own entrance while the rows below the first screen wait for the jump, rushes the fades still waiting so the rows it reaches fade in together, and gives way if the reader scrolled meanwhile ([load-transition](../../patterns/load-transition.md) Windows selected-row reveal). Keyboard focus stays on the pinned row, which stays in place, so a second Enter opens the profile (#318; before it, the collapsing Your page button handed focus to the list row, issue #208). The shared `BoardFooter.Inset` grows every focus scroll by the floating footer's height (`LeaderboardPaging.RevealAboveFooter`; aligned requests such as the centred jump too since #461), so a focused row never sits under the pager (WCAG 2.4.11; same pattern as Song Detail's pinned header). This was the page's own `OnRowsBringIntoViewRequested` until #409 moved it into `BoardFooter` for every board. Journey: `cols-full-rankings-focus-clear` (compact and medium: Down ×14 to rank 15, which starts below the fold at both presets, clear of the pinned row and pager, then Tab to the pinned row; at the 500×800 compact preset rank 12 already sits partly under the floating footer, so it can't prove the arrows scrolled, issue #538).
- Opened with `navToPlayer=true` (`AppRoute.FullRankings.RevealSelected`, from a Leaderboards card's "your rank" row, #370) the page reveals the selected row on its first load the same way, as the song board does for `navToPlayer`; Back to an already-created page does not reveal it again. Accessibility pages: `tools/windows/journeys/a11y-selected-row-reveal.json` `reveal-full-rankings-card` and `-still` (issue #470; keyboard open from the card, row 60's phrase, fill, 40 epx target clear of the pinned row, rows → pinned row → First order, Down/Up/Tab, and a still reveal with motion off).
- At large text a ranking row that cannot fit moves the "X / Y" songs label under the name (`LeaderboardColumnPlan.MetaBelowName`, `LeaderboardEntryRow.PlaceMeta`) instead of truncating the name to "…" (issue #208, WCAG 1.4.4). If the name is still squeezed (live: "#1,450" with an 11-character rating at 200% text, compact), the row stacks on two lines (`ValueBelowName`): rank and name across the rating's column, then the songs label from the rank's edge and the rating. The songs label ellipsizes rather than clip. Applies to every ranking board that uses the shared row. From 150% text a name that still doesn't fit wraps onto more lines and the row grows, rather than scrolling or ellipsizing (`MarqueeText.WrapsAtLargeText`, issue #455, [leaderboard-row](../../patterns/leaderboard-row.md) R3). Journey: `tools/windows/journeys/a11y-leaderboard-names.json`.
- Footer edge (issue #308, web board `Page.tsx` `useScrollMask`, 40 px linear, [scroll-edge](../../patterns/scroll-edge.md) R2–R4/R7): Rows end at the floating pager and pinned your-rank row through the shared bottom-chrome ramp `BoardFooterFade.Attach` (`Controls/BoardFooterFade`, the same component as Song Leaderboard): clear at the footer's top, opaque 40 epx above it on a linear ramp, the depth min(remaining scroll, 40) so nothing is dimmed at the end. Contrast themes, Windows transparency effects off, Increase Contrast and Less Transparency make it a hard cut at the footer's top. The source is the `BoardFadeSource` wrapper (the load swap animates the list's own visual) and the raw-view `EdgeFadeLayer` `fst.full-rankings.footer-fade` reports `hidden`, `fading:40`, `end` or `hard-edge` (journeys `tools/windows/journeys/a11y-board-footer-fade.json` and `-hard.json`). Before #308 the rows met the pager and pinned your-rank row at a hard edge. The contrast `FooterPlate` stays behind the footer.
- Loading placement ([load-transition](../../patterns/load-transition.md) R13, #624): the ring centres between the retained header and the floating pager, not in the whole page. `LoadSwapVisual.PlaceSpinner` insets the Raw `fst.full-rankings.loading-region` while the ring is active; the ring stays the one named busy stop. Journey: `a11y-loading-placement.json` (`assertcentred` region → ring, `assertgap` region → pager 0 epx; normal and text-225).

## Live findings (2026-09-28)

- Production serves ranking rows with an **empty `accountId` and no `displayName`** (Lead, Total Score, rank 15). Validating every row's ID rejected the whole page; such rows are now accepted, shown as "Unknown User" and not interactive (`AccountRankingEntry.HasProfile`). The same tolerance applies to band rows without `bandId`/`teamKey` and solo chart rows.
- Lead Total Score: 869,000 ranked players (34,760 pages); a rank-40 selected player's pinned row → page 2 verified live (then via Your page; since #318 the pinned row jumps).

## Split view (#652)

Full Rankings is a split sub-page, not a list page ([split-panes](../../patterns/split-panes.md) R7 Windows variant): opened from Leaderboards when the content area holds two 480 epx halves, it shows in the trailing half beside the hub (`OnDemandSplitHost`, `fst.split.pane`, Close `fst.split.close`); otherwise it is pushed full width. A row always opens the player's profile full width over the split (`LeaderboardEntryRow` → `MainWindow.Navigate`), and Back returns to the split. The page-local profile column (1100 epx page, 560 epx list, auto-selected row with `LeaderboardEntryRow.IsCurrent`, `IRouteHost`) was removed. Journey: `leaderboards-split-wide` in `tools/windows/journeys/split-panes.json`.
