# Leaderboard row columns — Windows notes

> **What:** Windows implementation and validation of the shared column fitting. **Read when:** changing `windows/Festival.Core/Domain/LeaderboardColumnLayout.cs` or `windows/Festival.App/Controls/LeaderboardEntryRow`. Behavior: [spec.md](spec.md).

- **Fitter:** `Festival.Core/Domain/LeaderboardColumnLayout.Fit` over a `LeaderboardSection` measured from every row plus the pinned row (`LeaderboardColumns.Measure`). Each row reads its section through `Section`, so rows never measure themselves alone. Breakpoints are effective pixels of the row width: season from 520 epx, stars from 700 epx, and column gaps of 8 epx below 420 epx (12 above). A shown column keeps its width on rows without a value. Large text drops stars, then season, before squeezing the name, and at accessibility sizes moves score and badge (or the rankings songs label) under the name on every row of the section. Unit tests: `LeaderboardColumnLayoutTests` and `LeaderboardUnifyTests` (Festival.Core.Tests).
- **Row:** `Controls/LeaderboardEntryRow` (design: [design/windows.md](../../design/windows.md), "Leaderboard rows: one design"). Its surface and badge brushes are set in code, so it re-applies them on `ContrastTheme.Changed`. Hover, pressed and the pager's disabled brushes are theme dictionaries (issue #242).
- **Validation (issue #242, 2026-10-04):** against the live public service, rows and the pinned row share column positions at compact, medium, wide, maximized and both snaps (UIA bounds). That holds under Desert and Night sky, text 200% (stacked rows at compact), display 100%/150% and the light system theme, with 0 Axe errors. Results per configuration: [song-leaderboard/windows.md](../../pages/song-leaderboard/windows.md#validation-issue-242-2026-10-04).
- **Accessibility test (issue #409):** `tools/windows/journeys/a11y-leaderboard-columns.json` (fixture, `a11y_matrix.py`). It keeps the shared columns tested:
  - **Pinned row:** its accuracy and season sit in the listed rows' columns, and a row without accuracy keeps the badge slot so its season still lines up.
  - **Hidden columns:** below 520 epx the season and stars columns hide, but row names still read them (labels never drop data).
  - **Every row:** one 40+ epx Button stop, read rows → pinned row → pager.
  - **Keyboard order (#456 review):** the rows are one Tab stop and Up/Down move between them (the Fluent list model, as in `score-accuracy-keyboard` and `kb-fr-rows`). Tab then reaches the pinned row and the pager, and Shift+Tab walks back to the song header (Full Rankings: back through the last row to Rank by). `assertfocus` checks each hop at every size and at text 200%/225%. Re-entry into the rows with Shift+Tab lands on the repeater's last realized row, which depends on scroll, so the journeys assert the hops on either side of it instead of that row.
  - **Focus not obscured (WCAG 2.4.11):** arrowing down to row 12 keeps the focused row clear of the floating pinned row and pager (`assertapart`) on the song board, Full Rankings, Band Rankings and the song band board, and a below-the-fold card on Player Bands at compact and medium (`*-focus-clear` pages). Before #409, the song board, both band boards and Player Bands scrolled the focused row only to the viewport's bottom edge, under the footer. `BoardFooter.Inset` now owns the guard for every board ([design/windows.md](../../design/windows.md), floating board footer).
  - **Large text:** text 200%/225% keeps the badge column and names.
  - **Full Rankings:** rows and the pinned row read every column.
  - **CI:** `test_a11y.test_leaderboard_column_pages` guards the page set and `test_leaderboard_column_keyboard_order` the asserted focus path.
  - **Selectors:** columns are found by raw-view IDs (`fst.score.accuracy.<row-suffix>`, `fst.score.season.<row-suffix>`; the pinned row's suffix is `spotlight-footer`). Rankings rows clear their column IDs, so their alignment is checked only by bounds in manual runs.
