# What's New changelog — Windows notes

> **What:** the WinUI What's New dialog, its launch gate and Settings replay as built. **Read when:** changing the changelog content, gate or dialog on Windows. Spec: [spec.md](spec.md); iPhone: [ios.md](ios.md).

## Implementation

| Piece | Where |
|---|---|
| Entries, hash, Title Case, Manual filter | `Festival.Core/Domain/Changelog.cs` (`Changelog`, `WhatsNewGate`, `WhatsNewMode`): `Entries` decoded (bounded) from the embedded resource `Festival.Core/WhatsNew.json`, generated by `windows-release-build` (checked-in placeholder `2610.01.01`); `IsPending` is false for `EmptyHash`. Tests: `WhatsNewTests` |
| Groups, tester notes, channel | `Changelog.cs`: `ChangelogGroup`/`TesterNotes` decoded verbatim from `groups`/`testflight`; `Changelog.DisplayBlocks(channel)` → `WhatsNewBlock` (`Headed` when any group has a category). `InstallChannels.Resolve`: `Store` only when `Package.Current.SignatureKind` is `Store`; unpackaged builds (default `WindowsPackageType=None`) throw → `Tester`. Debug/automation override `--distribution store\|tester` or `FST_DEBUG_DISTRIBUTION`. Resolved once in `InitializeWhatsNew` |
| Dismissal record | `Data/ChangelogSeenStore.cs` → `whats-new.json` in the app data folder (`AppStateFiles.WhatsNew`, kept by Settings Reset); `{version, hash}` ≤ 1 KB, hash ≤ 32, version ≤ 64; invalid → show again |
| Dialog | `Festival.App/MainWindow.WhatsNew.cs`: `ContentDialog` "What's New · <app version>", Title Case level-2 block headings (`SubtitleTextBlockStyle`), level-3 category headings (`BodyStrongTextBlockStyle`, only when `Headed`) with bullets in a scroller, **Dismiss** (close button spanning the command row, centred like the web's full-width button; Esc and a click outside also dismiss and record; operator batch 6.14). The notes scroller is a named tab stop that opens focused, so arrow and Page keys scroll long notes (issue #235). Its height is the window less 240 epx and refits while the dialog is open. IDs `fst.whats-new.dialog`, `fst.whats-new.list` (the scroller, named after the title), `fst.whats-new.dismiss`, `fst.whats-new.section.{b}` and `fst.whats-new.group.{b}.{g}` (headings) |
| Replay | Settings → Version → **What's New · Show** (`fst.settings.whats-new`) → `MainWindow.ShowWhatsNew()` |

## Gate and ordering

- Checked 700 ms after launch (the timer lives in a field: until 2026-09-28 it was a local that was collected before firing, so the launch dialog never appeared) so the first page's first-run carousel claims the dialog slot first; `MainWindow.ShowDialogAsync` serializes ContentDialogs, so What's New follows a carousel and a later carousel waits for it. Never presented into a minimized/hidden window (retries).
- `--whats-new off|on|fresh|force` (or `FST_DEBUG_WHATS_NEW` in Debug/automation launches): Debug and automation default **off**, Release normal; `fresh` forgets the dismissal once.

## Validation (issue #235, 2026-10-04)

Every reachable state runs in `python tools/windows/ui_journey.py tools/windows/journeys/whats-new.json` on the loopback fixture. The dismissal and the relaunch share `FST_DEBUG_DATA_DIR={shots}/whats-new-data`, so the relaunch reads the seen record the dismissal wrote. `whats-new.json` uses only UIA patterns and posted keys, so it also runs while the console is locked. The two backdrop-click journeys need real mouse input on an unlocked console and are kept apart in `journeys/whats-new-pointer.json`: a locked console drops or refuses `SendInput` (see Open). The accessibility pages are in `journeys/a11y-whats-new.json`. How each state shows on Windows:

| State | Windows evidence |
|---|---|
| waiting-for-first-run | `launch-order-carousel-then-whats-new`: with both forced, the carousel shows and What's New is absent; Esc closes the carousel, then What's New opens |
| presented | `fst.whats-new.dialog` with the title, a level-2 heading per version (`section.0`), bullets and Dismiss; focus starts on the notes list |
| dismissed | `presented-dismiss-records`: Tab moves to Dismiss and Enter closes the dialog, which writes `whats-new.json` (`fresh` forgets an earlier record first) |
| hidden-seen | `dismissed-relaunch-hidden-seen`: a relaunch in `on` mode with the same data folder shows no dialog, and Songs takes input |
| replay | `replay-from-settings-keyboard`: Enter on Settings → What's New · Show reopens the dialog with focus on the notes; Esc returns focus to the row |
| (channel-pending) | unreachable: the install channel resolves synchronously at launch |

Per configuration (fixture runs use `ui_journey` and `a11y_matrix --scan --tabs 6`; live runs use the public service with no profile):

| Configuration | Findings |
|---|---|
| Compact (500 epx), snap-left | the dialog fills the width less its margins and the notes wrap; 0 Axe errors; 2 Tab stops (notes, Dismiss) |
| Medium, wide, maximized | the dialog sizes to its notes up to ContentDialog's maximum width (548 epx), centred over the dimmed page; 0 Axe errors |
| Resize across breakpoints | `presented-resize-across-breakpoints`: compact → wide → medium → compact with the dialog open keeps the heading and Dismiss on screen. Fixed: the notes height was fixed when the dialog opened, so long notes could be clipped after the window shrank. It now refits on `XamlRoot.Changed`, like the Feedback dialog |
| Light / dark system theme | the dialog keeps the app's dark brand surface ([design/windows.md](../../design/windows.md)); 0 Axe errors |
| Desert, Night sky | system colours: window background and text, outlined dialog and notes, and Dismiss in Highlight with a text backplate; 0 Axe errors |
| Text 200% | the title, headings and bullets wrap and Dismiss grows; 0 Axe errors at compact and medium |
| Display 100% / 150% (and the host's 300%) | layout identical in epx; 0 Axe errors |
| Keyboard | the dialog opens with focus on the notes (visible focus rectangle), and Down scrolls them. Tab moves to Dismiss and Shift+Tab back; Enter or Esc dismisses. After the Settings replay, focus returns to the row (`kb-whats-new-dismiss`, `kb-whats-new-replay` at C/M/W). Fixed: the notes were not a tab stop, so the keyboard could not scroll long notes (Licenses and Privacy Policy had the same fix in #215) |

Narrator: "What's New · <version>" dialog, then the notes list (named after the title), the version heading (level 2), the category headings when present (level 3), then each bullet's text (the bullet glyph is Raw), and the Dismiss button. Fixed: Dismiss and the headings had no automation ID.

Deliberate deviations from the winui-design/code-review skills:
- A modal `ContentDialog`, not a `TeachingTip` or `InfoBar`: the spec makes What's New a modal that shares the first-run dialog slot.
- The dark-only theme ([design/windows.md](../../design/windows.md)).
- English literals (no `.resw` yet).
- Notes built in code from bounded data (≤ 20 entries × 40 bullets), not a data template.
