# Service status — Windows notes

> **What:** the Windows port of the shared failed-read status ([spec.md](spec.md)). **Read when:** showing a failed public read on a Windows page, or changing `windows/Festival.App/Controls/ServiceStatusView*`, `ServiceStatusInline*` or `Festival.Core/ViewModels/ServiceStatusViewModel.cs`.

- Model: `ServiceStatusViewModel` (unit-tested) turns a read error into the [issue vocabulary](spec.md#issue-vocabulary), runs the scrape-freeze countdown (`CountdownText` `m:ss`, `CountdownAnnouncement` "Trying again automatically in N seconds", `HasCountdown` only while a freeze counts down) and doubles consecutive waits up to 300 s. `Report` starts the countdown synchronously, so a readout taken right after it is deterministic.
- Full page: `ServiceStatusView` is an `FSTCardStyle` card (max 480 epx, centred). Heading `SubtitleTextBlockStyle` at heading level 2, message, countdown `BodyStrongTextBlockStyle`, then an accent Retry ("Retry" / "Retry Now", `MinHeight` = `FSTMinTargetSize` 40 epx). The countdown is **collapsed** unless `HasCountdown`, so other states have no blank line above Retry. It announces heading + message once per newly shown issue (`ScreenReader.Announce`, a UIA notification) and not on each tick. Under a contrast theme the accent Retry is HighlightText on Highlight, so it sets `HighContrastAdjustment="None"` (otherwise WinUI paints a Window backplate box behind the label; precedent `LeaderboardEntryRow`).
- Inline: `ServiceStatusInline` is the one section row (Leaderboards instrument cards and Spotlight, Song Detail history / instrument / band previews, Band Detail history and songs, Rivals sections). Title `BodyStrongTextBlockStyle`, message, the same collapsed countdown and a standard-button Retry at 40 epx. It is silent (spec: a page of failing sections must not flood Narrator); its UIA peer is a `Group` named by `AutomationProperties.Name`, else the status title. `IsCentered` centres text and Retry (Song Detail history). Hosts wrap it in `FSTCardStyle` where the section has no card of its own. `HitTargetMarkupTests.ServiceStatus_PagesUseTheSharedControls` fails if a page hand-writes a status row again. Before issue #233, nine copies had drifted: missing countdowns, 36 epx Retry, IDs on panels UIA skips.
- IDs: full page `<IdPrefix>.title|.countdown|.retry` (default `fst.service-status`; only the control lab changes it). Inline: the row is `<IdPrefix>` (default `fst.service-status.inline`), with `.title|.countdown|.retry`. `TitleAutomationId` / `RetryAutomationId` keep a page's existing IDs (`fst.history.error` / `fst.history.retry`, Spotlight `<prefix>.retry`, Band preview `RetryAutomationId`).
- Design (`winui-design`): `winapp find-ui` lists `InfoBar` for "app-wide status messages that remain visible until dismissed". These are placeholder content for one page or section, with a Retry action and no dismiss, so they stay cards. That is a deliberate deviation, and the web and Apple ports use the same card. The app is dark-only (`RequestedTheme="Dark"`, [design/windows.md](../../design/windows.md)). Windows draws no pulsing symbol and does not animate the count, so Reduce Motion has nothing to remove.
- Control lab: `FST_DEBUG_CONTROL_LAB=service-status` (or `--control-lab service-status`) shows every state with a fake reload. Each state sits in an `AccessibleGroup` named by its section title, so the lab's same-named Retry siblings stay unique for Axe. Each has a readout `fst.service-status.<state>.value` ("Reloads: N, next wait: S s" / "Reloads: N, no automatic retry"). Section prefixes: `fst.service-status.<countdown|retrying|unavailable|offline|syncing|not-found|other|inline|inline-offline>`.

## Validation (issue #233)

Commands:
- `python tools/windows/ui_journey.py tools/windows/journeys/service-status.json`: every state at wide and compact. It checks each state's title, message, countdown visibility and Retry, then tests Retry Now (resets to 240 s, then 300 s cap inline), a manual Retry, and backoff: Retry-After 2 reaches "Reloads: 4, next wait: 32 s" and "Reloads: 5, next wait: 64 s".
- `python tools/windows/a11y_matrix.py --pages tools/windows/journeys/a11y-service-status.json --scan --tabs 9 --mode <mode>`: lab pages `service-status-lab`, `-errors` and `-inline`.

These states need fixtures: the live public service cannot be made to freeze, fail or 404 on demand. Host pages were re-run through their own fixture journeys.
