# CHOpt Paths — Android notes

> **What:** the Android Paths sheet: selection, loading, image/text rendering and settings it reads. **Read when:** changing `ui/songdetail/SongPathsSheet.kt`, `presentation/songs/SongPathsViewModel.kt` or `data/paths/`. Behavior: [spec.md](spec.md).

- Opens from Song Detail's **Paths** button as a full-height `ModalBottomSheet` (`fst.song-detail.paths`, below the status bar via `festivalSheetTop`): modal, so the page can't be used behind it and focus returns on close. Layout (web `PathsModal`, operator 6.27): a "Paths" header, the image/table filling the sheet, and the web's bottom control row (`fst.paths.selectors`): frosted instrument-icon, difficulty and view buttons (`fst.paths.{instrument,difficulty,display}.open`), each opening its panel above the row: the shared Instrument Selector (required, `fst.paths.instrument.<wireId>`), a 2×2 difficulty grid and Image/Text (`fst.paths.difficulty.<label>`, `fst.paths.display.<label>`, purple when chosen). When one row cannot fit the widest difficulty label (`controlRowFits`: about 300 dp at 100% text, e.g. a 320 dp phone), the difficulty button takes its own line above the two icon buttons (`fst.paths.selectors.stacked`; issue #130: "Expert" wrapped to "Expe / rt").
- Each opening: first path chart (visible, charted, not Karaoke — `PathCapability.menuInstruments`), **Expert**, and the saved `pathDefaultView`. The view model is keyed per song and outlives the sheet (rotation keeps the selection), so `SongDetailRoute` counts openings in a saveable `pathsOpening` and calls `SongPathsViewModel.beginOpening(opening, settings.pathDefaultView)` synchronously before the sheet reads its state: a new opening resets chart, difficulty and view and reloads; the same opening (recomposition, rotation) is a no-op. Before issue #164, reopening Paths on the same song kept the previous opening's chart and view and ignored a default changed in Settings since.
- Reads `GET /api/paths/{song}/{chart}/{difficulty}` (PNG) or `/data` (schema-2 JSON) with `generationId` = catalogue `pathArtifactGenerationId`, through the shared pinned gate. PNG IHDR is bounded before decoding (`PathImageValidation`); JSON is validated (`SongPathData.validate`).
- `SongPathsViewModel` cancels the older request and uses a revision counter, so an old reply never paints; 404 → "No … path has been generated" (`fst.paths.not-generated`), other failures → inline service status with Retry.
- Image: decoded off the main thread with `inSampleSize` (≤ 2048 px wide, ≤ 16 MP), fills the width and scrolls vertically; 100–300% zoom buttons float over its top-right corner with horizontal scroll (no pinch conflict with the sheet). The bitmap is decoded while the spinner is still up (`decodeImage`), so the chart fades in already drawn.
- Switching (issue #70, web `PathsModal`): changing instrument, difficulty or Image/Text fades the old content out (300 ms, `PathSwapPhase.ContentOut`), fades the spinner in and holds it at least 400 ms for Image / 500 ms for Text (`PathSwapTiming`), fades it out (300 ms), then fades the new content in. The fades use the web's `ease` curve (Compose `Ease`; linear before issue #177). The text table reveals by its rows instead: the container snaps in, and each activation card runs the shared `festivalFadeIn` (400 ms `fadeInUp`, 12 dp drift) `PathSwapTiming.rowStagger(i)` = i × 60 ms later (web `PathDataTable` `textStagger`, `STAGGER_ROW_MS`; issue #177). It still fades out as a whole. The fetch runs during the fade-out; `state.shown` keeps the old labels on screen until the commit. A switch made during the spinner keeps the spinner (no extra fade), and a revision check means only the latest selection is ever shown. Text→text also fades (the web hard-cuts; the issue asks for the fade). Reduce Motion: no waits, minimum spinner or row stagger; alpha snaps. A polite live region (`fst.paths.status`) announces "Loading X Y path" and then what loaded (image, N activations, not generated or unavailable).
- Text (web `PathDataTable`, 6.27): no path summary or max-score line; one frosted card per activation. Phones: ACTIVATION (five 22 dp fret pills, active in the web fret colours, inactive muted with a border), BEAT / TIME `mm:ss:mmm` / SCORE, then OVERDRIVE % as an amber bar with the rounded percent. Panes ≥ 600 dp **in 100%-text dp** (`usesPathGrid(width, fontScale)`: width ÷ font scale): the desktop grid in the Settings column order (`pathColumnOrder`) under an uppercase header. Below that, cards (issue #130: a 640 dp landscape sheet at 200% used the five-column grid and clipped "187.", "01:34:"). At large text (`isLargeText()`, ≥ 1.3×) BEAT, TIME and SCORE stack one per line and values may wrap (`oneLineUnlessLarge()`); three weighted columns clipped "01:34:534" to "01:34:53" at 200% on a phone. The path instruction text is not shown (web), but each card is one TalkBack stop whose sentence includes it.
- Book posture: on a separating hinge, `FestivalModalSheet` keeps the **whole** sheet on one side ([design/android.md](../../design/android.md) sheets, `SheetHinge`, issue #125): on a half-open book fold it fills the leading half (~426 dp), so the path, status, spinner, control row, panels and drag handle all sit before the hinge and nothing straddles it (M3 foldables: "Never place interactive content or critical information across the hinge area"). The grid/cards choice uses that half's width (cards), and the half still fits one control row. Issue #130 first split the sheet itself across the hinge (path in the start pane, controls in a ~288 dp end pane, `fst.paths.hinge-split`). That was built before #125 merged. Once both were on master the sheet no longer spanned the hinge, the in-sheet split could never trigger, and its Robolectric test failed `android-unit`, so issue #289 removed it. Large text and TalkBack behave the same: the sheet still stays on one side.
- Karaoke warning (Karaoke visible and not permanently dismissed): a native `AlertDialog` ("Some Instruments Unavailable" / "Karaoke is not available for path visualization yet."); **OK** hides it for this opening, **Don't Show Again** sets `pathUnavailableWarningDismissed` via `SettingsRepository.update`.
- Swipe to dismiss ([modal-shell](../../patterns/modal-shell.md) R3; issues #96, #192): the sheet relies on `FestivalModalSheet`'s Material `ModalBottomSheet` gestures, so a downward drag on the header, the image or the text table closes it. The image and table scroll inside the sheet through nested scroll: when either is scrolled down, a downward drag first scrolls it back to the top, and only then pulls the sheet. A quick fling can do both in one gesture. Zoom uses buttons only (no pinch), so no gesture competes with the swipe. Do not set `sheetGesturesEnabled = false` or consume vertical drags in the sheet body: the swipe tests fail if you do.
- IDs: `fst.paths.{image,table,table.header,zoom,zoom-in,zoom-out,loading,status,error,not-generated,karaoke-warning,warning.ok,warning.never,close}`, `fst.paths.row.<n>`, `fst.paths.fret.<colour>.<on|off>`.

Open: column reordering from inside the sheet (Settings owns it; the sheet follows `pathColumnOrder`).

The half-open rows above predate #125 on master. Since issue #289 (2026-10-04), the whole sheet sits in the leading half at both font scales, and there is no in-sheet split. `SongPathsSheetUiTest` checks that every row, control, option, image and zoom button ends before the hinge. Accessibility there (issue #384): `SongPathsSheetUiTest#halfOpenBookPostureKeepsPathAndControlsOffTheHinge` (100%) and `#halfOpenAtLargeTextKeepsTheSheetOffTheHinge` (200%, CI `android-unit`) check that the "Paths" heading, the labelled 48 dp Close button, the first card's activation description, the three labelled 48 dp `Button` controls ("Collapsed"/"Expanded") and the open difficulty panel's four 48 dp `RadioButton` options (Expert selected) sit before the hinge, in reading order heading → Close → card → controls (Difficulty first when the row stacks). The connected `SongPathsDeviceTest#halfOpenSheetStaysOnOneSideAndReadsInOrderAtEveryTextSize` (FST_Book_Fold half-open) repeats this at 100% and 200% with ATF, no clipped text, the TalkBack reading order, Easy → Expert between the cards and the controls in the difficulty panel, and a card that grows at 200%.

Touch targets: close, zoom and carousel buttons are 48 dp, the control buttons 52 dp tall, and the option cells and warning buttons 48 dp. Contrast: text passes 4.5:1 (lowest: muted text on the frosted control at 5.9:1, and white on the purple choice at 5.7:1). The active fret pills pass 3:1 against the card (lowest: red at 4.9:1). Inactive fret slots keep the web's subtle border (1.3:1) as placeholders; the coloured active pills and each card's spoken sentence carry the activation.

Material 3 review (`material-3` skill, Compose guidance):

- The controls follow the guidance: modal bottom sheet with drag handle and close; `AlertDialog` for the Karaoke warning; 48 dp minimum touch targets; the whole sheet kept to one side of a separating hinge (foldables: "Never place interactive content or critical information across the hinge area").
- Deliberate deviations:
  - Dark-only brand theme and frosted product surfaces ([android.md](../../platforms/android.md)).
  - A 640 dp-capped bottom sheet rather than a side sheet on expanded windows (web `PathsModal` parity; the sheet keeps the image full height).
  - Option panels stay open after a choice and close on reselect (web).
  - On narrow panes, the stacked control row reads difficulty before instrument and view.

Tests: `SongPathsSheetUiTest` (Robolectric, every reachable state: image/text loading and loaded, missing, offline, instrument and difficulty switch, warning, zoom, saved column order, large text, narrow pane, half-open and flat folds) and the connected `SongPathsDeviceTest`. Motion is checked frame by frame from drawn pixels with the test clock paused: `imageSwitchFadesOnTheWebEaseCurve` samples the image fade-in and the fade-out on a difficulty switch halfway through (CSS `ease` ≈80%; it fails for linear easing), `textRowsStaggerInAfterTheSpinnerLikeWebTextStagger` the 60 ms row stagger and `reducedMotionShowsTextRowsWithoutStagger` the instant reduced-motion reveal. Issue #164: `settings/PathDefaultViewUiTest#everyPathsOpeningStartsAtTheSavedDefault`, `SongDetailAndShopTest#pathsNewOpeningResetsToTheSavedDefault` and the connected `PathDefaultViewDeviceTest#savedTextDefaultOpensEveryPathsSheetAsTheTable`. `TextLayoutResult.hasVisualOverflow` from semantics misreports wrap-content `Text` (it re-lays out at the parent's max width). The device test therefore compares each line and the paragraph against the node size.

## Validation (issue #192, 2026-10-06): swipe to dismiss

This validates #96 on Android. It ran on the live public service (keyless public HTTPS, no profile selected) with the debug APK, `tools/android/device.py drive` and `FST_DEBUG_STILL_BACKGROUND=1`, on "24K Magic" (`song:55fb0157-…`), at animator scale 0 unless noted. Each run opened Paths (Karaoke warning, then OK) and swiped down from mid-sheet to the bottom edge. It did this once in Image mode (image at the top), once in Text mode and once from the header. The UIAutomator tree afterwards had to show the sheet gone and Song Detail back. Nothing failed, and no app code changed.

Tests (issue #192): Robolectric `SongPathsSheetUiTest` covers `swipeDownOnTheTextTableDismisses`, `swipeDownOnTheImageDismisses` and `swipeDownOnTheHeaderDismisses`. `zoomedImageScrolledDownReturnsToTheTopBeforeDismissing` checks that panning the zoomed image leaves the sheet open and that a later swipe dismisses it. As a negative control, all four Robolectric swipe tests fail with `sheetGesturesEnabled = false`.
