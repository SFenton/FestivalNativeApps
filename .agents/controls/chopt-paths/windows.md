# CHOpt Paths — Windows notes

> **What:** the Windows Paths dialog. **Read when:** changing `windows/Festival.App/Controls/SongPathsView*` or `SongPathsViewModel`. Behavior and wire: [spec.md](spec.md).

- Opened from Song Detail's accent **Paths** button as a modal `ContentDialog` (`fst.paths`), `FullSizeDesired`, max width `min(1200, window − 48)`; the dialog contains and restores focus (the web dialog doesn't). Esc/Close dismiss and cancel any in-flight read.
- Each opening resets to the first visible charted path instrument (Karaoke excluded), **Expert**, and Settings' `PathDefaultView`. Wide (≥ 900 epx of dialog content): the web **Instrument Selector** (`Controls/InstrumentSelector`, `Required`, `CompactMode.Never`, Karaoke hidden; `fst.paths.instrument.<Solo_X>`) centred above difficulty and Image/Text `RadioButtons`. Below 900 epx the chart fills the sheet and one bottom row holds an instrument toggle (icon + chevron, `fst.paths.instrument.compact`) plus difficulty/display `ComboBox`es (`fst.paths.{difficulty,display}.compact`); the toggle opens an auto-compact Instrument Selector above the row (`fst.paths.instrument.compact-picker.*`) that closes on a pick, like the web's accordion. The content view gets an explicit width (dialog width − 48): a `ContentDialog` sizes to its content, and without it the sheet collapsed to its 548 epx minimum.
- Reads: `GetPathImageAsync` / `GetPathDataAsync` with the catalogue's `pathArtifactGenerationId`; a revision counter drops any response older than the current selection. HTTP 404 shows "No path has been generated…" (`fst.paths.empty`), not an error; other failures use the service-status view with Retry.
- Image: PNG header/size validated in Core before decode (≤ 8 MB, ≤ 8192 × 30000, ≤ 24 MP); decoded at ≤ 4096 px wide; fit to width, native pinch / Ctrl+wheel zoom (1–3×) plus Zoom out/in buttons.
- Centring (issue #87): `PathImage` is `HorizontalAlignment="Center"` in `ImageScroller` and its fit width is `SongPathsViewModel.FitImageWidth` (full viewport, never upscaled past its pixel width), so the margins are equal at fit zoom and while a zoomed chart is still narrower than the sheet. The old `Left` alignment + `viewport − 16` left a narrow chart flush left (UIA: image x = scroller x). The Fluent auto-hiding (conscious) scroll bars stay: they overlay the content, collapse to a thin panning indicator and hide when idle, matching every other Windows scroll area; hiding them would leave mouse users without horizontal panning when zoomed. Verified: fit-zoom margins equal within 1 epx at compact/medium/wide and after Image↔Text, difficulty and instrument switches; UIA `ScrollPattern` still scrolls vertically and (compact, 225%) horizontally.
- Switching (issue #70, web `PathsModal`): `SongPathsViewModel.Phase` (`PathSwapPhase`) sequences a change of instrument, difficulty or Image/Text. `ChartContent` fades out (300 ms `ScalarTransition` on `ContentOpacity`), the `ProgressRing` (`fst.paths.loading`) fades in and stays at least 400 ms for Image / 500 ms for Text (`PathSwapTiming`), fades out, then the new chart or table fades in. The fetch and the PNG decode (`PrepareImageAsync`) run during the fade/spinner, and the presented instrument/difficulty/view stay on the old values until the commit, so a stale chart never flashes and rapid switches settle on the latest selection. Text→text also fades (the web hard-cuts). Without motion (`AnimateSwaps` = `Motion.Allowed` false) there are no transitions, waits or minimum spinner. Narrator: `Announced` raises "Loading X Y path" and then a summary through `ScreenReader.Announce` (not on the first opening, which the dialog title covers; failures are announced by the service-status view).
- Text (web `PathDataTable`): **no path summary or max score**; a muted uppercase column header row (Activation, Beat, Time, Overdrive %, Score) in Settings' `PathColumnOrder`, then one card per activation with the web grid widths (note minmax(190, 1fr), beat 80, time 110, Overdrive 1fr, score 100): five 22 epx fret pills (web `FRET_COLORS`, inactive `#223047`), beat, `mm:ss:SSS`, an 8 epx amber (`#F5A623`) Overdrive bar with its clamped %, score; unknown values are a muted "—". Below 640 epx of table width cards stack like the web's mobile rows (note, then beat/time/score, then Overdrive, each under a caption) and the header hides. Rows stagger in (`FadeIn.Stagger`). Each card is one Narrator item (`PathActivationRow.AccessibleName`). Native addition: an "Open" label after the pills when the anchor chord has an open note (the web shows nothing). Header drag-to-reorder is not ported (Settings owns the order).
- **Some Instruments Unavailable** (gap 17, batch 6.27): a native `ContentDialog` (`fst.paths.warning`) shown **before** the Paths dialog (WinUI shows one `ContentDialog` at a time) on the **first Paths opening of each app session** while Karaoke is visible (`FestivalSession.PathNoticeShown`): **OK** (default) or **Don't show again** (persists `PathUnavailableWarningDismissed`). `SongPathsView.ShowAsync` owns both dialogs; Song Detail only calls it.
