# CHOpt Paths — Windows notes

> **What:** the Windows Paths dialog. **Read when:** changing `windows/Festival.App/Controls/SongPathsView*` or `SongPathsViewModel`. Behavior and wire: [spec.md](spec.md).

- Opened from Song Detail's accent **Paths** button as a modal `ContentDialog` (`fst.paths`), `FullSizeDesired`, width `max(320, min(1200, window − 24))`; the dialog contains and restores focus (the web dialog doesn't). Esc/Close dismiss and cancel any in-flight read.
- Each opening resets to the first visible charted path instrument (Karaoke excluded), **Expert**, and Settings' `PathDefaultView`. Wide (≥ 900 epx of dialog content): the web **Instrument Selector** (`Controls/InstrumentSelector`, `Required`, `CompactMode.Never`, Karaoke hidden; `fst.paths.instrument.<Solo_X>`) centred above difficulty and Image/Text `RadioButtons`. Below 900 epx the chart fills the sheet above three native `ComboBox`es of equal height: instrument (`fst.paths.instrument.compact`, Narrator name "Instrument"), difficulty and display (`fst.paths.{difficulty,display}.compact`). Since issue #280 each box is as wide as its longest option (`PathSelectorLayout.BoxWidth`: options measured at the current text scale plus the template's 12 epx padding and 38 epx glyph column; minimums 120 instrument, 96 display), so no label clips and a box never changes width with the selection. When the three don't fit on one line (`PathSelectorLayout.Stacks`) the instrument box spans the first line and difficulty and display share the second; Tab order stays instrument, difficulty, display. The instrument box lists `SongPathsViewModel.InstrumentOptions` (`PathInstrumentOption`: 24 epx icon + name for every item; `ToString()` is the name, so Narrator reads "Instrument, combo box, Bass") bound to `InstrumentIndex`. Issue #88 replaced the earlier icon toggle + accordion (web mobile) with this Fluent ComboBox to match its siblings: a flat list of mutually exclusive options. The wide layout keeps the icon selector because its siblings there are `RadioButtons`. The content view gets an explicit width, the dialog width less its theme chrome (`ContentDialogPadding` + `ContentDialogBorderWidth`, 2 × (24 + 1) = 50 epx): a `ContentDialog` sizes to its content, and without it the sheet collapsed to its 548 epx minimum. Until issue #269 it subtracted only the padding (48), so the view was 2 epx wider than the content box and the compact row's Display box lost its right border and focus ring.
- Reads: `GetPathImageAsync` / `GetPathDataAsync` with the catalogue's `pathArtifactGenerationId`; a revision counter drops any response older than the current selection. HTTP 404 shows "No path has been generated…" (`fst.paths.empty`), not an error; other failures use the service-status view with Retry.
- Image: PNG header/size validated in Core before decode (≤ 8 MB, ≤ 8192 × 30000, ≤ 24 MP); decoded at ≤ 4096 px wide; fit to width, native pinch / Ctrl+wheel zoom (1–3×) plus Zoom out/in buttons, each at least 40 × 40 epx (`FSTMinTargetSize`, issue #430; a bare icon `Button` is 38 × 27). The scroller's reported zoom goes through `SongPathsViewModel.NormalizeZoom` (clamped, snapped onto 1×/3× within 0.005) so the buttons disable exactly when the label reads 100%/300% (issue #279).
- Centring (issue #87): `PathImage` is `HorizontalAlignment="Center"` in `ImageScroller` and its fit width is `SongPathsViewModel.FitImageWidth` (full viewport, never upscaled past its pixel width), so the margins are equal at fit zoom and while a zoomed chart is still narrower than the sheet. The old `Left` alignment + `viewport − 16` left a narrow chart flush left (UIA: image x = scroller x). Scroll bars (issue #279, owner acceptance "no scroll bar or indicator shows beside the path image while it is scrolled"): `ImageScroller` has `Horizontal/VerticalScrollBarVisibility="Hidden"` with both scroll modes `Auto` and `ZoomMode="Enabled"`, so wheel, Ctrl+wheel, pinch, touch, touchpad and arrow/Page keys still scroll and zoom while no bar or conscious indicator is drawn. The one exception mirrors the macOS Paths precedent ([macos.md](macos.md): hidden indicators that still show when System Settings asks to always show scroll bars): when Windows' Settings › Accessibility › Visual effects › **Always show scrollbars** is on (`UISettings.AutoHideScrollBars` false), `ApplyScrollBars` switches them to `Auto` (`SongPathsViewModel.ShowChartScrollBars`, followed live through `AutoHideScrollBarsChanged`), because the user asked the system for visible bars and a mouse user without a tilt wheel may need one to pan a zoomed chart sideways. Never set the bars back to `Auto` unconditionally: #87's earlier "auto-hiding overlay" exception still drew the indicator while scrolling. `assertnoscrollbar:id=fst.paths.image-scroller` fails if the scroller holds any `ScrollBar` part (an `Auto` bar stays in the UIA tree, drawn as soon as pointer input scrolls; a `Hidden` one is collapsed out of it). Verified: fit-zoom margins equal within 1 epx at compact/medium/wide and after Image↔Text, difficulty and instrument switches; UIA `ScrollPattern` still scrolls vertically and (compact, 225%) horizontally.
- Switching (issue #70, web `PathsModal`): `SongPathsViewModel.Phase` (`PathSwapPhase`) sequences a change of instrument, difficulty or Image/Text. `ChartContent` fades out (300 ms `ScalarTransition` on `ContentOpacity`), the `ProgressRing` (`fst.paths.loading`) fades in and stays at least 400 ms for Image / 500 ms for Text (`PathSwapTiming`), fades out, then the new chart or table fades in. The fetch and the PNG decode (`PrepareImageAsync`) run during the fade/spinner, and the presented instrument/difficulty/view stay on the old values until the commit, so a stale chart never flashes and rapid switches settle on the latest selection. Text→text also fades (the web hard-cuts). Without motion (`AnimateSwaps` = `Motion.Allowed` false) there are no transitions, waits or minimum spinner. Narrator: `Announced` raises "Loading X Y path" and then a summary ("X Y path image loaded" / "X Y path loaded, N activations") through `ScreenReader.Announce` (not on the first opening, which the dialog title covers; failures are announced by the service-status view). The view passes itself, a `UserControl` without an automation peer, so this was silent until issue #269 made `Announce` raise from the nearest ancestor peer; journeys assert both announcements. CI (issue #430): `windows-ui` runs `journeys/a11y-paths-swap.json` (`paths-swap[-display|-keyboard|-keyboard-wide|-motion-reduced|-motion-system]`) at normal, 225% text and Animation effects off: mid-swap the old chart leaves UIA, the spinner reads "Busy Loading path, ProgressRing" between the selectors and Close, the selectors stay enabled with the new value, both announcements are heard, keyboard switches keep focus on the selector, and the zoom buttons, selectors and Close are 40 epx targets.
- Text (web `PathDataTable`): **no path summary or max score**; a muted uppercase column header row (Activation, Beat, Time, Overdrive %, Score) in Settings' `PathColumnOrder`, then one card per activation with the web grid widths (note minmax(190, 1fr), beat 80, time 110, Overdrive 1fr, score 100; Core `PathTableLayout`): five 22 epx fret pills (web `FRET_COLORS`, inactive `#223047`), beat, `mm:ss:SSS`, an 8 epx amber (`#F5A623`) Overdrive bar with its clamped %, score; unknown values are a muted "—". Since issue #223 the fixed columns and the Overdrive label grow with Windows text size (`TextScaling.ScaledWidth`), and the stack breakpoint grows by the same amount (640 epx at 100%, 962 at 200%), so "00:06:250" and six-digit scores never clip. Below the breakpoint cards stack like the web's mobile rows (note, then beat/time/score, then Overdrive, each under a caption) and the header hides. Colours are `FSTPath*` theme brushes (`Themes/Styles.xaml`): contrast themes map captions to WindowText, lit pills to Highlight with a WindowText ring, unlit pills to Window with a GrayText ring and the bar to Highlight on GrayText ([contrast roles](../../design/windows.md)); the table rebuilds on `ContrastTheme.Changed`, so a theme switched while the dialog is open applies at once. `ShowAsync` subscribes for the dialog's lifetime: inside a `ContentDialog` the view gets spurious `Unloaded` events while still shown, so Loaded/Unloaded subscriptions were dropped at once. Rows stagger in (`FadeIn.Stagger`). Each card is one Narrator item (`PathActivationRow.AccessibleName`). Native addition: an "Open" label after the pills when the anchor chord has an open note (the web shows nothing). Header drag-to-reorder is not ported (Settings owns the order).
- Keyboard (issue #223): the chart (`fst.paths.image-scroller`, "Path chart") and the table (`fst.paths.table`, "Path table") scrollers are Tab stops, so arrow keys, Page Up/Down and Home/End scroll a long chart or table without a mouse. Tab order (the spec's order; the dialog's only command, Close, is its footer, so it comes last): instrument (wide: each instrument button), difficulty, display, Zoom out/in (Image, when enabled), chart or table, Close, then back to the instrument. Opening focuses the first instrument control. The selectors precede `ChartArea` in the XAML at every width (the compact row is drawn below the chart but declared before it), which is what keeps this order; `paths-focus-order[-text][-wide]` assert every stop and fail on a reorder.
- **Some Instruments Unavailable** (gap 17, batch 6.27): a native `ContentDialog` (`fst.paths.warning`) shown **before** the Paths dialog (WinUI shows one `ContentDialog` at a time) on the **first Paths opening of each app session** while Karaoke is visible (`FestivalSession.PathNoticeShown`): **OK** (default) or **Don't show again** (persists `PathUnavailableWarningDismissed`). `SongPathsView.ShowAsync` owns both dialogs; Song Detail only calls it.

## Design decisions (winui-design, issue #223)

Checked 2026-10-04 with the winui-design and winui-code-review skills (`winapp find-ui "data table"` returns only ListView samples; `winapp find-api UISettings.TextScaleFactor`).
- The text view stays a stack of cards, not a `ListView` grid: each activation is one Narrator item, and the web's card rows are the reference. The skill's "hard-coded color literals → `{ThemeResource}` brushes by semantic name" and "only `SystemColor*Brush` resources inside an HC dictionary" drove the `FSTPath*` brushes. The fret hues stay web data colours outside contrast themes; the open note is also a label, so colour is never the only cue.
- The app is dark-only by design ([design/windows.md](../../design/windows.md)): a light system theme renders the same dark dialog.
- The accent **Close** is the shared `FestivalDialog` button. Under Desert its label used to sit on a white box; since issue #239 it's HighlightText on Highlight in every dialog (`DialogChrome.CommandLabelsWithoutBackplate`).
- Live text-size changes apply on the next opening, like every page (`TextScaleLayout.Factor` is read once per launch).

## Design decisions (winui-design, issue #280)

Checked 2026-10-06 with the winui-design and winui-code-review skills. Agent decisions; the owner may override with `/choose`.
- **Compact selectors reflow instead of clipping.** Everlong's live list includes "Pro Drums + Cymbals"; the instrument box had `MaxWidth` 200 and a `StackPanel` item template (ellipsis never applies), so the label clipped mid-word ("Pro Drums + Cymb") at 100% text and lost "+ Cymbals" at 200%, and the box resized whenever the selection changed. Options were (a) keep one row and trim with an ellipsis, (b) let the box grow past the row, (c) size each box to its longest option and reflow difficulty and display onto a second line when needed. Chose (c): the skill's layout review says to "pick the lightest change… Resize… Reflow: sequence can wrap", and WCAG 1.4.4 needs text resized to 200% without loss of content. The item template is now a `Grid` (icon `Auto`, name `*`), so trimming remains a last resort on the narrowest windows when stacked.
- **No visible `Header` on the compact boxes.** Their values (an instrument, a difficulty, Image/Text) are self-describing and the web shows no captions; the boxes keep their Narrator names (`AutomationProperties.Name`). Headers would cost a line under the chart in the compact layout.
- **Wide layout keeps the web icon selector**, since its siblings are `RadioButtons` (issue #88).
