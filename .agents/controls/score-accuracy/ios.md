# Score accuracy — iPhone notes

> **What:** the SwiftUI badge implementation and its layout constraints. **Read when:** changing `SongLeaderboardEntryRow` or the accuracy badge. Spec: [spec.md](spec.md); iPad-only lessons: [ipados.md](ipados.md).

- Full combo uses the web's gold italic text and outline, skewed at ordinary text sizes; other scores use white text on the graded tint.
- Ordinary text sizes reserve one fixed column for graded, FC and missing rows: **80pt text / 96pt outer × 24pt**; the missing-accuracy slot is invisible and hidden from accessibility, so equal-digit scores align within 1pt. Accessibility sizes stack values with unconstrained width.
- Size the badge with an explicit scaled `frame` — **never `padding` inside it** (see iPad layout loop).
- Full Solo List: `.accessibilityElement(children: .contain)` keeps the badge's `fst.score.accuracy.*` ID beside the row ID. Detail preview rows still inherit `fst.song-detail.preview-row.*`; a separate child ID/focus is pending.
- **Band cards:** Song Detail previews and the full song band board show only the percentage, including at accessibility sizes (`SongBandAccuracyBadge` / `UKAccuracyBadgeView.band`). The badge grows with Dynamic Type without adding the spoken description as visible lines. The card's single button still speaks both full combo and accuracy. Selected-band spotlight rows keep the Solo row's badge rule. HIG [Typography](https://developer.apple.com/design/human-interface-guidelines/typography#Supporting-Dynamic-Type) (should): adapt layouts for all Dynamic Type sizes.
- Tests: `ScoreFormattingTests` (tint ramp), `scoreAccuracyBadgeRendersSourceStates` (five hosted states), `testSongDetailShowsTopScorePreviewAndFullChart` (non-FC vs FC labels and pixels in Detail and Solo), `testSoloScoresAtLargestTextSize`, `testBandCardShowsPercentAndSpeaksFullComboAtAX5`.
- Solo badges size wrapped descriptions to the allotted width and align the lines to the leading edge at accessibility text sizes; compact text stays centered. For AX5 captures, scroll the entire badge above the fixed pager before measuring actual fill, outline, text contrast and multiline alignment. Verify that every line paints, including the final percentage: a complete accessibility label and a hittable badge do not establish that. Verify pagination through the pager's `Page` accessibility value, not through a separately exposed text label.
- Separate from this badge: [score-metadata pills](../song-score-metadata/ios.md) use scaled horizontal insets; do not copy that padding here.
