# Songs Filter — iPhone notes

> **What:** the SwiftUI Filter sheet as built, layout lessons and open work. **Read when:** changing Songs filtering on iPhone (Lane S). Spec: [spec.md](spec.md).

- Entry points: `apple/Sources/FestivalCore/{SongGeneralFilter,SongShopFilter,SongPlayerScoreFilter}.swift`, `apple/Sources/FestivalUI/Features/Songs/SongsFilterSheet.swift`. `SongShopFilter.filtered` preserves input order; `FestivalSession.shopOffersById` comes only from the validated feed; one `SongShopPublicationPolicy` decision gates Filter, Shop Sort/grouping and row badges.
- Toolbar Filter for every viewer while saved filters decode (issue #77); its tint and accessibility value name active General choices ("Year filter", "Duration filter", "Item Shop filter", "Double Bass filter") and score checks.
- **General (#77):** `SongGeneralFilter` (excluded decades / minute buckets, `SongShopFilter` available/unavailable, Double Bass pair) is one bounded JSON value under `fst.songs.generalFilters` (≤4096 bytes, decades 0–9990 step 10, durations 0–10, unique; else the corrupt-filter Reset screen). Legacy `fst.songs.filterInShop` / `.filterLeavingTomorrow` migrate once to Available only and are removed on save. The sheet lists General first as separate Form sections, each a `DisclosureGroup` (`fst.songs.filter.{year,duration,shop,double-bass}` on the label; options `.shop-available`/`.shop-unavailable`, `.double-bass.{supported,unsupported}`, `.<year|duration>.<key>`; the heading is `fst.songs.filter.general`, shared with Android/Windows) that opens only while restricted (HIG Disclosure controls: "Hide details until relevant"); Year/Duration Select All / Clear All sit in the section header like the per-instrument buckets. Options come from the loaded catalogue (`decades(in:)`, `durationBuckets(in:)`). Item Shop shows only while Shop is visible and notes "Item Shop filters need matching public Songs and Shop data." when one category is off without a matching feed. Player sections stay gated on `selectedPlayer`; Reset Filters clears everything. iOS uses switches in list rows (HIG Toggles "Use the switch style only in a list row"); macOS: [macos.md](macos.md).
- The single-chart Instrument picker (previously its own always-visible toolbar `Menu` on Songs) is now part of this sheet's draft: `draftInstrument`/`appliedInstrument`, applied with the Shop and score checks as each changes (no Cancel/Apply since operator 2026-09-28; Done closes), matching web's `FilterDraft.instrumentFilter`. Shown only when a player is selected (`selectedPlayer`), since Filter itself only reaches mobile users with player/Shop data.
- **Percentile and Stars (Lane A3):** with a selected player and one instrument chosen, two disclosure sections follow the score checks: Percentile (No Score, Top 1%…Top 100%) and Stars (gold, 5…1 star images, No Score), each with Select All / Clear All (`fst.songs.filter.{percentile,stars}[.select-all|.clear-all|.<key>]`). They are part of `SongPlayerScoreFilter` (`excludedStars`/`excludedPercentiles`, web `starsFilter`/`percentileFilter` `false` entries), so they share its bounded decoding (unknown or duplicate keys → the corrupt-filter Reset screen), its pause rules, and its reset on player deselection. Buckets read the Songs instrument's score only (`SongStarsBucket`, `SongPercentileBucket`: first threshold ≥ `rank / totalEntries × 100`, 0 for no score or no rank) and apply only while Songs shows one visible instrument; without one the saved choice is kept but inert, like the web. Older saved filters (no bucket keys) decode unchanged and filters without buckets encode to the same bytes.
- **Profile change reset (#359):** `FestivalSession.deselectPlayer()` and a band→player `selectPlayer` apply the web rule (`SongSettingsReset.shouldReset`, Core) and `SongsPresetStore.resetForProfileChange` writes `SongsSavedState.resetForProfileChange()` (default General and score filters; Score/Percentile/Stars sort → Title A–Z) to the `@AppStorage` keys, then bumps `songSettingsResetRevision`, on which `FestivalRootView` and `MacRootView` clear the root-owned `songsInstrument`. Player-to-player keeps everything. Without a player `SongsScreen` shows no score-filter or player-sort notice (stale saved values are inert, like the web); the Filter Invalid Scores, hidden-chart, publication-mismatch and Shop notices are unchanged. HIG design-principles.md: "Keep visual and interaction behavior consistent so people learn quickly and can predict new interactions" (same reset as web and every Apple form factor). Tests: `SongSettingsResetTests`, `ProfileSelectionSessionTests.songSettingsResetOnlyWhenAProfileIsLeft`, `.bandToPlayerSwitchResetsSongSettings`; device `testPlayerScoreFilterSettingsPauseAndDeselectScope`.
- Sheet: opaque full-height system sheet; General sections + Instrument section (when a player is selected) + "Player Score and FC Filters" disclosure (expanded when a saved predicate exists); the shared `FestivalModal`'s system Close top-right (`fst.songs.filter.done` kept); Reset inside the Form (now also clears the instrument choice).
- Put the chart ID on the disclosure **label**, not the whole `DisclosureGroup` (iOS 26 replaced all nested toggle IDs). The iOS title and Form are separate vertical siblings so AX5 text scrolls in a clipped viewport, not behind Liquid Glass.
- At AX5, scroll the **Form itself** until Reset is fully above the footer.
- Tests: `SongGeneralFilterTests`, `songsGeneralFilterSheetPaintsChoicesWithoutAProfileAndLargeText`, hosted `filter-anonymous-*` scenarios, `shopSongFiltersMatchSourceAndRejectAbsentFeed`, `shopPublicationMatchPreservesValidatedEmptyWithoutMixingGenerations`, `songsPauseShopDerivedRowsAcrossFailedPublicationRollover`, `SongScoreBucketsTests`, device `testSelectedShopFilterAppliesLiveAndSurvivesRelaunch`, `testSelectedPlayerScoreFilterAppliesLiveAndSurvivesColdRelaunch`, `testSelectedShopFilterPausesAndRecoversAcrossShopStates`; pinned rollover fixture 8777 ([fixtures](../../testing/fixtures.md)).
- **Accessibility (#432, for #77).** Without a profile VoiceOver reads only General: the heading, its hint, each group as a disclosure named "<title>, <hint>" with its expanded state, its options as switches (checkboxes on the Mac) named for the choice, then Reset Filters. Select All / Clear All sit in the section header, which is read before the group, and every open group has the same pair, so their spoken names add the group ("Select All, Year", "Clear All, Duration"; per-instrument Season/Percentile/Stars/Intensity too) while the visible text stays the web's; Voice Control also answers to "Select All" (HIG Accessibility: "Label elements appropriately for Voice Control"). Tests: hosted `SongsFilterAccessibilityTests` (`apple-ci`: no-profile reading order and roles, restricted names/state/drawn order, accessibility press applies, General before player sections, narrow-width wrap), device `SongsFilterAccessibilityJourneyTests` (Filter Songs, or at large text the folded Sort and Filter menu's Filter…, named and 44 pt; every audit but Dynamic Type collapsed and with Year open; switches and Select All / Clear All at least 44x44 pt; at AX5 order, growth of the group labels and Item Shop texts, hints wrap, Hit region at the sheet's ends; Dynamic Type audited with the Shop hidden and Text clipped at the default size, see [accessibility open findings](../../testing/apple/accessibility.md#open-findings-not-waived)). Select All / Clear All fill 44x44 pt on iPhone and iPad like the section header's View All (HIG Accessibility: 44x44 pt default control size; the bare header text measured 60x18 pt); the Mac keeps borderless metrics. The journey also runs on iPad (`FestivalMobileIPadUITests`) and the folded iPhone Duo (`uitest --device duo`), where Sort and Filter Songs sit in the system vertical bar: that bar drops `accessibilityValue`, so they read their state in the label ("Filter Songs, No filters", [page-tools R17](../../patterns/page-tools-and-nav-chrome.md)), and Filter Songs, drawn 38 pt there, opens from every near-miss tap in a 44x44 pt square. On the folded Duo the sheet's Close sits in its own vertical bar beside the rows and the Form runs to the window edge; the audit reports a Year decade switch as Dynamic Type "partially unsupported", which passes only when that decade measures at least 1.35x taller at AX5 in the same test (`dynamic-type-grows` evidence). On iPad the audit also sees the dimmed Songs page around the form sheet: element-less Contrast and Element detection issues there are left to `IPadAccessibilityAuditTests` page `filter-sheet` (no profile), and a Contrast issue on text the sheet's edge cuts through passes only when a second Contrast audit, with that text scrolled whole into view, doesn't report it (`contrast-rendered`, scrolled into view first).
- Open: after a drawer Deselect the iPhone Filter/Sort dock stays unregistered until Songs reappears (also on `master`; UI tests call `reshowSongsDock`); season / threshold / intensity / band sections; Shop WebSocket; rapid transitions; other AX5 states; saved-Shop-sort + failed-Shop audit.
