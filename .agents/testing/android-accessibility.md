> **What:** the Android accessibility phase: tools, what was checked on which device, findings, fixes and open gaps. **Read when:** writing the ATF journey every Android UI change ships with ([strategy](strategy.md#accessibility-tests-with-every-change)), changing semantics, touch targets, colours, text sizes or multi-column layouts on Android, or re-running the TalkBack/ATF/large-text passes. Tooling: [android.md](android.md#accessibility-tooling).

Clipping checks: `TextLayoutResult.hasVisualOverflow` read through the `GetTextLayoutResult` semantics action reports overflow for any plain `Text` narrower than its parent allows: that path re-lays out the paragraph at the parent's max width and compares it with the node's size (issue #130: the zoom "100%"). It is reliable only for text that fills its width. Otherwise compare each line's width (`getLineRight − getLineLeft`) and `multiParagraph.height` with `size`, and check `isLineEllipsized` (`SongPathsDeviceTest.assertNoClippedText`).

Instant-under-Reduce-Motion checks (load-transition R6): hold the read that triggers the motion (`FakeTransport.beforeRespond` awaiting a `CompletableDeferred`), set `rule.mainClock.autoAdvance = false`, release it, step `advanceTimeByFrame()` until the new content composes, then allow only a few frames (`SongBandLeaderboardJourneyTest` allows 10) for the end state and assert that `advanceTimeBy(1_000)` leaves it unmoved. Read Compose semantics bounds while the clock is paused, not `UiAutomation` nodes, and restore `autoAdvance` in a `finally`. Mutation-check the test: forcing the animated path must fail it (#461).

(3) Flat → Top Songs → half open → Global on a two-lane window (`@HalfOpenFoldJourney`, so it runs in `android-fold`; it skips on one-lane windows, where the bug can't occur). Overview must stay before the hinge, with Lead beside it and read next. Each case was mutation-checked by reverting its #111 fix (`QuickLinks.needsReland`, `SelectedProfileStore.wasInterrupted`, `rememberProfileGridState`) and confirming the matching test fails. Results: 3 pass + 1 skip on FST_Phone, 4/4 on FST_Book_Fold unfolded with `fstRequireHinge=true`, and the CI fold run (`--posture half`, annotation filter) passes it. ## Reading order (TalkBack, verified)

Phone: top app bar (menu/Back, title, page actions, Search, Notifications, profile) → page content in visual order, headings marked → navigation bar tabs → floating toolbar page actions. Wide windows (passport, tri-fold, tablet): top app bar → rail (one group: menu, destinations, profile, Settings) → list pane → detail pane. Quick Links announce the current section. Songs bucket headings (Duration, Year and the other Quick Links sorts) are read in place, each before its own rows: a `talkback_walk.py` walk of Duration (FST_Phone, live service, issue #441) read "Under 1 Minute. Heading. In list. 743 items", its rows, then "1 to 2 minutes. Heading". `JourneyHarness.readingOrder` walks the raw tree, where a `LazyColumn` lists sticky headers after its items, unless the journey calls `publishTalkBackTree()` after launch: then it follows Compose's traversal links, TalkBack's order. `SongsBucketHeaderAccessibilityJourneyTest` checks both its stops' shown-top order and that published order; a pinned title is read before the partly hidden row beneath it (`rememberPinnedHeaderReadOrder`, #462). While the next heading pushes the pinned one out (issue #288; journeys added for #452 at the fade, at 200% text and with the hard edge that the app's Reduce Transparency, the app's Reduce Motion and the system's Remove animations each force alone), each heading stays one stop before its rows, the pushed heading is still read and both titles draw at full opacity; with the hard edge no row shows behind the pinned title; no defect was found. Sheets start at their title (or the drag handle) and end with Close/drag handle. Paged boards read rows → pinned "your rank" row → pager on every page, the player's own included ([leaderboard-row](../patterns/leaderboard-row.md) R5/R7; `SongLeaderboardJourneyTest`, `FullRankingsPinnedRowAccessibilityJourneyTest`). Rows the 40 dp footer ramp dims stay stops read before the pager, and no row's TalkBack bounds reach under the footer, pager-only boards included. A row peeking only a sliver above the footer (a Pixel 6 rests with one on Song Leaderboard) loses its text children to the list's clip, as at any list edge, so its stop reads unlabelled until scrolled in; journeys require a label only on rows showing at least half their height or the ramp's 40 dp, and check that a sliver row composes one ([scroll-edge](../patterns/scroll-edge.md) R7; `BoardFooterFadeAccessibilityJourneyTest`, #473; with no selected player, each in-app R7 setting and the pager's labels, 48 dp targets and polite page label: `BoardFooterFadeNoPlayerAccessibilityJourneyTest`, #462).
