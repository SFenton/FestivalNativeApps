# Windows testing

> **What:** Windows unit/coverage, UI-automation, accessibility and performance-test rules and commands. **Read when:** writing or running Windows tests or changing `windows/**`. Architecture, tooling and `uiwin.py`: [platforms/windows.md](../platforms/windows.md).

- Separate logic tests (testable view models) from XAML/UI automation; **95% / 90%** line coverage via Cobertura XML, which `tools/coverage_gate.py` parses and merges.
- Compare app/game impact in Release builds with representative workloads.
- Installed-PWA reference (Edge app, same window presets, video + measured animations): `tools/windows/pwa.py`; findings and gaps in [pwa-reference/](pwa-reference/README.md).

## Layers

| Layer | Where | Command |
|---|---|---|
| Logic + view models | `windows/Festival.Core.Tests` (xUnit, fake `HttpMessageHandler`, `FakeTimeProvider`) | `pwsh tools/windows/test.ps1` |
| Coverage | coverlet Cobertura → `windows/.artifacts/coverage/coverage.cobertura.xml`, gated by `tools/coverage_gate.py --language csharp` | `pwsh tools/windows/test.ps1 -Coverage` |
| Visual smoke | Screenshot of the running app | `pwsh tools/windows/screenshot.ps1 -Launch -Tab songs -Out …` |
| Perf | Release/AOT scenarios | `pwsh tools/windows/perf.ps1`, `bench.ps1` |

- `contracts/coverage-rules.json` classifies C# by folder: `windows/**/Data/*.cs` and `Domain/*.cs` are **logic (95%)**, `Views/*.cs` and `ViewModels/*.cs` are **UX (90%)**. Keep new Core files in those folders (flat) so the gate sees them.
- Fixtures: tests reuse `contracts/fixtures/{songs-demo,publication}.json`; manual fixture runs use `tools/mock_service.py` (`launch.ps1 -Fixture`). No production payloads in tests.
- View-model timing uses `TimeProvider`; tests advance `FakeTimeProvider` (search debounce, profile search, scrape-freeze countdown and backoff).
- XAML code-behind (`windows/Festival.App`) has no unit coverage; it is kept thin. UI automation (FlaUI/UIA) is not set up in this lane yet; the device-lab lane's `uiwin.py` drives the app by the `fst.*` AutomationIds.

## Desktop session

SSH runs in session 0 (no desktop). `_common.ps1` runs GUI work through a one-shot `schtasks /IT` task in the signed-in console session (no stored credentials), and every hop holds the shared FIFO `desktop` lock via `tools/windows/desktop_lock.py`, so it queues with `uiwin.py` and other lanes. From session 0 `Process.MainWindowHandle` is always 0, so window lookups happen inside that task. `PrintWindow(PW_RENDERFULLCONTENT)` captures the DirectComposition content; the capture process must be DPI-aware. From Git Bash, prefix route arguments with `MSYS_NO_PATHCONV=1` or `/songs/…` becomes a Windows path.

## UI automation

- **Proven on `sfenton-music`:** from SSH (session 0), UIA queries, pattern invocation, keyboard and mouse input, window resizing and window screenshots all work through the one-shot interactive task hop in `tools/windows/uiwin.py`. They need the operator logged on at the console. Do not configure autologon without separate authorization.
- Drive the app only through `uiwin.py` so lanes serialize on the desktop lock (≤300 s per hold). It shares the operator's real desktop, so keep holds short and always `close` what you launch.
- Locate elements by `AutomationProperties.AutomationId` from the `product.json` test-ID registry (`drive … invoke:id=fst.nav.settings`), never by pixel coordinates except as a last resort.
- Window-size evidence: capture each surface at `compact`, `medium`, `wide`, `snap-left`/`snap-right`, `maximized`, `full-screen` and `portrait-tablet`. The `.json` sidecar records px/epx size, DPI scale and monitor. Real touch and tablet posture need touch hardware.
- In-process automated UI tests (FlaUI in a test project) are the Windows lane's choice; `FstUia` is a lab driver, not a test framework.
- Feature UI journeys live in `tools/windows/journeys/<feature>.steps` (`uiwin.py drive --steps-file`; every `waitfor` fails the run when its element never appears). `invoke`/`waitfor` need the element on screen: resize, `scroll`, or use the input-free `reveal:<sel>` (scrolls it into view through UIA ScrollItem; a target that is not realized yet steps the enclosing scroller through the UIA Scroll pattern until it is on screen) or `scrollto:<sel>,<pct>` (sets a scroller's vertical position), which also work on a locked console where real input is denied. Fixture runs: start `tools/mock_service.py --port <free port>` and pass `--extra FST_BASE_URL=http://127.0.0.1:<port>/`.
- **Journey runner:** `python tools/windows/ui_journey.py tools/windows/journeys/<feature>.json [--only NAME] [--shots DIR] [--retries N] [--large-catalogue] [--fixture SCRIPT]` automates the above for JSON journey lists (route + preset + steps): it starts the fixture service with a larger listen backlog (`--large-catalogue` adds the 108 synthetic `fixture-song-<n>` rows, e.g. for the difficulty-meter journeys; `--fixture` swaps in a `mock_service` wrapper such as `tools/windows/star_rating_fixture.py`), launches this worktree's Debug build per journey, saves `<name>-failure.png` on failure and reports a pass on retry as `FLAKY`. A journey's optional `"args": [...]` are passed to the app as extra launch arguments (e.g. `--control-lab=instrument-selector` for `journeys/instrument-selector.json`). A journey's optional `"fixture"` list (e.g. `["--band-rankings", "empty"]`) starts it against `tools/windows/rivals_fixture.py` (or `--fixture`) with those flags; `a11y_matrix.py` pages take the same key and share one fixture service per distinct list. `--band-rankings empty|unavailable|anonymous` serves an empty board, an HTTP 500, or a board whose second team has blank member names and no team key. `--song-leaderboard anonymous` blanks the account ID and display name of rank 3 on the Song page's Lead (`Solo_Guitar`) chart read, so the top-10 row without an account (UIA Text, no Invoke, not focusable; issue #263) is reachable. Deep-link routes lose everything after `&` in the desktop hop, so reach query-string routes by clicking through. Panels are not in the UIA control view: wait on text/controls, not `StackPanel` IDs.
- Rivals keeps its own runner, `python tools/windows/rivals_journey.py [--shots DIR] [--sizes compact,medium,wide]` (anonymized fixture via `tools/windows/rivals_fixture.py`, isolated `FST_SETTINGS_PATH`, screenshot + tree on failure; see [rivals/windows.md](../pages/rivals/windows.md)). Two fixture findings: .NET's pooled client intermittently hits `WSAECONNABORTED` against the stdlib HTTP/1.0 server (the app shows "You're offline") until responses carry `Connection: close`; and ItemsRepeater keeps recycled off-screen elements with their old AutomationIds, which the driver's first-match lookup can hit, so keep IDs unique per state (e.g. per tab).
- Suggestions keeps its own runner, `python tools/windows/suggestions_journey.py [--only NAME] [--sizes LIST] [--shots DIR]` (issue #205): it serves the parity fixture through `suggestions_fixture_server.py` (state accounts `-syncing` 202, `-denied` 403, `-slow`), isolates settings/app data, and covers loaded at three widths, resize, arrow keys, filter, filtered-empty, load-more, end-of-mix (`FST_DEBUG_SUGGESTIONS_LIMIT=12`), Song Detail, the no-player redirect, loading, syncing, denied and offline, plus `rival-rows` (issue #259: single-rival rows draw no rival name pill and name the rival in their UIA name; mixed rows keep it), using pattern steps that also run on a locked console. See [suggestions/windows.md](../pages/suggestions/windows.md).
- Global search keeps its own runner, `python tools/windows/search_journey.py [--axe]`: it wraps `ui_journey.py`, logs fixture request paths (no query strings) and fails on any `/api/bands/search`, isolates settings per journey (`--settings-path`, `--first-run=off`), passes routes as app arguments so `--exe` can target the Release/AOT build, and with `--axe` runs `tools/windows/axe_scan.ps1` (AxeWindowsCLI in the desktop session under the lock) on the Search page. Suggestion popups are separate windows: capture them with `shot:<png>@screen`. Its state matrix (every reachable state, each mode) is `tools/windows/journeys/a11y-search.json` for `a11y_matrix.py --fixture tools/windows/profile_fixture.py` (issue #234). CHOpt Path Default View matrix pages (live-safe, with a keyboard page): `tools/windows/journeys/a11y-settings-path-view.json`. Live-safe Version card matrix pages (`a11y_matrix.py --live`): `tools/windows/journeys/a11y-settings-version.json`. Expanded states for the matrix (`{stem}` shots per section, a keyboard page): `tools/windows/journeys/settings-states.json`.
- Leaderboards keeps its own runner, `python tools/windows/leaderboards_journey.py [--only NAME] [--sizes compact,medium,wide] [--shots DIR] [--exe …]` (issue #207): `tools/windows/leaderboards_fixture.py` wraps the mock service with per-board empty, scrape-frozen and failing overrides, so every overview state (anonymous, selected inside/outside the top ten, not yet ranked, failed spotlight, empty, frozen countdown, all cards failing, Rank By, Quick Links, View All, row opens) runs with UIA patterns only, so it also passes on a locked console.
- Feedback Form keeps its own runner, `python tools/windows/journeys/feedback.py [NAMES] [--preset compact|medium|wide|maximized|snap-left…] [--shots DIR]` (issue #236): journeys `unavailable`, `validation`, `submit`, `error` cover every [feedback-form](../controls/feedback-form/windows.md) state with UIA patterns only. `tools/windows/feedback_fixture.py` switches `/api/features`, the POST outcome and the status poll through `GET /__feedback__/mode?features=&post=&status=&reset=1`. `status=hold` answers each poll with `processing` at once: a held response would hit the app's request timeout while the journey waits for the desktop lock. The fixture also rewrites .NET's bare multipart names (`name=kind`) to quoted ones, because `mock_service` only matches `name="kind"` (the real ASP.NET service accepts both). The system file picker is driven by `id=1148&class=Edit` (file name) and `id=1&class=Button` (Open): selectors take `&class=<ClassName>`. Phases also check the fixture's snapshot (POST count, status reads, last submission summary); a failed phase dumps `tree-N-failed.txt`.
- App navigation keeps its own runner, `python tools/windows/journeys/navigation.py [NAMES] [--shots DIR]` (issue #225): journeys `songs`, `leaderboards`, `settings`, `player`, `band`, `reselect`, `compact`, `keyboard` launch on the anonymized Rivals fixture, drive the pane with `select:id=fst.nav.*` (WinUI's item peer raises `ItemInvoked`, so re-selecting the current item pops to root) and check the tree for the selected item, pane order, accelerators and forbidden player-only items. - Songs Filter keeps its own runner, `python tools/windows/songs_filter_journey.py [--only NAME] [--sizes compact,medium,wide] [--shots DIR] [--exe …]` (issue #219): one scenario per reachable [songs-filter](../controls/songs-filter/windows.md) spec state, with `tools/windows/songs_filter_fixture.py` (`--shop demo|empty|error`) for the Shop pauses. - Item Shop keeps its own runner, `python tools/windows/shop_journey.py [--only NAME] [--sizes compact,medium,wide] [--shots DIR] [--exe …]` (issue #224): `tools/windows/shop_fixture.py` switches the Shop feed (demo, empty, 503, held `slow`) and the catalogue (ok, 503) between phases through `GET /__shop__/mode`, covering every shop-offers contract state (offline uses a closed loopback port). A fixed fixture delay is not a loading state: the drive can queue minutes on the shared desktop lock after launch, so `slow` holds the response until the journey switches the mode back.
- Notifications keeps its own runner, `python tools/windows/notifications_journey.py [--only NAME] [--sizes compact,medium,wide] [--shots DIR] [--exe …]` (issue #229): `tools/windows/notifications_fixture.py` switches the feed (rich five-row, generated-empty, never generated, 503, held `slow`) through `GET /__notifications__/mode` and reports how many notifications reads it served (`reset=1` zeroes it), so `no-profile` proves the hidden bell sends no read (`?reads=0` step). `fixture-feed-empty`/`-new`/`-error` keep fixed feeds for `a11y_matrix.py --pages tools/windows/journeys/a11y-notifications.json --fixture tools/windows/notifications_fixture.py`. - Tool unit tests: `python -m unittest discover -s tools/windows/tests` (and `tools/android/tests`).

- **Release/AOT pass (2026-09-28, win-shell2):** bands, whats-new, search, songs (songs-player, shop, no-player, shop-hidden at compact/wide) and rivals no-player all pass on `--exe aot`. The outside-click journey was flaky on AOT until `DialogChrome.LightDismiss` hooked the backdrop on `Loaded` as well as `Opened`.
- **Release/AOT journeys:** every journey script takes `--exe debug|release|aot|<path>` (`tools/windows/journey_exe.py`); `uiwin.py launch` turns on [automation mode](../platforms/windows.md#tooling-toolswindows-powershell-7) so Release builds honour the same `FST_*` hooks. Run the ship build with e.g. `python tools/windows/ui_journey.py tools/windows/journeys/bands.json --exe aot`.
- Live driver regression (needs the console session; takes the desktop lock): `python tools/windows/tests/live_occluded_drive.py` launches two Debug instances at the same preset with separate `FST_DEBUG_DATA_DIR`s, mouse-clicks the **covered** one and asserts only it navigated, then checks `--isolate` minimizes and restores the covering window.
- Other lanes' app windows are usually on top of yours (all launches are centred). `drive` foregrounds the target before real input and fails with the covering windows' names if it can't; add `--isolate` to minimize other instances for the request. Prefer UIA-pattern steps (`invoke`, `toggle`, `select`, `expand`/`collapse`, `setvalue:<selector>|<text>` for text boxes), which work while covered.
- **Locked console (issue #194, 2026-10-03):** while the signed-in session is locked, real input (`click`, `type`, `key`, `tabwalk`) goes to the lock screen and fails, but UIA patterns, `setvalue`, `waitfor`/`waitgone` and PrintWindow `shot`s still work. Write journeys that must run unattended with pattern steps only, and assert disappearance with `waitgone:<selector>[@timeout]` (fails while any match is still on screen) rather than a fixed `wait`. Bring below-the-fold content on screen with `scrollinto:<selector>[@timeout]` (UIA ScrollItem, else paging the nearest scrollable ancestor; while a virtualized list hasn't realized the item yet, paging the window's largest scrollable region down) instead of `scroll:`, and use `toggle:` for `ToggleButton`s: `invoke:` falls back to a real click when there is no Invoke pattern, which silently does nothing while locked. `songs_journey.py`'s `songs-search/sort/jump/filter-empty/syncing/denied/filter-invalid/error` `songs-sort-*` and `shop-states/shop-compact-states/shop-error/shop-hidden-states` scenarios are written this way. A `{relaunch}` step in a `songs_journey.py` scenario closes and relaunches the app on the same settings file (persistence checks need a file-backed `selectedPlayer`, not `FST_DEBUG_PROFILE`, whose settings live in memory).
- Debug launches from each worktree get their own app data folder (settings, selected profile, seen-state, diagnostics log); pass `--extra FST_DEBUG_DATA_DIR=<dir>` for a throwaway one (e.g. first-run journeys) instead of deleting shared files.
- At compact widths (<641 epx) the pane is LeftMinimal: open it with `invoke:id=PART_PaneToggleButton` before `invoke:id=fst.nav.*`.

- Parts marked `AccessibilityView=Raw` (e.g. a row's accuracy pill, read only through the row's one name) are invisible to the driver's default control-view search: select them with `raw=<AutomationId>`. `assertname:<selector>[@timeout]|<text>` checks a UIA name (a raw `TextBlock`'s name is its text), and `assertaligned:<selector>|<selector>` fails unless both horizontal centres are within 2 px (results in the `aligned` output). `assertbelow:<a>|<b>` needs `a`'s vertical centre at least 8 px below `b`'s and `assertlevel:<a>|<b>` needs them within 4 px (results in `vertical`), e.g. a chip wrapped under its row's text vs inline on the row's centre line. `assertgap:<a>|<b>|<epx>` needs the gap from `a`'s bottom edge to `b`'s top edge to be `<epx>` effective pixels (window DPI) within 1 epx (results in `gaps`), e.g. a list's last row above a pinned footer (issue #293, `boards-ui.json` `song-board-end-gap-*`). `pin:<selector>` records an element's window-relative rect and a later `assertpinned:<selector>` (same selector, same `drive` request) fails if it moved more than 1 px (results in `pinned`), e.g. a page toolbar while its list scrolls (issue #252, `anchored-controls.json`).
- **Scrolled matrix pages end on a deterministic edge** (issue #259): `scrollinto` stops as soon as any part of the target is on screen and a `ListView` scrolls the least distance, so the list's final offset depends on size and scale, and whatever row then sits exactly on the viewport's edge reports a zero-height, not-offscreen rectangle (Axe `BoundingRectangleSizeReasonable`, [windows-accessibility](windows-accessibility.md#open-issues) item 3) in some configurations only. After `scrollinto`, pin the target with `scrollinset:<target>|<list>|<epx>` (UIA Scroll pattern, no input, works while the console is locked): it scrolls until the target's top sits `<epx>` below the list's top. Pick an inset smaller than the gap above the target (Suggestions cards: 8 of the 16-epx container margin), so the top edge crosses empty space. `assertinset:…|0` cannot check this, because UIA clips a partly scrolled-out element's rectangle to the viewport, so its top always reads as the edge. A remaining finding is a setup defect to fix, not a result to defer (`a11y.json` `suggestions-rivals`).
- Axe scans every top-level window of the process (`_N_of_M.a11ytest` per window); `.a11ytest` files are zips whose `el.snapshot` holds per-element `ScanResults` (Status 3 = fail), readable in Accessibility Insights.
- **Per-page fixtures** (issue #206): an `a11y.json` page's `"fixture"` list is either extra flags for the shared `rivals_fixture.py` (`["--band-rankings", "empty"]`) or, when it starts with a `.py` name, its own wrapper script and flags (`["shop_fixture.py", "--shop", "empty"]`); pages with the same script and flags share one fixture process. `tools/windows/shop_fixture.py` (shared with `shop_journey.py`, issue #224) serves the rivals fixture with a fixed `/api/shop` mode (`--shop demo|empty|error|slow|shop-single`) and optionally fails `/api/songs` (`--songs error` or `--songs-fail`), so the Item Shop's empty, failed-feed and "Song details unavailable" states are reachable without editing fixture JSON.
- "Focusable sibling elements must not have the same Name" fires wherever cards repeat rows (the same player atop several charts): wrap each card in `Controls/AccessibleGroup` (a named UIA `Group`), which also makes Narrator announce the card on entry.
- Buttons whose content is a panel (icon + `TextBlock`) get no UIA name: set `AutomationProperties.Name` (Axe "Name must not be null").
- System modes change the operator's real desktop. The runner writes the previous values to `~/.fst-locks/uiwin/a11y-sysset-restore.json` before changing anything and replays a leftover file at the start of its next hold, so a killed run cannot leave a contrast theme on for other lanes. Still prefer letting a mode run finish.
- `--exe debug|release|aot` runs the matrix on a publish in automation mode (same as `uiwin.py launch`).
- Text size is read by apps at launch; `text-*` modes set it before launching, so the running operator desktop only changes for new windows.
- `scale-*` modes change the primary display's scale (`DisplayConfigSetDeviceInfo` relative steps, as Settings › Display does); window presets are effective pixels, so a `wide` preset is clamped by the scaled desktop (1440×900 epx at 150% on the 4K host, 1280×672 at its normal 300%).
- While the console session is locked, the driver **posts** keyboard steps (`type`, `key`, `tabwalk`) to the app window (`FstUia/PostedInput.cs`: `WM_KEYDOWN`/`WM_CHAR`/`WM_KEYUP` with the modifier state) instead of `SendInput`, which a locked desktop drops; a request's `post_keys: true` forces it. `focus:` and `waitfor:` still need an on-screen element (realized and inside the viewport), and mouse steps need an unlocked desktop. When the Axe output file cannot be written (`Win32Exception` from the locked desktop's screenshot), the scan retries without an output file and still reports its error count.

### Narrator manual script (operator)

Start Narrator (Ctrl+Win+Enter), launch a fixture build (`python tools/windows/a11y_matrix.py` launch flags, or `uiwin.py launch … --arg=--base-url --arg=http://127.0.0.1:<port>/`), then:

1. **Shell**: Tab from the page into the title bar. Expect "Search songs and players, edit" (search landmark), "Notifications, button", "Select a player profile, button". Caps+F7 → Landmarks lists "Page content" (main) and "Search". Ctrl+1…7 / Ctrl+comma switch sections; pane items read "Songs, Ctrl+1".
2. **Songs**: Ctrl+F → "Search songs, edit". Type "fix": after a pause Narrator says "2 songs". Tab → "Sort Songs, button, collapsed"; Enter opens the flyout, Esc closes it and focus returns to Sort. Down into rows: each row reads title, artist · year, shop state, chart statuses.
3. **Slow load**: with a throttled or stopped fixture, open Leaderboards → "Loading …" after ~1 s, then "<Title>, page 1 of N" on completion; stop the fixture and Retry → the service-status heading and message are announced once.
4. **Leaderboards / Rivals / Rival Detail**: Narrator enters each card as "<Lead>, group"; H / Shift+H move between Level 1/2 headings.
5. **Song Detail**: Paths opens a dialog; Esc closes it and focus returns to Paths. Alt+Left goes back (also from inside a text field).
6. **Profile flyout**: Enter on the profile button → focus in "Find Player"; results list reads each player; Esc returns to the button.
7. **Settings**: every toggle reads its label and state; "Reset" confirmation dialog traps focus until closed.
8. **First run** (`--first-run=force`): the dialog reads its page title; Esc closes it.
