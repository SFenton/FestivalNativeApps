# Windows testing

> **What:** Windows unit/coverage, UI-automation, accessibility and performance-test rules and commands. **Read when:** writing or running Windows tests or changing `windows/**`. Architecture, tooling and `uiwin.py`: [platforms/windows.md](../platforms/windows.md).

- Separate logic tests (testable view models) from XAML/UI automation; **95% / 90%** line coverage via Cobertura XML, which `tools/coverage_gate.py` parses and merges.
- Compare app/game impact in Release builds with representative workloads.
- Installed-PWA reference (Edge app, same window presets, video + measured animations): `tools/windows/pwa.py`; findings and gaps in [pwa-reference/](pwa-reference/README.md).

## Layers

| Layer | Where | Command |
|---|---|---|
| Logic + view models | `windows/Festival.Core.Tests` (xUnit, fake `HttpMessageHandler`, `FakeTimeProvider`) | `pwsh tools/windows/test.ps1` |
| Coverage | coverlet Cobertura → `windows/.artifacts/coverage/coverage.cobertura.xml`, gated by `tools/coverage_gate.py --language csharp` | `pwsh tools/windows/test.ps1 -Coverage` |
| Visual smoke | Screenshot of the running app | `pwsh tools/windows/screenshot.ps1 -Launch -Tab songs -Out …` |
| Perf | Release/AOT scenarios | `pwsh tools/windows/perf.ps1`, `bench.ps1` |

- `contracts/coverage-rules.json` classifies C# by folder: `windows/**/Data/*.cs` and `Domain/*.cs` are **logic (95%)**, `Views/*.cs` and `ViewModels/*.cs` are **UX (90%)**. Keep new Core files in those folders (flat) so the gate sees them.
- Fixtures: tests reuse `contracts/fixtures/{songs-demo,publication}.json`; manual fixture runs use `tools/mock_service.py` (`launch.ps1 -Fixture`). No production payloads in tests.
- View-model timing uses `TimeProvider`; tests advance `FakeTimeProvider` (search debounce, profile search, scrape-freeze countdown and backoff).
- XAML code-behind (`windows/Festival.App`) has no unit coverage; it is kept thin. UI automation (FlaUI/UIA) is not set up in this lane yet; the device-lab lane's `uiwin.py` drives the app by the `fst.*` AutomationIds.

## Desktop session

SSH runs in session 0 (no desktop). `_common.ps1` runs GUI work through a one-shot `schtasks /IT` task in the signed-in console session (no stored credentials), and every hop holds the shared FIFO `desktop` lock via `tools/windows/desktop_lock.py`, so it queues with `uiwin.py` and other lanes. From session 0 `Process.MainWindowHandle` is always 0, so window lookups happen inside that task. `PrintWindow(PW_RENDERFULLCONTENT)` captures the DirectComposition content; the capture process must be DPI-aware. From Git Bash, prefix route arguments with `MSYS_NO_PATHCONV=1` or `/songs/…` becomes a Windows path.

## UI automation

- **Proven on `sfenton-music`:** from SSH (session 0), UIA queries, pattern invocation, keyboard and mouse input, window resizing and window screenshots all work through the one-shot interactive task hop in `tools/windows/uiwin.py`. They need the operator logged on at the console. Do not configure autologon without separate authorization.
- Drive the app only through `uiwin.py` so lanes serialize on the desktop lock (≤300 s per hold). It shares the operator's real desktop, so keep holds short and always `close` what you launch.
- Locate elements by `AutomationProperties.AutomationId` from the `product.json` test-ID registry (`drive … invoke:id=fst.nav.settings`), never by pixel coordinates except as a last resort.
- Window-size evidence: capture each surface at `compact`, `medium`, `wide`, `snap-left`/`snap-right`, `maximized`, `full-screen` and `portrait-tablet`. The `.json` sidecar records px/epx size, DPI scale and monitor. Real touch and tablet posture need touch hardware.
- In-process automated UI tests (FlaUI in a test project) are the Windows lane's choice; `FstUia` is a lab driver, not a test framework.
- Feature UI journeys live in `tools/windows/journeys/<feature>.steps` (`uiwin.py drive --steps-file`; every `waitfor` fails the run when its element never appears). `invoke`/`waitfor` need the element on screen: resize, `scroll`, or use the input-free `reveal:<sel>` (scrolls it into view through UIA ScrollItem; a target that is not realized yet steps the enclosing scroller through the UIA Scroll pattern until it is on screen) or `scrollto:<sel>,<pct>` (sets a scroller's vertical position), which also work on a locked console where real input is denied. Fixture runs: start `tools/mock_service.py --port <free port>` and pass `--extra FST_BASE_URL=http://127.0.0.1:<port>/`.
- **Journey runner:** `python tools/windows/ui_journey.py tools/windows/journeys/<feature>.json [--only NAME] [--shots DIR] [--retries N] [--large-catalogue] [--fixture SCRIPT]` automates the above for JSON journey lists (route + preset + steps): it starts the fixture service with a larger listen backlog (`--large-catalogue` adds the 108 synthetic `fixture-song-<n>` rows, e.g. for the difficulty-meter journeys; `--fixture` swaps in a `mock_service` wrapper such as `tools/windows/star_rating_fixture.py`), launches this worktree's Debug build per journey, saves `<name>-failure.png` on failure and reports a pass on retry as `FLAKY`. A journey's optional `"args": [...]` are passed to the app as extra launch arguments (e.g. `--control-lab=instrument-selector` for `journeys/instrument-selector.json`). A journey's optional `"fixture"` list (e.g. `["--band-rankings", "empty"]`) starts it against `tools/windows/rivals_fixture.py` (or `--fixture`) with those flags; `a11y_matrix.py` pages take the same key and share one fixture service per distinct list. `--band-rankings empty|unavailable|anonymous` serves an empty board, an HTTP 500, or a board whose second team has blank member names and no team key. `--song-leaderboard anonymous` blanks the account ID and display name of rank 3 on the Song page's Lead (`Solo_Guitar`) chart read, so the top-10 row without an account (UIA Text, no Invoke, not focusable; issue #263) is reachable. `--player-bands fail-once` answers each player-bands group read (`/api/player/{id}/bands?group=…`) with HTTP 500 the first time, so the profile's inline Bands failure and its Retry recovery are reachable (issue #312; `profile.py` journeys take the same `fixture` list). `--board-pages flaky` fails the 1st, 3rd, … read of each later page of a paged board (solo song board `offset` > 0, Full or Band Rankings `page` > 1) with HTTP 500 and passes the next, so a failed page change and its Retry recovery are reachable (issue #283; `boards-ui.json` `*-failed-page-retry-recovers`). In a journey's `extra` values and an `a11y_matrix` page's `env` values, `{repo}` becomes the repository root (and `{shots}`, in journeys, the shots folder), so a hook can point at a checked-in file under `tools/windows/fixtures/` (e.g. `FST_DEBUG_WHATS_NEW_FILE` with `whats-new-grouped.json`, issue #274). Deep-link routes lose everything after `&` in the desktop hop, so reach query-string routes by clicking through. Panels are not in the UIA control view: wait on text/controls, not `StackPanel` IDs.

- Other lanes' app windows are usually on top of yours (all launches are centred). `drive` foregrounds the target before real input and fails with the covering windows' names if it can't; add `--isolate` to minimize other instances for the request. Prefer UIA-pattern steps (`invoke`, `toggle`, `select`, `expand`/`collapse`, `setvalue:<selector>|<text>` for text boxes), which work while covered.
- **Locked console (issue #194, 2026-10-03):** while the signed-in session is locked, real input (`click`, `type`, `key`, `tabwalk`) goes to the lock screen and fails, but UIA patterns, `setvalue`, `waitfor`/`waitgone` and PrintWindow `shot`s still work. Write journeys that must run unattended with pattern steps only, and assert disappearance with `waitgone:<selector>[@timeout]` (fails while any match is still on screen) rather than a fixed `wait`. Bring below-the-fold content on screen with `scrollinto:<selector>[@timeout]` (UIA ScrollItem, else paging the nearest scrollable ancestor; while a virtualized list hasn't realized the item yet, paging the window's largest scrollable region down) instead of `scroll:`, and use `toggle:` for `ToggleButton`s: `invoke:` falls back to a real click when there is no Invoke pattern, which silently does nothing while locked. `songs_journey.py`'s `songs-search/sort/jump/filter-empty/syncing/denied/filter-invalid/error` `songs-sort-*` and `shop-states/shop-compact-states/shop-error/shop-hidden-states` scenarios are written this way. A `{relaunch}` step in a `songs_journey.py` scenario closes and relaunches the app on the same settings file (persistence checks need a file-backed `selectedPlayer`, not `FST_DEBUG_PROFILE`, whose settings live in memory).
- Debug launches from each worktree get their own app data folder (settings, selected profile, seen-state, diagnostics log); pass `--extra FST_DEBUG_DATA_DIR=<dir>` for a throwaway one (e.g. first-run journeys) instead of deleting shared files.

Crop a whole row, not the ring: the ring is a raw view with no peer (issue #397, `a11y-shop-list-row.json`). `pin:<selector>` records an element's window-relative rect and a later `assertpinned:<selector>` (same selector, same `drive` request) fails if it moved more than 1 px (results in `pinned`), e.g. a page toolbar while its list scrolls (issue #252, `anchored-controls.json`). `assertnoscrollbar:<selector>` fails if the scroller contains any UIA `ScrollBar`, idle or shown: a WinUI `Auto` bar stays in the tree while idle (and after input-free `scrollto:`), drawn as soon as mouse or touch scrolls, so checking only on-screen bars proves nothing on a locked console; a `Hidden` bar is collapsed out of the tree (issue #279, Paths chart). `assertsize:<selector>|<w>x<h>` fails if the element is smaller than `<w>`×`<h>` epx, allowing one device pixel because UIA rounds each edge of a half-pixel-placed element separately (0 skips a side; results in `sizes`). `assertapart:<a>|<b>` fails if their bounds overlap (results in `apart`). `assertat:<selector>|<dx>,<dy>` checks the point `<dx>,<dy>` epx from the centre (issue #271, results in `hits`). The point must lie inside the element; the UIA hit test there (`FromPoint`) must return the element or a descendant; and the point must not be in the window's non-client area. A locked console's `FromPoint` returns the lock screen, so the driver falls back to the bounds check (`method: "bounds"`). Non-client means the title bar's `InputNonClientPointerSource` child window region (`caption`) or the caption buttons. The TitleBar truncates its passthrough rects to whole device pixels, so a point on the element's last pixel row can read as caption: it passes when the pixel one step toward the centre is client (`edge_pixel` in the result; a failure message lists the caption band's rect). `WM_NCHITTEST` on the top-level window reports caption everywhere in a WinAppSDK title bar, so the driver doesn't use it.
- **Paint and bold assertions** (issue #272): decorative (Raw) visuals such as album art, a card's stroke and gap, a pill's colour or an unread dot aren't in a row's UIA name, so a name check passes without them. `assertpaint:<selector>|<probe>|…` captures the window with `PrintWindow` (flyouts and occluded windows included) and checks pixels at effective-pixel offsets from the element's bounds: a probe is `[name:]<L|R|C><epx>,<T|B|M><epx>[,<x2>,<y2>][=|!=<#RRGGBB|@name>[~tol]]` (`L`/`T` from the start, `R`/`B` inward from the end, `C`/`M` from the centre; negative offsets go outside). A point matches when every channel is within the tolerance (default 16); an area (two corners) matches with at least 4 epx² of matching pixels (`=`) or fewer (`!=`). `@name` compares with an earlier named point's sample, so contrast themes can check a stroke against their own fill. It retries for 3 s, and the samples appear in the `paint` output. `assertbold:<selector>|<run>|…` (`assertbold:<sel>|` for none) waits up to 5 s until the bold (weight 700) runs of the element's text, or of its first descendant with the Text pattern, are exactly the trimmed runs given. A WinUI `TextBlock`'s TextPattern has no `Format` unit, `FindAttribute` is not implemented, and the character range at index *i* reports the combined weight of characters *i*−1 and *i* (mixed at a run edge), so the driver decodes weights left to right. Check each new probe by removing its visual once: it must fail (`notifications_journey.py` `media_paint`). Probe only rows that fit the viewport whole: `scrollinto` stops at a partly visible ListView item, so a clipped card's `M`/`B` offsets miss. Start a gap area 1 epx (not 1.5) inside a 1 epx stroke so display 150% rounding doesn't pull the stroke into it.
- **Scrolled matrix pages end on a deterministic edge** (issue #259): `scrollinto` stops as soon as any part of the target is on screen and a `ListView` scrolls the least distance, so the list's final offset depends on size and scale, and whatever row then sits exactly on the viewport's edge reports a zero-height, not-offscreen rectangle (Axe `BoundingRectangleSizeReasonable`, [windows-accessibility](windows-accessibility.md#open-issues) item 3) in some configurations only. After `scrollinto`, pin the target with `scrollinset:<target>|<list>|<epx>` (UIA Scroll pattern, no input, works while the console is locked): it scrolls until the target's top sits `<epx>` below the list's top. Pick an inset smaller than the gap above the target (Suggestions cards: 8 of the 16-epx container margin), so the top edge crosses empty space. `assertinset:…|0` cannot check this, because UIA clips a partly scrolled-out element's rectangle to the viewport, so its top always reads as the edge. A remaining finding is a setup defect to fix, not a result to defer (`a11y.json` `suggestions-rivals`).
- Axe scans every top-level window of the process (`_N_of_M.a11ytest` per window); `.a11ytest` files are zips whose `el.snapshot` holds per-element `ScanResults` (Status 3 = fail), readable in Accessibility Insights.
- **Per-page fixtures** (issue #206): an `a11y.json` page's `"fixture"` list is either extra flags for the shared `rivals_fixture.py` (`["--band-rankings", "empty"]`) or, when it starts with a `.py` name, its own wrapper script and flags (`["shop_fixture.py", "--shop", "empty"]`); pages with the same script and flags share one fixture process. `tools/windows/shop_fixture.py` (shared with `shop_journey.py`, issue #224) serves the rivals fixture with a fixed `/api/shop` mode (`--shop demo|empty|error|slow|shop-single|long-title`; `long-title` renames `fixture-pulse` to a title and artist too long for a list row at medium, issue #397) and optionally fails `/api/songs` (`--songs error` or `--songs-fail`), so the Item Shop's empty, failed-feed and "Song details unavailable" states are reachable without editing fixture JSON.
- "Focusable sibling elements must not have the same Name" fires wherever cards repeat rows (the same player atop several charts): wrap each card in `Controls/AccessibleGroup` (a named UIA `Group`), which also makes Narrator announce the card on entry.
- Buttons whose content is a panel (icon + `TextBlock`) get no UIA name: set `AutomationProperties.Name` (Axe "Name must not be null").
- System modes change the operator's real desktop. The runner writes the previous values to `~/.fst-locks/uiwin/a11y-sysset-restore.json` before changing anything and replays a leftover file at the start of its next hold, so a killed run cannot leave a contrast theme on for other lanes. Still prefer letting a mode run finish.
- `--exe debug|release|aot` runs the matrix on a publish in automation mode (same as `uiwin.py launch`).
- Text size is read by apps at launch; `text-*` modes set it before launching, so the running operator desktop only changes for new windows.
- `scale-*` modes change the primary display's scale (`DisplayConfigSetDeviceInfo` relative steps, as Settings › Display does); window presets are effective pixels, so a `wide` preset is clamped by the scaled desktop (1440×900 epx at 150% on the 4K host, 1280×672 at its normal 300%).
- While the console session is locked, the driver **posts** keyboard steps (`type`, `key`, `tabwalk`) to the app window (`FstUia/PostedInput.cs`: `WM_KEYDOWN`/`WM_CHAR`/`WM_KEYUP` with the modifier state) instead of `SendInput`, which a locked desktop drops; a request's `post_keys: true` forces it. `focus:` and `waitfor:` still need an on-screen element (realized and inside the viewport), and mouse steps need an unlocked desktop. Posting `WM_LBUTTONDOWN`/`UP` to the XAML island's `InputSiteWindowClass` child doesn't reach WinUI (its lifted input stack ignores posted pointer messages), and touch injection on a locked session goes to the lock screen, so `tapat:`/`clickat:` refuse to run there (issue #271). `drag:<from>|<to>[|<dy>]` (issue #372) also refuses. On an unlocked console it presses the mouse 16 epx inside the source's left edge (a reorder grip), moves in steps to the target's left inset at its centre plus `dy` epx, and releases. When the Axe output file cannot be written (`Win32Exception` from the locked desktop's screenshot), the scan retries without an output file and still reports its error count.
- **Prove announcements, don't infer them from code** (issue #269): `listen:announcements` records the app's UIA notification events (what Narrator speaks) and a later `assertannounced:<text>[@secs]` (exact, or `~<regex>`) in the same drive waits for one; the failure lists what was heard and the result carries `announcements`. `assertannouncedcount:<n>|<text>` checks that exactly `n` match so far, so a value announced once isn't repeated by later polls (`a11y-settings-service-info.json` `settings-service-info-monotonic`, issue #275). It works on a locked console, unlike live Narrator. #70's Paths announcements were claimed for months while `ScreenReader.Announce` silently raised nothing from a `UserControl`; `journeys/paths.json` `paths-{swap-announced,display-toggle,rapid-switch,keyboard-switch}[-wide]` now assert them.
- **Narrator model** (issue #271): live Narrator cannot run on the locked lane console, cannot be scripted, and its ETW provider carries no spoken text. `FstUia/Narration.cs` models default-verbosity Narrator from the UIA properties it reads: the phrase is Name, localized control type, "unavailable", expand/collapse, toggle state, "selected", Value (when not the name), ItemStatus, HelpText and AcceleratorKey, joined with ", ". The reading order is a pre-order walk of the control view that skips off-screen elements and unnamed containers and stops at named leaves (buttons, list items, text, edits and so on). `narrate:`/`assertread:`/`assertorder:` assert it with no input. It is evidence for UIA order and phrasing, not for Narrator's own speech (verbosity, scan mode, pronunciation): the operator script below still needs a live run when an unlocked session is available.
- **Assert what Narrator reads after a control's name** (issue #280): `assertstate:<sel>|value=<text>[@secs]` compares the UIA Value, else the Selection pattern's selected item name (a `ComboBox`'s current option, "Instrument, combo box, Bass"). Scope list-item checks to the open popup with `&class=ComboBoxItem`: a bare `name=Bass` also matches the page behind a dialog (`paths-instrument-hidden`).
