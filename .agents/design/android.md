# Android design (Compose)

> **What:** adaptive navigation, chrome and surfaces per Android form factor. **Read when:** laying out Android screens. Split into `design/android/<form-factor>.md` once a form factor has its own decisions.

- Material 3 first, Fluent 2 second ([fluent](fluent.md)); brand colors from `BrandTokens` (same values as Apple). Dark scheme only for now.
- Window-size policy (`AdaptiveLayoutPolicy`, unit-tested) drives `NavigationSuiteScaffoldLayout` with an explicit `NavigationSuiteType` (Material 3's `navigationSuiteType` rules plus a large-window drawer): width < 600 dp → `ShortNavigationBarCompact`; compact height (< 480 dp) or **tabletop** → bottom `ShortNavigationBarMedium` (controls in the lower half); < 1200 dp → `WideNavigationRailCollapsed` (+ modal drawer from the rail header); ≥ 1200 dp → `NavigationDrawer` (permanent, 280 dp, growing with the font scale up to M3's 360 dp: `permanentDrawerWidth`, issue #101) listing tabs + extras. Bars sit below the content (not overlaid). Tabs follow `FestivalTabPolicy` (Apple/web `BottomNav`): Leaderboards+Rivals replace Compete at ≥ 600 dp.
- Top bars: hamburger (modal drawer, bar layouts only) or back leading; screen actions and **global search** (icon — [global-search](../controls/global-search/android.md)), the notifications slot, then the profile avatar **rightmost on every page**, pushed pages included (batch 7.12; Deselect lives only in the drawer; with a profile selected it opens Statistics, otherwise the profile sheet, issue #290). On compact windows the screen actions (not search, which stays in the top bar everywhere) move to an end-aligned **floating toolbar** over the bottom bar ([app-navigation](../controls/app-navigation/android.md)) (initials when selected). Drawer = web sidebar: Songs, Suggestions, Statistics, Rivals, Leaderboards, Item Shop, then the profile row / Select Profile and Settings at the bottom (the rail pins Profile + Settings to its bottom edge). The modal drawer takes gestures only while open, so edge swipes stay system (predictive) back.
- List-detail (M3 adaptive list-detail; operator 2026-09-28: **two populated columns whenever the width allows**, never an empty "Select a …" pane — same rule as Apple Duo/iPad and Windows): `core/shell/ListDetailPolicy.kt`. On expanded windows or across a separating vertical hinge, Songs and Licenses always show list + detail (Songs list 40% clamped to 320–440 dp, or up to the hinge); the detail is the last row picked (on any width, so unfolding restores it), else the list's first row (`SongsRoute(onListHead = …)` reports it; the pane shows the spinner until the list loads). A list that loads empty collapses to one full-width list, except across a hinge (end pane shows the empty state). Back leaves the page normally (no pane to close). Rivals, Bands and Compete have no list-detail placeholder panes (their two-pane layouts split content, not a selection).
- Glass cards: translucent `Surface` (`surfaceFrosted`) + 1 dp white 8% border, 12 dp corners, whole card is the tap target, no chevrons. No blur (moving backdrop). Increased contrast (OS contrast level on Android 14+ **or** the in-app toggle) → opaque surface + 2 dp white border.
- Section headers: white, bold, Title Case, `heading()` semantics.
- Backdrop: one shared artwork layer behind the shell; covers change every 5 s with a 1 s crossfade, zoom/pan animated in `graphicsLayer` (draw phase only), 0.7 black dim; still on reduced motion (animator scale 0 or in-app toggle), none on data saver, static focused cover on Song Detail.
- Load entrances: `Modifier.festivalFadeIn(isLoaded)` (`ui/common/FadeInOnLoad.kt`, web `fadeInUp`: 400 ms CSS `ease-out` fade + 12 dp rise (`styles/animations.css`, `packages/theme/src/animation.ts`), 125 ms stagger via `fadeInStagger`, `rememberRevealed` for freshly composed children). Drawn in `graphicsLayer` only; cached content appears at once; reduced motion shows content immediately. Scroll pages whose sections start loading when scrolled to provide a page fade window (`LocalFadeInWindow provides rememberFadeInWindow(listOrGridState)`, iOS `FestivalFadeInScope`, issue #60): once a scroll moves the list more than 4 dp, content that finishes loading appears in place; running fades finish. Applied to Player Profile and Leaderboards. Song Detail, Shop, Global Search and Player Bands don't need it (their content is loaded behind the page gate or fades only at load), and Suggestions must not use it (it fades each newly generated batch).
- **Page load gate** (batch 6.41, web `LoadGate`/`LoadPhase`): wrap a page's data-dependent content in `FestivalLoadGate(ready) { … Modifier.staggered(i) … }` (`ui/common/LoadGate.kt`, phases in `core/shell/LoadGatePhase.kt`). Only the spinner shows until ready, it fades out over 500 ms (web `SPINNER_FADE_MS`), then the content is composed and staggers in; data ready at first composition shows at once; content already in stays up through a refresh; Reduce Motion skips the fade and stagger. Pages must not show half-built content. `composeWhileLoading = true` composes the content invisibly (hidden from accessibility) under the spinner for pages whose children start their own loads when composed. Adopted by Licenses; other lanes adopt it on their pages.
- **Load swap** (issue #71, web `useLoadPhase` + `PaginatedLeaderboard`): for pages and cards whose content **reloads** on a selector, filter, page or tab change, `rememberLoadSwap(target, ready, key)` (`ui/common/LoadSwap.kt`, pure phases in `core/shell/LoadSwapPhase.kt`) holds the last shown value, fades it out (300 ms), shows `LoadSwapSpinner` / `loadSwapSpinnerItem` until the new data is ready, fades the spinner (500 ms), then staggers the new content in (`Modifier.staggered(i)`). `key` is the selection, so a cache hit still runs the swap; silent refreshes (`RetryingLoader.refresh`, same key) update in place; data ready at first composition shows at once. Reduce Motion: no fades and no waits. `current` is snapshot state so lazy-list DSL readers see the swapped value. Content kept composed beneath the spinner (a pinned score row, #149; the Leaderboards overview list, which keeps loading its cards there, #178) takes `swap.pinnedContentModifier`, never a bare `alpha(0f)`: hidden, unread by TalkBack and untouchable, so a tap on the spinner can't open an invisible card. Client-side sorts/filters (Songs, Suggestions, Player History, Rival Detail) do not use it, matching the web.

- **Empty states** (batch 6.33, web `EmptyState fullPage`): `FestivalEmptyState(title, subtitle?, icon?)` centres vertically in its space; in a lazy list use `festivalEmptyStateItem(...)`, which fills the viewport height so "No songs" sits mid-page below the header rows.
- Launch: SplashScreen API (`androidx.core:core-splashscreen`, all API levels; `Theme.Festival.Starting` → `Theme.Festival`): the launcher icon on the brand background `#1A0830`, like the installed PWA's splash (PWA gap 2), dismissed on the first frame. The icon is the app's own placeholder; using the web logo needs the asset-licensing gate. Cold-start clip: `showcase/and-polish/coldstart-FST_Phone.mp4`.
- Launcher label (issue #79): `MainActivity` has its own `android:label="@string/launcher_name"` (`FST`), which launchers show under the icon, so the home screen and app drawer don't truncate it. The application label stays `@string/app_name` (`Festival Score Tracker`) for Settings → Apps, and in-app branding is unchanged. `MainActivityTest.launcherLabelIsShortWhileTheAppKeepsItsFullName` guards both; `aapt dump badging` shows `launchable-activity … label='FST'`. The activity label also becomes the window title, which TalkBack announces when the app opens, so `MainActivity.onCreate` calls `setTitle(R.string.app_name)` to keep that announcement "Festival Score Tracker" (issue #182; `dumpsys accessibility` → `mAccessibilityWindowTitle`). The Recents chip keeps the launcher label "FST", like the iOS app switcher.
- Loading: one indicator everywhere, `FestivalLoading` (`ui/common/ServiceStatus.kt`): white indeterminate arc on a 10% white track, 36 dp (24/48 variants), no visible caption (never the blue theme primary). Text is white by default; muted gray only for timestamps and chart axes.
- Marquee: overflowing single-line content text (song titles, artists, player/rival/band member names) uses `FestivalMarqueeText` (`ui/common/MarqueeText.kt`, web `MarqueeText`: 8 s cycle whatever the length, ~5% pause at each end, 28 dp between copies, `basicMarquee` in the draw phase); it truncates with an ellipsis under Remove animations / Reduce Motion. Labels, pills and badges keep ellipsis. Its drawn mode (`Static`/`Scrolling`/`Truncated`/`Wrapped`, or `Held` while a newer modal covers it: [modal-shell](../patterns/modal-shell.md) R10) is the semantics property `FestivalMarquee.ModeKey`, so journeys assert what shows rather than only that text exists.
- Sheets and dialogs: build every modal with the shared component in `ui/common/FestivalModal.kt` (issue #23): `FestivalModalSheet` (`ModalBottomSheet` on the card color, `festivalSheetTop()` so an expanded sheet stops 8 dp below the status bar/camera — M3 draws expanded sheets to the window top, batch 6.28 — and a TalkBack pane title; `festivalSheetHingeSide()` keeps it on one side of a **separating** fold, the wider or leading half in book posture and below the hinge in tabletop, per M3 "Never place interactive content or critical information across the hinge area", issue #125; the side rule is the shared `core/nav/HingeSide.kt`, [modal-shell](../patterns/modal-shell.md) R8), `FestivalModalDialog` (centred M3 dialog card, 560 dp max, nearly full width on compact windows; it stays beside a separating hinge by default (`avoidHinge`, `core/nav/DialogHinge.kt`: First Run tour, issue #139; What's New and Privacy Policy, issue #146), and the Feedback full-screen/centred dialog does the same; the `Dialog` is keyed on `densityDpi`, because a display-size change otherwise removes its window while the composition still holds it) and `FestivalAlertDialog` (confirm/notice `AlertDialog` with text buttons). Sheets and dialogs share `FestivalModalHeader`: a Title Case heading (Sort Songs, Find Rival, Profiles), optional header actions such as Reset, then Material's standard close icon button (`Icons.Filled.Close`, TalkBack "Close", 48 dp) at the **top end** (M3 full-screen dialog / side-sheet pattern; matches Apple's top-right Close and the web). Close slides a sheet away first (instantly under Reduce Motion); swipe, scrim and back also dismiss. Live-apply sheets use Close instead of Done and keep their `.done` tags (as on Apple). Never hand-roll a ✕, a footer Close or a bare `ModalBottomSheet`/`AlertDialog`.
- In-app accessibility overrides follow the OS by default and can only make the app more accessible.
