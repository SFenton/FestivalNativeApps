# Android design (Compose)

> **What:** adaptive navigation, chrome and surfaces per Android form factor. **Read when:** laying out Android screens. Split into `design/android/<form-factor>.md` once a form factor has its own decisions.

- Material 3 first, Fluent 2 second ([fluent](fluent.md)); brand colors from `BrandTokens` (same values as Apple). Dark scheme only for now.
- Window-size policy (`AdaptiveLayoutPolicy`, unit-tested) drives `NavigationSuiteScaffoldLayout` with an explicit `NavigationSuiteType` (Material 3's `navigationSuiteType` rules plus a large-window drawer): width < 600 dp → `ShortNavigationBarCompact`; compact height (< 480 dp) or **tabletop** → bottom `ShortNavigationBarMedium` (controls in the lower half); < 1200 dp → `WideNavigationRailCollapsed` (+ modal drawer from the rail header); ≥ 1200 dp → `NavigationDrawer` (permanent, 280 dp) listing tabs + extras. Bars sit below the content (not overlaid). Tabs follow `FestivalTabPolicy` (Apple/web `BottomNav`): Leaderboards+Rivals replace Compete at ≥ 600 dp.
- Top bars: hamburger (modal drawer, bar layouts only) or back leading; screen actions and **global search** (icon — [global-search](../controls/global-search/android.md)), the notifications slot, then the profile avatar **rightmost** on tab roots. On compact windows the screen actions (not search, which stays in the top bar everywhere) move to an end-aligned **floating toolbar** over the bottom bar ([app-navigation](../controls/app-navigation/android.md)) (initials when selected). Drawer = web sidebar: Songs, Suggestions, Statistics, Rivals, Leaderboards, Item Shop, then the profile row / Select Profile and Settings at the bottom (the rail pins Profile + Settings to its bottom edge). The modal drawer takes gestures only while open, so edge swipes stay system (predictive) back.
- List-detail (M3 adaptive list-detail, operator 2026-09-28: no big empty detail pane): Songs (and Licenses) on expanded windows show the **list full width until something is selected**, then list + detail (list 40% clamped to 320–440 dp); back closes the detail. A vertical **separating** hinge (book posture) always splits at the hinge, with a slim "Select a song" prompt in the empty end pane. Rivals, Bands and Compete have no list-detail placeholder panes (their two-pane layouts split content, not a selection).
- Glass cards: translucent `Surface` (`surfaceFrosted`) + 1 dp white 8% border, 12 dp corners, whole card is the tap target, no chevrons. No blur (moving backdrop). Increased contrast (OS contrast level on Android 14+ **or** the in-app toggle) → opaque surface + 2 dp white border.
- Section headers: white, bold, Title Case, `heading()` semantics.
- Backdrop: one shared artwork layer behind the shell; covers change every 5 s with a 1 s crossfade, zoom/pan animated in `graphicsLayer` (draw phase only), 0.7 black dim; still on reduced motion (animator scale 0 or in-app toggle), none on data saver, static focused cover on Song Detail.
- Load entrances: `Modifier.festivalFadeIn(isLoaded)` (`ui/common/FadeInOnLoad.kt`, web `fadeInUp`: 400 ms CSS `ease-out` fade + 12 dp rise (`styles/animations.css`, `packages/theme/src/animation.ts`), 125 ms stagger via `fadeInStagger`, `rememberRevealed` for freshly composed children). Drawn in `graphicsLayer` only; cached content appears at once; reduced motion shows content immediately.
- **Page load gate** (batch 6.41, web `LoadGate`/`LoadPhase`): wrap a page's data-dependent content in `FestivalLoadGate(ready) { … Modifier.staggered(i) … }` (`ui/common/LoadGate.kt`, phases in `core/shell/LoadGatePhase.kt`). Only the spinner shows until ready, it fades out over 500 ms (web `SPINNER_FADE_MS`), then the content is composed and staggers in; data ready at first composition shows at once; content already in stays up through a refresh; Reduce Motion skips the fade and stagger. Pages must not show half-built content. Adopted by Licenses; other lanes adopt it on their pages.
- **Empty states** (batch 6.33, web `EmptyState fullPage`): `FestivalEmptyState(title, subtitle?, icon?)` centres vertically in its space; in a lazy list use `festivalEmptyStateItem(...)`, which fills the viewport height so "No songs" sits mid-page below the header rows.
- Launch: SplashScreen API (`androidx.core:core-splashscreen`, all API levels; `Theme.Festival.Starting` → `Theme.Festival`): the launcher icon on the brand background `#1A0830`, like the installed PWA's splash (PWA gap 2), dismissed on the first frame. The icon is the app's own placeholder; using the web logo needs the asset-licensing gate. Cold-start clip: `showcase/and-polish/coldstart-FST_Phone.mp4`.
- Loading: one indicator everywhere, `FestivalLoading` (`ui/common/ServiceStatus.kt`): white indeterminate arc on a 10% white track, 36 dp (24/48 variants), no visible caption (never the blue theme primary). Text is white by default; muted gray only for timestamps and chart axes.
- Marquee: overflowing single-line content text (song titles, artists, player/rival/band member names) uses `FestivalMarqueeText` (`ui/common/MarqueeText.kt`, web `MarqueeText`: 8 s cycle whatever the length, ~5% pause at each end, 28 dp between copies, `basicMarquee` in the draw phase); it truncates with an ellipsis under Remove animations / Reduce Motion. Labels, pills and badges keep ellipsis.
- Sheets: `ModalBottomSheet` on the card color with Title Case headers (Sort Songs, Instrument, Find Player). Pass `Modifier.festivalSheetTop()` (`ui/common/FestivalSheet.kt`, batch 6.28) as the sheet modifier so an expanded sheet stops 8 dp below the status bar/camera instead of covering it (M3 draws expanded sheets to the window top and only pads the content). Adopted by Notifications, Quick Links and Licenses; other lanes' sheets (profile, sort/filter, paths, suggestions) should adopt it.
- In-app accessibility overrides follow the OS by default and can only make the app more accessible.

| Form factor | Verified on the FST AVDs (`tools/android/search_journey.py`, screenshots `android/reports/screenshots/search-*.png`, `shell-*.png`) |
|---|---|
| Phone | Short bar; Songs list only, Detail pushed; search = full-screen view from the top-bar icon |
| Passport fold | Folded (cover) = phone. Unfolded (≈ 840 dp) = rail + Songs list-detail at the hinge; the list pane is < 400 dp so search is the icon, and its docked panel stays left of the fold |
| Book fold | Folded = phone. Unfolded / book posture = rail + list-detail at the hinge, docked search left of the fold. **Tabletop** (half-open, rotated) = docked panel capped above the fold (verified); bottom bar per policy (hidden by the IME in the capture). Search text/scope/results survive every posture change (docked ↔ full screen) |
| Tablet | Landscape = permanent drawer + list-detail, search icon → docked panel; portrait = rail, docked search re-anchored on rotation |
| Tri-fold | Folded (360 dp) = phone; partial (720 dp) = rail + docked search; unfolded (1080 dp) = rail + list-detail. FLAT folds only (no tabletop) |
| Resizable | Presets phone → tablet → desktop switch bar → rail → permanent drawer live with search open |
