# Windows design (WinUI 3)

> **What:** WinUI 3 chrome, Fluent content and motion decisions for the Windows app. **Read when:** laying out Windows screens or adding chrome, cards, headers or motion. Architecture and perf: [platforms/windows.md](../platforms/windows.md).

## Chrome (system-owned)

| Element | Decision |
|---|---|
| Window | No Mica: the shared artwork backdrop (`Controls/ArtworkBackground`, brand `#1A0830` base) spans the whole window behind the title bar and the pane (operator 2026-09-28), so its 0.7 black scrim covers every edge. `Styles.xaml` clears NavigationView's content layer (`LayerFill`, 1,1,0,0 stroke, 8 px corner), which had inset the page and left an undimmed strip on the left/top edges |
| Title bar | WinUI `TitleBar` control, `ExtendsContentIntoTitleBar`, tall height; owns Back and pane toggle (NavigationView's own are hidden). Transparent over the backdrop; caption buttons are white (70% inactive) with subtle hover/pressed fills, system colours under contrast themes (`MainWindow.TitleBar.cs`). The title, pane toggle and Back stay **white whether or not the window is active**, and the search/bell/avatar keep full opacity (`Styles.xaml` overrides `TitleBar*Foreground*` and `TitleBarDeactivatedOpacity`; operator batch 6.6). Back is shown only when the section stack can go back (Windows 11 Settings pattern), never as a gray disabled arrow. The notifications `InfoBadge` sits inside a 36×32 box in the bell button (no negative margins, which the button's rounded content clip cut off) |
| Notifications | Bell (`fst.shell.notifications`) only while a profile is selected (operator 2026-09-28; notifications are player-scoped) |
| Profile | `PersonPicture` button at the **top-right** of the title bar (`TitleBar.RightHeader`, `fst.shell.profile`); flyout with Find Player search, results and Deselect |
| Navigation | `NavigationView` pane in the web sidebar's order: Songs · Suggestions* · Statistics* · Rivals* · Leaderboards · Item Shop (*player selected; Item Shop hidden by Hide Item Shop), Settings as the footer item. No Bands or Licenses items (operator 2026-09-28): Bands opens from search and leaderboard links, Licenses from Settings. Wide split set: Leaderboards and Rivals are separate items. `PaneDisplayMode="Auto"` with the default thresholds: **LeftMinimal below 641 epx** (compact windows get the full content width; the title-bar pane toggle opens the pane as a light-dismiss overlay that closes on selection), icon rail (LeftCompact) 641–1007 epx, expanded Left from 1008 epx (snapped halves of a 2560-epx desktop are expanded). The earlier "blank title bar in LeftMinimal" was the artwork composition visual overflowing its host (LeftMinimal has no rounded content border to clip it); the backdrop now clips itself. Only a collapse made while Expanded is remembered: opening/closing the overlay pane in a compact window never leaves a widened window on the icon rail. Evidence: `windows/reports/screenshots/shell-*.png` (`tools/windows/shell_matrix.py`). In LeftMinimal the pane items leave the UIA tree until the pane opens, so automation invokes `id=PART_PaneToggleButton` first. **Pane corners** (issue #55, check of Apple #17's concentric flyout): no change. Windows displays have no rounded corners to follow; DWM rounds top-level windows itself (8 epx, square when maximized or snapped) and exposes only a corner *preference*, not the resolved radius. The overlay pane keeps WinUI's Fluent `OverlayCornerRadius` (8 epx) on its free (right) corners, the same radius as the window, and its start edge sits flush in the window's bottom-left corner, which DWM clips (verified at the compact preset, 2026-10-02). Re-checked by issue #255 (2026-10-05) at every size, theme, text and display scale, with the `a11y-pane-corners.json` journey: still no change ([per configuration](../controls/app-navigation/windows.md#pane-corners-validation-issue-255-2026-10-05)) |
| Stacks | One `Frame` per section; switching sections keeps each stack; re-invoking the current section pops to root. Alt+Left, the Back key and mouse XButton1 go back |

## Content (branded, Fluent tokens)

- **Theme: dark only** (`App.xaml` `RequestedTheme="Dark"`; the product's design, which follows the web app). The Windows light/dark app setting does not change the app, a deliberate deviation from winui-design's "support Light, Dark and High Contrast". High Contrast is honoured through the `HighContrast` dictionaries and system colours. Checked in issue #195 (light and dark system themes look the same; Axe 0 errors in both).
- Brand colours come from the generated `contracts/generated/windows/BrandTokens.xaml` (linked, never copied). Content-only brushes (`FSTCardSurfaceBrush`, header, meter) live in `windows/Festival.App/Themes/Styles.xaml` with a `HighContrast` theme dictionary mapping to system colours.
- **Navigation pane:** docked (expanded or icon rail) it is transparent over the backdrop; only when it overlays content (LeftMinimal flyout, rail opened over content) does it get `FSTOverlayPaneBrush`, an in-app acrylic tinted `#121826` (blurred only while the overlay is open). Item hover/selection keep the Fluent `SubtleFill` states.
- **Text colour:** white by default. `FSTSecondaryTextBrush` is white (lines differ by size/weight); `FSTDeemphasisTextBrush` (the web's `textSecondary` `#D7DEE8`) is reserved for true de-emphasis such as notification timestamps. In-app More Contrast turns that white too.
- **Stars:** always the web's star images (`Assets/Stars/star_white.png`, `star_gold.png`) through `Controls/StarRow` (web `MiniStars`: 1–5 white stars, or five gold stars ringed in gold for six; `Domain/StarRating`), never ★ glyphs.
- **Cards** (`FSTCardStyle`): 8 px radius, 1 px stroke, 16 px padding, **solid** `#C7121826` surface. No in-app Acrylic: a blur over animated art is recomputed every frame. When Windows transparency effects are off, the shell makes the card surface opaque at runtime.
- **Leaderboard rows: one design** (operator batch 7.7; web `entryRow` + `LeaderboardEntry`/`RankingEntry`): every board (Song Detail previews and score history, song leaderboards and their pinned row, Full/Band Rankings, the Leaderboards overview and its spotlight) draws its rows with `Controls/LeaderboardEntryRow` over a Core row contract (`ILeaderboardScoreRow` / `ILeaderboardRankingRow` in `ViewModels/LeaderboardEntryRows.cs`). Each row is its own frosted 48 epx row (12 epx radius, 12 epx sides, 4 epx apart; no card around the rows, no hairlines); empty, loading and failed boards sit on their own card. Columns: rank (left-aligned, web `computeRankWidth` 8.5 epx per character) · name (scrolls through `Controls/MarqueeText` when it doesn't fit, ellipsized with the full name as the row tooltip when motion is off; issue #292 reversed batch 7.14's truncation) · season (score rows from 520 epx) or the small `X / Y` songs label · score, or the `accentBlueBright` rating with an optional Bayesian caption · accuracy badge (fixed "XX.X%" width; gold skewed outline for FC) · stars (song boards, rows from 700 epx) · in-card chevron. Which columns show and their widths are decided once per section (issue #37) by `Domain/LeaderboardColumnLayout.Fit` over a `LeaderboardSection` measured from every row plus the pinned row (`LeaderboardColumns.Measure`, shared through each row's `Section`): shown columns keep their width on rows without a value (blank badge/star slot), and large text drops stars, then season, before squeezing the name. The whole row is one Button: one Tab stop with the full UIA name (Android one-stop-per-row learning). The surface is a Border behind a transparent Button, so hover and press tint the frosted fill instead of replacing it.
- **Selected player rows**: the web's `purpleHighlight` fill (`FSTPlayerRowBrush` `#BF4B0F63`) and `purpleHighlightBorder` (`#807C3AED`); rank and name bold, plus the songs label and rating on rankings rows (web `isPlayer`, operator batch 6.42). The score-history personal best uses the same treatment.
- **Floating board footer** (web `FixedLeaderboardPlayerFooter` + `FixedLeaderboardPagination`, `Controls/BoardFooter`): the pinned "your rank" row and the pager float over the bottom of the scrolling rows, which get a bottom inset as tall as the footer. The pinned row sits on the opaque `FSTFloatingBackplateBrush`, a solid stand-in for the web's backdrop blur, which would be recomputed every frame over animated art; the pager wears the rows' own card surface (#319, [surface-materials](../patterns/surface-materials.md) R1). There is no separate **Your page** button: the pinned row itself jumps to its page or opens the profile ([leaderboard-row](../patterns/leaderboard-row.md) R7, #307 and #318).
- **Pager** (operator batch 7.4, `Controls/LeaderboardsPager` over `IBoardPager`): the web `Paginator`, « ‹ `page / total` › as separate 40 epx circles with `textSecondary` chevrons, each circle and the 40 epx `page / total` badge on the rows' `FSTCardSurfaceBrush` + `FSTCardStrokeBrush` (#319: a surface `Border` behind a transparent `Button`, so the transparency and contrast fallbacks match the rows), disabled at 30% opacity, surface included, from the model's `CanGoBack`/`CanGoForward` as well as `IsEnabled` (under a contrast theme the host stays fully opaque, so its Window surface and rim stay solid, and only the glyph turns `SystemColorGrayTextColor`; `Festival.Core/Domain/PagerDimming.cs`, re-applied on `ContrastTheme.Changed`); hidden with a single page (web `totalPages > 1`); « and » drop below 380 epx. Keyboard: Left/Right/Home/End while focus is in the pager (web `keyboard` Paginator) and Ctrl+Left/Ctrl+Right from anywhere on the page (the tooltips name them); a button disabled under focus hands focus to an enabled one. Used by Full Rankings, Band Rankings, song leaderboards, the song band leaderboard and Player Bands.
- **Cards of rows** (`FSTRowsCardStyle`, operator batch 6.2/6.4/6.5): only for non-leaderboard lists (Search results): a 4 epx card inset, rows with 12 epx side padding whose hover/press fill (`FSTRowHoverBrush`) spans the card, and a hairline (`FSTRowSeparatorBrush`) between rows via `Controls/RowSeparators`. ListViews in such cards use `FSTCardListViewItemStyle`.
- **Modals** are built with `Controls/FestivalDialog.Create` and shown with `FestivalDialog.ShowAsync` (issue #23): a dark `ContentDialog` whose standard **Close** command (`CloseButtonText`: Close, Cancel or Dismiss; Esc triggers it too) dismisses it — no custom close glyph or in-content Close button. A lone command button spans the command row (`DialogChrome.FullWidthSingleButton`, web full-width modal buttons; rule in Core `ModalCommands`). `ShowAsync` goes through `MainWindow.ShowDialogAsync` (one dialog at a time), which adds `DialogChrome.LightDismiss`: a click on the dimmed backdrop closes the dialog like Esc (operator batch 6.14). It also adds `DialogChrome.ClearOfTitleBar` (issue #244). That puts top and bottom margins equal to the title-bar height (48 epx) on the template's `BackgroundElement`, so a tall dialog never grows into the caption band, where the window's own × sat over its top-right corner and quit the app. A taller body scrolls in the ContentDialog's own content scroller. Alerts with their own choices (Paths' Karaoke notice) pass an empty `closeText`. Under a contrast theme the command labels drop WinUI's automatic text backplate (`DialogChrome.CommandLabelsWithoutBackplate`; issue #239): the template already pairs them in system colours, and the backplate drew a Window box inside the default button's Highlight fill. Light-dismiss flyouts (profile, sort/filter, notifications) are not modals and keep their flyout behaviour.
- **Load-swap gate** (web `useLoadPhase`/`LoadGate`, issue #71): user-initiated page or board reloads run content out (300 ms) → centered white spinner → spinner out (500 ms) → content in with the existing `FadeIn` stagger. `Domain/LoadSwap` owns the phase/revision/timing with `TimeProvider`; `Controls/LoadSwapVisual` applies the WinUI opacity transitions and hides content from hit testing while it fades. With system/app Reduce Motion off, there are no fades, waits or minimum spinner time. Silent background refreshes keep content in place; pure client-side Songs sort/filter/search and Shop List/Grid restagger without a spinner. Applied to Leaderboards overview and the paged boards (Full Rankings, Band Rankings, solo song leaderboard, song band leaderboard, Player Bands); Paths keeps its compatible modal-specific swap from issue #70.
- **Page-ready gate** (web page-ready, operator batch 6.41): pages show one white ring until their first screenful is ready, then fade/stagger their content in; they never appear as a wall of skeletons. Songs (first-row art), Item Shop (first-tile art, again after List/Grid), Leaderboards (`LeaderboardsViewModel.IsReady`: first four instrument cards settled, now behind the shared load-swap gate on Rank By/F5 reload).
- **Section headers** (`FSTSectionHeaderStyle`): white Title Case `SubtitleTextBlockStyle`, heading level 2 for UIA.
- **Card headers sit outside (above) cards** app-wide, like the web's `InstrumentHeader` in a card label: `Controls/CardHeader` (36 epx instrument icon, title heading, optional subtitle such as "12,345 total entries"). Band-size headers (Duos/Trios/Quads) have no icon; the Leaderboards headers carry no metric subtitle (the Rank By button names it). Used on Song Detail, Leaderboards, Rivals, Rival Detail, Suggestions and the profile instrument sections.
- **"View all"** follows the [view-all-cta](../patterns/view-all-cta.md) pattern: a full-width brand-purple accent button (`FSTViewAllButtonStyle`) below a card's rows: below the top ten, or below row eleven when the selected player ranks outside it. Accent buttons use the web's `#7C3AED` (Styles.xaml overrides `AccentButton*` brushes), not the Windows accent colour; contrast themes keep system colours. **One button everywhere (issue #268):** Song Detail's View Full Leaderboard (instrument and band cards) and Score History's View All Scores, Leaderboards' View All Rankings and the Rivals hub's View All Rivals (both tabs; `/compete` opens the same page) all use the style with no per-page `Margin`, `MinHeight`, colour or font overrides. The style owns the 4 epx gap above the button, the 40 epx `FSTMinTargetSize` minimum height and `HighContrastAdjustment="None"` (contrast themes draw it HighlightText on Highlight; WinUI's automatic backplate drew a Window box behind the label, as on `ServiceStatusView`'s Retry). The card view model supplies `ViewAllText`, `ViewAllName` and `ViewAllAutomationId`. The name follows `ViewAllCta.Name`: the visible label first, then the card (WCAG 2.5.3), e.g. "View All Rivals, Lead Rivals" or "View Full Leaderboard, Duos". `ViewAllCtaTests` guards the consumers, the style and the name rule.
- **Filter and sort flyouts apply live** (operator 2026-09-28): no Cancel/Apply; each valid change commits at once and Reset restores defaults. Drafts load the applied value on open (`Begin()`), then turn live (`IsLive`); an inverted difficulty range waits until valid. Light dismiss / Esc closes.
- **Average stars** of exactly six draw five gold star images (web `GoldStars`) on the profile's per-instrument "Avg Stars" tile and the band "Avg Stars" card; other values show up to two decimals (web `formatClamped2`).
- **Songs rows**: ≥ 64 px card rows, 44 px art, title/`artist · year · duration`, 2 px gold (New) / red (Leaving Tomorrow) Shop border; trailing chart meter, status chips or metadata pills that wrap under the title in narrow lists ([songs/windows.md](../pages/songs/windows.md)). Rows have no chevron (card is the target, as on iPhone).
- **Jump index**: `SemanticZoom` (Ctrl+minus / pinch / header tap / **Jump** button) over group headers is the Windows equivalent of the iPhone section scrubber.
- **Wrapping rows of small items** (chips, pills, dialog selectors): `Controls/FlowPanel` (WinUI has no WrapPanel).
- **Difficulty meter**: branded 62×20 geometry from `DifficultyScale` ([spec](../controls/difficulty-meter/spec.md)); one `Image`-typed UIA element; unfilled bars become GrayText outlines under contrast themes ([windows notes](../controls/difficulty-meter/windows.md)).
- Instrument icons: the Apple asset catalogue PNGs (144 px), decoded once at 72 px and shared.

## Motion

- **Content fades in as it loads** (web `fadeInUp`, `Controls/FadeIn` + Core `FadeInTiming`): 400 ms CSS ease-out `cubic-bezier(0,0,0.58,1)` from opacity 0 and 12 epx lower, on the compositor. `FadeIn.OnShow` fades page content each time it becomes visible (bound to a loaded state); `FadeIn.Stagger` on an `ItemsRepeater`/`ListViewBase` fades rows realized within 1 s of the items changing, `(index + 1) × 125 ms` apart, for the rows that fit (`FadeIn.RowHeight`, web `estimateVisibleCount`, capped at 20); later rows just appear. Pages kept in the navigation cache don't replay on return. Songs keeps its art-priming gate and then staggers the realized rows (`StaggerRealized`), re-staggering on sort/filter/search changes like the web. Off under `Services/Motion.Allowed` (Animation effects off, in-app or launch Reduce Motion). Scrolling does not replay fades (checked for issue #60 by logging each played `FadeIn.Prepare` in a fixture-backed run: Song Detail 14 fades and Leaderboards 99, all at load, none after scrolling down and back up), because card repeaters realize every card at load and `Stagger` only arms on an items change, so Windows needs no iOS-style fade scope. Issue #260 re-checked it against the live service (scrolled down and back up through UI Automation, logging every played fade): Song Detail, Leaderboards, Player Profile, Shop and Player Bands play every content fade at load and none while scrolling (only the Song Detail pinned header fades in when it pins, as chrome). It also fixed two gaps. `FadeIn.Restagger(list, batchStart)` arms an appended batch only (Core `FadeInTiming.BatchDelay`: rows before the batch show in place, the batch staggers from its own first row; `MergeBatchStart` keeps back-to-back batches as one reveal). Suggestions uses it from `SuggestionsViewModel.CardsAdded` (0 for the first batch, new mix or filter change), as the web's `revealedCountRef` does. Global Search re-arms each results list when its section appears, because live rows stayed behind the spinner past the 1 s window and never faded. Validated after the fix against the live service: compact, medium, wide, maximized and snapped left (scroll down and back up: 0 fades while scrolling back on every page; Suggestions fades only each new batch's first visible cards), plus text 200% (compact) and the live a11y matrix in light, dark, Desert, Night sky, text 200% and display 100%/150% (Axe 0 errors and clean Tab walks, apart from the Search edge-clip artifact in [windows-accessibility](../testing/windows-accessibility.md#open-issues) item 7).
- **Item Shop pulse** (`Controls/ShopPulseFill`): see [song-detail/windows.md](../pages/song-detail/windows.md); looping motion also stops while the window is hidden (`Motion.Paused`, fed by the backdrop's occlusion policy).
- `Controls/MarqueeText` (operator 2026-09-28: like the web): any overflowing single line scrolls a two-copy track (8 s cycle, 5% dwell at each end, 28 epx gap, phase-aligned across instances from one epoch) via a compositor `Translation.X` animation; text that fits is plain. Any measurable overflow (over 0.1 epx) counts: a grid can measure a star column a fraction narrower than it arranges it, and the TextBlock then ellipsizes even a 0.3 epx overflow, so the old 1 epx slack left long names stuck as "Name…" in stacked leaderboard rows (issue #292, live 360 epx). Stopped (ellipsized) under Animation effects off, in-app/launch Reduce Motion, a hidden window (`Motion.Paused`) or when unloaded. Used for song titles/artists in Songs, Suggestions, Search, Shop, Rivals song rows and Band Detail songs, player and band names in every `LeaderboardEntryRow` (issue #292), and for card headers (`CardHeader`). UIA always reads the full text. `Stop()` touches the compositor animation only after `Play()` has started it: `Play`'s synchronous layout pass can rebind a recycled row, and `StopAnimation("Translation.X")` before Translation is enabled throws inside a XAML callback and fail-fasts the app (#276, Back from Band Rankings). Rows inside a cached page's cards use a non-virtualizing layout (`LeaderboardsCardGridLayout` with `MaxColumns="1"`), so Back doesn't re-estimate them ([compete/windows](../pages/compete/windows.md)).

Artwork motion follows [artwork-background](../controls/artwork-background/windows.md); system "Animation effects" off or in-app Reduce Motion gives a still cover. Sort/Filter use light-dismiss `Flyout`s whose changes apply live (see Content above), so there is nothing to discard.

## Accessibility

- AutomationIds follow the `product.json` families (`fst.nav.*`, `fst.songs.*`, `fst.profile.*`, `fst.service-status.*`, `fst.settings.*`). Decorative art is `AccessibilityView.Raw`. Rows set their UIA name to title + subtitle; buttons whose content is a panel set `AutomationProperties.Name`.
- **Groups:** cards that repeat rows (Leaderboards instrument/band cards, Rivals sections, Rival Detail categories) are wrapped in `Controls/AccessibleGroup`, a named UIA `Group`: Narrator says "Lead, group" on entry, and the same player atop several charts is not an ambiguous sibling.
- **Landmarks and headings:** page content (`FrameHost`) is the Main landmark ("Page content"), the title-bar search box the Search landmark; page titles are heading level 1, section headers level 2.
- **Announcements:** `Services/ScreenReader` raises UIA notifications (a live region alone does not speak in WinUI) from Core `LoadAnnouncer`: "Loading …" only when a read takes over 1 s, then the page's result summary (e.g. "245 songs", "Lead Rankings, page 1 of 20") after a 600 ms quiet period, so typing a search speaks only the final count. The shared service-status view announces each newly shown failure (heading + message) once. Settings Service Info announces each newly accepted band-discovery attempt count once, from the attempt line, with the phase row's spoken progress (issue #275). `ScreenReader.Announce` raises from the nearest element with an automation peer (the given element, else its closest visual ancestor): pages, `UserControl`s and panels have none, and raising from them was silently dropped until issue #269. Never call `RaiseNotificationEvent` on a peer you haven't null-checked, and prove new announcements with `listen:announcements` + `assertannounced:` ([testing/windows](../testing/windows.md)).
- **Collections:** `ItemsRepeater` is one Tab stop with no arrow-key navigation by default, which hid every item after the first from the keyboard. Card and control repeaters set `TabFocusNavigation="Local"`; row lists stay one Tab stop with `XYFocusKeyboardNavigation="Enabled"` (Up/Down between rows). Large uniform tile grids (the Item Shop grid, over 120 live tiles) follow the row-list rule with `TabFocusNavigation="Once"` (arrows move in two dimensions, like a Fluent `GridView`); Tab otherwise needed one press per tile to leave the page (issue #206). New repeaters must pick one of the two.
- **Quick Links:** a jump (menu or pane) scrolls, moves keyboard focus to the section's first focusable element and announces "<Section> section", like a web skip link.
- **Touch targets** (issue #72, Fluent "Guidelines for touch targets": 40x40 epx minimum): `Themes/Styles.xaml` `FSTMinTargetSize` (40) is the `MinWidth`/`MinHeight` of the title-bar Search, bell and profile buttons, and the `MinHeight` of the page tool buttons: Songs Sort/Filter/Jump (Jump is icon-only at compact, so also `MinWidth`), Suggestions Filter, history Sort, Leaderboards Rank By, the Full Rankings Instrument/Rank By and Band Rankings Band Size/Rank By pickers (#271; every `DropDownButton` now), the Song Detail pinned Paths and `QuickLinksMenuButton`. Default WinUI buttons are 32 epx tall, and the old 32/36 epx title-bar glyph buttons let a tap 18 epx off-centre fall through to the title bar. Buttons sharing a row with a 40 epx tool (Song Detail Paths/Item Shop, Player Profile Select/Deselect) use the same height; the Songs search box stays 32 and is vertically centred. Container spacing (8 epx) keeps neighbouring targets apart. The title bar recomputes its passthrough regions after the search box/button swap, the bell appearing or the title clearing (#271, `QueueDragRegionRefresh`, see [page-tools R10](../patterns/page-tools-and-nav-chrome.md)); otherwise taps on the swapped-in Search control drag the window. `HitTargetMarkupTests` guards the markup; [windows-accessibility.md](../testing/windows-accessibility.md#checks) has the live off-centre click check.
- **Keyboard:** Ctrl+1…7 open the visible pane sections in order and Ctrl+comma opens Settings (tooltips "Songs (Ctrl+1)", UIA `AcceleratorKey`); Alt shows access keys on pane items (S, U, T, R, L, I, E in pane order) and the profile button (P); Ctrl+E global search, Ctrl+F in-page find, F5 refresh on ranking/rivals pages; Alt+Left / Back / XButton1 go back, including from a focused text field (tunneling `PreviewKeyDown`). The TitleBar itself is not a tab stop. Flyouts and dialogs close on Esc and return focus to their invoker. Back to a cached section root returns focus to the control that opened the pushed page without scrolling (`Services/CachedPageScroll`, agent decision #276; [Compete notes](../pages/compete/windows.md)).
- **Contrast themes:** the artwork backdrop is hidden (`ArtworkPlaybackPolicy` `HighContrast` input → `Hidden`), so content sits on the theme's window colour; card, header, secondary-text and meter brushes map to system colours in the `HighContrast` theme dictionary.
- **Contrast roles** (decided 2026-09-29, win-unify; Fluent contrast-theme guidance: use the system colour pairs by meaning, never a brand hue): `Themes/Styles.xaml` defines role brushes with the brand value in `Default` and a system colour in `HighContrast`, and `Services/ContrastTheme` (`IsOn`, `Brush`) serves code that computes a brand tint. Meaning never rests on hue alone: shape, weight, text and the UIA name carry it too.

Charts (rank history bars, score history bars and line) keep brand data hues; their values are on the axes and in each bar's UIA name. In contrast themes both charts draw axes, gridlines and bar outlines in WindowText (#195 Song Detail, #204 Rank History, #212 shared graph).
- **Live contrast switch** (issue #214): `{ThemeResource}` brushes follow a contrast theme switched on while a page is open, but a scoped `<StaticResource x:Key="ButtonBackground" ResourceKey="FST…"/>` alias resolves once and keeps the old theme's brush. For new scoped lightweight styling, merge a theme-dictionary file (`Themes/{NavRow,FirstRun,Danger}ButtonResources.xaml`) instead; other pages' `FSTDanger*` aliases are open in [settings/windows.md](../pages/settings/windows.md#open). - **Text size:** controls keep `IsTextScaleFactorEnabled`; at ≥150% the title-bar caption text is dropped so the global search box keeps its width.
- **Motion and transparency:** system Animation effects off or in-app Reduce Motion → still artwork and no marquee; transparency off or in-app Less Transparency → opaque cards and the overlay pane's acrylic uses its solid fallback.
