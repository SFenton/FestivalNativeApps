# Navigation accessories (iPhone, Duo, pre-26)

> **What:** Lane A2's decision record for where each page's controls go: the top navigation bar, the bottom page-tools row beside the tab bar (Music's mini-player slot), global search, or the page content. Covers iOS 26.1+ (Liquid Glass), iOS 17–26.0, and the iPhone Duo vertical bar. **Read when:** adding a toolbar item, search field or persistent action to any Apple page.

"Nav bar accessory" in operator requests means the **bottom page-tools row**: the controls above the floating tab bar that tuck in beside it when it minimizes, like Music's mini player. The web calls its tab bar "BottomNav", hence the name. Since issue #89 (2026-10-03) it is the app's own `PageToolsDock`, not the system `tabViewBottomAccessory`, because the owner asked for the tools *next to* the search field, collapsing to [tab] [search] [sort] [filter] [quick links].

## APIs (iOS 27.1 SDK; verified in the swiftinterface and on the iOS 26.5 simulator)

| API | Availability | Finding |
|---|---|---|
| `tabViewBottomAccessory { }` / `(isEnabled:)` | 26.0 / **26.1** | One accessory per `TabView`, attached at the root. It sits above the tab bar and moves **inline** beside the minimized tab bar (`tabViewBottomAccessoryPlacement` `.expanded`/`.inline`). It is always **one full-width system capsule** (27,737 348×44 expanded; it fills the space beside the minimized tab inline), so separate round tools can never sit beside it: **no longer used** (issue #89) |
| `tabBarMinimizeBehavior(.onScrollDown)` | 26.0 | Collapses the tab bar to the selected tab on scroll, **with or without an accessory**. No public value reports it (26.5, iPhone 17 Pro): the `UITabBar` frame (0,791 402×83), `contentLayoutGuide`, the tab's safe area (bottom 83) and `UIScene` traits stay put. Only the bar's largest visible subview (the glass platter) changes: 43,791 317×62 expanded (three tabs) → 28,798 48×48 minimized (XCUITest reports the tab button's value "Collapsed"). KVO on that view's frame never fires; KVO on `tabBar.layer.sublayers` fires on every change (3× minimize, 2× expand). `TabBarWatcher` uses that |
| `toolbarMinimizationBehavior`, `UIBarMinimization` | **27.0** | The public minimize state; not on the 26.x iPhone, so not used yet |
| `Tab(role: .search)` + `tabViewSearchActivation(.searchTabSelection)` | 18 / 26 | The system search tab **counts toward the five-tab limit**: with five sections the bar became Songs · Suggestions · Compete · Statistics · **More**, hiding Settings and Search. Rejected |
| `.searchable` in a tab's `NavigationStack` | 15+ | Field in the nav-bar drawer under the large title |
| `searchToolbarBehavior(.minimize)` | 26.0 | Field becomes a **top** toolbar button, trailing, **after** the avatar (breaks the avatar-rightmost rule) |
| `DefaultToolbarItem(kind: .search, placement: .bottomBar)` | 26.0 | Inside a `TabView` the bottom toolbar renders **behind** the floating tab bar: unusable |
| `.searchable(isPresented:)` set programmatically | 17+ | Did **not** activate a minimized field on 26.5 (from a button or a `.task`) |
| `TextField` inside the accessory | 26.1 | Taps did not focus it, and the accessory does not ride above the keyboard: rejected. Songs' dock search is still a field-shaped button that opens a focused bar above the keyboard (rule 14) |
| `Menu` inside the accessory | 26.1 | Highlights on tap but never opens (26.5, issue #42). The dock is ordinary SwiftUI over the `TabView`, where Quick Links' round `Menu` opens |
| `safeAreaBar(edge:)` | 26.0 | Custom bar that insets the safe area and extends scroll-edge effects |
| `ToolbarItemPlacement.subtitle` / `.largeSubtitle` / `.largeTitle` | 26.0 | Text beneath/around the title. Not used yet |
| `ToolbarItemVisibilityPriority`, `toolbarMinimizationBehavior` | **27.0** | Duo overflow priority (W1/W3 use it for bell and avatar). Not on the 26.5 iPhone |

## Rules (operator, 2026-09-28: "search and profile in the header, page tools float"; issue #42, 2026-10-01: Songs search rides the bottom on iOS 26.1+; issue #89, 2026-10-03: search and the round tools share one row that tucks in beside the minimized tab bar)

1. **Header (top navigation bar):** global **Search** and the **profile avatar** are separate buttons on every page, avatar rightmost (`FestivalRootTrailingItems` on tab roots: Search, then the bell and the avatar as separate glass buttons; `.globalSearchToolbarItem()` on pushed pages). The avatar opens profile selection (select, switch, deselect).
2. **One row of separate controls beside the tab bar** (issues #42 and #89; iPhone iOS 26.1+, horizontal tab bar). `PageToolsDock` (`Common/TabAccessory/PageToolsDock.swift`), an overlay on the root `TabView` from `festivalTabAccessoryHost()`, draws the front page's registered controls (`TabAccessoryRegistry.frontItems`) in one row in a `GlassEffectContainer` (`FestivalGlassGroup`, 12 pt spacing): Songs' **search** field capsule (`DockItemKind.field`, flexible width) then icon-only **round** glass buttons, **Sort · Filter · Quick Links** (48 pt circles, the minimized tab's size). Each page shows only what it has; with no field the circles align trailing. Expanded, the row spans 20 pt margins 10 pt above the tab bar's glass; when scrolling minimizes the tab bar it moves into the tab-bar row beside the round tab, its far margin mirroring the tab's (402 pt iPhone: x 88–374, centred on the tab), and the search field shrinks to "Search" or its magnifier alone (HIG Search fields: "choose an expanded field or button according to available space"). Animated with `.smooth(0.35)`, no animation under system or app Reduce Motion (HIG Accessibility: "reduce automatic and repetitive animation"). `TabBarWatcher` reports the bar's `TabBarGeometry` (pure `isMinimized`: platter width ≤ 1.5 × height), `PageToolsDockLayout.resolve` places the row (pure, RTL mirrored: the minimized tab sits on the leading side); if the tab bar is not found the row rests where a standard bar would put it (expanded), never over the tabs. Each tab's `FestivalTabStack` keeps a `PageToolsDockLayout.pageInset` (58 pt) bottom `safeAreaPadding` while its page has dock controls (`FloatingPageControls.inset`), so lists and the A–Z rail end above the expanded row and page-owned bottom bars (the Full Rankings pager, Lane PB) stack above it. The open Songs search bar hides the row (`setDockSuppressed`). VoiceOver reaches the row after the tab bar (it overlays the `TabView`). `PageToolsPresentation.resolve` picks `.accessory` (this row), `.floating` or nil (Duo rail, iPad, Mac) and the host publishes it as `\.pageToolsPresentation`. **iOS 17–26.0:** no row; Sort, Filter and Quick Links float as separate round 50 pt buttons trailing-aligned above the tab bar (`FloatingPageControls`), and Songs keeps its `.searchable` drawer field.
3. **Search is its own control; actions are their own buttons** (issue #89 reverses the issue #42 "one capsule" call). In the system accessory's one shared capsule, Filter, Sort and Quick Links read as part of the search bar, and a page's only tool (Quick Links) spanned it as a full-width text capsule; floating the tools *above* the capsule (the first #89 fix) kept them apart but not beside it. HIG Toolbars: "A tab bar navigates app areas; a toolbar acts on content" and "Separate text from symbol actions so they don't appear as one control"; HIG Buttons: "Icon-only buttons typically use `circle`" and "the hit region is at least 44x44 pt". So the field is its own capsule and each tool an icon-only circle with its own VoiceOver label (Quick Links: "Quick Links", value = the current section) and a 48 pt hit square (`FloatingPageToolLabelStyle`, rule 13). Global Search, the bell and the avatar stay in the header (rule 1); profile Select stays a header button (rule 4). HIG Tab bars (iOS): "With an attached accessory such as Music's MiniPlayer, scrolling down can minimize the bar and move the accessory inline; tapping a tab or scrolling to the top exits … when minimized, the current tab is at the leading bottom, the accessory is centered". HIG Search fields: "Place search at the bottom if there's room; this keeps priority search easy to reach."
4. **Player page Select / Switch / Deselect** is its own header button (text, prominent for Select/Switch; `ProfileIdentityToolbarItem`), `VerticalBarActionItem` in the Duo rail.
5. **Duo vertical bar, iPad, Mac:** no floating controls (`isTabAccessoryAvailable == false`); the same tools are toolbar items.
6. **Pages register, the root publishes.** `.festivalTabAccessory(token:order:kind:isEnabled:) { … }` registers a tool while its view is visible (`DockOrder`: Search 0, Sort 10, Filter 20, Quick Links 30, the web's Songs FAB order; `kind: .field` for the flexible field capsule); `.quickLinks(…)` registers Quick Links itself (`QuickLinksMenu`, a round `Menu` everywhere on iPhone) and `QuickLinksToolbarItem` steps aside. Tools render in the root's environment: pass closures and include every displayed value in `token`. Never put a `Menu` in the system `tabViewBottomAccessory`: it does not open there.
7. **Sheets apply immediately.** Songs Filter and Sort have no Cancel/Apply: every change applies, and a trailing **Done** closes the standard `festivalSheet` modal.
8. **The tab bar minimizes on scroll** (iOS 26.1+, horizontal tab bar, issue #42): `tabBarMinimizeBehavior(.onScrollDown)`, so the page-tools row moves beside the selected tab (rule 2); scrolling to the top or tapping the tab expands it again (system behavior, Reduce Motion handled by the system). Applies on every tab; the Duo rail, iPad and Mac keep `.automatic`.

9. **Header legibility:** every page gets `TopEdgeScrim` (`Common/Chrome/PageChrome.swift`): iOS 26 `scrollEdgeEffectStyle(.soft, for: .top)` plus a dark gradient behind the bar region over the artwork (the gradient alone before 26). Collapsed inline titles are 20 pt semibold, Dynamic Type scaled (`NavigationTitleStyle`).
10. **Bell only with a selected profile**; Search and the avatar always show. On a 375 pt-wide iPhone a tab root carries at most drawer + page action + Search + bell + avatar; titles collapse inline beside them rather than truncating (large titles sit below the bar).
11. **Sheets open at the large detent** (`festivalSheet`, both presets); `.compact` can still be dragged down to medium.
12. **Floating tools rise into the bar while scrolled** (issue #13, iPhone iOS 17–26.0 only; on 26.1+ the row follows the minimized tab bar instead and `PageToolsHandOff.toolsInBar(scrolled:presentation:)` is false). A page whose tools float may hand them to the navigation bar once its list scrolls away from the top, for every viewer, and take them back at the top. Use `PageToolsHandOff` (`Common/TabAccessory/PageToolsHandOff.swift`) for the decision, the shared animation and the dock transition; `FloatingPageControls` already animates its half. Under system or app Reduce Motion it is a cross-fade (HIG Accessibility: "replacing axis transitions with fades"). Never toggle `toolbar(removing: .title)` with it: removing the title removes the large title and jumps the list; use a permanent empty `.principal` item when the inline title has no room. Keep the trailing side at three groups (HIG Toolbars: "generally use no more than three groups"); the system overflows the rest into **More**. A page's inline list filter stays pinned (`.navigationBarDrawer(displayMode: .always)`; HIG Search fields: "consider pinning it to the top toolbar while scrolling"). Songs only so far; Suggestions' Filter and Search are toolbar items already.
13. **Forgiving hit regions** (issue #15, iPhone; HIG Buttons: "the hit region is at least 44x44 pt"). Floating page tools render their label through `FloatingPageToolLabelStyle` (`Common/TabAccessory/TabAccessory.swift`): a 50 pt square frame and rectangular `contentShape` *inside* the label, because a SwiftUI `Menu` (Quick Links) only answers taps on its label and ignores a frame applied around it. `FloatingPageControls.spacing` and `PageToolsDockLayout.spacing` (12 pt) keep neighbouring squares apart (50 pt squares before 26.1, 48 pt in the 26.1+ row). Header items stay standard bar buttons (symbol or image `Label`), which the system already expands to about ±20 pt around the 36 pt glass; a custom-view item does not get that expansion, so the selected-profile monogram is rendered to a cached image with original rendering (`MonogramLabel`/`MonogramImageCache` in `App/Shell/RootChrome.swift`) and shows as a round button like Search and the bell. Measured on iOS 26.5: drawer, Search, bell, profile, Choose Profile, in-bar Songs tools and Suggestions Filter accept taps 20 pt off-centre; the dock Quick Links menu used to miss at ±12 pt vertical. Tests: `NavButtonHitRegionTests` (unit), `NavButtonHitRegionJourneyTests` (XCUITest; needs `mock_service.py --large-catalogue` and `TEST_RUNNER_FST_SONGS_SCROLL_FIXTURE_URL`).
14. **Songs search leads the row** (issues #42 and #89; the only `.field`): a field-shaped glass capsule button (`SongsSearchAccessoryButton`, "Search songs or artists", shortened to "Search" or the magnifier beside the minimized tab bar, VoiceOver "Search Songs", the query once typed plus an inline Clear) opens `SongsSearchBar`, a glass field in the page's bottom `safeAreaInset`, focused on open, so it rides above the keyboard while the row steps aside (HIG Search fields: a bottom field "animates above the keyboard when tapped"). Return keeps the query and closes; the trailing Cancel clears and closes; losing focus closes. Move transition, a fade under Reduce Motion. It filters the Songs list like the web dock's search; global search stays the header button. The row is fixed-height like the tab bar, so its text stops at `PageToolsDock.maxTypeSize` (xxxLarge) and every dock control shows the Large Content Viewer; the XCUITest accessibility audit flags that search button (Dynamic Type, text clipped), which the system accessory hid from it, so Songs audits accept only those two findings on `fst.songs.search.open` (`SongsUITestSupport.auditSongsWithDock`). Its 0.8-opacity placeholder fails the audit's contrast check over Item Shop rows, as it did in the system accessory (open). Elsewhere Songs keeps `.searchable` "Filter Songs" (nav-bar drawer, pinned on iOS 17–26.0 iPhone).

## Transitions and small widths (Lane A3)

- **One page's tools at a time.** Pages are transparent over the shared artwork, so during a push or pop the outgoing page's floating buttons showed through beside the incoming page's. `TabAccessoryRegistry` records pages in appearance order (`pageAppeared`/`pageDisappeared` from each `FloatingPageControls`); only the latest page still on screen shows its tools (`isFront`/`frontItems`), while every page keeps its bottom inset so layout never jumps. SwiftUI calls the incoming page's `onAppear` when the transition starts and the outgoing page's `onDisappear` when it ends; a cancelled interactive pop hands the tools back when the revealed page disappears again. Verified by recording a Songs → Song Detail push and pop (frames show only one set).
- **Search sheet → push:** the chosen route is stored and pushed in the sheet's `onDismiss` (A2, `4e49ae7`), like the profile sheet.
- **No duplicate Search:** a root screen pushed as a page (Leaderboards from the drawer) already ends with `FestivalRootTrailingItems`; `GlobalSearchToolbarItem` reads `FestivalRootTrailingProvidedKey` and steps aside.
- **375 pt (iPhone SE width):** no FST SE simulator exists, so `FST_DEBUG_CANVAS_WIDTH=375` (Debug) lays the whole app out in a 375 pt canvas on the 402 pt iPhone 17 Pro. Captured with SFentonX: every tab root's large title (Songs, Suggestions, Compete, the player name on Statistics, Settings, Leaderboards) fits untruncated beside drawer + page action + Search + bell + avatar.

## Quick Links: a round floating button

**Round button on iPhone, toolbar item elsewhere** (issue #89, 2026-10-03). This lane first kept Quick Links in the top toolbar; the operator then asked for the web's bottom FAB dock, then separate floating buttons (2026-09-28); issue #42 moved every page tool into the tab-bar accessory, where Quick Links had to open a sheet (a `Menu` cannot open there) and, alone on a page, filled the capsule with its title. Issue #89 asked for "just a circle" next to the search bar: on every iPhone it is a round glass `Menu` (icon `list.bullet.indent` only, after Sort/Filter, opening upward), in the 26.1+ row beside the minimized tab bar; on the Duo rail, iPad and Mac it stays a toolbar `Menu` (inspector later). Both mark the active section with a checkmark. `QuickLinksSheet` was removed.

## Drawer

Matches the web sidebar (`Sidebar.tsx`): Songs, Suggestions*, Statistics*, Rivals*, Leaderboards, Item Shop (*player), the current destination highlighted; the profile row (name → profile, **Deselect**) or **Select Profile**, then **Settings** pinned at the bottom. Bands and Licenses are not listed (Bands: search and leaderboard links; Licenses: Settings).
