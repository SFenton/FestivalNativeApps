# macOS design

> **What:** the Mac shell and page-layout decisions, each with the `apple-hig` file it rests on. **Read when:** changing the Mac window, sidebar, toolbar, menus, Settings window or a page's Mac layout. Host limits and the evidence tool: [platforms/apple/macos.md](../../platforms/apple/macos.md).

Code: `apple/Apps/macOS/FestivalDesktopApp.swift` (scenes) and `apple/Sources/FestivalUI/Mac/**` (`MacRootView`, `MacNavigation`, `MacListDetailStack`, `MacColumnDivider`, `MacKeyboardNavigation`, `MacCommands`, `MacPageMenus`, `MacCopy`, `MacSettingsView`, `MacDebugHooks`); shared Mac-aware pieces: `Features/Settings/SettingsPane.swift`, `Common/FestivalRowButtonStyle.swift`, `Features/Songs/SongRowLayoutPolicy.swift`. The iPhone/iPad `FestivalRootView` is not used on the Mac; pages, `AppRouteDestination`, `ListDetailPolicy` and `FestivalSession` are shared. HIG files are `~/.claude/skills/apple-hig/references/hig/<file>.md`.

## Shell decisions

| Decision | HIG basis (file › clause) |
|---|---|
| One primary `Window` (no File › New Window, tabbing off) holding a `NavigationSplitView`: sidebar + detail. New Window stays out: one session and one selected player drive every page, and no page is a document to compare side by side | windows › "Choose the right moment to open a new window … avoid it as default behavior unless it makes sense for your app"; designing-for-macos › "fewer nested levels and less modality" |
| Sidebar rows follow the web pinned sidebar: Songs, Suggestions\*, Statistics\*, Rivals\*, Compete\*, Leaderboards, Item Shop (\* selected player; Item Shop hidden by Settings › Hide Item Shop). SF Symbols tinted by the accent | sidebars › "Consider using familiar SF Symbols … in macOS, honor the accent color people choose" |
| Sidebar collapsible (toolbar button + View › Show/Hide Sidebar via `SidebarCommands`), shown by default; width 190–300 pt (ideal 220) | sidebars › "do not hide it by default … macOS a show/hide button or View-menu commands" |
| Selected player in the sidebar footer (name → Statistics, **Deselect**; **Select Profile** when anonymous). The same actions are in the Profile menu and the toolbar avatar (with a player it selects Statistics, help "Show Statistics for <name>"; anonymous it opens the sheet: `MacNavigationModel.pressProfileButton`, issue #290) | sidebars › macOS "Keep critical information/actions away from the bottom, which may be offscreen" (hence the duplicates) |
| **Settings is a Settings window** (App menu › Settings…, ⌘,), not a sidebar row: a `TabView` toolbar of panes **General** (Accessibility, Item Shop, Leaderboards, Feedback when the service enables it, Diagnostics in Debug, Reset), **Songs** (Song Rows, Show Instruments, Show Instrument Metadata), **Paths** (CHOpt Paths, Invalid Scores), **Guides**, **Service**, **About** (version, What's New, Licenses). Each pane is a subset of the shared `SettingsScreen(pane:)` with the same keys and identifiers, in its own stack (Licenses opens inside About); the window is titled for its pane and restores the last one (`fst.mac.settingsPane`). Single choices are pop-up buttons; glass-section rows use the 28 pt Mac minimum height | settings › macOS "a toolbar of related panes … title the window for its pane … restore the last pane"; pop-up-buttons › "a flat list of mutually exclusive options"; accessibility › macOS control size 28×28 pt default; keyboards › "Command-Comma … Open app settings window" |
| One shell-owned trailing toolbar group: Search, bell (selected player only, unread badge), profile avatar. Pages omit their copies via `\.shellOwnsGlobalToolbar`, because both columns of a split contribute to the one unified toolbar | toolbars › "generally use no more than three groups"; "Trailing: important always-available items … optional search" |
| Page tools stay page toolbar items (Songs Sort/Filter, Item Shop Filter, Leaderboards Rank By, Quick Links, Song Detail Item Shop/Paths); Songs' inline "Filter Songs" `.searchable` sits at the toolbar's trailing end | search-fields › iPadOS and macOS "put search at the trailing side of the toolbar, especially in split views where people search across columns while keeping the selected item visible in detail" |
| Global search stays the Search sheet (⌘K, Edit › Search Festival… ⌘F), not a second toolbar field beside Songs' filter field | search-fields › "Use an inline field when adjacency clarifies that it filters one view rather than searches globally" |
| Window: default 1280×820 pt, minimum 760×540 pt; frame kept with an autosave name; AppKit restoration **off** (`isRestorable = false`) so a crash or forced quit never leads to the "reopen windows" prompt; the last sidebar destination is restored from `fst.mac.destination` | windows › "Make sure windows adapt fluidly to different sizes"; launching › "Restore as much granular prior state as possible on restart" |

## Menu bar (`MacCommands`)

| Menu | Items |
|---|---|
| App | About, **Settings… ⌘,** (system) |
| File | **Close ⌘W** only (New items and the system Close group replaced; one window) |
| Edit | Standard text editing; **Copy ⌘C** with no focused text copies the selected row's song title or player/band/rival name (`MacSelectionCopyResponder` after the window in the responder chain, so the system item keeps its validation); **Search Festival… ⌘F** |
| View | **Refresh ⌘R** (the frontmost page's own refresh via the shared `RefreshCommandRegistry`, else rebuilds the detail column), **Enter/Exit Full Screen ⌃⌘F** (system `toggleFullScreen`, title follows state), **Sort…**, **Filter…** (page-published via `macPageCommands`, disabled when the page has none), **Rank By ▸** (the front rankings page's metrics, checkmark on the one in effect; Leaderboards, Full Rankings, Band Rankings, Band Detail publish `macRankByCommands`; elsewhere the account metrics stay listed, disabled), **Instrument ▸** (Full Rankings' Settings-visible charts via `macInstrumentCommands`, checkmark on the current board; elsewhere every chart stays listed, disabled; issue #294), **Scroll to Selection ⌘J** (the focused list's selected/highlighted row), Show/Hide Sidebar ⌃⌘S (`SidebarCommands`), toolbar items |
| Go | **Back ⌘[**, every destination (⌘1…⌘n for the n-th visible row; hidden rows disabled, never removed), **Search… ⌘K**, **Quick Links ▸** (the page's sections, the active one checked; "No Sections" disabled when the page has fewer than two), **Next Section ⌥⌘↓**, **Previous Section ⌥⌘↑** (disabled at the ends). The detail column's Quick Links win over the list column's (`MacQuickLinksPublisher` keys by column) |
| Song | **Paths…**, **Open in Item Shop** (Song Detail's toolbar tools, published through `macSongCommands`) |
| Profile | Select/Switch Profile… ⇧⌘P, Deselect Profile, **Find Rival…** (Rivals), Notifications |
| Window | System (Minimize, Zoom, Bring All to Front) |
| Help | Festival Score Tracker Website, What's New, Licenses |

Menu commands publish only from the **top page of their column** (`\.macPageIsTop`, set by `MacStack`): a page under a push stays alive and would otherwise fight the page in front. Quick Links, Rank By and Instrument use focused scene values like Sort/Filter, so they read disabled while the app is in the background.

Basis: menus › "Make sure a submenu remains available even when its items are unavailable", "Consider a checkmark to show an attribute is in effect", "Prefer a submenu to indenting items"; keyboards › Command-J "Scroll to selection" (standard; Quick Links therefore uses ⌥⌘↑/↓, Option "for less-common commands or power features"); the-menu-bar › "Provide a View menu even if it holds only Enter/Exit Full Screen", "Ensure show/hide titles reflect current state", File menu "Close … Closes the current window", Edit menu "Copy … To the Clipboard"; going-full-screen › macOS "Use the system full-screen experience … View menu item or Control-Command-F"; the-menu-bar › "Disable, don't hide, unavailable items", "Provide app-specific menus for custom commands", "Provide a Window menu even if your app has only one window"; toolbars › macOS "Every toolbar item must also be a menu-bar command"; keyboards › "Define custom keyboard shortcuts for only the most frequently used app-specific commands" (Sort, Filter and Notifications have none) and "List modifier keys in the correct order". Back with two columns never empties a root list's detail (it would only auto-select again): `MacSidebarPolicy.backPath`.

## Layout at Mac widths

| Rule | Basis |
|---|---|
| **Two populated columns** (`MacListDetailStack`) for Songs, Full Rankings → Player and Rivals lists from 820 pt of content: list 38% within 340–560 pt beside a **draggable 1 pt divider** (`MacColumnDivider`: 8 pt grab area, column-resize pointer, double-click resets, an adjustable slider for assistive technologies); a dragged width is clamped to 340–680 pt with the detail ≥ 480 pt and remembered in `fst.mac.listColumnWidth`. Detail is never empty: last selection, else the **topmost** visible row auto-selects (rows offer their top edge to the shared `ListDetailAutoSelectCollector`); a list with no row after 2.5 s collapses to one column and splits again when its first row appears. One toolbar **Back** (`MacSidebarPolicy.backPath`) serves both columns | split-views › macOS "draggable dividers resize them … set reasonable minimum/maximum defaults so the divider stays visible", "Prefer the 1 pt thin divider"; pointing-devices › macOS "Resize left/right" pointer; split-views › "Persistently highlight the current selection" (`listDetailSelectable`) |
| Every Mac column publishes its own `DeviceLayout`; width class is **regular from 720 pt** (`MacLayoutPolicy`), so Leaderboards/Compete cards and Profile instrument tiles use two columns and Settings/Licenses use the 680 pt readable width (web detail-card grid: two 420 px columns from 844 px) | layout (foundation); designing-for-macos › "show more content … while keeping information density comfortable" |
| Songs **Sort is a popover** from its toolbar button (no modal chrome; closes on an outside click); **Filter is a sheet** (long form) with grouped form style and a 560×640 pt default (`macSheetFrame`) | popovers › "Limit a popover to a little information or functionality"; popovers › "Use a Close … only for confirmation"; sheets › macOS "Present a sheet in a reasonable default size" |
| Item Shop **Filter is a short sheet** (three switches + Reset, 420×360 pt `macSheetFrame`) from its toolbar button and View › Filter… (`macPageCommands(filter:)`) | sheets › macOS "Present a sheet in a reasonable default size"; toolbars › macOS "Every toolbar item must also be a menu-bar command" |
| Profile, Search, Notifications and What's New are window sheets (Close in the sheet's bottom bar) | sheets › "Display only one sheet at a time" (menu items disable while one is open) |
| Toolbar buttons and sidebar rows carry `.help` tooltips naming their shortcut | pointing-devices › macOS pointer conventions (system hover/selection states on standard controls) |
| **Row interaction**: whole-row buttons (list/detail links, leaderboard and score-preview rows, Shop, Suggestions, Notifications, Bands rows, view-all buttons) tint white 7% under the pointer and 14% pressed, never scale, and draw the system keyboard-focus colour as a 3 pt ring in the card's shape when Full Keyboard Access focuses them; Return opens a focused row as Space does. `festivalRowButtonStyle()` (plain on iPhone/iPad); list/detail links decorate their label instead of replacing the style. Mac Songs rows are the link's label (an invisible link's ring would be invisible) | pointing-devices › "reserve scaling for elements that can grow without crowding neighbors (not table rows); … consider tint without scale and shadow"; focus-and-selection › "Rely on system focus effects", "highlight items in lists"; keyboards › "Support Full Keyboard Access" |
| **Arrow keys in lists** (`MacKeyboardNavigation`, applied by `MacStack` to every page): a page that offers rows is **one keyboard focus stop** that takes focus once when its rows first arrive and when a row is clicked; ↑/↓ move the selection (←/→ and grid rows in the Item Shop artwork grid), Home/End jump, Return opens, Escape clears an unopened highlight. In a split's **list column the selection is the detail route**, so the detail follows every move; in one column a highlight moves and Return pushes. Pages declare rows from their data (`macKeyboardRows`), not from built rows, because lazy `List`/`LazyVStack` rows do not exist off screen; each row gets its scroll identity and highlight from `macKeyboardRow` (Leaderboards rows name their lazily built card, scrolled to first). Songs (every song in list order), Full Rankings, Band Rankings, Rivals (every section's preview rows, in section order), Leaderboards (each card's rows, then View All, card order) and the Item Shop (list rows → Song Detail, grid cards → the official Item Shop, as a click does) | focus-and-selection › "you only need focus for content like list items, text fields and search fields", "highlight items in lists and collections", "You can ring an item that fills a cell, like a photo" (grid cards get a 4 pt ring); keyboards › "holding an arrow key moves the selection by the smallest app-defined unit of distance until released"; split-views › "selecting an item in the primary pane shows its contents in the secondary" |
| **Selection colour follows focus**: a split's selection and a keyboard highlight are accent while their column has keyboard focus and gray otherwise (also in an inactive window) | focus-and-selection › "white text on an accent-color highlight when focused, standard text on gray when not (`UICollectionView`, `NSTableView`)" |
| **Continuous decoration pauses while the window cannot be seen** (minimized, fully covered, another Space, locked screen; `NSWindow.occlusionState`, hide reported after 0.5 s because covering flapped it): the artwork carousel, song-cover fades, Shop pulses and marquee titles share `AnimationActivity.sceneActive` (scene active **and** `\.festivalWindowVisible`), as the Windows app pauses when occluded or minimized | No HIG clause covers hidden windows; parity with the Windows app and energy (nothing on screen changes). The pause also applies to the inactive-scene rule the iPhone uses |
| **Songs rows on one line** when the row fits artwork, a 180 pt title column, the chips and the Shop slot (`SongRowLayoutPolicy`, the web's desktop `songRow`; decided per list, so rows never mix layouts). Fits in one column (content ≥ 650 pt with nine instruments) but not in the 340–680 pt list column. Leaderboard rows already match the web's 48 px `entryRow` with 4 px gaps, so they are unchanged | designing-for-macos › "show more content … while keeping information density comfortable"; lists-and-tables › "Keep item text succinct" |

## Implementation gotchas

- Inside the window's `NavigationSplitView`, a page pushed in a **nested** `NavigationStack` (the split's columns) is presented over both columns (list column) or not at all (detail column). Each split column therefore draws its top route as its root and turns pushes into path writes (`MacListDetailStack.pushes(after:)`); only the one-column arrangement uses real pushes. An `HSplitView` also lost its divider position when a pushed list page split after first layout (detail at zero width), so the columns are an `HStack`; a draggable divider is open.
- Toolbar items attached outside a `NavigationStack` disappear once a page is pushed: the global group is added to every page of the primary column (`MacGlobalToolbar`).
- An environment value published **around** a column's `NavigationStack` (`publishesDeviceLayout`) did not reach its pushed destinations: every pushed Mac page read the default zero-width compact `DeviceLayout` (Band Detail and Player Profile stayed one column). `MacStack` reads the column layout (`MacColumnLayoutReader`) and sets it on each destination. Values set higher up (the window root) do reach them.
- A lazy list's first `onAppear` is not its first row (Full Rankings auto-selected #6), hence topmost-by-geometry.
- An `.accessibilityIdentifier` on a non-element container replaces every child element's identifier: the split `HStack` hid all row and divider IDs until it became `.accessibilityElement(children: .contain)`. The iPad `ListDetailStack` (`fst.nav.list-detail` on the `NavigationSplitView`) has the same pattern.
- A view with an `.accessibilityAdjustableAction` on a `Divider` exposes `AXUnknown` with no value; `.accessibilityRepresentation { Slider }` gives a real `AXSlider`.
- The empty-list collapse waits 2.5 s of wall-clock time (`\.macListCollapseDelay`); hosted auto-select tests lengthen it, because a loaded machine (parallel suite plus other lanes) reached it before the first row offered itself.
- Menu focused values (`macPageCommands`, `macSongCommands`) need a key window; two pages publishing one key at once would fight, hence a separate key for Song Detail.

## Open gaps

- Arrow keys were verified through `NSWindow.sendEvent` in hosted tests and in the live app (`mac_app.py command key:…`) with the window **inactive** (the tools never activate the app), so live shots show the gray, unfocused selection; the accent focused state, Tab order and the menu items' enabled states in a key window still need an operator check (Full Keyboard Access and Automation Mode are system settings agents must not change).
- First-run copy comes from the web catalogue ("Tap …", "bottom tabs"); the Mac carousel rewrites it to "Click …" and "the sidebar" (`FirstRunCopy.mac`, writing › "describe gestures correctly"). "the action button" (Paths slide) still names the iPhone control.
- Song Detail, Player Profile and Suggestions use the full column width (no readable-width cap); Song Detail's instrument cards should follow the web's two-column card grid at regular width.
- Player Bands rows are opaque edge-to-edge list rows on the Mac (iPhone design), not glass cards.
- Rivalry and Band Detail are not captured on the Mac (need live ids); the CHOpt path image shows mojibake in artist names (service-rendered PNG, not native text).
- Real Liquid Glass appearance and VoiceOver/Full Keyboard Access on the Mac are unverified (Automation Mode needs operator authentication).
- 2026-10-04: the always-on two-column list/detail and draggable divider are superseded by [split-view.md](split-view.md) (on-demand split fixed at the content-area midpoint; persistent sidebar stays).
