# Festival Native Apps: agent entry point

Read this file first, then [.agents/README.md](.agents/README.md) to the relevant **pattern**, page, control, platform and test rules. For the current plan, lanes and file ownership read [PROGRESS.md](PROGRESS.md) §1–3 and §5 only; §4 and §6 are history. **Tracker issues** (release-machine workers) start with the [fix-reported-issue](.agents/skills/fix-reported-issue/SKILL.md) skill. The machine-readable contract is [contracts/product.json](contracts/product.json); documentation alone cannot declare a platform complete.

## Invariants

- **Pattern first (operator, 2026-10-05).** A behavior that appears on more than one page or platform (scroll-edge fades, materials, nav chrome, modals, leaderboard rows, load transitions, empty/error states, Quick Links, section headers) has one record in [.agents/patterns](.agents/patterns/README.md) and `contracts/patterns.json`, with its canonical component per platform. Fix the pattern, not the instance: extend the canonical component and sweep its consumers; never add a parallel implementation. Changing a pattern rule, nav chrome or materials, or departing from platform guidance the owner hasn't chosen, is a **documented design decision** ([design-decision](.agents/skills/design-decision/SKILL.md)): agents decide (operator, 2026-10-05: automated), weighing options with the design ladder and precedence table, post the rationale on the issue and record it in the pattern doc; the owner may override with `/choose`. `python3 tools/pattern_guard.py` guards the known regressions.
- Implement **native** SwiftUI for iOS/iPadOS and macOS, Kotlin/Compose for Android, and provisionally C#/WinUI 3 for Windows. Fluent semantic design tokens guide content; system navigation, safe areas and accessibility are native. Do not copy device-pixel heuristics or ship a WebView/React Native UI.
- Never embed or request the service's privileged `X-API-Key`. Native Debug and Release launches use keyless public HTTPS by default; fixture-backed tests must explicitly select a loopback origin. Document each public endpoint's wire format and side effects; use mock fixtures for automated UI tests. Do not send selected-profile headers: they can register activity even on cached GETs. Call band search only as the allowlist allows (read-only since the #320 service fix; until it is deployed its missing-projection fallback writes membership state), and never call player stats (its GET may store tiers), band sync-status (its GET registers bands), profile tracking, name refresh, scrape, maintenance or load tests against production. Require an authorized mutation-free service policy before enabling the blocked reads. Details and endpoint allowlist: [.agents/platforms/service-safety.md](.agents/platforms/service-safety.md).
- **Online-only for now** (operator, 2026-09-27): do not build offline/warm-cache disclosure UX. In-process caches for speed are fine. Existing publication-provenance guards may stay, but new features should not add new provenance machinery.
- Never apply Shop-derived Songs filters, Shop sort/grouping or Song-row Shop badges to catalogue rows from a different observed publication. A failed new-catalogue read may retain older rows, but must show explicit paused state rather than hide, reorder or badge them from a newer Shop feed. Once an identity is selected, public Shop membership filtering does not depend on player-score synchronization.
- Never project a newer selected-player score index, FC chip or numeric metadata onto retained older Songs rows. Track the score index's observed publication separately, require catalogue, score and session observations to match, and show a readable paused state until Songs update. Missing provenance is not an anonymous/no-score success; an observed ID is not a response-header proof.
- Apply Songs' selected-player Score/FC filters only to a matching, available score index; pause rather than interpret 202/403, publication mismatch or unsupported invalid-score substitution as missing scores. Preserve independent public Shop filtering. Saved per-chart predicates must be bounded/typed, scoped to Settings-visible charts and cleared on confirmed player deselection; a corrupt saved filter blocks unfiltered success until explicit Reset.
- Treat page artwork as decorative and ephemeral: use only the shared bounded in-process byte/decoded-image caches, clear them on a known publication change, and stop loads/animation for Low Data Mode, inactive scenes or opaque accessibility presentation. Never bundle third-party album art into distributable apps.
- Keep the Apple `UILaunchScreen` key and named launch color asset: without them, older iOS/iPadOS runtimes may run in legacy 320×480 or 768×1024 compatibility frames and invalidate layout/audit evidence. Compare app screenshots against simulator framebuffer dimensions rather than the XCTest runner's `UIScreen`.
- The source website is an independently owned, currently dirty worktree. Read it for behavior; never reset, commit, or amend its changes as part of this repo. Pin a clean source revision before certifying full parity.
- Build on all platforms as needed, but run **one product simulator/emulator at a time per host**. Never stop, reset or repurpose another project's devices. On this Mac, pin `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` per command rather than changing the global developer directory.
- **Ownership (operator, 2026-10-02):** Opus 5.5 (this orchestrator) owns **macOS, iPadOS and iPhone Duo**, in that priority (macOS to parity first; skip ahead to iPad, then Duo, when blocked). iPhone, Android and Windows are developed by separate Copilot sessions on the machine mesh via issues/PRs — do not take iPhone/Android/Windows work, and avoid editing iPhone-only code; shared Swift changes must keep the iPhone build and tests green. Keep each platform's accessibility, coverage, visual and performance evidence separate; shared Swift work does not certify another platform.
- **Apple design guidance:** every Apple UI decision (macOS, iPadOS, iPhone, Duo) goes through the installed **`apple-hig` skill** (`~/.claude/skills/apple-hig`; run its `scripts/hig_route.py` helper and read the routed files) before implementing or reviewing; cite the HIG file in the page/control `*.md` note. iPhone Duo adaptation work uses the skill's **`/duo`** workflow (`references/duo.md`, stage by stage, native code only) — it is the sanctioned shortcut for bringing Duo up to speed. Apple HIG still wins over Fluent where they conflict.
- Use `master` as the integration branch. Push accepted small cohesive commits; other hosts pull after each integration. Parallel lanes work in separate worktrees on disjoint folders (see PROGRESS.md) and integrate with `tools/lane_integrate.sh`. PR auto-merge is permitted only when the PR author is exactly `SFenton`; all others, including bots, require manual merge.
- App versions are `YYMM.DD.NN` tags (`<platform>/v<version>`) created by `version-bump.yml` on master; only that bump starts a build/release. Never hand-edit `WhatsNew.json` or the version: put user-facing notes in `Release-Note:` / `Release-Note-iOS|macOS|Android|Windows:` commit trailers ([release machine](.agents/workflow/release-machine.md#versions-notes-and-whats-new)).
- Require a page spec, control state/transition spec, test IDs, visual references and accessibility order before declaring a surface ported. `python3 tools/verify_product.py --strict` is the parity inventory gate; source coverage is separately at least **95% non-UX / 90% UX** on each language/platform. Finite reachable control states, screenshots, navigation and accessibility need independent evidence, not just line coverage.
- Make a deterministic tool or fixture for a repeated reliable operation before turning it into longer agent prose. Keep contracts, scripts and these guidelines synchronized as product discoveries occur; no generation from expanded TypeScript models without verifying the actual wire payload.
- Document functions in language-standard form: Swift DocC `///` with parameters/return and `// MARK: -` regions; Kotlin KDoc and `// region`; C# XML docs and `#region`; C++ Doxygen; Python docstrings. Add only clarifying inline comments. Test behavior shifts, not only compilation.

## Change loop

1. **Reproduce, don't just read:** check the installed PWA on the target platform (reference captures + behavior notes in `.agents/testing/pwa-reference/`; capture new states with `tools/pwa_*` / platform PWA tools when missing). Find the precedent: `python3 tools/pattern_guard.py index` / `which <file>` and the owning pattern docs ([consistency-sweep](.agents/skills/consistency-sweep/SKILL.md)). Then read the web source for the page/control (`$FST_WEB_SRC`; agent hosts `~/fst-agents/repos/FortniteFestivalLeaderboardScraper/FortniteFestivalWeb/src`, the operator Mac `~/repos/FortniteFestivalLeaderboardScraper/FortniteFestivalWeb/src`) and its spec: `.agents/pages/<id>/spec.md` or `.agents/controls/<id>/spec.md`, plus only your platform's file (`ios.md`, `ipados.md`, …). Identify inputs, states, dependent controls and navigation edges. Compare against the web app at the same viewport; Apple HIG wins over Fluent where they conflict.
2. Implement in your lane's folders. Add unit tests for new non-UX logic as you go, and with every UI fix or feature a UX test and an **accessibility test** on each platform you change (name/role/state, reading order, target size, text scaling; [accessibility tests with every change](.agents/testing/strategy.md#accessibility-tests-with-every-change)). Run only new/changed tests while iterating.
3. Check visually with `python3 tools/ios_sim.py build` + `python3 tools/ios_sim.py shot --tab … --route …` (serialized simulator; never call `simctl` directly while other lanes run).
4. Record durable findings as rules in the right `.agents` file, the pattern doc first when the behavior is shared ([docs conventions](.agents/workflow/docs-conventions.md); `python3 .agents/_tools/check_docs.py --fix` and `python3 tools/pattern_guard.py` must pass). Commit small cohesive commits, integrate with `tools/lane_integrate.sh`, and update PROGRESS.md in your final report. UX and accessibility tests ship in the same PR as the change; whole-app audits come when the app is complete and screen-reader walkthroughs after that (see PROGRESS.md §3).

Opus 5.5 is the orchestrator and sole researcher; there are no tandem research/review passes. Production access, signing, asset licensing, deployment and publication have separate approval gates.
